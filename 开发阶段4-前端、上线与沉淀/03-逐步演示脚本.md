# 03 · 逐步演示脚本

> 对应路线图第 14 周演示准备。本文给出现场路径和解说词；本轮不录制视频。

## 一、环境准备

1. 启动阶段一与阶段二本地容器、Go API、网关，并按阶段三 README 启动 FastAPI。确认 `/api/v1/ping` 和预测服务 `/health` 可用。
2. 在忽略的根 `.env` 设置本机配置；本地开发 WebSocket 白名单为 `WS_ALLOWED_ORIGINS=http://127.0.0.1:5173`。启动后端时确认该环境变量已加载。
3. 用 Node 24 在 `stages/04-frontend/` 执行 `npm ci`、`npm run dev`，浏览器打开 `http://127.0.0.1:5173`。
4. 准备已有登录账号、测试设备与温度 `>55` 的重要告警规则。使用阶段二 `scripts/smoke-stage2.py` 的 MQTT 上报方式，或阶段三回放脚本制造连续遥测和越限；正式演示前先确认上报设备在设备页可见。

## 二、点击路径与解说

### 步骤 1 · 登录与总览

在登录页输入已有账号密码，进入“运行总览”，不刷新页面。

> 解说词：“前端使用现有 JWT 接口；总览首先取当前汇总和近期曲线，随后用一次性票据接入实时通道。这里的百分比是当前运行正常占比，功率是瞬时功率。”

### 步骤 2 · 实时变化和告警

让回放脚本先上报正常温度，再上报超过规则阈值的温度；在总览选择该设备，观察功率曲线变化与重要告警弹窗。可点顶栏“静音提示音”。

> 解说词：“数据由 MQTT 经网关落库并进入实时推送；越限由后端规则判断。页面展示新告警，并保留历史告警入口。”

### 步骤 3 · 告警确认和关联曲线

点击总览告警进入“告警中心”详情，核对实测值和阈值，点击“确认告警”，再点“查看关联设备曲线”。在设备详情切换温度指标与 1 小时或 24 小时范围。

> 解说词：“确认记录操作人与时间。历史曲线从 TDengine 查询真实遥测，24 小时窗口会分段查询并保留极值。”

### 步骤 4 · 预测排行与依据

点击侧栏“故障预测”，打开一台有预测结果的设备“查看依据”，展示概率、窗口时间、模型版本、来源和主要特征贡献。

> 解说词：“排行区分有效、过期和无结果。当前模型基于合成数据训练；特征贡献解释模型本次判断，不能直接当作故障原因或真实场站效果。”

## 三、收尾核对

- 全程无需手动刷新；检查控制台错误与实时连接状态。
- 若只有旧预测，明确展示“结果过期”，不要口述为当前风险。
- 演示完毕保留告警确认记录。第 15 周公网部署见 [[04-第15周·部署上线]]；第一版 M4 现场证据见 [[07-第一版M4现场复验]]。视频复盘属于后续对外材料，不影响第一版验收。阶段五飞书业务通知需另按 [[开发阶段5-飞书告警通知/02-验证与运维]] 核对。
