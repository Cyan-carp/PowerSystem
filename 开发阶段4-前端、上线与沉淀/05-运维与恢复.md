# 05 · 运维与恢复

> 对应路线图第 15 周监控、备份和恢复任务。以下操作面向 R730xd `/opt/powersystem`，详尽脚本见 [[stages/04-frontend/deploy/README.md]]。

## 一、监控与故障注入

- Prometheus 每 **15 秒**采集 Go API `/metrics`、node-exporter 主机指标和 cAdvisor 容器指标；三个 target 均为 `up`。Grafana 内网看板包含 API 可用性、当前告警、请求、耗时、主机与容器资源。
- 规则 `PowerSystemAPIDown` 在 API 抓取失败 1 分钟后触发；`PowerSystemDiskHigh` 在磁盘使用率超过 80% 持续 5 分钟后触发。Grafana 当前告警面板从 Prometheus `ALERTS` 读取。邮箱与 Webhook 通知本周没有接入。
- 现场暂停 API **95 秒**后，`PowerSystemAPIDown` 状态为 `firing`；解除暂停后，首次探测即可访问 `/api/v1/ping`，20 秒后告警列表为空。演练期间以 shell trap 保证 API 恢复。
- Prometheus 与 Grafana 仅绑定 R730xd 回环地址 `19090`、`13000`，可用 SSH 本地转发访问。数据库、MQTT、AI 与指标端口均不经 FRP 暴露。

> 95 秒为本次注入时长；`recovery_seconds=0` 是解除暂停后第一次 1 秒探测的结果，不表示所有前端连接在零秒完成重连。WebSocket 建连及遥测事件已单独经公网验证。

## 二、每天加密备份

- R730xd `/etc/cron.d/powersystem-backup` 每天 **02:30** 执行 `backup.sh`；云端 `/etc/cron.d/powersystem-backup-retention` 每天 **03:00** 清理超过 7 天的备份。两台服务器定时服务均运行。
- 备份包含 PostgreSQL `pg_dump`、TDengine `taosdump`、网关和模拟器 SQLite 在线快照以及模型 `model.json`、`metadata.json`。每个文件计算 SHA256，再将包用 GPG AES256 对称加密，经只允许 SFTP 的 `powersystem-backup` 账号传到云端 `/srv/powersystem-backups/`。
- `.env`、加密口令、备份私钥与演示账号口令均只存服务器私有路径，不入 Git。云端只保留加密包及其 SHA256 文件。
- 首次有效备份 `powersystem-20260928T124506Z` 上传成功；修正校验文件为相对路径后，`powersystem-20260928T125448Z.tar.gz.gpg.sha256` 在云端执行 `sha256sum -c` 显示 **OK**。
- 最终脚本复验生成 `powersystem-20260928T134419Z`，回读云端密文后 SHA256 校验为 **OK**，明文临时目录在脚本退出时自动清理。

#### 手动备份

```bash
bash /opt/powersystem/stages/04-frontend/deploy/backup.sh
```

## 三、隔离恢复演练

演练使用 `powersystem-20260928T124506Z`，在独立 Compose 项目 `powersystem-restore-1790599552` 和新数据卷内恢复，未覆盖生产卷。

- GPG 解密成功；模型、PostgreSQL、两份 SQLite 快照及 TDengine 导出文件的 SHA256 全部校验通过。
- `pg_restore` 后 inbox 为 **597** 条；`taosdump` 恢复后 TDengine 遥测也为 **597** 条，三张子表恢复成功。
- 网关和模拟器 SQLite 快照文件为 **2** 份。API 当前没有 SQLite 主文件；其相关状态使用 PostgreSQL/Redis，并未伪造第三份快照。
- 核对完成后，按精确项目名删除隔离恢复容器及测试卷，并清理演练解密目录；生产卷和加密备份保留。

#### 恢复核对

```bash
bash /opt/powersystem/stages/04-frontend/deploy/restore-verify.sh /var/backups/powersystem/powersystem-20260928T124506Z.tar.gz.gpg
```

> 恢复脚本会创建独立项目与数据卷。清理演练资源前核对 `isolated_project` 名称，绝不对生产 Compose 项目执行 `down -v`。
