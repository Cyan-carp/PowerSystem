# 01 · 公网攻击面收敛

> 本页记录第一版从旧 HTTP 演示入口升级到可信 HTTPS/WSS、最小端口和公钥运维入口的设计与实施结果。具体服务器命令仍以 `stages/04-frontend/deploy/README.md` 为准。

## 一、入口链路

当前外部用户只访问云端 `443`。云端 Nginx 使用受信任的 Let's Encrypt IP 证书终止 TLS，再经 `127.0.0.1:3667` 转发到共享 FRP；WebSocket Upgrade 头同步转发。旧 `3667` 监听因共享 FRP 进程仍存在，但 IPv4 和 IPv6 防火墙规则拒绝非回环访问，并由 systemd 在开机时恢复规则。

证书续期计时器每日运行两次。手工续期服务和 `certbot renew --dry-run` 已通过；续期脚本只在证书文件变化后校验并重载 Nginx。

## 二、服务器边界

- R730xd 和云端 SSH 均使用公钥，密码认证关闭；root 只允许无密码的公钥方式。
- R730xd 仅将前端、Prometheus 和 Grafana 绑定到宿主机回环地址；数据库、MQTT、Redis、TDengine、AI、API 和飞书适配器没有直接映射公网。
- 已移除需要宿主机高权限挂载的 cAdvisor，监控改用不具备 Docker 控制能力的主机与应用指标。
- 公网注册接口由 Nginx 拒绝，登录限速保留；管理员由服务器本机脚本创建。

## 三、仓库公开安全

第一版候选检查覆盖常见私钥头、GitHub 令牌、云密钥和飞书机器人 URL；另将服务器现用的密码、签名、令牌和备份口令逐项与候选文本比对，均未命中。远端 `main`、`dev` 可达历史也按常见格式扫描，未发现对应命中；公开 Release 没有上传资产。

公开 IP、端口和路径属于攻击面线索，但当前未发现能直接登录服务器的凭据。真正影响服务器控制权的是 GitHub 写权限、部署密钥、Webhook、分支保护和实际部署流程；这些管理端设置仍应由仓库所有者定期核对，并固定从审查过的提交或标签部署。

> 静态扫描只能说明给定模式和已知值未命中，不能证明所有形式的秘密都不存在；每次发布仍须重新检查暂存文件、历史新增和 GitHub 管理设置。
