# 02 · 加密备份与隔离恢复

> 本页记录第一版备份对象、加密传输、隔离恢复和整机丢失时的关键依赖。备份包与私有配置不进入公开仓库。

## 一、备份链路

R730xd 的 `powersystem-backup.timer` 每天触发 `backup.sh`。脚本要求通过私有文件或环境变量显式设置异地目标，不再内置作者账号和目录；随后完成以下工作：

1. 导出 PostgreSQL 与 TDengine。
2. 对网关和模拟器 SQLite 队列做在线快照。
3. 收集模型、元数据、`.env`、飞书 Webhook、签名密钥和业务通知令牌。
4. 对所有文件生成 SHA256 清单并打包。
5. 使用服务器私有口令进行 GPG AES256 整包加密。
6. 通过仅允许 SFTP 的专用账号上传异地密文和摘要。

## 二、隔离恢复

`restore-verify.sh` 解密后先验证内部 SHA256，再创建独立 Compose 项目和独立数据卷，恢复 PostgreSQL 与 TDengine并核对两个 SQLite 队列、模型、私有配置和 `business_notification_outbox` 表。验证过程不停止生产服务，也不复用生产卷。

2026-09-29 的两次记录：

- 更新前：PostgreSQL 与 TDengine 各 43,113 条，两个 SQLite 队列存在。
- 第一版部署后：PostgreSQL 与 TDengine 各 44,295 条，两个队列、模型、`.env`、三个通知私有文件和业务投递表均核对通过。

两份密文的 R730xd 与云端 SHA256 一致。测试用隔离项目、临时卷和解密目录已清理；生产卷与云端密文保留。

## 三、整机恢复缺口

加密口令目前只存在于 R730xd 的 root 私有文件。若整机同时丢失，云端密文仍在，但无法仅凭密文重建口令。项目所有者已选择自行离线保管第二份，步骤见 [[备份口令离线交接与整机恢复步骤]]。

> 只有当副本位于 R730xd 之外，并用隐藏输入核对显示 `MATCH`，整机灾难恢复才可判为通过。口令本身不得写入项目笔记、聊天、截图或 GitHub。
