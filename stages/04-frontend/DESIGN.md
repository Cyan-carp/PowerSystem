# 设计说明 · 浅色控制台

> 记录这一版界面的前提、取舍与已知问题，不是使用文档。启动方式见 `README.md`。

| 项 | 内容 |

## 二、方向从哪来

先出过四张互不借鉴的风格稿：

- **A** Linear 式暗色：近黑画布、细发线、单一淡紫。
- **B** 杂志编辑感：奶油纸底、巨型衬线数字、橙色。
- **C** 系统化浅色控制台：灰蓝底、白卡片、indigo、环图 + 面积图 + 数据表。
- **D** 等距 2.5D 沙盘：云端平台、发光边节点、玻璃拟态卡。

选 **C**。理由不是它最有个性，而是它最能承载「每天看很多遍」的工作：信息密度可控、状态色有明确语义、表格与图表都有成熟读法。A 的深色在这个项目里已被否决过两次；B 的大数字会挤掉 143 行设备台账；D 的立体插画撑不起告警流与表格。

这一版是**整站重构**：沿用上一版的信息架构与真实数据口径，视觉系统整体替换为 C。

## 三、关键设计决策

**指标卡只放四个数，且四个数都能点。** 当前出力、设备在线、今日发电、活动告警——其中「设备在线」进设备台账、「活动告警」进告警中心，跳转后看到的筛选结果与卡片数字一致（活动 = 未处理 + 已确认）。

**功率曲线是手写 SVG，不引图表库。** 需要控制的东西很少：一条折线、一层渐变面积、四条网格、六个时间刻度、一个悬停探针。手写换来三件事：轴上限取整到 1/2/2.5/5 的整十倍（不会出现 13,249.7 这种刻度）、曲线右端始终有一个「当前点」、导出 CSV 不需要经过图表实例。

**右栏三张卡片的指标，全部换成真实可算的口径。** 参考稿里的「2:00 AM」「+」是装饰，这里换成了：

| 卡片 | 第一个环 | 第二个环 |
| --- | --- | --- |
| 资源状况 | 边节点在线 3/5 | 模型一致率 4/5（`model_stale` 判定） |
| 设备状态 | 设备在线率 142/143 | 健康度 96（后端加权分） |
| 告警构成 | 紧急 / 重要 / 次要的 100% 堆叠条 + 已恢复计数 | — |

**「告警趋势」改成「告警构成」。** 假后端只有 26 条告警、跨度数小时，画不出可信的 7 日趋势；把级别构成与已恢复数画清楚，比编一条趋势线诚实。

**表格用固定布局 + 百分比列宽。** 自动布局会把剩余宽度全灌给第一列，形成一个大洞；固定布局让每列宽度可预期，第一列再配 `min-width: 0` + 省略号。窄屏不压扁，改为表内横向滚动。

**状态色只出现在胶囊、圆点和进度条上。** 表格文字保持中性色；健康分 72–87 的设备进度条用品牌蓝而不是橙色——整张表 80 多台「注意」全染橙，就没人会注意真正的异常。语义交给状态胶囊。

**详情一律走右侧抽屉。** 告警、健康、预测共用同一个 420px 抽屉组件；地址栏同步 `?id=`，可以直接分享到某一条。抽屉支持 Esc 关闭、点遮罩关闭。（设备详情在第十节改成了独立路由，因为它要放曲线查询与导出，抽屉装不下。）

**空态不摆一句「暂无数据」。** 助手页没有消息时给一个居中的欢迎区 + 三个可直接点的示例问题；表格筛空时说明「当前筛选下没有告警/设备」。

## 四、与参考稿的偏差

参考稿是单页静态稿，这里要落到四个路由和真实接口，以下是有意偏离：

1. **Assets 表换成「场站对比」。** 云边协同的核心是「哪个站出问题了」；一行一个场站，在册/在线率/当前出力/活动告警/遥测未知，点行进该场站的设备清单。参考稿的 6 列结构保留。（第二轮曾做成「边节点状态」，第十节因真后端没有边节点资源而换回场站维度。）
2. **设备台账单独成页，143 台设备、8 行/页、18 页。** 参考稿的 `01 / 18` 分页在这里是真实可用的。
3. **资源/设备环图的两个环都有含义**（见上表），不做装饰性仪表。
4. **不做「Insights」二级页签。** 只有四个模块，顶栏显示当前页名即可，不做假导航。
5. **图表范围是 6 / 24 / 48 小时**，不是「Last 7 days」：假后端的日照曲线按天重复，给 7 天只会得到七条一样的山丘。

## 五、评审改了什么

按截图逐轮修的实际问题：

1. **边节点名称与「上行链路」串列。** 根因是 `.cell-stack` 里放了两个 `span`（行内元素），省略号不生效。改为 flex 列 + `display:block` + 表格 `table-layout: fixed`。
2. **「批次同步率 0%」。** `/edge/sync` 只返回在途批次（lagging / blocked / inflight），没有已同步批次，算出来恒为 0。换成模型一致率（4/5 节点同版），并把「在途 8 批」写进下方提示。
3. **纵轴上限 20k，曲线只到 13k。** 轴步长改为 nice number，上限落在 15k，刻度变成 0 / 5k / 10k / 15k。
4. **分页在首屏之外。** 表格页从 10 行/页降到 8 行/页，18 页正好对应 143 台设备。
5. **设备表一片橙色。** 健康分 75–87 占多数，进度条改为品牌蓝，橙色留给状态胶囊。
6. **告警构成把「已恢复」算进级别堆叠条，比例超过 100%。** 堆叠条只放三个级别，已恢复单独一行。
7. **持续时长显示「41 分 0 秒」。** 整分钟不再补 0 秒。
8. **顶栏「处理告警 19」跳过去只有 13 条。** 按钮改为带未处理数（13），概览卡「活动告警 19」跳到新增的「活动」筛选。
9. **助手页首屏一大片空白。** 增加欢迎态与示例问题。
10. **1280px 下三卡被挤到表格之后。** 两栏断点从 1360 调到 1240，1280 仍保持左右布局。
11. **窄屏卡片标题被搜索框挤成竖排。** 390px 下「告警列表」四个字各占一行。`.card-head` 改为可换行、标题与副标题 `flex: 0 0 auto`；≤760px 时带搜索框的卡片头让工具条独占整行。
12. **告警读数不合量纲。** 假后端原来给五种指标发同一组数字，于是出现「失效风险 78.1 / 阈值 72」。改成按温度 ℃ / 电压 V / 电流 A / 功率 kW / 失效风险 0–1 概率各自取值，表格与抽屉补单位与小数位，解读文案里的单位也随指标走。
13. **示例问题在助手页出现两次**（空态一处、右栏一处）。右栏「试试这样问」改为只在对话开始后出现。
14. **设备表图标按健康分着色**，75 分占多数造成整列警示橙。图标只表达设备类型（统一品牌蓝），分级交给进度条与状态胶囊。
15. **遥测状态码直接显示「1」**。映射成 运行 / 停机 / 故障。
16. **右栏标签「云 · 边」与「端」不对称**，统一为「云边」「端侧」。

## 六、第二轮：按参考稿逐项收敛（ui-ux-pro-max）

第一版虽然用了 C 的方向，但构图与细节离参考稿还有距离。第二轮用 C 图对应的 skill（`ui-ux-pro-max`，四张概念稿里 A 来自 awesome-design-html、B 来自 frontend-design-3、D 为独立方案）逐项对齐：

| 参考稿的特征 | 这一轮怎么改 |
| --- | --- |
| 明亮企业蓝，不是紫调 indigo | 主色 `#4f46e5 → #2f6bff`，连带曲线、环图、渐变、图标轨阴影全部换掉 |
| 左指标卡 + 右栏从顶部开始 | 指标卡从通栏移进左栏，右栏与指标卡同一起点；≤1440px 数值与内边距收一档 |
| 指标卡是裸色字形图标 | 去掉 32px 底色方块，23px 描边图标直接着色；活动告警不再用红，避免把计数读成「全是紧急」（第三轮定为品牌蓝） |
| 搜索框紧接页名 | 顶栏改三段栅格，搜索框改为浅灰填充（第三轮改成页名后直接跟搜索，见第八节） |
| 更松的留白与更软的阴影 | 卡片内边距 18→20px、圆角放大，阴影改为「大而淡」的多层 |
| 表头浅灰底、分页在左下 | 表头改 `#f5f7fb` + 600 字重；分页控件移到左侧、当前页改白底边框，条目统计挪到右侧 |
| 每张卡右上角「···」 | 新增 `CardMenu`：不是装饰，点开是「导出该卡数据 JSON」与对应页面跳转，Esc / 点外关闭；曲线卡与边节点卡把原图标按钮（导出 CSV、重新载入）收进同一菜单，全站统一为「每卡一个 ···」 |
| 更粗的环图 | 环宽 9→11px |

**仍然不照抄的部分**：参考稿里环图中心的「+」与「2:00 AM」标签、把「2:00 MWh」写进表格、坐标轴上的时间串行，都是 AI 出图的痕迹，没有信息量。这一版保留真实口径（百分比、单位、采样点数），只取它的视觉语言。

## 七、补齐功能页：健康 / 预测 / 报表 / 定期任务

这四页不是新需求，是最初独立重写时漏掉的：本目录只做了主干四页，原项目 `PowerSystem/stages/04-frontend` 的 10 个视图一直原样保留、未被删除。假后端本来就带着 `/health/*`、`/predictions`、`/reports/*`、`/agent/schedules` 全部接口，所以补齐页面不需要改后端契约（只在读任务时补了一次排期重算）。

| 页面 | 取数 | 关键口径 |
| --- | --- | --- |
| 健康排行 | `/health/devices` + `/stations` | 只用有效遥测算分；无采样记「未知」，不进排名也不拉低场站均分；名次直接用后端 `rank` |
| 故障预测 | `/predictions` + `/stations` | 概率条上必须画阈值竖线，否则「76%」看不出是否越线；分桶按 20% 一档；`stale` 单独提示 |
| 统计报表 | `/reports/availability`、`/reports/alarm-timeliness` | 可用率分母是「有数据时长」，未知单列；及时性拆确认/恢复/遥测恢复/预测恢复四行 |
| 定期任务 | `/agent/schedules` + `/:id/history` | 暂停立即生效，恢复与新建/修改都走审批（提交生成待批运行）；授权到期自动暂停 |

**这一轮踩到并修掉的两个口径错误：**

1. **报表把「台·时」当成墙钟小时。** 假后端按设备返回运行/停机/故障毫秒，直接相加再除以 3600000，会得到「40 台设备 7 天 = 6,593 小时」这种超过窗口时长的数。改为表格用「台·时」并在脚注写清 `设备数 × 小时`；概览格换成 **故障占比 / 未知占比**，这两个比值与设备数无关。
2. **定期任务的「下次执行」显示在过去。** 假后端的 `next_run_at` 是服务启动时算的，长跑之后必然过期。改为读取时按配置重算：`daily` 按配置时刻取下一个未来点，`interval` 仅在过期后顺延，避免每刷新一次就往后跳。

**故意没做的：** 登录与鉴权、告警的确认/派单写操作、报表自定义时间范围（后端固定 7 天窗口，界面不放假控件）。（设备详情独立路由当时也在这一列，第十节补上了。）

## 九、未验证 / 已知边界

- **只在 Chromium 下核对过 1600×1000、1280×900、900×1000、390×844 四个尺寸**；未测 Safari / Firefox，未测真机触摸与横向滚动手感。
- **没有登录页与鉴权。** 假后端不校验令牌，统一 `mock-token`；真实接入要补 401 与刷新流程。
- **全站只读。** 告警的确认 / 恢复 / 派单没有写接口，抽屉里明确写了这一点，不放无效按钮。
- **功率数值有两套口径。** `/dashboard/summary` 的「当前出力」固定在 mock 的 13:30 日照系数上，曲线按真实时刻逐点累加，右端与卡片可能差 1–2%。这是假后端的设定，不是前端计算错误。
- **健康分档位（良好 / 注意 / 待改善）是前端划的**，真后端只给 0–100 分和 `state`；`state` 四态（在线/离线/故障/未知）来自 `health.go`，别拿分数档位当状态用。
- **告警读数已按指标量纲重排**，但仍是 26 条固定样例、每 37 分钟一条，时间分布与级别分布都不代表真实场站；真实接入要换成规则引擎输出。
- 界面质量与视觉方向是两件事：这里验证的是真实数据下的渲染、跳转与空态，不代表这套风格已经是最终选择。

## 十、第四轮：深蓝主色、设备详情独立成页、接口按真后端对齐

这一轮三件事并行：用户点名的六处视觉微调、把丢掉的设备详情场景补回来、以及**按真后端逐条核对接口**（后面要覆盖到真实服务器，臆造接口必须先清掉）。

### 10.1 视觉微调（用户逐条点名）

| 问题 | 改法 | 为什么 |
| --- | --- | --- |
| 「淡蓝色改成参考图的深蓝」 | `--brand #2f6bff → #2563eb`，`--info` 与 brand 合并；曲线、环图、进度条、指标卡图标统一跟变量走 | 原来的蓝偏亮，白底上发飘；参考图的蓝更沉，配灰蓝底更像生产系统 |

### 10.2 设备详情回到独立路由

原来点设备行开一个 420px 抽屉，只有最新一帧遥测。用户问「之前点进去看设备详细场景的页面呢」——那个页面在原项目里是 `DeviceDetailView.vue`，独立重写这一版时被压成了抽屉。

抽屉装不下这次要放的东西：指标下拉、15min/1h/4h/24h 四档预设、两个北京时间输入框、查询、导出 CSV、曲线本体。于是恢复成 `/devices/:id`，六个区块：

| 区块 | 取数 | 说明 |
| --- | --- | --- |
| 设备档案 | `GET /devices/:id` | 含 `reference_vendor/reference_model`、建档时间；`/devices` 列表接口不返回这些字段 |
| 健康评分 | `GET /health/devices` | 大分数 + 名次 + `matched_by`/`sampled_at_ms`；分数颜色与 `state` 胶囊分开 |
| 最新遥测 | `GET /devices/:id/telemetry/latest` | 四格：温度/功率/电压/电流；运行状态用 `status` 映射中文 |
| 历史曲线 | `GET /devices/:id/telemetry` | 见下方两条硬约束 |
| 该设备告警 | `GET /alarms?device_id=` | 只显示未归档，空态写「该设备当前没有未归档告警」 |
| 失效风险 | `GET /devices/:id/prediction` | 概率条 + 阈值竖线 + `top_factors` 贡献条 |

两条硬约束决定了实现方式：

1. **单次查询窗口 ≤ 24h、点数 ≤ 5000。** 24 小时按 5 秒采样是 17,280 点，必然超限。前端按 **6 小时分段**并发取回再按时间戳合并去重——24h 最多 4 个请求，每段 4,320 点。
2. **时间输入按 `+08:00` 解析，不跟随浏览器时区。** `datetime-local` 给出的是裸字符串，直接 `new Date(text)` 会按本机时区解释；显示时也先把时间戳 `+8h` 再 `toISOString().slice(0,16)`，否则同一时刻在值班室和服务器上差 8 小时。

### 10.3 接口按真后端对齐（改动最大的一块）

做法：把 `internal/api/server.go` 第 90–186 行的路由表抄下来，逐个读 handler 确认字段名、必填项与限制，再据此重写 `src/lib/api.ts`、以及假后端的对应实现。结果是**删掉四个臆造端点**：

| 删掉的端点 | 为什么删 |
| --- | --- |
| `GET /edge/nodes` | 真后端没有「边节点」这一资源；云边关系体现在场站与设备的 `scope`（baseline/business）上 |
| `GET /edge/sync` | 同上，也没有回传批次表 |
| `GET /edge/models` | 同上，模型版本只在 `/health/devices` 的 `rule_version`、`/predictions` 的 `model_version` 里出现 |
| `GET /dashboard/power-series` | 真后端没有聚合曲线接口；总览曲线改为按基线站 3 台设备分批取 `/devices/:id/telemetry` 相加 |

三条容易踩的契约细节：

- **信封与裸 JSON 并存。** `/agent/runs`、`/agent/schedules`、`/agent/rule-preview` 是网关 `c.Data(status, "application/json", raw)` 直接吐出来的，**不套 `{code,message,data}`**；其余接口都是 `ok(c, …)`。`api.ts` 因此有两条通道：`request`（校验 `code !== 0`）与 `rawRequest`（直接返回 body）。
- **分页 `page_size` 上限 100。** 要拿全量设备不能传 1000，得翻页。`data.ts` 的 `deviceIndex()` 按 100/页翻到底，缓存 60 秒——告警只返回 `device_id`，补名称全靠这张索引。
- **`/devices/:id/telemetry/export` 是另一个窗口限制**（≤ 7 天），CSV 带 BOM、11 列固定表头；前端对 `Content-Type` 做校验，不是 `text/csv` 就抛错，避免把 JSON 错误当文件下载下来。

### 10.4 三个「构建能过、运行才炸」的坑

1. **`const window = computed(...)` 把全局 `window` 遮蔽了。** 详情页里用 `window` 命名查询时间窗口，于是 `window.setInterval` 变成「对 computed ref 取 setInterval」——运行时 `TypeError: window.setInterval is not a function`，而 `vite build` 完全通过。改名 `range` 即解决；`ReportsView` 里两个同名局部变量一并改掉。
2. **接口改名后漏改调用点。** `api.health()` 在重写时并成了 `healthDevices()`/`healthStations()`，健康页漏改，页面直接显示「健康数据未取到：TypeError: api.health is not a function」。教训：这类错误只在打开页面的那一刻暴露，所以回归必须**逐页截图**，不能只看构建结果。
3. **健康 `state` 是英文四态。** `health.go` 只返回 `online / offline / fault / unknown`；前端原来按「良好 / 注意 / 未知」筛选，接真后端后筛选结果永远为空。改法：`state` 四态直出、中文名走 `HEALTH_STATE_CN` 映射；「良好 / 注意 / 待改善」退回成**分数档位的统计口径**（概览格），不再参与筛选。假后端同步改成英文，并把离线/故障的分数从 `null`/42 改为 `0`，与真后端「离线记 0 分但不解释为已证实故障」一致。

### 10.5 助手补会话能力

原来助手页只有一条随时间累积的对话流，刷新即丢，也没有历史。补上：

- 顶栏与右栏各一个「新会话」；右栏「历史会话」卡读 `GET /agent/sessions`，点击 `GET /agent/sessions/:id` 回放 `turns`，删除走 `DELETE /agent/sessions/:id`。
- 发问走 `POST /agent/runs`（裸 JSON），首轮由服务端分配 `session_id`，前端拿到后回填标题并刷新列表。
- 空态仍是欢迎区 + 三个示例问题；「试试这样问」只在对话开始后出现在右栏，避免与空态重复。

### 10.6 这一轮的验证

- `vite build` 通过（14 个 chunk，新增 `DeviceDetailView`）。
- **9 条路由 × 4 档视口（1600×1080 / 1280×900 / 900×1000 / 390×844）无横向溢出、无 pageerror**（`.tools/responsive.mjs`）。
- 交互冒烟：`flow.mjs` 23 项、`flow2.mjs` 17 项全通过，含「点行进详情页 / 返回列表 / 会话新增与新建」。
- `screenshots/` 10 张图按新视觉重出；详情页视口高度按内容实测取 1400，一屏装完六个区块。

## 十一、第五轮：按 C 参考稿收敛表格、图表与字重，补回告警解读

这一轮全部由用户逐条点名，原则是「参考图怎么画就怎么画，不要自己创新」。

### 11.1 场站对比表改成参考稿的 Assets 表

| 改动 | 之前 | 现在 |
| --- | --- | --- |
| 对齐 | 数值列右对齐 | **全部左对齐**，数值与表头用同一条左边线 |
| 在线率 | 进度条 + 百分比 | **圆点 + 百分比**（≥95% 绿、85–95% 琥珀、其余红） |
| 活动告警 / 遥测未知 | 纯数字 | 圆点 + 数字（0 灰、1–2 琥珀、≥3 红） |
| 场站图标 | 带浅色底方块 | **裸色字形**，只有品牌蓝 |
| 表头 | 加粗深色 | 11.5px、500、`#4b5566`、`#f7f8fb` 底，上下各一条细线 |
| 页脚 | 分页条 + 跳转按钮 | 删除；只有「存在未注册设备」时才留一行警示 |

理由：进度条在 5 行的小表里既占宽又抢眼，而参考稿用「颜色 + 文字」就够了；表格里出现第三种视觉元素（条）之后，扫读速度反而下降。

### 11.2 功率曲线补齐竖向辅助线

`.grid` 里原来只有横向线。现在按 x 轴刻度再画一组等距虚线，和横线同色（`#ccd5e3`）、同 `3 4` 虚线节奏——参考稿的读法是「任一数据点都能顺到时间轴和功率轴」，只有横线时时间读数只能靠猜。渐变填充同时从 0.16 提到 0.20，面积才在浅底上浮出来。

### 11.3 指标卡按参考稿的比例重排

| 元素 | 之前 | 现在 |
| --- | --- | --- |
| 图标 | 23px / 1.7 | **27px / 1.85**，裸色不套底 |
| 图标与标签间距 | 7px | 13px |
| 标签 | 12px | 12.5px / 500 |
| 数值 | 30px / 700 | **31px / 700**，字距 −0.03em |
| 单位 | 13px / 600 | 13.5px / 500（更弱，让数字独占） |
| 内边距 | 18/20/16 | 16/18/18 |

「当前出力」同时改成 **实时有功功率**——「出力」在电力行业虽然通用，但「当前出力」读起来像口语，指标卡上应写清楚量纲与口径。

### 11.4 标题不再靠字重拉层级

中文只有 400 / 700 两档真实字重，写 `font-weight: 600/650` 会被渲染成粗体——这就是「场站总览、功率输出太粗」的根因。改为**字号拉层级、字重统一 500（渲染为常规）**：页标题 16px、卡片标题 15px、面板标题 15.5px。层级仍清楚，但不再一整屏粗体。

### 11.5 删除标题后的声明文字

九个页面的 `<p class="page-sub">` 全部删除（`口径与 /dashboard/overview 一致`、`提问走 /agent/runs` 这类），卡片里跟标题并排的接口路径与「数据来自 …」也一并去掉。参考稿的标题后面什么都不跟，说明信息要靠页面自己讲清楚。设备详情页的「数据源 /devices/:id · …」同样删除。

### 11.6 顶栏：图标放大 + 一条竖线

- 新增**告警解读**入口，样式为浅边框按钮（品牌蓝描边 + 星形图标 + 红点）。

### 11.7 告警解读回来了（`components/AlarmInsight.vue`）

上一版整站重写时这块丢了，只剩顶栏的告警通知弹层。现在补成右侧 420px 抽屉，内容六段：

1. **切换条**：最近 6 条未处理告警，点一下换一条；
2. **抬头**：级别胶囊 + 设备名 + 指标越限 + 触发时刻 + 响应时限（紧急 15 分钟 / 重要 2 小时 / 次要当日）；
3. **读数**：实测 / 阈值 / 越限百分比 + 越限条 + 判据与规则版本；
4. **可能成因**：按指标给三条模板（温度→散热遮挡、电压→组串开路、电流→短路熔断、功率→限发降载、失效风险→部件劣化）；
5. **建议动作**：三条有序步骤，按指标区分；
6. **旁证**：健康分与名次、该设备告警数、失效风险与阈值、告警来源。

**没有新增后端接口**：数据全部来自 `/alarms`、`/devices/:id`、`/health/devices`、`/devices/:id/prediction`，解读文本是前端规则生成的排查顺序，不是模型输出，面板底部明确写了这一点。
