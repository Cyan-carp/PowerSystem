# V4-S07 本机受控运维人工验收

本说明只适用于明确启动的独立S07本机环境；实际状态、运行编号和端口以本轮`environment.json`及正式测试页为准。不得访问生产做写验收。合成身份凭据由本轮聊天交接，不写入正式笔记。

## 第一批：批准、拒绝、刷新与证据包

1. 从本轮指定本机入口登录合成管理员，进入智能助手。发送`重启 s07-demo`；等待待批准动作，刷新页面，核对动作仍在原问题下。
2. 打开“核对并决定”，检查影响、目标版本、策略、站内目的地及恢复边界；批准。预期最终展示实际重启与健康检查通过，原问题下只有一份主结果。
3. 同会话再次发送`重启 s07-demo`并拒绝。预期未执行修改，不出现成功重启结论。刷新、切换会话再返回，检查两轮分别归位。
4. 发送`证据 s07-demo`，下载`service-evidence.json`并打开。预期包含本轮run/action引用、登记目标、健康观察、过滤事件及不完整日志声明，不包含日志原文/凭据/任意命令。

反馈模板：待批刷新=；批准结果文字=；拒绝结果文字=；返回原轮及重复=；证据包下载/打开=；异常步骤=。

## 第二批：过期与恢复状态

按Codex在第一批反馈复核后提供的短步骤执行；不要求持续守屏或等待精确过期时刻。Codex先准备已过期的真实批准并核对后台，再通知刷新读取。检查失效动作无有效批准入口、旧轮结果不重复或串轮。

## 复核边界

人工反馈只证明本人页面观察。Codex必须结合真实decision/refresh/download HTTP、阶段9批准/执行次数、适配器持久回执及实际进程代次复核；单凭202、截图或口头“正常”不能签收。技术并发、权限、撤权、漂移、未知、迁移、健康失败和冷恢复由Codex负责。停止订阅不等于取消任务，已发出的重启不会因取消自动撤销。

验收期间保留服务，明确告知本轮状态；结束时按实例/PID/专用PG路径核验归属后停服，写cleanup证据。服务停止后本页步骤不能直接使用，不假定前轮仍运行。
