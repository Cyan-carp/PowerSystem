## 二、环境

- Node.js 20.19+ 或 22.12+；本机系统 Node 22.11 不符合 Vite 要求，本次使用 Node 24 运行。
- 本机 Go API、网关、EMQX、TDengine、PostgreSQL、Redis。预测服务按阶段三 README 启动。
- 将根目录 `.env.example` 复制为忽略的 `.env` 并填入本地配置；本地跨端口 WebSocket 开发需配置 `WS_ALLOWED_ORIGINS=http://127.0.0.1:5173`。该值是精确 Origin，生产同源访问保持默认校验。

## 三、启动

在本目录执行：

```powershell
npm ci
npm run dev
```

打开 `http://127.0.0.1:5173`。Vite 将 `/api` 和 `/ws` 代理到 `127.0.0.1:8080`；WebSocket 请求保留浏览器原始 Origin。登录使用已有账号，JWT 仅保存在当前标签页的 `sessionStorage`，刷新可继续使用，关闭标签页或退出登录会清除。

## 四、验证

```powershell
npm run typecheck
npm test
npm run build
```

`dist/`、`node_modules/` 不入库。设备详情的历史查询使用 RFC3339 时间，每个请求跨度最多 4 小时；可选范围最多 24 小时。24 小时多段结果在浏览器按时间合并并保留极值抽稀。总览的“运行正常占比”来自后端当前状态统计，不是设备健康评分。预测模型目前以合成数据训练，页面对过期与无结果单独标识。

## 五、第二版解读面板

工作台顶栏提供告警解读入口，总览自动展示活动未读事件。队列按级别和时间排序，首次进入、WebSocket 重连与每五秒补查通过 JWT 取结果；恢复事件不重新自动弹出。

每条结论和建议可展开引用证据，曲线与预测原值保留来源及时间。业务卡片调用既有确认接口，监控只记录当前用户已读，关闭不等于确认。管理员检测会请求供应商；页面不接收模型密钥。确认成功后主动取详情，避免并发刷新短暂覆盖已读状态。

实测与模型不可用边界见[阶段二前端笔记](../../notes/01-项目调研规划与开发建设记录/第二版-智能体升级/问答及调度业务主智能体/废案-旧智能体方案/02-功能开发与阶段交付/02-告警智能解读与大屏联动/03-大屏卡片与证据回链.md)。
