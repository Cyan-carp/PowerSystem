## 告警解读与受控演示

- 自动告警默认采用固定模板与数据库事实，新固定任务不进入模型HTTP/熔断/预算预占；只有显式手动model演示走阶段7专属官方DeepSeek通道，`deepseek-flash`、thinking disabled、非流式JSON、无tools，不与阶段8问答或阶段9运维共用配置/密钥或隐式回退。事实由Go类型化供给并渲染精确值，模型只作有来源解释；每任务持久预占最多两次，失败不冒充AI成功。
- 服务器手动演示复用真实告警/通知outbox/解读任务事务和网页共同确认服务；提交后仅传Redis ID/类型提示，运行API重读已提交演示事实后走原WS广播。脚本支持model/fixed、新建/查询/确认/恢复；确认要求真实既有操作账号，恢复后新建留历史，不直接SQL改状态冒充推送。请求键幂等、明确手动标记、两类手动演示均排除自然每日额度，不假装真实故障；业务正文归补充业务05，安装命令归部署源码README，现行版本只认唯一状态页。
- 清单核对的143台合成设备使用上海09/11/13/15/17五个合法异常遥测窗口、每站每日轮换一台、10分钟自然回落，由普通规则生成normal告警，受控全局每日最多5条。旧自动simulation_scenario仅保留历史，不自动重开/补建；新手动演示使用独立manual版本标记；模拟策略门控不限制真实设备告警，异常输入须满足原接入契约。
- 告警ID和扫描高水位不得在历史清理时归零；旧业务记录恢复是独立备份恢复操作，不能随镜像回退自动恢复。发布/清理证据的正式入口为部署日志30。
- 主机发布资产版本以DB已提交版本为权威，不将失败导入的临时主机版本当历史。私有compose环境与实际Executor登记目录有既有布局关系；保留该关系并在prepare前核对真实bind，仍被引用的原ma-m4私有目录不得清理。

## 独立虚拟机与迁机边界

- 应用运行主机与物理PVE节点分开登记：项目监控和运维诊断面向独立VM，旧物理资产保留历史并停用；现行节点、VMID和地址只认唯一状态页。
- 生产工具逐机绑定hostname、machine-id摘要、DMI和虚拟化类型及能力；恢复包的主机登记只作证据，不能自动激活或全局去掉身份校验。Collector用stripped machine-id摘要，host-profile用原始字节摘要，两者不可混算。
- 从宿主迁入VM必须按实际运行镜像和全卷清单冷迁，源停服并禁自动重启/落栅栏，目标执行原完整门禁建立新基线；新数据产生后不直接启旧副本。日后PVE关机迁移/重启须单独计划重验，不能用V4仅两写者的备份回执豁免全体启动变化。
