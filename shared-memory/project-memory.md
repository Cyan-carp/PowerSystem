# 项目公共记忆

> 仅记录跨对话长期有效、经过确认的项目事实。对话过程和临时任务状态不得写在这里。

## 项目定位

- 合成车队唯一清单为 `stages/01-data-chain/simulator/fleet.json`，包含四个业务站 140 台和 `ST-01` 基线三台。`all/business/baseline` 为统一范围，旧 API 默认 all，前端默认 business；正式导入只新增业务设备，不覆盖或复活旧行。

- 项目名称：PowerSystem（新能源设备智能运维平台）。
- 正式项目笔记位于 `notes/`，该目录是唯一 Obsidian Vault；不要把仓库根目录作为 Vault 打开。
- 阶段源码、脚本和配置位于 `stages/`，部署相关内容位于 `deploy/`，运行证据和大型归档位于 Git 忽略的 `artifacts/`。

## 告警解读与受控演示

- 告警解读由阶段7专属官方DeepSeek通道承担，`deepseek-flash`、thinking disabled、非流式JSON、无tools，不与阶段8问答或阶段9运维共用配置/密钥或隐式回退。事实由Go类型化供给并渲染精确值，模型只作有来源解释；每任务持久预占最多两次，失败不冒充AI成功。
- 清单核对的143台模拟设备采用北京时间09/11/13/15/17五个日槽、每站一台的受控演示，10分钟以演示结束原因结束。自然遥测/预测继续保存展示，但不据此为受控模拟设备新建自然告警；真实设备和平台监控旁路。策略异常暂停演示，不自动退回自然模拟告警。
- 告警ID和扫描高水位不得在历史清理时归零；旧业务记录恢复是独立备份恢复操作，不能随镜像回退自动恢复。发布/清理证据的正式入口为部署日志30。
- 主机发布资产版本以DB已提交版本为权威，不将失败导入的临时主机版本当历史。私有compose环境与实际Executor登记目录有既有布局关系；保留该关系并在prepare前核对真实bind，仍被引用的原ma-m4私有目录不得清理。

## 协作记忆约定

- Codex 与 Workbuddy 使用 `shared-memory/` 交换上下文。
- 每个对话在 `shared-memory/conversations/` 使用独立 Markdown 文件。
- Workbuddy 执行任务前必须先读取协作规范、项目公共记忆和当前对话记忆。
- Workbuddy 可在完成任务时将需要与 Codex 共享的结果直接追加到当前对话记忆；Codex 复核后再决定是否提炼为项目公共记忆。
- 共享记忆不得保存秘密或替代正式工程文档和验收证据。
- 所有者的长期验收偏好（2026-10-24）：适合分步交接、不需实时盯守的浏览器点击、下载、打开文件及页面反馈等，优先由本人手动操作。Codex先准备隔离环境、简明步骤、预期结果和反馈模板，再结合实际文件、后端状态及审计复核；不得仅凭口头正常或截图签收。技术性并发、权限、安全和迁移检查仍由Codex负责；只验证本阶段影响范围，不重复未受影响且已有明确证据的历史验收。待人工反馈的门槛不得提前记为通过。

## 维护原则

- 以后每次上传项目文件到服务器或生产部署，先遵守 `notes/02-工程规范边界与验收治理/项目工程规范/05-上传服务器规范.md`，以 active 指针和实际挂载定位目标，并在当次更新服务器目录定位卡；不能依赖历史批次路径。具体命令只在阶段四部署 README 维护。
- 仅在稳定事实对未来多个对话都有帮助时更新本文件。
- 项目事实发生变化时，应先更新正式真相入口，再同步本文件的简明摘要。
