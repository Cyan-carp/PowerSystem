- 项目名称：PowerSystem（新能源设备智能运维平台）。
- 正式项目笔记位于 `notes/`，该目录是唯一 Obsidian Vault；不要把仓库根目录作为 Vault 打开。
- 阶段源码、脚本和配置位于 `stages/`，部署相关内容位于 `deploy/`，运行证据和大型归档位于 Git 忽略的 `artifacts/`。

## 告警解读与受控演示

- 告警解读由阶段7专属官方DeepSeek通道承担，`deepseek-flash`、thinking disabled、非流式JSON、无tools，不与阶段8问答或阶段9运维共用配置/密钥或隐式回退。事实由Go类型化供给并渲染精确值，模型只作有来源解释；每任务持久预占最多两次，失败不冒充AI成功。
- 清单核对的143台模拟设备采用北京时间09/11/13/15/17五个日槽、每站一台的受控演示，10分钟以演示结束原因结束。自然遥测/预测继续保存展示，但不据此为受控模拟设备新建自然告警；真实设备和平台监控旁路。策略异常暂停演示，不自动退回自然模拟告警。
- 告警ID和扫描高水位不得在历史清理时归零；旧业务记录恢复是独立备份恢复操作，不能随镜像回退自动恢复。发布/清理证据的正式入口为部署日志30。

## 独立虚拟机与迁机边界

- 应用运行主机与物理PVE节点分开登记：项目监控和运维诊断面向独立VM，旧物理资产保留历史并停用；现行节点、VMID和地址只认唯一状态页。
- 生产工具逐机绑定hostname、machine-id摘要、DMI和虚拟化类型及能力；恢复包的主机登记只作证据，不能自动激活或全局去掉身份校验。Collector用stripped machine-id摘要，host-profile用原始字节摘要，两者不可混算。
- 从宿主迁入VM必须按实际运行镜像和全卷清单冷迁，源停服并禁自动重启/落栅栏，目标执行原完整门禁建立新基线；新数据产生后不直接启旧副本。日后PVE关机迁移/重启须单独计划重验，不能用V4仅两写者的备份回执豁免全体启动变化。

## 实际发布材料与恢复边界

- 全备使用active冻结编排，不把历史单份Compose当运行口径。两个SQLite由当前固定Ops镜像的一次性无网络、源卷只读辅助器调用backup API取快照，不要求生产定义backup-helper服务。
- 新全备release-assets归档各自当前frontend固定镜像与五应用完整源码/构建回执；四服务实际只读/run挂载按逐文件摘要纳入MA加密归档，包含动作与桥凭据。恢复只核字节/来源，不能自动激活主机登记、原批准/凭据或重放任务。旧格式全备没有该frontend镜像时仍按其原全量基线+前端胶囊组合恢复，不外推新范围。
- 清退旧备份前须核实际双端副本及适用恢复；旧restore目录与容器/卷/网络须按精确旧项目和外部引用退出。生产源停服栅栏、原业务卷、有效冻结私有材料/回退镜像不是备份清退对象；历史receipt/维护JSON保留审计不等于继续保留旧备份载荷。
