# Workbuddy 协作规范

## 零、长期分工（2026-11-04 所有者确认）

- **Codex 负责判断与调度**：问题判断、方案设计、任务拆分与调度、阶段验收和最终结论；集中复核重大阶段结果，信任 Workbuddy 的执行与自检，不逐任务重复诊断和测试。
- **Workbuddy 负责具体实施**：代码、文档、脚本、数据处理、构建与发布操作等所有具体实施默认交 Workbuddy 执行；Codex 不抢做实施。
- **任务交接**：Codex 给出明确目标、范围、验收口径和权限边界；Workbuddy 按授权执行并交接实际改动、验证结果、风险和待办。
- **复核节奏**：Codex 只在阶段节点、重大结果、高风险路径或证据冲突时复核；常规任务不逐条重复全量测试，也不因“再确认一遍”重跑已有明确证据的检查。
- **共同底线不变**：所有任务开始前读取协作规范、项目公共记忆和当前对话记忆；安全脱敏、生产状态唯一事实源、身份/权限/业务数据完整性边界继续适用。

## 零之一、长时间任务的会话监视（2026-11-04 所有者确认，稳定协作偏好）

- **场景**：Workbuddy 长时间执行任务时，若 Codex 没有需要并行处理的工作。
- **规则**：Codex 应停止当前会话，不持续监视 Workbuddy 进程；由用户自行观察 Workbuddy 进程，待其完成后由用户通知 Codex 继续。
- **适用范围**：本条为跨对话长期有效的协作偏好，不随单次任务变化；不影响既有分工、复核节奏与共同底线。

## 一、任务开始前

Codex 每次委派 Workbuddy 时，必须在任务提示中要求 Workbuddy 依次读取：

1. `shared-memory/workbuddy-collaboration.md`
2. `shared-memory/project-memory.md`
3. 当前对话对应的 `shared-memory/conversations/<YYYY-MM-DD>/<YYYY-MM-DD-简短主题>.md`（按会话日期分目录）
4. 与任务直接相关的正式工程规范、README 或源码文件

未指定当前对话记忆文件时，Workbuddy 不得自行猜测或复用其他对话文件，应在结果中明确指出缺失。

**同一协作会话内的读取节奏（2026-10-28 起）**

- 同一对话记忆文件的首个任务必须完整读取上述四项，并核对实际工作区。
- 后续任务改为增量读取：先看当前对话记忆新增段落与本轮任务直接相关的文件，再读上次读取后发生变更的规范/源码；不必重读未变更的全文。
- 每次结果中声明本次实际读取范围、未重读的文件及理由；涉及发布、权限、数据、迁移等风险变更时，无论是否增量，都必须重新现查相关规范与当前状态。

## 二、执行边界

- 只执行委派任务明确授权的读取、分析或修改范围。
- 不把共享记忆当作高于源码、正式工程规范、测试证据和生产状态的真相来源；发生冲突时，以最新正式材料为准，并报告差异。
- 不读取、记录或输出密码、令牌、私钥、密钥文件内容及未经脱敏的隐私数据。
- 不修改其他对话的记忆文件。
- 未获明确授权时，不发布、不部署、不推送、不删除材料，也不改动生产环境。
- **新工程规则须经所有者确认**：发现流程或规范问题时，Workbuddy 可起草拟改章节、理由与影响范围，Codex 复核并给出判断，经所有者明确同意后生效；不再固定由 Codex 落稿。不把一次性排障做法直接写成长期条款，也不在任务中顺手扩充规范。
- **不为修 Bug 扩建平台**：修复缺陷以最小改动为限，不自动新增发布子系统、门禁分支、脚本框架或绕过入口。需要扩建时先说明必要性、影响面与替代方案，等待授权。
- **缺陷分级**：结果中区分「阻塞缺陷」（影响正确性、安全、数据或本次交付，必须修复后才能签收）与「可排期建议」（不阻塞本次交付，登记待办另行安排），不用建议阻塞交付，也不用“后续优化”掩盖阻塞项。

## 三、审查节奏

- Codex 对同一协作会话采用集中复核：一批改动完成后统一看一次 diff 范围、受影响的检查器或定向证据，只在证据缺失、触及高风险路径或结论互相冲突时补做定向核查。
- Workbuddy 在交接前按任务授权完成自检；不逐条重复全量测试，也不为“再确认一遍”重跑已有明确证据的测试；复用旧证据须写明运行编号、摘要与复用理由。
- 复用或增量读取不等于跳过现查：发布、权限、迁移、恢复相关的事实与当前状态仍须现查；技术门禁、备份与测试按 05 的默认豁免执行，除非所有者另有明确指令，或 Codex 基于具体证据判断某项确需执行并先取得所有者决定。

## 四、结果交接

Workbuddy 是实施与交接主体，结果应清楚列出：

- 完成了什么；
- 修改了哪些文件；
- 本次实际读取范围（增量任务须列出未重读的全文及理由）；
- 做了哪些验证及结果，复用了哪些既有证据；
- 仍有哪些风险、限制或待办，并按「阻塞缺陷 / 可排期建议」分开列出；
- 哪些结论建议同步进当前对话记忆或项目公共记忆。

如果任务结果中存在需要与 Codex 共享的记忆，Workbuddy 可以直接追加到任务指定的当前对话记忆文件，并须在返回结果中明确列出写入的文件和内容摘要。写入内容限于本次任务的关键发现、决定、修改、验证结果、风险和待办，不得覆盖已有记录，也不得修改其他对话的记忆文件。

Codex 负责复核 Workbuddy 返回的结果及其记忆增量，复核聚焦重大阶段结果、跨任务一致性与高风险结论，不重复逐任务诊断。只有经 Codex 复核、跨对话长期有效的稳定事实，才可同步到 `project-memory.md`；Workbuddy 未获单独明确授权时不得直接修改项目公共记忆。

## 五、推荐委派提示模板

```text
执行任务前，请先读取：
- shared-memory/workbuddy-collaboration.md
- shared-memory/project-memory.md
- shared-memory/conversations/<YYYY-MM-DD>/<当前对话记忆文件>.md

同一对话内的后续任务可按增量读取（见协作规范第一节），并在结果中声明读取范围。

本任务由 Workbuddy 实施；Codex 负责问题判断、任务拆分与阶段复核。涉及服务器发布时，默认按 05 上传服务器规范效率优先执行：不跑技术门禁、不为发布新建备份、不跑发布前后自动化/手工测试；仍登记实际来源/镜像/配置、active/pending、状态页回写、服务器目录定位卡和必要回执。

然后完成以下任务：<任务说明>。
遵守读取到的协作边界；如有需要与 Codex 共享的记忆，可直接追加到上述当前对话记忆文件，并在完成后列出记忆增量、修改文件、验证结果、阻塞缺陷与可排期建议。不要修改其他对话记忆或 project-memory.md。
```
