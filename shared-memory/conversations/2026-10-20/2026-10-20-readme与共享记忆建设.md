### 实现要点

- 新增线程安全 `MidRegistry`：`mid -> (device_code, seq)`；`register` 对仍被占用的重复 mid 返回 `False` 且不覆盖原归属，`pop` 未知 mid 返回 `None`，`clear` 返回清理数量，消费后同一 mid 可重新注册。
- `Ledger` 构造器兼容 `Path | str` 与 `":memory:"`；新增 `pending_all(limit)`，按 `device_id, seq` 稳定排序返回 `(device_code, seq, payload)`，仅允许正整数上限，不删除任何 outbox 记录。
- 新增 `SharedPublisher`：整个车队复用一个 client，`client_id` 默认 `simulator-fleet` 且可配置；支持注入 `client` 或零参 `client_factory`，默认工厂内部才延迟导入 paho，构造器不连接、不启动 loop。
- `publish(device_code, seq, payload)` 在 `self.lock` 临界区内调用 `client.publish` 并注册 mid；仅 `rc == 0` 且 mid 为整数时注册，rc 失败或 mid 冲突均返回 `None`，outbox 保留。
- `on_publish` 仅在 registry 命中时按登记的 device/seq 调用 `ledger.acknowledge`；未知或断线清理后的旧 mid 不会误删队列。
- `on_disconnect` 只清空 registry 并返回清理数，不删 Ledger outbox；`on_connect` 调用 `flush_pending(reconnect_flush_limit)`，默认上限 `DEFAULT_FLUSH_LIMIT = 1000`，并公开 `flush_pending(limit)` 供主循环继续补发。
- 回调方法使用 paho Callback API v2 的五参数签名；`MQTT_ERR_SUCCESS` 用字面量 `0` 比较，避免离线路径导入 paho。
- 原 `Publisher` 类与 `main` 未改动。

### 风险与待办

- `SharedPublisher` 只负责组件与回调，不负责连接和 `loop_start`；Codex 主循环整合时需显式调用 `publisher.client.connect_async(...)`/`loop_start()`，或另加生命周期封装。
- `flush_pending` 不区分“已在途”记录；若在上一条同 `(device, seq)` 未 ack 前重复调用，会以新 mid 重发。后端按 `(device, seq)` 去重时可接受，但主循环应控制补发节奏或由 Codex 决定是否增加在途去重。
- `pending_all` 按 `device_id, seq` 排序，固定 limit 下可能优先补发字典序靠前的设备，暂未实现跨设备公平轮转。
- `on_publish` 按任务要求“registry 命中即 ack”，未区分 MQTT5 失败 reason code；若后续使用 MQTT5 失败回执，需要重新评估是否保留 outbox。
- 默认 `client_id=simulator-fleet` 为固定值；多实例并行时必须配置不同 client_id，避免 broker 会话互相顶替。
- rc 失败时 `publish` 只记录日志并返回 `None`，重试依赖调用方再次 `flush_pending`；未自动重试。

### 实现要点

- 删除 `SharedPublisher.lock` 作为 publish/on_publish 共用临界区。新增：
  - `_publish_lock`：只串行化 `client.publish`，任何回调都不获取。
  - `_state_lock`：只保护「发布进行中」标记、registry、最多 1 个早到 PUBACK；绝不跨 `client.publish`。
- `publish` 顺序：置标记（短状态锁）→ 释放 → `client.publish` → 短状态锁内清标记并登记 mid（或判定早到 ACK 命中）→ 锁外 ack ledger。
- 快速 PUBACK：回调在未知 mid 且当前有 publish 进行中时，只暂存 1 个候选；仅当它与 `publish` 返回的 mid 完全相等才确认，否则丢弃。失败 rc 时不确认；idle 时未知 mid 直接丢弃。
- `on_publish`：短状态锁内 pop registry，释放后再 `ledger.acknowledge`。
- `on_disconnect`：状态锁内清 registry 与早到候选；outbox 保留，重连后由新 mid 重新绑定，旧 mid 不误确认、不跨设备。
