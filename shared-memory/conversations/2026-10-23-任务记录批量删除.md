# 2026-10-23 任务记录批量删除（软删除）

> Workbuddy 会话记忆。仅记录本轮结论与可复核事实；`shared-memory/project-memory.md` 未改动，等待 Codex 复核后再决定是否提炼。

## 需求与口径

用户在智能助手页「任务记录」抽屉要求批量删除。开工时确认：前后端均无任务删除接口（09 只有 `POST/GET /internal/ma/v1/tasks*`），因此不是纯前端改动。

三条经用户确认的口径：

1. **软删除**：只写 `ma_tasks.deleted_at` / `deleted_by` 并从列表隐藏，审计数据保留。
2. **仅终态可删**：`queued`/`planning`/`executing`/`awaiting_approval` 不可勾选，服务端同样 409。
3. **详情仍可读**：只有 `listing()` 过滤，`get()`/`report()` 不过滤，对话内任务卡片不受影响。

选择软删除的硬约束：`ma_tasks` 被 9 张表 `REFERENCES` 且**全部没有 `ON DELETE CASCADE`**（steps、tool_calls、task_events、outbox、approvals、execution_attempts、security_reviews、security_review_events、security_gate_contexts）；物理删除会销毁不可变的安全审查材料。

## 接口

| 路径 | 语义 |
| --- | --- |
| `DELETE /api/v1/agent/tasks/:id`（JWT）→ `DELETE /internal/ma/v1/tasks/:id`（09） | 本人终态任务软删除 |
| 200 | `{task_id, deleted:true, already_deleted:false/true, deleted_at}`，重复删除幂等且时间戳不变 |
| 409 `task_not_terminal` | 非终态 |
| 404 `task_not_found` | 不存在或非本人（同码） |
| 409 `task_delete_unsupported` | 缺列时的防御分支（restore-readonly 旧备份） |

**09 恒返回 200**：Go `opsProxy` 只把 200 当成功，其余透传 400/401/403/404/409/429，204 会被降级成 503。

### 为什么必须做列探测

`Store.open` 的迁移整块被 `runtime_profile != "m4-restore-readonly"` 包裹，恢复库角色 `ma_restore_reader` 只有 SELECT 且 `default_transaction_read_only=on`，无法补 DDL。新代码 + 升级前备份的组合下，若列表硬写 `deleted_at IS NULL` 会 `UndefinedColumnError` → 503，而恢复探针只测 `GET /tasks/{id}` 与 `POST /cancel`，测不出来。

## 残留风险

- 未做批量接口，仍是前端串行单条 DELETE；选中上百条会慢，但每条幂等、部分失败只计数。
- 全选只覆盖「已加载 + 终态」；按钮与确认框复述数量。
- 删除成功后强制重置分页游标，避免 offset 前移漏读。
- `create()` 对已删任务的幂等键行为未调整（键由 Go 每次新生成，实际不触达）。
