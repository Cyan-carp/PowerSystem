# 2026-10-22 智能助手问答故障诊断与 SSE 兼容修复

## 现象

用户反馈生产智能助手"又不能正常问答"。前端可打开页面、会话列表可读，但提问后无有效回答。

## 诊断结论（已证实）

**根因是上游模型网关 hgapi.dieqiyun.top 的单方面行为变更，不是前端改动、也不是最近发布导致的。**

证据链：

1. `rag_turns` 最近三轮（2026-10-22 08:14/09:28 UTC）`status=degraded`、`warnings=["模型响应格式异常"]`、`answer_markdown` 为空；同一张表 2026-10-21 02:15 及更早为 `answered`，答案长度正常（84–15290 字符）。
2. 容器 `powersystem-stage4-agent-rag-1` 启动于 2026-10-20T14:30:15Z，故障期间未重启；容器内 `/app/rag_agent/provider.py` md5 `bba6eeca…` 与服务器源码、本地仓库 HEAD 完全一致 → 运行代码没有被改动过。同一份代码 10-21 正常、10-22 异常，排除代码回归。
3. 直接对上游做最小请求（生产同参数 `max_tokens=8192`，两次复现）：
   - `hgapi.dieqiyun.top/v1` + `stream:false` → `HTTP 200`、`Content-Type: text/event-stream`、body 仅 `: keepalive\n\n`（13 字节，无任何 `data:` 行）。
   - 同网关 + `stream:true` → 正常 SSE，`data:` 帧含 `delta.content`，以 `[DONE]` 结束。
   - `api.deepseek.com` + `stream:false`（告警解读通道）→ `HTTP 200`、`application/json`、734 字节正常 JSON。
4. 原 `provider.py` 只做 `response.json()["choices"][0]["message"]`，遇 SSE 文本抛 `ValueError`，被映射为"模型响应格式异常"，engine 走 degraded、答案置空。

## 影响面

- 智能助手（08-agent-rag，走 hgapi 网关）→ 全部空答案。
- 07-agent 主通道 `AGENT_LLM_BASE_URL` 同为 hgapi 且同样 `stream:false`（`agent/llm.py` 用 `client.stream()` 但 body 非流式、随后 `json.loads`）→ 同一故障模式，当前日志未见触发，属潜在风险；本次未改动。
- 告警解读（`AGENT_INTERPRET_LLM_BASE_URL=https://api.deepseek.com`）走官方通道 → 不受影响。

## 修复

改动文件：

- `stages/08-agent-rag/rag_agent/provider.py`
  - 请求体改 `stream: true`（上游只在该模式返回内容）。
  - 按 `content-type` 分流：`text/event-stream` 走新增 `parse_event_stream()` 聚合 `delta.content`；JSON 仍走 `message_from_json()`。
  - 新增 `merge_tool_calls()` 按 `index` 合并增量 `tool_calls`（id/name 取首个非空，arguments 拼接），保证工具调用语义不变。
  - 忽略 `reasoning_content`，不污染答案正文；仅 keepalive 无内容时抛 `ModelError("模型服务未返回内容")`，与"格式异常"区分。
- 新增 `stages/08-agent-rag/tests/test_provider.py`（9 项）：SSE 拼接、reasoning 隔离、tool_calls 合并、JSON 兼容、keepalive-only 报错、stream 协议断言、401 不泄露密钥、缺 index 合并、畸形帧忽略。
