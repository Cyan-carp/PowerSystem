# 2026-10-31 · 模型通道与额度面板

## 本轮目标

所有者希望在界面上像桌面客户端那样直接更换模型与 API Key，并看到剩余额度。

## 结论：拆两件事，本轮只做只读那半

| 能力 | 结论 |
| --- | --- |
| 查看两条通道的模型、地址、配置状态 | 已做（工作区） |
| 查看供应商剩余额度 | 已做（仅 DeepSeek 官方有额度接口） |
| 测试连接 | 已做（复用原 `POST /agent/model-probe`） |
| 界面改 Key / 换模型 | **未做**，属另一条写路径 |

不做改 Key 的三条硬约束（已核实，非推测）：

1. `07-agent/agent/config.py` 的 `Config` 是 `frozen=True`，`Config.load()` 在进程启动时读一次环境变量与 secret 文件，运行期不重读；改完必须重建容器。
2. 解读通道对模型有硬校验：`AGENT_INTERPRET_LLM_BASE_URL` 必须等于 `https://api.deepseek.com`、模型必须 `deepseek-flash`、`AGENT_INTERPRET_THINKING=disabled`，缺一即 `not_configured`，自动解读全部降级。
3. 运行期改 secret 会让运行态脱离冻结基线，下次 `prepare` 判 `active_manifest_changed`，`prepare`/`status`/`rollback` 一起失效。

## 关键设计决定

- **Key 不出各自服务。** 余额由 07（解读 Key）与 08（主助手 Key）各自查询，Go 只转发合并。没有把两份 Key 挂进 api 容器——那会多一处密钥暴露面。
- **非官方域名返回 `unsupported_provider`，不猜别家接口。** 把「查不到」显示成 0 余额，会让人去给没问题的账号充值。
- **金额按字符串透传**，前端不做浮点换算。
- **拉取失败保留上一次的值**，不清零（清零等于顶栏显示假的 `¥0.00`）；退出登录清空余额并停轮询。
- 顶栏胶囊仅管理员可见，窄屏只留图标。

## 已核实的事实

- DeepSeek 余额接口：`GET https://api.deepseek.com/user/balance`，返回 `is_available` 与 `balance_infos[]`（CNY/USD，total/granted/topped_up）。OpenAI 兼容协议本身没有额度端点。
- 三条模型通道互不复用凭据：07 解读、08 主助手、09/10 传统 v6 域（`hgapi.dieqiyun.top/v1`）。面板只覆盖前两条。
- `agentModelProbe` 有副作用：通过后清熔断键，并把最近 24 小时内因 `not_configured`/`auth_failed`/`quota_exhausted` 失败的解读改回 `pending`；限流 1 次/分钟。
