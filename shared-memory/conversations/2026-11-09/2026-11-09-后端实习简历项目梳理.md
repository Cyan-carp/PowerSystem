## 核查结论

- 主链路：Python 合成设备模拟器经 MQTT QoS1/EMQX 到 Go 网关、TDengine；后端以 PostgreSQL 持久收件表接入，确认时序落库后派生 Redis 最新值、告警和日聚合。网关 SQLite 待写队列、按设备序号去重和重启恢复均有源码与阶段说明。
- 业务：Go/Gin/GORM/pgx 提供设备、场站、遥测、规则、告警、总览及报表接口；JWT、角色控制、一次性 WebSocket 票据；告警状态与通知 outbox 事务写入，飞书适配器投递并重试。
- AI/Agent：Python FastAPI 的 XGBoost 故障风险服务；另有 FastAPI + LangGraph 主助手、Qdrant + 本地 E5 向量检索、独立 PostgreSQL 会话与 Redis 并发控制。助手已上线只读业务取证、会话记录、联网检索和知识检索；S06 告警确认/设备备注及 S08 本人定期日报/巡检需独立审查与本人批准。传统运维写和 S07 服务重启仍关闭。
- 其他：可用率小时汇总、电量日聚合、CSV 报表、模型质量与版本回退、Prometheus/Alertmanager/飞书监控通知、生产备份恢复发布工具。设备均为合成数据，真实场站预测效果未验证。
- 简历表述只描述项目功能，不推断用户个人开发职责；避免使用当前批次未通过的完整生产门禁、真实设备精度或长期稳定性指标。每条候选功能句控制在 80 字以内，按后端求职价值排序，Agent 内容靠前。
