## 二、本次核验发现的阻断性缺陷（交接文档未列）

- 生产编排最后一层 `runtime/interpretation-official-20261021-r4/private/official-overlay.json` 固定了 simulator 命令：`--fleet … --fault-mode off …`（覆盖了 `fleet-release-20261020-r1-overlay.json` 的 `scheduled`）。
- `simulator.py` 的 `apply_window_injection()` 首行即 `if fault_mode != "scheduled": return None`，即 **`fault_mode=off` 同时关闭五个十分钟窗口注入**。
- 新 API 的 `SIMULATION_ALARM_MODE=controlled` 只排空旧演示、不再新建演示告警。
- 结论：**若按现有冻结候选发布，生产将出现"零告警"**（无窗口注入 → 无 `origin=normal` 自然告警；旧演示也不再新建），相对现状（每日 5 条演示）是功能回退。交接文档"唯一阻塞是备份审批"的判断不完整。
- `--fault-mode off` 来自 2026-10-18 白天循环与故障注入解耦发布，用于避免基线三台（ST-01）恢复真实时钟故障排程；因此不能简单改回 `scheduled`。
