# 网站无法访问排查

- 任务：排查生产网站 `https://www.cyancarp.cn/` 无法打开的原因。
- 起始事实：当前系统状态页记录活动发布指针 `user-management-20261109-r1`，主入口 `www.cyancarp.cn`，IP `8.138.42.212`，备用 `8.138.10.222`。
- 边界：先进行只读诊断；如需生产变更，按现行生产发布与恢复规范执行并记录证据。
- 初查：2026-11-10 本地时间，域名解析到 `8.138.42.212`；HTTPS HEAD 返回 Nginx 502，HTTP 返回跳转 HTTPS 的 301。
- 现场只读核查：主入口与备用入口首页及主入口 `/api/v1/ping` 均返回 502。新云 Nginx 正常监听 443、`powersystem-edge-frps` 正常监听 7000，但 3667/7070 转发监听消失；FRPS 日志记录 2026-11-10 23:11:17 UTC 两个客户端代理同时退出。VM117 两个 `powersystem-web-*-frpc` 服务仍运行，但分别连接两台云主机超时。
- VM117 在运行，前端本机 `127.0.0.1:18080/` 返回 200，API 与前端容器均 healthy；故障不在前端镜像或容器启动。新云白名单自检 `pending=false, ready=true, sources_match=true`，但该检查只证明当前登记一致，不能证明网络出口可达。
- PVE `192.168.111.3`、R730XD `192.168.111.2` 均可 ping 本地网关 `192.168.111.1`，但连接新云 22/443 和公共地址 `1.1.1.1:443` 均超时。R730XD 的 `powersystem-source-refresh.service` 连续报 `operation_failed`、`entry_recovered=false`；VM117 查询公网地址也超时。Windows 本机当前默认路由走 WLAN `10.144.36.254`，与服务器使用的有线出口不同。
- 结论：公网回源链路断开，最可能是 `192.168.111.1` 所在有线网络的 WAN/上游出口故障或出口策略变化；尚未证明路由器内部的具体故障点。此时修改网页代码、重启容器或只改云端白名单均缺乏依据。未对生产服务、网关或云防火墙做任何修改。
- 待办：由所有者核对 `192.168.111.1` 的 WAN 在线状态、运营商链路与出口策略；出口恢复后复核 FRP 的 3667/7070 监听及公网首页和 API 200。若出口恢复而 7000 仍超时，再核对当前出口 IP 与云端白名单及自动对账状态。
- 用户反馈：截图显示其 Windows 本机 ping `192.168.111.1`、`.2`、`.3` 均通。这只验证内网连通，与服务器到公网的失败不矛盾。复测时 PVE 与 R730XD 分别连 `8.138.42.212:22/7000`、`1.1.1.1:443` 仍全部超时；网站与 API 仍 502，云端 7000 监听但 3667/7070 未恢复。Windows 有线 IP `192.168.111.235`，默认优先走 WLAN `10.144.36.254`；PVE/R730XD 默认走 `192.168.111.1`。因此从 Windows 能打开互联网不能证明服务器出口可用。
- 后续进一步缩小：PVE 对 `1.1.1.1` traceroute 到 `10.144.43.254`、`10.128.7.254`、`10.128.12.1`，说明 `.1` 到上游至少有部分路由；DNS 解析正常，TCP 53 到公共 DNS 可建立，但外部 80/443（百度、neverssl、两云 IP、公共地址）均超时。故应修正前述“WAN/上游出口故障”表述：不是网关物理完全断连，更可能为上游网络的访问控制、认证或出口策略问题，具体原因待查。Windows WLAN 走另一上游 `10.144.36.254`，不能替代有线出口测试。

## 全栈迁云可行性初查

- 用户目标：评估将生产网页及后端迁到云上，仅把合成遥测模拟器留本地。当前仅授权评估和只读检查，未授权购买、上传、部署、数据迁移或切换。
- 新云 `8.138.42.212` 实测：2 vCPU、内存 1,691,451,392 B（约 1.6 GiB）、无 swap，系统盘约 40 GB、已用约 20 GB、可用约 18.6 GB（17.3 GiB）；`/srv/powersystem-backups` 约 17 GB，9 个 GPG 密文总约 18,046,137,441 B。现役 Nginx 与 FRPS 在线；此节点目前承担入口及备份。
- 当前生产 VM117 记录配置为 8 核 16 GiB、64 GiB 系统盘、192 GiB 数据盘、21 个服务。2026-10-26 冷迁时 13 卷共 19,530,169,122 B；2026-11-07 日志记录磁盘余 57.6 GiB（具体盘和最新占用需恢复访问后现查）。最新成功全备约 4.64 GB。现有云主机 CPU、内存、磁盘均不足以直接承接全栈，尤其不能把历史冷迁卷大小误认为当前容量。
- 架构：前端静态资源迁到云很小，但 API/数据库继续在本地时仍会受本地断网影响。若要网页和历史查询在本地断网时持续可用，需把 API、gateway、EMQX、PostgreSQL、TDengine、Redis、Qdrant/RAG、AI/通知/监控及其持久数据与配置一起迁云；保留模拟器本地仅影响新遥测供数。
- 模拟器源码按 143 台/5 秒生成 2,471,040 条/日，使用 MQTT QoS1 与本地 SQLite `generated` + `outbox`；`generated` 没有删除逻辑，断网时本地账本继续增长。当前仓库 `DEFAULT_FLUSH_LIMIT=1000`，重连回调只触发一次 `flush_pending`；超过 1000 条的旧积压不保证自动排空（约 35 秒生成 1000 条）。需核对生产镜像是否同实现并先修复/验证补传语义。跨公网 MQTT 需要 TLS/认证/最小主题权限或私有隧道，不开放裸 1883。当前本地服务器对公网连接超时，分离后模拟器也无法供数，除非先解决出口。
- 额外迁移约束：生产身份/权限/业务动作绑定 VM117 主机与三库、来源；不能只复制镜像/卷。须审查主机登记、私有配置、备份目标、切换/前滚/回退与数据一致性。当前本地 `.2/.3` SSH 在本轮复查中超时，未能现查 VM 最新内存、卷与磁盘占用，容量方案只能给范围不能定最终规格。
- 可行方向：保持现有小云作为公网入口和异机备份目标，另配足够资源的云业务节点承载完整后端与数据；或升级现有轻量云套餐并加数据盘，但会与入口/备份共址且套餐升配有限制。模拟器若必须留本地则经安全链路连接云 MQTT，并接受本地断网时页面在线但数据变旧；若目标是数据也不中断，模拟器可一并迁云。
- 用户追问 home-dev：按手册和当前状态，`DESKTOP-LHHD9GR` 是 Windows 开发机，运行 5 个开发中间件容器/7卷与 Windows 原生 stage2-api，开发库当前仅 3 台有效设备，非生产 143 台数据副本；Docker Desktop 依赖登录、整机重启/休眠及 API 自启未签收。SSH 别名经新云 FRP `8.138.42.212:6002`，本轮实测云端 6000 FRPS 在监听但 6002 无监听，SSH `Connection refused`，因此当前不可现查机器规格/容器，也不能当现成生产恢复通道。即便其硬件够用，若网站业务搬到这台本地电脑，公网可用性仍取决于该电脑的电源、系统与网络；可作为开发/隔离验证或具备可靠出网后的模拟器候选，不能用开发卷直接替代生产卷。
