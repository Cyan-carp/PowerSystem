## 链路结构（供后续排查参考）

```
遥测样本 → service.ProcessSample
  → alarm_rules(device_id,metric,enabled) 逐条匹配
  → alarm_records（ux_alarm_active 保证 device+metric 仅一条未恢复）
→ interpretationScanner（每 1s，agent_scan_cursor 基线 + 反连接）
  → agent_interpretations(task_status=pending)
→ interpretationWorker（FOR UPDATE SKIP LOCKED，lease 60s，最多 3 次重试）
  → buildEventEvidence：E1 告警详情 / E2 设备档案 / E3 前 24h 同类告警 / E4 前 30min 遥测（>100 点等距压缩）
  → POST http://agent:8092/internal/agent/interpret（45s 超时）
  → 写回 result/evidence/reason
→ 前端 InterpretationPanel（挂在 ConsoleLayout，全局；5s 轮询）
```

`retryInterpretation` 对 `not_configured / auth_failed / quota_exhausted / answer_validation_failed / missing_event_evidence` **不重试**，其余最多 3 次。

## 追加（11:20）规则 13 关闭与残留失败根因

### 已完成

- `alarm_rules` id=13 已置 `enabled=false`。因直连 SQL 未走 API 的关单逻辑，告警 381 仍为 `unhandled`，需人工归档或用 `POST /api/v1/alarm-archive`。

### 前一轮归因修正（用户交叉审查结论）

旧解读模块强制 `tool_choice=submit_interpretation`，当前上游通道不兼容导致 502。"模型 API 不可用"的笼统归因不成立。`stages/07-agent/agent/llm.py:47-49` 已改为 `auto` 并留有注释。

### 残留失败的真实根因

`answer_validation_failed` 仍占约 47%（11 点 34 条中 16 条）。审计 `validation_code`：19 条 `invalid_answer_schema` + 1 条 `unsupported_numeric_claim`。

在容器内以真实证据 `alarm:390` 重放 6 次：

```
#   ms     finish      compl  reasoning  verdict
1   11107  length       1500   1473      TRUNCATED_JSON
2   12539  tool_calls   1147   -         OK
3    9470  tool_calls   1245   -         OK
4   14416  tool_calls    966   -         OK
5   10234  length       1500    732      TRUNCATED_JSON
6   12134  length       1500   1279      TRUNCATED_JSON
```

**`llm.py:44` 的 `max_tokens=1500` 是瓶颈**：推理模型的 reasoning token 计入该预算，真实告警证据（4 条、含 100 个遥测点）推理开销达 732–1473，留给答案 JSON 的余量不足，输出被截断成非法 JSON。

### 对照实验

| 配置 | 完整率 | 延迟 |
|---|---|---|
| `deepseek-v4.1-flash` + 1500 | 3/6 | 9–24 s |
| `deepseek-v4.1-flash` + 4096 | **4/4** | 11–18 s |
| `deepseek-v4-pro` + 1500 | 1/4 | 17–25 s |
| `deepseek-v4-pro` + 4096 | **4/4** | 22–28 s |

结论：优先 `flash + 4096`（比 pro 快约 10 s）。502 仍偶发（重放 5 次中 1 次），属上游通道问题，由 `retryInterpretation` 的 3 次重试覆盖，非本次根因。

### 超时约束链（必须同时对齐）

| 位置 | 现值 | 说明 |
|---|---|---|
| `agent/llm.py:44` | `max_tokens=1500` | 需提到 4096 |

### 探针缺陷（解释"健康检测显示正常"）

`agent/interpret.py:72-87 probe_interpretation` 使用单条 60 字合成证据，推理极短，永远不会触及 token 预算上限。健康检测因此对本缺陷完全失明。修复时应把它换成带 100 点遥测的真实规模证据夹具，否则同类问题仍无法被探针发现。
