# 04 · 前端与实时推送选型

> 回到 [[00-索引·技术选型]]
> 对应手册任务 8.7（实时推送）、8.8（前端框架与可视化）

## 一、实时推送

### 这层解决什么

页面怎么实时刷新（告警推送、遥测滚动、大屏刷新）。

### 候选横向对比

| 维度 | WebSocket | SSE | 前端轮询 |
| --- | --- | --- | --- |
| 需求匹配度 | ★双向长连接，服务器主动推 | 单向推送 | 被动拉取，实时性差 |
| 社区活跃度 | 高 | 中 | — |
| 学习曲线 | 低（gorilla/websocket 成熟） | 低 | 最低 |
| 生态与文档 | 极好 | 好 | — |
| 生产验证 | 监控系统标配 | 推送通知类 | 兜底方案 |
| 性能与资源开销 | 低 | 低 | 高（频繁请求） |
| 许可证 | 开放标准 | 开放标准 | — |

### 最终选择：WebSocket

- 双向实时、监控场景标配（Grafana 等监控产品同款），支撑 FR-02「10 秒内推送告警」与 NFR-03「告警 ≤ 10 秒」。

### 被否方案

- **否 SSE**：单向推送够用但不够灵活（无法做「确认告警」这类客户端上行）；**前端轮询仅作降级方案**。

## 二、前端框架与 UI

### 这层解决什么

运维大屏和管理页面用什么做。

### 候选横向对比

| 维度 | Vue3 + Element Plus | React + Ant Design |
| --- | --- | --- |
| 需求匹配度 | 后台管理 + 大屏，模板多 | 同能力 |
| 社区活跃度 | ★国内生态最好 | 高 |
| 学习曲线 | 低（模板化开发快） | 中（JSX 心智） |
| 生态与文档 | ★中文资料最密集 | 好 |
| 生产验证 | 国内后台项目主流 | 国内互联网主流 |
| 性能与资源开销 | 低 | 低 |
| 许可证 | MIT | MIT |

### 最终选择：Vue3 + Element Plus

- 国内生态最好、后台模板多、上手最快，契合「单人 + 数月工期」约束；对应 [[需求分析/05-功能结构图]] 的六大页面（总览大屏/设备列表/详情/告警中心/AI 预测页）。

### 被否方案

- **否 React + AntD**：能力相当，但 Vue 的模板化对「后台管理系统 + 大屏」场景上手更快，且国内中文资料更密集。

## 三、图表可视化

### 这层解决什么

实时曲线、历史曲线、大屏图表。

### 候选横向对比

| 维度 | ECharts | AntV (G2/G6) |
| --- | --- | --- |
| 需求匹配度 | ★曲线/大屏开箱即用 | 定制化强 |
| 社区活跃度 | ★国产图表标杆 | 高 |
| 学习曲线 | 低（示例库直接抄） | 中 |
| 生态与文档 | 极好 | 好 |
| 生产验证 | 大屏案例最丰富 | 阿里系 |
| 许可证 | Apache 2.0 | MIT |

### 最终选择：ECharts

- 国产图表库标杆、官方示例库（echarts.apache.org/examples）直接覆盖实时/历史曲线与大屏需求。

### 被否方案

- **否 AntV**：定制能力强但学习曲线更陡，本项目以「快速出大屏」为目标，ECharts 更顺。

## 结论

前端 = **Vue3 + Element Plus + ECharts**，推送 = **WebSocket**（SSE/轮询作降级），满足 FR-02/FR-06/FR-07 与 NFR-02/NFR-03。
