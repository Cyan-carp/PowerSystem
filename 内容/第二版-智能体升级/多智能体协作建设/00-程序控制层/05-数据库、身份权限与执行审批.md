# 05 · 数据库、身份权限与执行审批

> 2026-10-13当前路线：MA-M1～M3及SEC-M1既有签收保留；SEC-M2本机限定技术验收签收、窗口已关闭并实测阻断，可进入SEC-M3开发准备但未自动启动。安全前三阶段后先SEC-M4本地集成，再评估MA-M4发布。服务器保持既有发布。最新真相入口：[[内容/第二版-智能体升级/多智能体协作建设/02-安全审查模型/开发阶段2-强制门禁集成/03-SEC-M2测试与交付]]。


> 定义运维库、最小权限与审批一致性；对应MA-F05、MA-F11～MA-F13。

## 一、数据库与数据责任

独立逻辑库ma_ops、独立账号及迁移目录 `stages/09-ops-agent/deploy/`，沿用PostgreSQL。运维服务唯一写入；Supervisor通过API查询。业务GET仍从Go取数，不给运维模型业务库写权限。

迁移按阶段追加：MA-M1只建任务、步骤、调用、事件、outbox和会话删除屏障；MA-M2再建资产/版本；MA-M3再建审批/执行尝试/策略版本；不提前为候选Agent创建无用表。

| 表 | 最小字段与约束 |
| --- | --- |
| ma_tasks | UUID task_id/trace_id/session_id；BIGINT user_id/parent_turn_id；幂等键、request_hash、intent、targets、constraints、status、阶段截止、epoch、租约、时间、cancel_requested |
| ma_task_steps | task_id + step_no主键；工具/版本、经Schema验证且不含凭据的参数JSON及摘要、risk、required、status、结果、error、epoch、时间 |
| ma_tool_calls | UUID call_id；task/step/trace/epoch、脱敏参数/结果引用、args_hash、status、error、耗时与时间 |
| ma_task_events | 单调event_seq；task_id、前后状态、epoch、原因及时间 |
| ma_outbox | event_id、task_id、投递状态、尝试次数、next_attempt_at、last_error |
| ma_session_guards | session_id、user_id、删除屏障状态与操作ID |
| ma_assets / ma_asset_versions | 在册归属、连接引用、风险类型、父子关系、版本快照 |
| ma_approvals | approval_id、task/step、target_version、container_id、args_hash、policy_version、expires_at、决定及消费时间 |
| ma_execution_attempts | task/step/approval唯一尝试；epoch、开始/结束、结果是否确定 |

## 二、约束、删除与保留

- UNIQUE(user_id,idempotency_key)，同键载荷冲突409；步骤PRIMARY KEY(task_id,step_no)。
- 任务状态、风险、步骤状态及审批状态使用CHECK；索引覆盖user_id/created_at、session/status、状态租约扫描和outbox待投递。
- 会话和轮次只存逻辑关联，不跨库外键；parent_turn_id保存后绑定，同关联幂等。
- 任务/步骤与审计不设置级联删除；本期无公共任务删除接口，会话删除不抹审计。
- 资产修改保留新版本快照；审批使用快照版本而不是只看updated_at。
- 数据库不能保存JWT、签名材料、SSH私钥、模型密钥或完整生产日志；仅脱敏结构结果及私有证据引用。
- 审计JSONL写Git之外独立目录；数据库是查询真相，JSONL失败标audit_degraded，R0可保留结果，写步骤的前置审计无法保存则阻断。

## 三、权限矩阵

| 能力 | operator | admin |
| --- | --- | --- |
| 普通技术与平台聊天 | 允许 | 允许 |
| 自己的平台R0任务 | 允许 | 允许 |
| 本项目脱敏基础设施R0诊断 | 允许 | 允许 |
| 读取/取消自己任务 | 允许 | 允许 |
| 读取别人的任务/审批 | 404 | 404 |
| 资产清单导入、策略激活 | 不允许 | 受控管理 |
| 发起演练容器写任务 | 不允许 | 仅开关与规则及独立演练窗口允许时 |
| 审批自己演练任务 | 不允许 | 仅程序审批接口 |
| 实际设备、核心服务或高危操作 | 不允许 | 不在本期开放 |

当前没有viewer/auditor和资产级ACL；admin的管理职责不意味着能读其他用户聊天/任务。服务端每次读取/审批验证当前用户，失效JWT不得仅凭会话ID放行。基础设施步骤调用前通过Go私有身份接口重新核对当前用户表角色，不能沿用规划时的旧角色；身份依赖失败则停止执行。

## 四、审批卡与绑定

卡片由程序根据工具清单和资产事实生成，字段包括approval_id、task_id、step_no、operation、target、container_id、risk_class、impact、rollback_limit、args_hash、asset_version、policy_version、expires_at。

影响展示为估计与已知边界，不写固定“必然中断30秒”。rollback_limit明确「恢复镜像/配置不等于回滚数据」，演练容器无状态证明必须真实核对。

审批pending → approved/rejected/expired，approved还需记录consumed_at；模型不能提交decision。默认30分钟过期，拒绝/过期/放弃使尚未执行部分cancelled。

## 五、执行一致性

管理员点击批准后，数据库同事务核对所有者、当前角色、pending及过期，保存决定并生成执行outbox。重复同决定返回已有状态；相反决定409，不产生第二次投递授权。

执行器领取已批准计划后重新检查开关、资产版本、实际容器ID、参数摘要、策略和epoch；任何变化要求新的审批，不复用旧卡。审批消费与ma_execution_attempts插入同事务，唯一约束阻止重复写尝试。

若事务提交后程序崩溃、动作是否发出未知，保持execution_uncertain，不自动补执行；通过只读状态核对与人工新任务处理。数据库无法与Docker重启构成分布式原子事务，不能用审批消费声称绝对exactly-once。

## 六、边界修订位置

BND-P06登记在现有边界台账，状态为MA-M3本机隔离技术验收通过、默认关闭。具体审批设计由本页维护，工程规范只维护文档与归属规则，避免三处复制同一策略。

真正开放必须满足MA-M3独立验收及明确目标/窗口/影响范围；此次建档授权不等于授权现在重启容器。
