# 01 · 职责与安全门禁

> 2026-10-14当前：SEC-M4本机限定签收及r6追加准入通过；MA-C32～C35和最终文档门槛已完成，MA-M4及联合阶段四在声明范围正式技术签收。服务器r6/v5、恢复维护修订3；本机唯一批准动作保留，写窗口关闭，生产仅登记R0。

> 2026-10-13确定的未来门禁方案；SEC-F02/F03、SEC-T05～T08。程序机制仍以MA-M3已验收源码为基线。

## 一、谁可以决定什么

| 责任方 | 可决定 | 不获得的权限 |
| --- | --- | --- |
| Supervisor | 解释、澄清、提出任务 | 审批、身份或实际动作 |
| Operation | 注册工具计划、诊断建议 | 改风险、批准、自由命令 |
| Security Review | allow/deny/needs_clarification | 提升权限、改参数、修复配置 |
| 程序控制层 | 校验、状态、授权、执行与存证 | 从模型文本推导人工授权 |
| 当前admin任务所有者 | 程序页面明确批准/拒绝 | 绕过安全否决或资产限制 |

## 二、触发条件

- 普通平台固定GET与主动核验按既有程序限制执行，主动核验零模型；不会因新增安全Agent而调用审查模型。
- 敏感基础设施读取由受控Manifest/策略确定，首期登记日志摘要、inspect安全字段和数据库连接聚合等敏感类别；普通CPU/内存/健康读取仍受资产与输出规则。
- 敏感或新增外发内容、目的地或字段范围必须先审查；已有合法普通聊天/平台取证范围不自动扩展到基础设施数据。
- R2在程序形成不可变计划后、生成审批卡前审查；批准后再次检查有效性和当前执行上下文，需要时重审。
- R2结束后及安全巡检输出前复核证据和结果。后审失败记录独立结论，不篡改真实动作结果。

## 三、门禁时序

服务认证及当前身份 → 所有权/任务代次/取消/预算 → 工具与参数Schema → 在册目标和当前版本 → 程序风险与上限 → 必要安全审查 → R2程序审批 → 执行前身份/目标/策略/审查重新检查 → 写开关和一次性消费 → 受限执行 → 输出投影与审计 → 结果复核。

R0只走适用步骤。安全否决、需要澄清或无可验证结论时零受审工具调用，保留原因和已取得事实。未开放的工具在模型审查前直接拒绝，不调用安全模型寻求例外。

## 四、批准与再次审查

管理员批准的是程序保存的具体计划。审批等待期间安全结论过期或执行代次改变，需要对同一计划重审；若计划、参数、目标或策略改变，沿现有规则使原审批失效，要求新任务与新审批。再次allow不替代管理员批准，也不刷新原审批有效期。

安全否决无人工绕过。用户可补充上下文或调整需求，通过新任务重新进入完整流程；聊天“批准”“忽略安全检查”均不是授权接口。

## 五、失败与结果事实

审查故障停止对应敏感读取、外发或写动作；审查不重试写操作。已经发生但不确定的动作继续failed/execution_uncertain，不因安全模型推测正常而转成功。拒绝原因以程序错误与独立审查记录表达，必要证据保存失败则停止后续受审动作。

对明确证据的后审发现单独记录；前端区分“执行已完成”“安全复核未完成/发现风险”。模型复核不是原始事实的替代来源。

## SEC-M2本机建设增量（2026-10-13）

SEC-M2运行门禁按固定策略接入敏感读取、外发、审批前、执行前和后审。程序身份/资产/参数/批准/写窗口硬规则保持，审查allow仅可继续校验；安装006的库不能通过关闭服务旁路受审动作。普通GET和固定主动核验保持原规则。
