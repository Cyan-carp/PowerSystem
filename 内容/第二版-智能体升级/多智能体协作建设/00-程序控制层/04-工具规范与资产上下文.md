# 04 · 工具规范与资产上下文

> 2026-10-14当前：SEC-M4本机限定签收及r6追加准入通过；MA-C32～C35和最终文档门槛已完成，MA-M4及联合阶段四在声明范围正式技术签收。服务器r6/v5、恢复维护修订3；本机唯一批准动作保留，写窗口关闭，生产仅登记R0。

> 规定注册清单、资产解析及受限执行层；对应MA-F04、MA-F08～MA-F10、MA-F12。

## 一、Tool Manifest

每个工具注册name、version、category、risk_class、args_schema、returns_schema、timeout_sec、required_roles、approval_policy、idempotent、target_kinds、enabled及output_fields。未知工具、额外参数或关闭工具在调用前阻断，不能交模型决定例外。

```json
{
  "name": "docker.get_container_stats",
  "version": "1.0",
  "risk_class": "R0",
  "required_roles": ["operator", "admin"],
  "approval_policy": "none",
  "idempotent": true,
  "target_kinds": ["container"],
  "timeout_sec": 15,
  "enabled": true,
  "output_fields": ["cpu_percent", "memory_usage_bytes", "memory_limit_bytes", "memory_working_set_bytes", "sample_seconds", "vantage", "sampled_at", "collected_at", "truncated", "complete"]
}
```

工具统一接收args与程序context（task_id、step_no、call_id、trace_id、epoch）；统一返回status、data、error、evidence_refs、duration_ms。输入严格校验，输出脱敏并限长；无异常数据和读取失败不使用相同结果。

## 二、第一期平台工具（MA-M1）

| 运维工具 | 原阶段8名称 | 保留口径 |
| --- | --- | --- |
| platform.list_devices | list_devices | id ASC，keyword/group和分页 |
| platform.get_device | get_device | 同一设备ID/编码 |
| platform.get_telemetry | get_telemetry | latest/history，指标与时区时间 |
| platform.get_prediction | get_prediction | 概率、阈值、来源及stale原值 |
| platform.list_alarms | list_alarms | unhandled/acked/recovered筛选 |
| platform.get_alarm_statistics | get_alarm_statistics | 数据库聚合与完整性 |
| platform.get_alarm_detail | get_alarm_detail | 原详情语义 |
| platform.get_dashboard_summary | get_dashboard_summary | 原业务汇总 |

全部R0，固定GET路径与当前JWT；运维服务没有业务库连接凭据。主动核验仅固定台账、最新遥测、当前未恢复告警和可选预测；分页不全标complete=false，不以少数页判定无告警。

## 三、基础设施工具（MA-M2）

- Linux：get_cpu_usage、get_memory_usage、get_disk_status、list_services、get_system_logs。主机采样和容器内采样明确区分，不能把运维服务容器资源当主机资源。
- Docker：list_containers、inspect_container、get_container_stats、get_container_logs。只返回本项目在册对象；inspect排除Env、凭据、完整挂载与非必要网络详情。
- PostgreSQL：get_db_status、get_connection_stats。固定查询模板和只读账号，只取聚合计数/状态；不读取业务记录或任意SQL正文。
- 慢查询读取：仅已有采集能力且归属明确时另行注册；缺少能力返回capability_unavailable，不安装扩展、开启生产日志或虚构结果。

日志默认最近100行，上限500行/32KiB，受15秒超时保护；返回截断、采集时间及过滤说明，不把截断日志当完整日志。数据库查询按固定健康模板和聚合统计执行，不以模型SQL取代模板。

## 四、资产上下文

资产字段包含asset_id、kind、display_name、project_scope、parent_id、enabled、criticality、environment、version、verified_at、connection_ref与脱敏attrs。IP、端口、Compose归属、容器实际ID由私有台账维护，模型仅获得必要别名和结构化事实。

一期受控清单由admin核对后导入，不建设新的资产管理大屏；所有更新留版本与快照。资产必须enabled、归属本项目且已核实连接目标；未核对资产返回asset_not_verified，不探测其他服务。

模型用语“服务器”对应多个候选时要求选择；父子关系仅帮助定位，不自动赋予管理整个PVE宿主机或其他容器的权限。核心服务与演练容器明确标criticality/environment，策略按资产类型限制。

## 五、受限执行适配层

模型所在进程不直接挂Docker socket、加入docker组或读取root私钥。执行适配层作为独立无模型组件，持有最小凭据，接受带服务认证的工具名/资产ID/参数；再次检查清单、项目归属、调用预算和审批绑定。

主机读取使用专用SSH身份、固定已知主机密钥与受限命令入口；禁止拼接shell、命令替换、通配路径或关闭主机密钥校验。Docker采集程序本阶段仅允许登记对象固定GET读取，拒绝exec/create/remove/prune/卷操作；限制输出字段。演练容器restart已在MA-M3本机隔离范围实现和验收，当前写窗口关闭。

> [Docker官方安全说明](https://docs.docker.com/engine/security/)将daemon控制权视为高权限能力。socket文件挂载为只读不能代替daemon操作授权。

## 六、MA-M3唯一演练写工具（当前关闭）

`docker.restart_drill_container`按R2管理，不因无状态就写成R1。仅admin、仅在册专用隔离演练容器、OPS_WRITE_ENABLED=true、有效一次性审批时可执行。

审批前取得完整容器实际ID、镜像摘要、无状态证明、健康检查与影响说明；执行前再次核对。restart的宽限参数固定在清单，默认10秒，单步15秒仍保持；结果超时就记录不确定并读取状态，不延长后自动重启第二次。

不注册stop/start通用管理、镜像清理、数据库会话终止、核心容器重启、卷删除、关机或PVE快照。镜像/配置基线不能证明数据库数据可回滚。

## 七、闸门顺序

服务与身份 → task所有者/执行代次 → Manifest与Schema → 目标在册与当前版本 → 程序计算风险及任务上限 → 当前角色 → 写开关/一次性审批 → 调用 → 输出脱敏与审计。

任一步失败零工具执行，保存guard_blocked证据。模型不能降低工具清单风险，前端不能仅隐藏按钮代替服务端拒绝。

## 平台GET参数补充（2026-10-12）

历史遥测沿用已有RFC3339带时区区间且最多24小时的契约，运维参数校验先拒绝越界，不静默裁剪。当前状态查询未要求历史或趋势时不额外读取历史遥测。最终输出严格限定summary/clarification字符串与hypotheses/recommendations字符串数组；异常仅记录类型和字段位置，不保存校验输入。

## 安全审查规划增量（2026-10-13）

未来程序策略/Manifest标识敏感R0及外发类别，模型不能自行跳过审查。普通固定平台GET、主动核验和非敏感资源读取保持既有程序检查；采集仍通过受限适配层，不把Docker/SSH/业务权限交给安全模型。

详细契约见[[06-审查协议、外发与审计]]；当前状态与原签收范围见总索引和历史页。

## SEC-M2本机建设增量（2026-10-13）

敏感集合为项目服务日志摘要、容器日志摘要、容器安全inspect与数据库连接聚合。受审计划先保存，通过后才建call或发grant；内部snapshot也领取一次短期许可并回调核验。SEC-M2许可仅本机fixture/acceptance登记对象，生产读取不得借此外发。
