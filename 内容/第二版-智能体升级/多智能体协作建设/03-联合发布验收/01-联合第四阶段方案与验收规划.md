# 01 · 联合第四阶段方案与验收规划

> 2026-10-14归属整理：依据既有规划、联合启动增量和已签收证据形成统一维护入口；整理发生在实际验收之后，原日期、编号、批次、失败及签收边界保留。

## 一、规划依据与形成时间

2026-10-13公用路线及延期条件要求安全前三阶段签收后，先SEC-M4本地协作集成，再推进MA-M4服务器发布验收。2026-10-14所有者要求联合启动两侧第四阶段，原两份方案承接本地集成与服务器发布两层任务。

本页将既有要求集中整理为共同规划视图。它是验收后文档归属完善，不倒写为部署前已存在一套独立联合方案；原方案与变更历史分别保留在两层明细及[[05-第四阶段延期与恢复条件]]。

## 二、共同目标与边界

共同验收链为用户需求 → Supervisor → Operation计划/固定巡检 → 必要Security审查 → 程序最后门禁与受限执行 → 事实/诊断/审查分区 → Supervisor及本人任务卡。平台固定GET和主动核验仍按既有程序执行，主动核验零模型。

- Supervisor负责聊天、澄清、需求指令及汇总；Operation负责注册工具计划和诊断；Security给独立意见。
- 程序控制层拥有身份、所有权、工具/参数、资产版本、风险、预算、审批一次消费、执行和审计；模型不拥有执行凭据或自由命令。
- 本机R2只验证已授权的无状态隔离演练对象、本人admin卡片批准与关闭；服务器仅在册项目R0，生产写关闭。
- 恢复副本独立只读，无生产执行凭据，Worker/投递/执行关闭，不重放queued或approved。

## 三、统一任务分工

**本地协作集成层，原SEC-M4编号保持**

| 原任务 | 联合交付责任 |
| --- | --- |
| SEC-T13 | 三智能体完整任务/审查/审批/证据链及兼容 |
| SEC-T14 | 并发、预算、取消、依赖故障、恢复与隔离 |
| SEC-T15 | 固定真实模型样例、误拒/漏放、引用、耗时及成本 |
| SEC-T16 | 本人页面、文档/问题归档、本机正式签收 |

**服务器发布层，原MA-M4编号保持**

| 原任务 | 联合交付责任 |
| --- | --- |
| MA-T17 | 固定配套候选、部署、实际旧版回退及同候选恢复 |
| MA-T18 | 最终加密备份、两目标核对、隔离恢复及公网权限/页面 |
| MA-T19 | 唯一固定镜像完整观察、跨层证据/文档与最终签收 |

## 四、执行顺序与跨层门槛

1. 核对前三阶段签收和数据/目的地/对象授权，固定本地及服务器运行档。
2. 完成本地三智能体、程序/专库、质量、页面及恢复分层验收，形成SEC-M4本机签收。
3. 固定同候选源码/依赖/策略/许可/镜像，更新前备份后配套发布API、前端、Supervisor、Operation、Security与Executor。
4. 真实服务器闭环及权限验收，实际回退旧版并恢复同候选，完成最终加密备份、双目标实算核对及隔离恢复。
5. 在写关闭、公共入口恢复、无在途任务前提下开始唯一连续观察；完成共同文档与证据核对后联合签收。

服务器遇到策略或候选修订时保留失败、版本化许可并重新取得相应准入，受影响验证另批执行。同候选恢复/观察要求不因联合启动而跳过；纯文档整理单独记录摘要，不改变运行核心或重写历史签收。

## 七、共同签收与未覆盖范围

共同签收需本机SEC签收及候选追加准入、服务器四项、问题归属与最终文档/证据同候选一致。程序、模型、真实工具、页面、恢复及文档各层独立判定；源码/镜像改变或窗口中断不得拼接观察。

模型意见不代表授权或专业事实。专业来源审核、真实场站效果、生产核心写、全私有云管理和模型长期/持续负载性能仍是后续范围；技术签收不自动启动这些事项。
