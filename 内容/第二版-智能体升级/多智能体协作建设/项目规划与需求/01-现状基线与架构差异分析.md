## 二、当前代码的关键事实（2026-10-13本地文件核对）

- 阶段8正常工具为search_knowledge、web_search、dispatch_ops_task、get_ops_task；平台八类GET和固定核验已迁移到阶段9。
- 阶段9具备API/Store/Worker/Executor、ma_ops迁移001～004、队列/outbox、资产与审批；主机采集和演练broker为独立无模型执行组件。
- Go当前JWT/用户表只接受admin/operator，无逐设备ACL或viewer/auditor。会话UUID、用户/轮次BIGINT，临时JWT不持久化。
- 当前R2仅本机专用隔离无状态容器，模型生成计划后等待程序页面审批；写窗口关闭，不向服务器开放写能力。
- 原WebSocket广播业务事件；本人任务仍使用受鉴权轮询，未新增定向安全推送。
- 安全服务、ma-review/v1、005安全迁移及程序模块已在SEC-M1构建；security_reviews公开报告、巡检路由和Worker门禁接入仍未实现，专库已验证通过，当前0731/v6完整闭环及常规30秒补查签收，临时例外已关闭，原型号404已按明确调整解阻。

源码形态与既有正式页声明分别核对；本轮不重新运行套件、登录服务器、调用模型或导入知识。

## 三、参考稿差异处理

| 参考稿内容 | 本规划处理 |
| --- | --- |
| Supervisor + Operation Agent | 采用；明确模型规划与程序执行层分工 |
| FastAPI、LangGraph、Redis Stream | 采用既有栈，不新增通用代理框架 |
| ma/v1、独立运维服务8094 | 已在MA-M1实现；安全增量另规划 |
| Supervisor直接访问运维数据库 | 修正为服务接口访问，运维服务唯一写入 |
| parent_turn_id为UUID | 修正为现有BIGINT，允许保存聊天后补齐 |
| viewer/operator/admin/auditor矩阵 | 继续使用现有operator/admin |
| ma_ops与现有库物理分离 | 修正为独立逻辑库、独立账号与权限 |
| 用户任务经原WebSocket推送 | 一期改为鉴权查询和2秒轮询 |
| 悬空镜像清理是低危可逆写 | 不采用首批工具；删除不等于可逆 |
| MySQL等跨项目对象 | 不自动纳入；首期PostgreSQL和本项目服务 |
| PVE在二期，MA-M3却要求快照 | 解除矛盾：本期不含PVE快照 |

## 四、现有问题不能被新架构自动解决

原回答质量问题包括未查数却声称已查、时间表述错误及阈值推断不可靠。拆成两个智能体并不自动解决这些问题；只将程序事实独立展示，评测与专业适用性继续单独跟踪。

现行资料不自动证明真实机型配置，合成遥测不证明真实设备效果。原失败批次和专业审核pending继续保留，不能在新业务建档时抹除。


## 六、三智能体架构差异

新增独立Security服务与模型配置，程序发送最小审查材料并校验合法结论；程序控制层及R2管理员审批保持。安全不直接连接业务数据库或执行凭据；主体仍是现有技术栈和ma/v1任务，未增通用Agent框架。

初始“双智能体＋Security候选”基线见历史页；当前安全已纳入规划，Network/Backup/Deployment、多Worker授权、PVE和资产ACL仍候选。MA-M4按新的安全集成前置延期。

## SEC-M2本机建设增量（2026-10-13）

第一版业务、阶段7历史解读、阶段8当前问答/RAG/BND和MA前三阶段保持既有边界。SEC-M2本机候选新增程序强制门禁与本人审查报告；不迁移生产任务/日志，不更新服务器。原“待接入”状态为建设前历史。
