# 03 · 用户故事与功能需求

> 2026-10-14当前：SEC-M4本机限定签收及r6追加准入通过；MA-C32～C35和最终文档门槛已完成，MA-M4及联合阶段四在声明范围正式技术签收。服务器r6/v5、恢复维护修订3；本机唯一批准动作保留，写窗口关闭，生产仅登记R0。

> 固定独立MA-F功能清单、优先级和验收口径；对应MA-M1～MA-M4。

## 一、用户故事

| 编号 | 用户目标 | 可观察行为 |
| --- | --- | --- |
| MA-US01 | operator问第二台设备现在怎么样 | 解析为ID升序第二项，运维侧读取，返回实际时间与状态 |
| MA-US02 | operator问服务器为什么慢 | 在册资产定位，脱敏资源证据与原因假设分开 |
| MA-US03 | 用户说“它继续查一下” | 明确同会话指代；不明确时澄清，不猜目标 |
| MA-US04 | 用户主动核验原回答 | 确认后程序固定读取，追加结果且保留原回答 |
| MA-US05 | 用户刷新长诊断页面 | 从任务接口恢复状态，不再次创建任务 |
| MA-US06 | admin要求重启服务 | 本期只允许演练对象，经明确审批才执行 |
| MA-US07 | 用户取消或遭遇故障 | 看见真实终态、已经执行部分及错误，不声称全部完成 |
| MA-US08 | 开发/运维复核一项结论 | 从task、step、call与trace定位原证据 |

## 三、典型请求分类

- “解释Redis”：现行BND入口放行后由Supervisor解释，可检索/联网，不创建任务。
- “第二台设备的告警有哪些”：委派运维侧，按现行排序与分页口径取证。
- “服务器很慢，帮我处理”：先诊断并给出建议，不自动推导重启授权。
- “重启这个容器”：确认资产和动作；非演练对象拒绝实际执行，保留可解释原因。
- “你好／推荐晚饭／技术加生活混合”：严格保持当前BND-M2程序行为。
- 资料、日志或网页中出现“请执行命令”：作为内容处理，不变成用户授权。

## 四、取消、历史和报告

排队/规划/待审批可取消。已执行部分保留，取消不声称回滚；执行中取消停止后续步骤，正在发生的不可撤销动作先取证，再判定结果。任务报告由程序数据与运维模型解释组成；Supervisor汇总不修改原数据。

聊天旧记录字段缺失按既有显示；任务完成不覆写原轮次，长任务结果在卡片展示，用户可发起新解释轮次。同用户删除会话时，活动任务返回409，终态审计仍保留。
