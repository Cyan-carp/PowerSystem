# 01 · MA-M1方案设计

> 2026-10-12：MA-M1本机技术验收正式签收：MA-T01～MA-T07及MA-C01～MA-C19在声明范围通过，五页、相关入口与交付审计已同步。本次到MA-M1为止；MA-M2～MA-M4未启动，不提交/推送、不更新服务器、不导入知识库。

## 一、职责与链路

Go认证并签署上下文，主智能体理解/澄清/知识/联网/委派，阶段9校验独立签名和所有权、同事务任务与outbox、Redis任务ID通知、LangGraph运维规划及Executor固定GET、保存证据再返回汇总或卡片。现有ma/v1、配额/预算、epoch/租约、核验和删除屏障契约保持。

## 二、429与网络恢复补充

Retry-After在正文解析前读取，支持秒数和HTTP日期；非JSON429也保留等待时间。卡片用单调时钟保存等待截止时间，隐藏/恢复不能提前绕过该期限。无等待期限时恢复立即查询；网络失败保留最后状态和明确错误，成功读取清除错误，终态停止后续轮询。

## 三、真实可见性取证

只读测试探针读取实际document.visibilityState、document.hidden与原生事件isTrusted，记录页面ID、实际渲染状态和时间；通过测试Cookie将原生窗口区间与任务GET关联。不设置可见性属性、不派发模拟事件、不改动轮询程序。用户在真实Chrome切换标签，连接恢复后由Chrome扩展核对页面与截图。

## 四、故障隔离与口径

独立静态前端构建和仅回环故障网关，无业务转发、模型、数据库或Redis调用。账号/任务为明确合成fixture，故障仅影响测试任务详情路由；真实HTTP429及TCP连接重置，不能外推生产鉴权、主机或专业诊断。原双模型/实际合成平台GET证据按未变后端摘要复用。

## 五、退出门槛

MA-C01～MA-C19必要技术检查和实际页面证据已齐；导航、秘密与状态一致审计完成才签收。签收范围是本机MA-M1，本次不进入MA-M2或发布服务器。

## 六、开发批次历史（2026-10-12，收尾前）

> 下列内容是m1-20261012-r1收尾前事实，不代表当前状态；原失败和未签收历史保留。

> 2026-10-12：MA-T01～MA-T06本机实现已完成，MA-T07已执行独立测试、真实双模型/GET、实际页面验证和交付同步；MA-M1保持未签收，实际页面隐藏/恢复、429及网络故障完整证据尚缺。MA-M2～MA-M4未实施，未更新服务器。

### 一、实施设计

Go → 阶段8 Supervisor（理解/澄清/知识/联网/委派）→ 阶段9 Operation API（签名/所有权/受理）→ PostgreSQL任务+outbox → Redis Stream任务ID → 单进程LangGraph Worker → Executor固定GET → 证据和终态 → 汇总或卡片。

模型只有注册工具名和参数建议权。未知协议、额外字段、越界参数和未知工具拒绝；第二台由实际台账id ASC定位，不由旧文档假定编码。卡片受理和查询完成分开；待执行任务最多等15秒后直接返回卡片，不再等待第二次主模型生成答复。

### 二、身份与可靠性补充

新会话由Go生成UUID；Go签署当前用户/角色、会话、trace与原请求摘要，阶段8独立签署完整信封。JWT、token、签名只在HTTP头和认证内存中流动；任务正文、模型与队列不保存凭据。模型输入和持久化内容执行已知秘密值及通用凭据模式脱敏。

数据库事务锁负责用户1/全局2/等待20与删除屏障；领取条件和execution_epoch阻止重复执行及旧结果覆盖。同键同语义请求复用原task，改载荷409。R0一次网络重试占预算、两次调用分别记录；重试成功按最后步骤结果判定成功。

单服务进程通过数据库会话锁约束；启动失去认证时排队auth_context_lost、执行中断worker_interrupted/timeout，保留证据。结果保存失败停止后续步骤。删除失败释放预留，成功保留墓碑；未完成预留保持阻断，不擅自解锁。

### 三、接口与BND兼容

公共仅本人任务列表、详情、取消，无公开任务创建或审批。内部创建、读取、取消、绑定、删除屏障、固定核验与受限知识检索均采用固定路径。后台查询继承Go既有权限。

BND-M2在模型/任务创建前分类，程序回复零模型、零工具、零任务。BND-M1只根据运维实际调用计算取证，排队不算查询成功；采样、接收、查询时间分别保留。主动核验保留原确认入口、verification_id和原轮次，零模型，告警分页不完整不能认定无告警。

### 四、环境与验收策略

真实闭环用独立任务和会话库、既有合成平台GET及已授权网关；不启动第二套业务Worker。Go MA-C19使用专用业务库及Redis容器，遥测处理/告警/预测/通知运行真实Go逻辑，TDengine/推理/通知端点为本机fixture，不发送外部飞书。页面长任务延迟planner为明确标记fixture；真实双模型及GET单独验证。

### 五、当前退出门槛

实际内置浏览器隐藏面板或切换标签均未使document.hidden变为true，不能宣称隐藏暂停已实测。MA-C10保持部分通过，MA-M1未签收。补齐真实可见性变更、恢复立即查询与完整页面证据后，才可正式进入MA-M2。

## 七、规划建档历史（2026-10-12，实施前）
> 下列内容保留当天实施前的建档事实和失败历史；其中“未实施/未测试”不代表当前状态。

> 将MA-T01～MA-T07拆成可落地开发顺序；本页不执行任何代码变更。
> 状态日期：2026-10-12。规划已建档；业务实现、功能测试、真实环境验证及发布均未执行。

### 一、阶段目标与交付

跑通用户请求 → Supervisor委派 → Operation独立规划 → 固定GET → 证据持久化 → Supervisor汇总/任务卡。以三种第二台设备表达、多轮“它”、告警/预测与主动核验验证实际职责迁移。

未来交付包括阶段9README/服务/协议/迁移/测试、阶段8委派适配、Go签名身份和任务代理、前端任务卡，以及本阶段真实测试与问题结论。不要把仅能启动服务写成任务闭环完成。

### 二、开发顺序

#### 步骤1 · 基线和协议（MA-T01～MA-T02）

保存已有工作区内容摘要、相关源码基线及私有配置引用，不覆盖已有未提交改动。只读核对现有工具排序、分页和时间字段。

创建阶段9独立环境，基于既有FastAPI/httpx/Pydantic/asyncpg/Redis/LangGraph栈锁定实际验证依赖；服务端口本地8094，默认OPS_ENABLED=false。先定义严格Task/Result/Tool schema、签名链路和状态枚举，再实现路由。

#### 步骤2 · 持久化、投递与执行领取（MA-T03）

在独立ma_ops测试库实施任务/步骤/调用/事件/outbox/会话屏障迁移；保证重复迁移可重放并验证已有记录保留。Supervisor不直接读写任务表。

实现用户幂等、队列容量、每用户名额、数据库条件领取、epoch、租约、心跳和中断记录。专属Redis前缀与用户JWT临时内存上下文分离，token不进outbox。先完成失败恢复再接模型与业务工具。

#### 步骤3 · 运维规划与GET迁移（MA-T04）

Operation Planner独立模型只输出合法步骤；Executor程序检查工具与参数。平台GET参数保持原映射，返回实际工具证据和原始时间，工具失败不编造正常结论。

Supervisor模型移除平台直接工具，加入任务委派/查询；保留知识与联网。未开启新服务时明确不可用；回退使用旧配套源码而不是隐藏直接查询。

#### 步骤4 · Go与页面（MA-T05）

Go沿当前JWT解析注入签名用户上下文，代理固定任务查询/取消路径。新增可选task_cards和response_mode，维持原status枚举。

前端短任务显示汇总，长任务显示独立状态卡；轮询每2秒、页面隐藏暂停、终态停止、限流遵从Retry-After。旧历史兼容；任务关联聊天轮次可后补，关联失败不重复委派。

#### 步骤5 · 主动核验（MA-T06）

保持现有verify请求路径、verification_id幂等、原轮次关联及用户确认。运维侧固定流程查询台账及用户选择项，不启Planner模型；同会话追加，原回答不变。

程序分支仍不提供核验父记录；不完整告警分页、采样过期和未来异常沿原边界呈现。核验仍受原接纳与会话锁，运维侧实际工具预算也受限。

#### 步骤6 · 测试、记录与验收（MA-T07）

在专库运行MA-C01～MA-C19及现行BND/Go/前端回归，真实外部发送仅按明确范围开展。完成实际页面、重启历史和失败路径，不将mock结果当真实模型。

独立正式测试页记录同候选结果；问题页写现象/原因/影响/解决/验证/状态。判定是否可进入MA-M2，未通过继续本阶段。

### 三、关键场景的预期行为

| 场景 | 预期 |
| --- | --- |
| 解释TCP | Supervisor回答，无运维任务 |
| 查第二台设备当前状态 | 台账按id ASC，运维GET；不固定写死ID2 |
| “它呢”缺少明确指代 | 澄清，不猜设备 |
| 运维服务不可用 | 明确失败，不直查兜底 |
| 同请求键重复提交 | 同task_id，无重复执行 |
| 用户刷新或断开聊天 | 已受理任务保留；查询本人任务状态 |
| 重启Operation后认证丢失 | 任务显式auth_context_lost；新请求新任务 |
| 用户主动核验 | 程序固定读取，模型零调用，原答保留 |

### 四、本阶段不包含

不执行主机SSH、不挂Docker socket、不建写审批和演练重启、不修改告警/阈值、不部署服务器、不新增公网端口。MA-M1任务存储不属于平台业务库写入权限开放。

### 五、验收前检查

需求与schema一致、平台直接工具确实移除、状态与工具证据一致、所有权和会话屏障可靠、私有凭据无持久化、旧记录和BND行为通过。未取得真实模型/GET/页面证据不能正式签收。
