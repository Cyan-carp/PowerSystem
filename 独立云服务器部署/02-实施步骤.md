# 02 · 新云与 R730xd 实施步骤

> 本页按预检、入口、证书、备份和上线核对的顺序给出可复核操作。

以下命令在目标 Linux 主机以 root 执行。逐节核对输出，任何一步失败先修复，不跳过到开启流量。代码仓库只提供模板，安装后的私密值只保存在 `/etc`。记录实施时的 UTC 时间和版本到 [验收日志](05-验收与变更日志.md)。

## A. 新云只读预检

1. 在云控制台确认实例地域/安全组/磁盘、公网 IP；用已从控制台取得的 ED25519 指纹确认 SSH 首次握手。先建立公钥登录，保持控制台会话，再轮换初始密码并按现有 SSH 基线关闭 root 密码登录。执行 `sshd -t` 后才 reload；从第二终端重新登录成功前不关闭原会话。
2. `cat /etc/os-release; uname -m; free -h; df -B1 /srv /; ss -lntup; nginx -V 2>&1 | grep http_sub_module`。若 Nginx 尚未安装，先安装再确认 `http_sub_module` 可用；域名备案号展示依赖它。
3. 从 R730xd 确认最近有效密文：`latest=$(find /var/backups/powersystem -maxdepth 1 -name 'powersystem-*.tar.gz.gpg' -type f -printf '%T@ %p\n' | sort -nr | head -1 | cut -d' ' -f2-); test -s "$latest"; cd /var/backups/powersystem && sha256sum -c "$(basename "$latest").sha256"; stat -c %s "$latest"`。先确认其对应旧云密文 SHA256 一致。把得到的字节数传给新云的 [`scripts/check-backup-space.sh`](scripts/check-backup-space.sh)：`bash check-backup-space.sh <字节数> /srv/powersystem-backups`；脚本核对接收目录所在文件系统的可用字节是否 ≥ `max(10737418240, 30 × stat字节数)`。记录其输出和 `df -B1` 原值。未通过则停止新云备份配置。

## B. 新云 FRP 与 TLS 身份

1. 安装 `nginx`、`openssh-server`、`curl`、`ca-certificates`、`python3-venv`。按 CPU 架构从 [frp v0.71.0 官方发布](https://github.com/fatedier/frp/releases/tag/v0.71.0)下载对应 Linux tarball，在可信网络核对发布资产/摘要，记录实际 SHA256；把 **frps** 放 `/opt/powersystem-edge/frps`，权限 755。创建无 shell 系统用户 `powersystem-edge`，专用目录 `/etc/powersystem-edge` 权限 750。下载示例（R730xd 同版本，只安装 `frpc`）：

   ```bash
   case "$(uname -m)" in x86_64) frp_arch=amd64;; aarch64) frp_arch=arm64;; *) echo 'unsupported CPU' >&2; exit 1;; esac
   frp_asset="frp_0.71.0_linux_${frp_arch}"
   install -d -o root -g root -m 755 /opt/powersystem-edge
   curl --fail --location --proto '=https' --tlsv1.2 \
     "https://github.com/fatedier/frp/releases/download/v0.71.0/${frp_asset}.tar.gz" \
     --output "/tmp/${frp_asset}.tar.gz"
   sha256sum "/tmp/${frp_asset}.tar.gz"
   tar -tzf "/tmp/${frp_asset}.tar.gz" | head
   tar -xzf "/tmp/${frp_asset}.tar.gz" -C /tmp
   install -o root -g root -m 755 "/tmp/${frp_asset}/frps" /opt/powersystem-edge/frps
   /opt/powersystem-edge/frps --version
   ```

   在记录中保存 tarball 的 SHA256 和官方下载页核对结果；未核对来源时不要执行解压内容。
2. 从本目录 `config/frps.toml` 安装至 `/etc/powersystem-edge/frps.toml`。示例准备命令如下，`frp-token` 不得输出到终端或日志：

   ```bash
   useradd --system --no-create-home --shell /usr/sbin/nologin powersystem-edge
   install -d -o root -g powersystem-edge -m 750 /etc/powersystem-edge
   install -d -o root -g root -m 755 /opt/powersystem-edge /srv/powersystem-backups
   install -o root -g powersystem-edge -m 640 config/frps.toml /etc/powersystem-edge/frps.toml
   (umask 077; openssl rand -hex 32 > /etc/powersystem-edge/frp-token)
   chown root:powersystem-edge /etc/powersystem-edge/frp-token
   chmod 640 /etc/powersystem-edge/frp-token
   openssl req -x509 -newkey rsa:3072 -nodes -sha256 -days 825 \
     -keyout /etc/powersystem-edge/frp-server.key \
     -out /etc/powersystem-edge/frp-server.crt \
     -subj '/CN=8.138.42.212' -addext 'subjectAltName=IP:8.138.42.212'
   chown root:powersystem-edge /etc/powersystem-edge/frp-server.key
   chmod 640 /etc/powersystem-edge/frp-server.key
   chmod 644 /etc/powersystem-edge/frp-server.crt
   ```

   公证书复制到 R730xd 的 `/etc/powersystem-edge/frp-server.crt` 并核对 SHA256，私钥只留新云。FRP TLS 证书用于 frpc 认证 frps，与公网 Nginx 证书独立；不要复用公开网站证书私钥。参见 [FRP TLS 官方说明](https://gofrp.org/en/docs/features/common/network/network-tls/) 和[文件 token](https://gofrp.org/en/docs/features/common/authentication/)。
3. 安装 `config/powersystem-edge-frps.service` 为 `/etc/systemd/system/powersystem-edge-frps.service`。先 `/opt/powersystem-edge/frps verify -c /etc/powersystem-edge/frps.toml`，再 `systemctl daemon-reload; systemctl enable --now powersystem-edge-frps`，核对日志无 token/TLS 泄漏、仅监听预期端口。`allowPorts` 仅限 3667/7070。
4. 云安全组：22/7070 仅管理出口 IP，7000 仅 R730xd 出口 IP，80/443 对需要的访问网开放；3667 拒绝公网。把 R730xd 实际出口 IPv4 和管理员当前出口 IPv4 分别写入私有 `/etc/powersystem-edge/allowed-client-ipv4`、`allowed-admin-ipv4`（root 600）。安装 `config/powersystem-edge-firewall.sh` 为 `/usr/local/sbin/powersystem-edge-firewall`（755），对应 service 到 `/etc/systemd/system/`，`systemctl daemon-reload; systemctl enable --now powersystem-edge-firewall`；主机规则允许前者访问 7000、后者访问 7070，阻断其他来源以及公网 3667，IPv6 的三个端口均拒绝。来源 IP 变化时先经 22 或控制台更新文件并重跑 service。先确认 SSH 会话/控制台可恢复，再改防火墙；重启后复验。未备案时 80 只供 IP 证书 HTTP-01，不提供域名网站。

## C. 新云 IP HTTPS，域名 Host 隔离

1. 安装 Certbot 5.4 或更高版本，记录版本；建议 `python3 -m venv /opt/powersystem-edge/certbot-venv && /opt/powersystem-edge/certbot-venv/bin/pip install 'certbot==5.8.0'`。创建 `/var/www/powersystem-acme/.well-known/acme-challenge/`，移除发行版默认 Nginx 站点；先将 `config/ip-bootstrap.conf` 安装到 `sites-enabled/powersystem-ip.conf`，执行 `nginx -t && systemctl reload nginx`。从外部确认 `Host: www.cyancarp.cn` 的 HTTP 请求返回 421，不进入业务。
2. 先用 Let's Encrypt **staging** 演练，再申请生产 IP 证书：`/opt/powersystem-edge/certbot-venv/bin/certbot certonly --preferred-profile shortlived --webroot --webroot-path /var/www/powersystem-acme --ip-address 8.138.42.212`。staging 命令增加 `--staging`，其证书不可信，不能作为验收。IP 证书有效期六天，续期需高频执行。证书路径应为 `/etc/letsencrypt/live/8.138.42.212/`；核对证书 SAN 和到期日。[官方命令说明](https://letsencrypt.org/2026/03/11/shorter-certs-certbot)。
3. 用 `config/ip-https.conf` 替换 bootstrap，`nginx -t && systemctl reload nginx`。安装本目录 `config/powersystem-edge-cert-renew.service/.timer` 到 `/etc/systemd/system/`，`systemctl daemon-reload; systemctl enable --now powersystem-edge-cert-renew.timer`；执行 `/opt/powersystem-edge/certbot-venv/bin/certbot renew --dry-run`，记录 timer 和下次运行时间。deploy hook 只在证书更新后 reload。
4. `config/domain-after-filing.conf.disabled` 与 `config/domain-http-bootstrap.conf.disabled` 可以复制到新云的**非** `sites-enabled` 目录作为待启用资料。备案前 Nginx 生效配置中不得出现 `server_name www.cyancarp.cn`；用 `nginx -T` 检查。外部测试 80 域名 Host 返回 421，443 域名 Host 不返回业务 HTML/API；IP `https://8.138.42.212/` 可以访问。

## D. 新云受限 SFTP（磁盘门槛通过后）

1. 创建 `powersystem-backup` 无登录 shell 账号：`useradd --system --no-create-home --home-dir /incoming --shell /usr/sbin/nologin powersystem-backup`。主目录在 chroot 内为 `/incoming`，禁止密码登录。创建 `/srv/powersystem-backups` 为 `root:root 755`、`/srv/powersystem-backups/incoming` 为 `powersystem-backup:powersystem-backup 700`。chroot 及所有父目录不得由该用户写入。放置 R730xd 现有 `/etc/powersystem/backup-ed25519.pub` 到新云 `/etc/ssh/authorized_keys/powersystem-backup`（root 拥有、644；这是公钥，sshd 以目标用户身份读取）；如果只有私钥，在 R730xd 用 `ssh-keygen -y -f /etc/powersystem/backup-ed25519` 导出公钥，绝不复制私钥。
2. 可使用本目录 [`scripts/install-sftp-receiver.sh`](scripts/install-sftp-receiver.sh) 在磁盘门槛通过且公钥已核验后安装受限账号。它使用 `config/sshd-powersystem-backup.conf`，等价的关键配置如下：

   ```text
   Match User powersystem-backup
       ChrootDirectory /srv/powersystem-backups
       ForceCommand internal-sftp
       AuthorizedKeysFile /etc/ssh/authorized_keys/%u
       PasswordAuthentication no
       PermitTTY no
       AllowTcpForwarding no
       X11Forwarding no
   ```

   `sshd -t && systemctl reload ssh` 后，从 R730xd 用备份私钥 `sftp -b /dev/null -i /etc/powersystem/backup-ed25519 powersystem-backup@8.138.42.212` 测试，确认 shell、端口转发和越出 `/incoming` 被拒绝。云端只允许保存密文与其 `.sha256` 文件，定期核对权限、空间与保留期限。

## E. R730xd 追加专用 FRP 与双目标备份

1. 保留原 `/opt/frp/frpc.toml` 和 `frpc.service` 不动。安装与新云同版本的 **frpc** 到 `/opt/powersystem-edge/frpc`，创建系统用户/目录。复制 `config/frpc.toml`、`config/powersystem-edge-frpc.service` 到相应 `/etc` 路径；安全地复制 token 和服务端公证书，权限 600/644。`frpc verify -c /etc/powersystem-edge/frpc.toml` 后启用新 service。确认新旧 `frpc` 均 active、新云 3667/7070 建立，业务 `127.0.0.1:18080` 正常。
2. 将新云 **ED25519 主机公钥**经控制台指纹核验后加入备份用户使用的 `known_hosts`。用 R730xd 备份密钥测试 SFTP。仅在磁盘门槛、目录权限和传输成功后，把 `powersystem-backup@8.138.42.212:/incoming/` 写入 `/etc/powersystem/backup-secondary-target`（root 600）；保留 `/etc/powersystem/backup-target` 原值。新版 `backup.sh` 不配置副目标时仍是原单云行为。
3. 执行一次 `bash stages/04-frontend/deploy/backup.sh`；核对两台云收到**同一份**密文及 `.sha256`，分别由云端管理员计算 SHA256，与 R730xd 本地一致。脚本任一上传失败会退出非零并留下本地密文；告警/日志要显示是哪台目标失败。然后在 R730xd 执行 `restore-verify.sh` 对同份密文做隔离恢复。

此处只新增边缘入口与备份目的地，不运行 Compose 重建、不迁移 PostgreSQL/TDengine/Redis 卷、不修改旧共享 FRP。

## F. 上线核对与观察

1. 从独立网络对 `https://8.138.42.212/` 和旧 IP 分别核对证书链、80→443、`/api/v1/ping`、登录页及核心路由；未登录总览应为 401，`/internal/agent/health` 与注册接口应为 403。域名 Host 的 80/443 在备案前应为 421，`nginx -T` 不应有启用的 `server_name www.cyancarp.cn`。
2. 在 R730xd 以 root 运行本目录的 [`scripts/check-auth-wss.py`](scripts/check-auth-wss.py)：`python3 check-auth-wss.py /etc/powersystem/demo-password`。脚本仅输出两个 IP 的登录、总览、设备、告警、预测、Agent 解读 API 与 WSS 状态，不输出密码、JWT 或 ticket。若没有预建的 `demo-operator`，用现有获授权账号调整脚本中的用户名和其私有口令路径，勿把口令传入命令行或日志。两个入口各自登录，浏览器会话不共享。
3. 从**不在白名单中的外部节点**探测 3667/7000/7070 均不可达；从 R730xd 确认 7000 所需 FRP 会话正常；从当前允许的管理来源以公钥经新云 7070 登录 R730xd，并核对目标主机指纹。云控制台另核安全组，不以主机规则代替安全组配置核对。
4. 在旧云、新云和 R730xd 对同名 `.tar.gz.gpg.sha256` 分别执行 `sha256sum -c`。在 R730xd 对这一份密文执行 `restore-verify.sh`，记录双库行数、模型、队列、Agent 与私有配置文件校验。隔离项目和明文临时目录清理时先核对精确路径。
5. 受控短停新云专用 `powersystem-edge-frps`，确认旧 IP 与 R730xd 本地业务正常后立即恢复。随后在 R730xd 运行 `bash observe-dual-entrances.sh 61 30 /var/log/powersystem-edge-observe-YYYYMMDD.csv`，首末采样跨越 30 分钟；检查退出码为 0、输出 `samples=61 failures=0`、CSV 共 62 行（含表头），两个业务容器重启计数不变。脚本与 CSV 均留在 R730xd 的受限目录，不包含业务密钥。
6. 记录各项实际结果与 UTC 时间到 [05 验收与变更日志](05-验收与变更日志.md)；不能把域名备案后的步骤提前勾选。
