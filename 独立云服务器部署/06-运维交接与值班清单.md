# 06 · 运维交接与值班清单

> 本页供值班人员核对入口、证书、备份、容量和常见故障的处置顺序。

本页供部署完成后的值班人员使用。业务真实运行位置仍是 R730xd；两台云机只提供入口和异地密文。所有命令均在对应主机以有权限的账号执行，输出要脱敏后再进入工单。正式结果以 [05 验收与变更日志](05-验收与变更日志.md) 为准。

## 服务和配置索引

| 主机 | 服务/文件 | 用途与约束 |
| --- | --- | --- |
| R730xd | `frpc.service`、`/opt/frp/frpc.toml` | 旧云共享入口；本次未修改，回退新入口也不得停止。 |
| R730xd | `powersystem-edge-frpc.service`、`/etc/powersystem-edge/frpc.toml` | 只连新云，导出本机网页和 SSH；FRP token 在同目录受限文件，日志不能输出其内容。 |
| R730xd | `powersystem-backup.timer/.service`、`/opt/powersystem/stages/04-frontend/deploy/backup.sh` | 每日导出、加密并上传；主目标 `/etc/powersystem/backup-target` 保持旧云，副目标 `/etc/powersystem/backup-secondary-target` 指向新云。 |
| 新云 | `powersystem-edge-frps.service`、`/etc/powersystem-edge/frps.toml` | 独立 FRP 服务端；7000 控制、3667 网页代理、7070 R730xd SSH 代理。 |
| 新云 | `nginx.service`、`/etc/nginx/sites-enabled/powersystem-ip.conf` | IP HTTPS/WSS 与 HTTP-01；域名配置只保存在 `/etc/nginx/powersystem-disabled`，备案前不能链接到 `sites-enabled`。 |
| 新云 | `powersystem-edge-firewall.service`、`/etc/powersystem-edge/allowed-{client,admin}-ipv4` | 拒绝公网 3667，限制 7000/7070 来源。若出口 IP 变化，先经 22 或控制台核对身份并更新白名单。 |
| 新云 | `powersystem-edge-cert-renew.timer/.service` | 每天两次检查短期 IP 证书，签发成功后重载 Nginx。 |
| 新云 | `/srv/powersystem-backups/incoming` | 只存 `.tar.gz.gpg` 密文与 `.sha256`；没有解密口令。 |
| 旧云 | 原共享 FRP、Nginx、备份 SFTP | 手动备用入口；本次未停用和迁移。 |

## 每日交接时确认

1. 从可信外部网络分别访问 `https://8.138.42.212/api/v1/ping` 与 `https://8.138.10.222/api/v1/ping`，预期均为 HTTP 200。记录证书到期日及浏览器可信状态。备案前域名 Host 不应进入业务。
2. 在 R730xd 执行 `systemctl is-active frpc powersystem-edge-frpc powersystem-backup.timer`，再查看 `systemctl show powersystem-backup.service -p Result -p ExecMainStatus` 和最近一次日志：`journalctl -u powersystem-backup.service -n 80 --no-pager`。若最近一次失败，查明主/副目标，并核对本地密文仍存在。
3. 在新云执行 `systemctl is-active nginx powersystem-edge-frps powersystem-edge-firewall powersystem-edge-cert-renew.timer`、`df -h /srv/powersystem-backups`、`systemctl list-timers powersystem-edge-cert-renew.timer`。若短证书续期失败，先查 80 端口 challenge 与 Certbot 日志；不要关闭 TLS 验证绕过问题。
4. 在两台云机查最新同名备份和摘要，至少每日抽查最新一份：进入接收目录后运行 `sha256sum -c powersystem-实际时间.tar.gz.gpg.sha256`（将“实际时间”替换为该份密文文件名中的 UTC 时间）。不得在云机解密。若一端缺文件，先修传输并补传 **R730xd 本地保留的同一份密文**，再对比摘要。
5. 查看 R730xd 业务容器状态和 Agent 状态；两入口共享同一个业务源，两个入口都异常时先检查 R730xd。日志和截图只保留错误码、时间、服务名、脱敏摘要。

## 常见故障的先后顺序

| 现象 | 先确认 | 处置入口 |
| --- | --- | --- |
| 新 IP 502、旧 IP 正常 | 新云 frps、R730xd 新 frpc、7000 白名单、Nginx 上游 | [04 入口切换与回退](04-备份恢复与回退.md)；用户临时使用旧 IP 重新登录。 |
| 旧 IP 故障、新 IP 正常 | 旧云共享 FRP/Nginx，R730xd 原 frpc | 用户临时使用新 IP 重新登录；不改业务容器。 |
| 两个 IP 同时失败 | R730xd 业务 Nginx/API、容器、网络和两个 frpc | 按原业务运维手册处理；新云不是业务副本。 |
| 新云 7070 管理 SSH 失败 | 当前运维出口 IP 是否在 `allowed-admin-ipv4`、R730xd 新 frpc、云安全组 | 保留新云 22 与云控制台应急通道；更新白名单并重跑防火墙 service 后复测。 |
| 新云备份失败 | `df -h`、SFTP账号/密钥/主机指纹、`/incoming` 权限 | 保留本地密文，修复后重传同一份；见 [04 备份恢复](04-备份恢复与回退.md)。 |
| 新云证书临近到期 | timer、80 端口外部通达、Certbot 日志、ACME 路径 | 按 [03 域名与证书](03-域名与证书.md) 的 IP 续期步骤处理；IP 短证书不能按传统 90 天节奏巡检。 |

## 变更与容量纪律

- 修改 FRP、Nginx、sshd 前先保存原配置、验证新配置，再 reload/restart；从独立外部节点复测新旧入口。改防火墙或来源 IP 时先确认 22 与云控制台仍可恢复，不能先关闭唯一管理通路。
- 新云接收卷每次有业务数据量明显增长时，重新计算 `max(10 GiB, 30 × 最近有效密文大小)`；低于门槛时暂停新增备份接入和清理计划，先扩容或处理保留策略。备份保留期由所有者确定；批量清理前先核对至少一份两云同摘要、可隔离恢复的近期密文和服务器外解密口令副本。
- 每月至少选择新云的一份密文，在 R730xd 运行隔离恢复；记录双库、模型、队列、Agent、私有文件的结果。不要在新云保存明文或解密口令，不对生产 Compose 使用 `down -v`。
- 备案成功前不启用域名站点；备案成功后仍需按 [03](03-域名与证书.md) 核实真实备案号、域名证书与页脚。旧 IP 保持手动备用，域名与两个 IP 的浏览器会话分别登录。
- 新云的 root 初始密码曾在聊天中传递。所有者应经控制台和受控密码管理方式轮换，并保留至少一个经测试的公钥与应急通路；不要把新密码发到聊天或 Git。
