## 一、本页的维护与增补规则

- **单一声明**：同一约定只在本页声明一次；其他笔记需要时用双链指向本页对应章节，不复制条款。阶段内的具体操作命令以各阶段源码 README 为唯一维护入口，本页不复制命令清单。
- **AI 自动增补（长期约定）**：AI 助手在本仓库协作期间，对话中一旦形成新的工程约定（文件归属、命名、流程、边界、安全要求等具有长期效力的规则），应**主动判断归属章节、直接在本页合适位置增补条款**，并在当次回复中说明增补了什么、放在哪里；用户无需逐条要求"写进规范"。
- **增补前先查重**：写入前先检查本页是否已有同类条款，能并入原条款的不另起新条；拿不准归属时放入最贴近主题的章节末尾，并在回复中说明理由。
- **不写入本页的内容**：一次性操作决定、临时排障结论、阶段内具体实现细节，分别归入阶段笔记、问题记录页或测试交付页。
- **跨版本边界的单一入口**：长期有效的能力、服务器、数据、发布、验收与笔记限制，在本页写清维护规则，并同步 [[规范/项目边界与协作红线]] 的具体适用范围、原因和核验前提；使用手册、验收清单及阶段笔记只引用或说明与自身相关的例外，避免同一限制出现互相矛盾的版本。
- 本页自身的修改同样遵守第四、五章的排版与同步要求。

### 本机归档与服务器运行目录（2026-10-13兼容修订）

- `资产/runtime/`只收纳本机历史归档，例如已有的agent-status-fix-20261009.tar.gz；它不是在线模型、审计、发布材料或数据卷的统一新位置。
- 服务器继续使用`/opt/powersystem/runtime/`及私有配置指定的实际挂载源；本轮不移动这些目录、不改运行数据路径。`stages/`保存源码，两者用途不同。
- 知识清单的`path`是新布局物理路径，`title`保持原文档逻辑标识。更新来源路径不等于重建或导入知识；Docker内的文档挂载应与同版本清单一致。
- 发布/备份兼容新旧布局时优先新路径，旧路径只用于尚未迁移的服务器。新增目录不能扩大到`资产/runtime/`、凭据、审计或原始日志的公开打包范围；旧批次证据和源码摘要保持原样。

**目录树不能直接表达的特殊归属**

- 智能体知识源与设备操作边界：
  - **知识源受控**：未命中问题与搜索凭据属于私有运行材料，不自动加入知识库、不进入公开 Git；知识资产随版本构建，原始运行记录与人工审核状态分开保存。
  - **只读边界**：AI 可提出有来源的参考建议，但不能替代人员实施；涉及实际设备操作必须在建议旁醒目标注专业人员复核与实施，并允许逐条展开该建议实际引用的知识库章节、具体网页或业务证据；无法明确排除设备操作时保守提醒。
  - **审核不伪造**：阶段内暂缓专业来源审核的授权、原因与边界记录于阶段方案及正式测试页，不伪造审核、不自动补库。
  - **联网与白名单**：联网补充仍须通过原有证据与数字校验，不增加模型工程操作权限；适配升级前保存防线及工具白名单基线，交付时核对，运行失败批次独立留存。

- 阶段四第 15 周部署代码在 `stages/04-frontend/deploy/`；阶段六的 TLS、防火墙、证书、备份与恢复脚本也保持在该目录，`stages/06-security-recovery/` 只提供运行导航，避免破坏统一部署路径。
- 阶段五原始送达证据是历史事实，留在忽略的 `artifacts/stage4-前端上线/p0m4-20260929-113809/`；阶段五笔记引用即可，不重复生成验收记录。
- 阶段六私有恢复材料：加密包在异地备份主机，解密口令和私有配置在服务器/所有者离线介质；公开仓库只记录方法、计数、哈希核对结果和边界。

### 阶段完成与验收判定（强制）

每个阶段收尾时，除上述"测试交付""问题记录"两份笔记外，还必须形成一份**可复核的阶段验收结论**，集中回答五件事：本阶段做了什么、遇到什么问题、怎么解决的、还有哪些没解决、能否进入下一阶段。判定不通过就不能标记"已完成"，更不能进入下一阶段。

**验收结论必答项**

- **完成任务清单**：对照立项拆分（`01-智能体需求与可行性` 或对应阶段方案设计）逐项列出本阶段交付的任务，明确"已实现 / 已测试 / 已验收 / 真实环境已验证"四档，不得互相替代。
- **问题与解决**：本阶段遇到的错误统一指向独立问题记录页；验收结论只保留"问题 → 解决方式 → 验证结果"的结论性摘要，并链接到问题页。
- **未解决问题**：逐条列出仍未解决的问题，注明**归属阶段**与**是否阻塞本阶段验收**；阻塞项未清，阶段不能签收。
- **进入下一阶段判定**：给出明确结论"可进入 / 不可进入"，不可进入时写明缺什么证据、补什么验收。

**验收判定门槛（不满足不得签收）**

- 本阶段"测试与交付"笔记已形成，结论与证据对应，旧失败批次保留、不覆盖成通过。
- 独立问题记录页已核对：已解决项附验证结果，未解决项附归属与阻塞判断。
- 验收口径与立项口径一致；项目所有者在本阶段追加的增量验收（如联网五题、逐条人工来源审查）未完成时，阶段不得按"已完成"状态进入下一阶段。
- 判定依据必须有具体证据（运行编号、文件路径、镜像指纹、检查条数），不能只凭"HTTP 200""单次冒烟""数字与编号校验通过"或历史成功批次代偿。

> 判定边界：协议通过不等于来源支持；本机通过不等于服务器通过；旧镜像的观察/恢复结论不能转移到新镜像。下一阶段（V2-M4）的整体复核不能代偿本阶段（V2-M3）的增量验收。

## 五、笔记排版规范

统一沿用已有笔记风格（需求分析、技术选型、架构设计、开发阶段1 均为同一套）。

**文件骨架**

**正文元素**

6. **表格**：内容简短的并列信息、对照和清单用 Markdown 表格；长句或成组数字改用标题与列表。
7. **说明框**：关键提醒、设计决策的「为什么」用 `> 说明文字`。

9. **双链**：同目录互链用短链 `[[01-xxx]]`；跨目录用全路径 `[[内容/第一版-平台主体/开发阶段1-数据链路/01-环境与Git]]`（避免同名歧义）。
10. **术语**：编号（FR/NFR/任务号）与已有笔记严格对齐，不重号。

### 反堆叠写法（信息密度高的笔记必读）

笔记出现「整段灰墙、表格过宽、代码连片」的观感时，按下列规则重排，语义、命令、路径、编号一律不改：

**整段长文 → 列表**

- 一句话里串了多个并列事实、结果或边界声明时，拆成 2～4 条短列表。
- 每条只讲一件事；关键数字单独成行并加粗。

**宽表格 → 加粗标题 + 列表**

- 表格某列单元格塞进长句、多组数字或命令/路径时，放弃表格，改用「**加粗小标题** + 明细列表」。
- 典型场景：测试结果（`检查项 | 结果`）、现象排查（`现象 | 处理`）、联调记录（`检查点 | 实测值`）。
- 保留表格的前提：每格内容都是短词、短路径或单个数，读起来无需换行。

**代码块 → 步骤化**

- 连续多段命令堆在一起时，每段前加 `#### 步骤 N · 动词短语` 标题（如「步骤 1 · 预检并启动」）。
- 命令的关键注释（何时执行、环境要求、副作用）用 `>` 引用框紧跟其步骤，不埋进正文。

**边界与结论 → 引用框**

- 「不能只凭 X 判定通过」「此数据不代表真实场站」这类否定/限定结论，单独放 `>` 引用框与正文隔离。
- 需要列举判定依据时，在引用框内再嵌列表。

**分组小标题**

- 超过 6 条的无序列表，按主题拆成若干组，每组配一个加粗小标题（如「文件骨架 / 正文元素 / 链接与术语」）。
- 超过 6 行的表，按主题拆成多张表，各配加粗小标题。

### 9.2 环境前提与复现边界

**环境前提**

- 依赖：Docker Desktop Engine、Go 1.24+、Python 3.12+；端口 `1883`、`18083`、`6041`、`5432`、`6379`、`8080` 不应被其他服务占用。
- 仓库根目录 `.env` 为本机私有文件；新环境按 `.env.example` 准备，已有 Docker 卷必须使用与该卷匹配的密码。
- 四个基础容器（EMQX、TDengine、PostgreSQL、Redis）端口均映射到 `127.0.0.1`，仅供本机程序连接；数据库密码保存在被 Git 忽略的 `.env`，不写入笔记。

**复现边界**

- `artifacts/`、`.env`、Docker 数据卷不随 Git 迁移；换机器必须重新准备环境与生成数据，旧运行编号不会自动出现，以新运行编号保存证据。
- Docker CLI 未在 `PATH` 中不能直接判定 Docker Engine 不可用，应检查安装路径、服务端和容器状态；阶段一脚本的 `Get-DockerExe` 会尝试查找用户目录的 Docker Desktop 安装路径。
- Compose 容器与本机启动的 API/网关进程不要混为一谈；`ping` 只说明 API 接口可达，四容器状态、进程启动结果和烟测全通过，才能证明基础链路就绪。
- 烟测会在当前数据库创建测试账号、设备和遥测；需重跑完整 M2 时按阶段二 README 执行 `run-stage2-test.ps1`（约两小时并注入故障），短测不代替 M2。
- 停止服务分别用 `stop-ai.ps1` 与 `stop-stage2.ps1`；两者不会删除数据库卷，勿用 `docker compose down -v` 清理历史数据。
