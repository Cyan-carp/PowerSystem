# 06 · 立项论证（选题自检五问）

> 回到 [[00-索引·行业调研与产品分析]]
> 对应手册「任务 3：选题自检五问——立项前的最后关卡」。五个问题各写一段，任何一个答不出，就说明调研还没到位。

## 一、谁在为这个痛点流血，痛到什么程度？

**中小新能源场站的业主和值班员**，以及正在规模化扩张的新能源发电运营商。

他们面对的四大痛点（详见 [[01-行业背景与市场分析]]）：设备厂商协议不统一造成**数据孤岛**、场站偏远分散导致**巡检人力成本高**、事后维修导致**故障发现滞后**、海量告警靠**人工筛查**。量化看，风电事故 62% 源于部件失效、单次损失百万级；传统故障响应平均 48 小时，而头部企业的 AI 平台已能降故障率 34%、把非计划停机降 40%。**这个痛是真实的、量化的、正在流血的。**

## 二、为什么是现在做？

三个时机同时成熟（详见 [[02-政策环境与驱动力]]、[[03-技术现状与发展趋势]]）：

1. **政策时机**：「十五五」规划明文要求「智能识别、自动化巡检、故障智能诊断」；《能源数字化智能化若干意见》（2023）已点名「智能运维、故障诊断」场景。
2. **技术时机**：MQTT、时序数据库、XGBoost 等关键组件已高度成熟、开源可用，单人即可搭起企业级骨架。
3. **市场时机**：2025 年风光运维市场突破 700 亿元、智能运维渗透率仅 41%，**增量红利 + 存量改造叠加**，正是窗口期。

## 三、现有方案为什么不够好？

三类玩家各留缺口（详见 [[04-竞品分析]]）：

1. **通用平台「重而不专」**：阿里云/华为云 IoT 是底座，离新能源运维业务远，需大量二次开发。
2. **开源平台「全而不易」**：ThingsBoard 功能全但二开/运维门槛高，无原生 AI 与业务闭环。
3. **垂直平台「强而绑定」**：华为/金风/远景绑定自家硬件或单一品类，难低成本复制到异构中小场站。

**结论**：没有一家为「中小异构场站」提供低成本、可解释、开箱即用的方案——这就是我们的空间。

## 四、凭什么是你？

三条差异化能力支撑（详见 [[05-产品定位与差异化]]）：

1. **机理仿真数据方法**：不是编数据，而是基于光伏逆变器运行机理建模，正面回应「数据从哪来」的评委必问。
2. **可解释小数据 AI**：XGBoost + 特征重要性，用对照实验说话，而非追逐大模型黑盒——契合工业运维「要能讲清为什么报警」的真实需求。
3. **完整技术栈团队 + 全栈工程化**：Go 后端、Python ML、Vue 前端、物联网通信互补，能独立走完「数据链路 → 后端 → AI → 前端 → 部署」全流程。

## 五、做成的最小样子是什么？

> 一句话演示场景：

**某光伏电站值班员早上打开系统，看到 3 号逆变器被标记为「故障高风险」，点击查看它过去 72 小时的温度曲线和 AI 预测依据（特征重要性），一键生成检修工单。**

这个场景串起了整个系统的最小闭环：遥测采集 → 云边协同 → 告警/预测 → 可视化 → 处置闭环。能跑到这个颗粒度，就说明立项想清楚了。
