# 行业调研与产品分析 · 索引

> 本文件夹是「源网智联」新能源场站云边协同智能运维平台在**写代码之前**的地基文档，回答三个问题：**这个行业值不值得做、国家支不支持、我们凭什么做。**

## 一页读懂（给行业外人士）

> **国家为什么推**：国家发改委、国家能源局 2026 年印发的《可再生能源发展"十五五"规划》白纸黑字写着要「应用智能识别、自动化巡检、故障智能诊断等技术，提升新能源智慧运维水平」「支持区域新能源场站群一体化集控运维」——说白了，光伏风电建得越多，国家越要逼着这些场站用 AI 少用人、少停电。
>
> **市场有多大**：风光装机增长带来运维需求；市场规模、渗透率等具体估算仍需核对一手来源、年份与统计口径。见 [[01-行业背景与市场分析]] 的来源核验说明。
>
> **现在的人为什么痛苦**：异构设备数据难统一、场站分散增加巡检成本，故障发现滞后又使告警处理被动。案例中的降故障率、事故占比和损失金额仍需核对原始披露与口径，见 [[01-行业背景与市场分析]]。

## 项目一句话定位

**「源网智联」** = 面向中小新能源场站的云边协同智能运维平台，用**机理仿真数据 + 可解释的小数据 AI**，把运维从「被动响应」变成「主动预防」，实现低成本、可复制的场站少人化运维。

技术主线：`设备模拟器 → MQTT → Go 边缘网关 → 时序库 → Gin 后端 → XGBoost 故障预测 → Vue3 前端`

## 结论速览（答辩前核验）

1. **市场**：风光装机增长支撑运维需求；“700 亿元”“300 亿元”“41%”“28%+”目前只作待核线索，不用于答辩中的已证实市场结论。核验口径见 [[01-行业背景与市场分析]]。
2. **政策**：「十五五」规划明文要求「智能识别、自动化巡检、故障智能诊断」，AI+能源系列文件点出「设备故障预测性维护」。
3. **痛点根因**：数据孤岛（协议不统一）、巡检成本高（场站偏远分散）、故障发现滞后（事后维修）、告警淹没（缺收敛分级）。
4. **竞争格局**：可从通用平台、开源平台和垂直平台的适配成本与业务能力比较；头部份额等数字需补原始来源，见 [[04-竞品分析]]。
5. **我们的差异**：小数据可解释 AI（XGBoost+特征重要性）与 Docker 化部署是已实现的技术路线；相对商业平台的成本降幅尚无同口径实测。
