# 01 · 智能体需求与可行性

> 本页是第二版升级的立项笔记：回答为什么做、做什么、怎么做、怎么分期验收。编号沿用第一版体系顺延（用户故事 S-10 起、FR-20 起、NFR-14 起），不与第一版重号；正式并入《功能需求清单》等第一版需求笔记，待第二版业务完成后统一更新。

> **当前进度（2026-10-06）**：V2-M4 在合成演示与公开资料辅助建议范围正式技术签收，发布版本 v2.0.0；专业审核及真实设备适用性保持待办。正式交付见 [[第二版-智能体升级/开发阶段4-测试、安全复核与交付/05-V2-M4测试与交付]]。

## 一、背景与立项依据

- 第一版（六阶段合成演示系统）已发布 `v1.0.0`，设备接入、告警闭环、AI 预测、飞书通知、公网安全与恢复均已验收，主体功能不再大改。
- 第一版 [[第一版-平台主体/开发阶段3-AI预测模块/05-智能体接口设计]] 已预留方向：由诊断智能体把模型结果、历史曲线与告警关联起来，向值班员说明可能原因与人工检查步骤。第二版把这一方向扩展为完整业务。
- 第一版行业调研记录的运维痛点（故障发现滞后、依赖人工经验、运维人力紧张）在告警「已送达」之后仍然存在：值班员拿到告警后还要自己查曲线、翻文档、判断处置。**告警解读与使用引导是告警链路的自然延伸，不是另起炉灶。**

## 二、企业需求与价值

| 需求场景 | 现状缺口 | 智能体价值 |
| --- | --- | --- |
| 告警处置 | 告警弹窗只给「什么越限」，原因与处置靠值班员经验 | 自动关联预测、曲线与历史告警，给出可能原因与建议检查步骤，缩短研判时间 |
| 新人上手 | 平台页面与功能靠手册和口口相传 | 页面级使用引导，随功能版本同步，降低培训成本 |
| 值班问答 | 查数据要在多个页面间切换 | 用自然语言完成只读查询，结论附数据时间与来源，可回查 |
| 经验沉淀 | 处置经验留在个人脑子里 | 问答与解读记录留痕，形成可复核的处置参考 |

> 以上价值建立在合成演示数据之上；面向真实场站时，解读质量需用真实数据重新验证，不能外推。

## 三、功能范围（新增编号，第二版生效）

### 功能需求

| 编号 | 需求 | 描述 | 优先级 |
| --- | --- | --- | --- |
| FR-20 | 告警智能解读 | 设备越限、AI 风险、平台监控事件产生时，自动生成原因分析与处置建议，在大屏自动弹出解读卡片；解读附证据（数据时间、模型来源、引用曲线/告警） | Must |
| FR-21 | 平台使用引导 | 页面级功能导览与操作指导；内容与当前版本功能一致，功能变更后同步更新 | Should |
| FR-22 | 值班问答 | 基于平台实时数据与知识库的自然语言问答；只读查询，结论附证据来源 | Should |

### 非功能需求

| 编号 | 需求 | 描述 |
| --- | --- | --- |
| NFR-14 | 解读不阻塞告警主链路 | 智能体解读为异步附加链路；FR-02 的 10 秒告警延迟与 FR-19 的飞书投递不因智能体故障而回退 |
| NFR-15 | 智能体只读约束 | 交互问答通过当前用户 JWT 调用 Go；自动解读由 Go 提供受限事件证据包，Agent 不任意查询、不直连业务库。沿用现有角色权限（登录用户可读全部演示设备，尚无逐设备授权）；不自动处置、不远程控制、不自动建工单 |
| NFR-16 | 回答可溯源 | 每条解读/回答附证据来源与数据时间；模型不可用或数据不足时明确说明「无法判断」，不编造 |

### 用户故事

- **S-10**：作为值班员，我希望告警弹出时同步看到可能原因和建议检查步骤，以便不靠个人经验也能快速研判。
- **S-11**：作为新上岗值班员，我希望平台能告诉我每个页面怎么用，以便不翻手册也能完成日常操作。
- **S-12**：作为值班长，我希望智能体的每条结论都能点开看证据，以便采信前可以核对。

### 明确不做（延续第一版边界）

- 自动处置与远程控制（开机、停机、改参数）。
- 自动创建工单（第一版 FR-14 仍为 Could，不在本版）。
- 用智能体输出替代模型概率或告警状态；概率由模型给出，智能体不得改写。

## 四、可行性评估

**技术可行性**

- 数据与接口现成：第一版已有带 JWT 鉴权的只读 API（设备、遥测、告警、预测），[[第一版-平台主体/开发阶段3-AI预测模块/05-智能体接口设计]] 已定义 `get_prediction`、`get_telemetry`、`list_alarms` 三个只读工具，可直接作为工具链起点。
- 推送链路现成：WebSocket 实时推送与大屏弹窗组件已在阶段二、四验收，解读卡片可复用同一通道，不新建实时链路。
- 部署边界现成：阶段六的公网安全门禁、NFR-10 密钥私有配置可直接套用到智能体服务与 LLM 凭据。

**风险与对策**

| 风险 | 对策 |
| --- | --- |
| 大模型幻觉，给出错误处置建议 | 结论强制附证据引用；只读工具；处置一律人工确认；数据不足时明示无法判断 |
| 智能体故障拖垮告警主链路 | 解读走异步附加链路，主链路失败隔离（NFR-14） |
| LLM 调用成本与延迟 | 云端 API 与本地模型可切换；解读结果按事件缓存，重复事件不重复调用 |
| 引导内容过期 | 引导文案随功能版本更新，纳入阶段四验收抽查 |

**结论**：可行。P0 范围为 FR-20（告警解读与大屏弹窗），是第二版的主业务与亮点；FR-21、FR-22 在其后分期交付。

## 五、阶段拆分与任务

> 与第一版相同：每个阶段一个里程碑（V2-M1～V2-M4），各自有独立验收口径；源码沿用 `stages/` 分阶段目录（建目录时再定名），笔记统一进 `第二版-智能体升级/`。

| 阶段 | 目标 | 里程碑 |
| --- | --- | --- |
| 阶段一 · 智能体基础服务与只读工具链 | Agent 服务跑通 LLM 接入与只读工具调用，权限贯通 | V2-M1 |
| 阶段二 · 告警智能解读与大屏联动 | 告警事件触发解读并在大屏自动弹出（FR-20） | V2-M2 |
| 阶段三 · 使用引导与值班问答 | 知识库问答与页面引导上线（FR-21、FR-22） | V2-M3 |
| 阶段四 · 测试、安全复核与交付 | 测试矩阵、公网安全复核与文档收尾 | V2-M4 |

### 阶段一 · 智能体基础服务与只读工具链（V2-M1）

- V2-T01：Agent 服务骨架与 LLM 接入（云端/本地可切换，凭据按 NFR-10 私有配置）。
- V2-T02：只读工具集落地，沿用并扩展三个既有工具（如补 `list_devices`、告警详情查询）。
- V2-T03：当前用户 JWT 与现有角色权限贯通，伪造身份与跨用户会话访问明确拒绝；逐设备授权不在 V2-M1。
- V2-T04：会话与调用审计日志，回答格式强制携带证据字段。

**验收口径**：工具全链路带鉴权；无数据、越权、模型不可用时均明确拒绝而非编造；单测与联调证据入库。

### 阶段二 · 告警智能解读与大屏联动（V2-M2）

- V2-T05：告警事件触发解读的异步流水线，与 FR-02/FR-19 主链路隔离。
- V2-T06：大屏解读卡片自动弹出、确认流转与样式（沿用企业级硬朗视觉规范）。
- V2-T07：证据引用展示（数据时间、模型来源、关联曲线与历史告警）。

**验收口径**：合成告警端到端复现（越限 → 解读卡片弹出 → 人工确认）；回归验证告警主链路延迟不回退。

### 阶段三 · 使用引导与值班问答（V2-M3）

- V2-T08：平台知识库构建（使用手册、运维手册与笔记的结构化整理）。
- V2-T09：页面使用引导（功能导览与操作提示）。
- V2-T10：值班问答界面与证据回链。

**验收口径**：引导内容与当前版本功能抽查一致；问答结论逐条附证据来源。

> 范围变更（2026-10-03）：原立项大纲没有“联网五题全部通过”的硬门槛。项目所有者在第三阶段计划和随后博查接入计划中追加“本地知识未命中时联网补充、留档与五例真实搜索验收”，归属 V2-T08～T10／V2-M3；原 V2-M4 的整体准确性、安全复核与最终 Release 不替代该增量验收。五题除协议、引用与留档外，还须逐条人工核对来源能否直接支撑结论和建议；失败批次保留，不能只用某次 5/5 覆盖后续 4/5。

### 阶段四 · 测试、安全复核与交付（V2-M4）

- V2-T11：测试矩阵：解读准确性抽查、幻觉控制（无证据不结论）、延迟、权限、主链路降级隔离。
- V2-T12：公网安全复核，沿用阶段六发布门禁与 [[仓库公开与服务器安全要求]]。
- V2-T13：文档收尾：正式「测试与交付」笔记、验收清单与第一版偏版本笔记的统一更新。

**验收口径**：测试结论落在标题含「测试与交付」的正式笔记；[[项目验收与收尾清单]] 同步更新。

## 实施核对补充（2026-09-30）

- 阶段一方案与记录进入 [[第二版-智能体升级/开发阶段1-基础服务与只读工具链/00-索引·基础服务与只读工具链]]。
- 既有后端尚无逐设备授权，第一阶段沿用角色权限；工具名单不含业务写操作。
