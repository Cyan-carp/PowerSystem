# 02 · Agent服务与模型接入

> 对应 V2-T01。说明独立 FastAPI 服务、兼容 API 适配层与凭据配置；不把本地模拟器当作真实模型。

## 一、实现与配置

- 入口 `agent/main.py`，健康接口 `/health`；关闭公网 Swagger，内部接口需要独立服务令牌。
- Provider 使用 HTTPX，固定拼接 `/chat/completions`，不跟随重定向、不继承系统代理，不把用户 JWT 发给模型。
- `.env.example` 提供基地址、模型名、密钥文件、服务令牌文件；复制为阶段私有 `.env` 后配置。
- Go 与 Agent 读取同一服务令牌文件；模型密钥文件只含密钥。凭据、Redis URL 与配置不得写入公开笔记。

## 二、模型能力与限额

- 必须支持兼容 Chat Completions 与原生工具调用。预检实际请求普通回答和 `probe(value=7)` 工具调用。
- 本地 Ollama 使用兼容入口，所选模型仍须能力预检；无工具能力时明确失败，不降级伪装为智能体成功。
- 单次模型超时 20 秒、输出上限 1500 tokens，工具最多 5 轮／10 次，总期限 40 秒。
- 错误仅记录安全原因码，不返回供应商原始错误正文或认证头。

### 当前验证结果

| 检查项 | 结果 |
| --- | --- |
| 当前模型 | `deepseek-v4.1-flash` |
| 普通文本 | 通过，约 5.35 秒 |
| 原生工具调用 | 通过，约 2.39 秒 |
| 正常问答／同会话续聊 | 通过，约 6.462／4.919 秒 |
| 正式时间预算 | 保持 20 秒／次、40 秒／请求 |

> 旧密钥对应的 terra 模型曾超时，失败证据继续保留。项目所有者允许在模型超过 20 秒但能正常返回时放宽限制；当前模型未触发该条件，因此没有修改时间预算。完整记录见 [[05-V2-M1测试与交付]]。

## 三、故障隔离

- Provider 超时、认证失败、限流或格式错误返回 `degraded`，说明无法判断。
- Agent 健康不依赖模型；Go 启动与健康检查不依赖 Agent，配置无效只使智能体接口不可用。
- 客户端断开或 Go 超时会取消 Agent 编排和 HTTP 下游调用；取消结果仍记录审计。
- 不注册阶段二空路由；大屏与知识库留在对应阶段。
