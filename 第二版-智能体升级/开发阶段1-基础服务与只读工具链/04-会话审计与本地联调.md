# 04 · 会话审计与本地联调

> 对应 V2-T04。说明 Redis 会话、JSONL 审计、运行脚本和测试证据保留方式。

## 一、会话与审计

**会话隔离**

- Redis 键使用 `stage7:session:<UUID>:owner/lock/history`，与原业务键分离。
- Lua 原子校验用户与锁；跨用户 403，同会话并发 409；锁 50 秒，处理总期限 40 秒。
- 会话 TTL 24 小时，历史最多 20 条消息（10 轮）；过期会话可重新初始化，但不会读取上一份历史。
- 会话只保存对话上下文，不保存 JWT 或工具原始结果；当前状态问题重新取数。

**审计与失败策略**

- 审计按 UTC 日期写 JSONL，记录用户、请求、会话、模型、工具参数／状态、耗时、回答和证据；真实 token 与 API key 替换为脱敏标记。
- Redis 或审计写入失败时明确拒绝，避免无记录返回成功。

## 二、本机运行

#### 步骤 1 · 准备服务与私有配置

按 [[stages/07-agent/README]] 安装锁定依赖、准备阶段 `.env` 与密钥文件。四个基础容器已于 2026-09-30 恢复，原数据卷保留。

#### 步骤 2 · 启动与验证

```powershell
stages/07-agent/scripts/start-local-backend.ps1
stages/07-agent/scripts/preflight-stage7.ps1 -ProbeModel
stages/07-agent/scripts/start-agent.ps1
```

> 8080 必须空闲；已由原阶段启动脚本管理的进程应先通过其停止脚本结束。Agent 本机绑定 127.0.0.1:8092。密钥及 Redis 地址不打印。

#### 步骤 3 · 记录联调

准备私有测试操作员 JWT 文件并设置 `STAGE7_USER_TOKEN_FILE`，执行：

```powershell
stages/07-agent/scripts/run-stage7-test.ps1
```

> 证据按运行编号进入 `artifacts/stage7-智能体/`；不会自动声明 V2-M1 签收。

#### 步骤 4 · 停止本阶段进程

```powershell
stages/07-agent/scripts/stop-agent.ps1 -IncludeBackend
```

只停止记录中启动时间匹配的进程，不停止原数据容器。

## 三、本地模拟器与清理

**协议模拟器**

- 模拟器 `tests/fixture_model.py` 仅验证协议；固定模型名 `stage7-test-fixture`，监听回环 8093，不进入 Agent 镜像。
- 本轮私有模拟配置 `artifacts/stage7-智能体/private/fixture.env`，测试记录 `artifacts/stage7-智能体/local-fixture/`；使用 `-ConfigFile` 选择该文件。
- 模拟器通过 `Start-Stage7Managed -Name fixture` 启动；复现入口及完整参数见源码 README。
- `smoke-stage7.py --fixture` 会在本地创建两个 `v2m1_*` 操作员；后端短回归另有测试管理员及 `INV-SMOKE-*` 设备，全部为合成资产。

**真实模型与清理边界**

- 测试用户无后续登录需要时可由本机管理员按明确 ID 清理；先检查告警引用。原业务卷、模型与历史验收证据不得因清理测试而删除。
- 真实 API 联调另建本机 `v2real_*` 操作员，私有配置在阶段 `.env`；成功与失败批次、完整审计位置见测试交付页。
- 本轮结束已停止 Agent、Go API 与网关，基础 Docker 容器保留。
- 不公开私有配置、JWT 文件、审计或测试数据库。服务器部署与备份恢复留到后续发布阶段。
