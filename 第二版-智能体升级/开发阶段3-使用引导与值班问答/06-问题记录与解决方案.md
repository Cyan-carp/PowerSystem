# 06 · 问题记录与解决方案

> 集中记录第三阶段实施、测试与部署问题。每项包含现象、原因、影响、处理、验证与状态；正式结论见 [[05-V2-M3测试与交付]]。

> **当前汇总（2026-10-05）**：阻塞 V2-M3 技术签收的备份授权、已有账号登录、资料回答 JSON、实际页面、恢复和完整观察均已解决并取得同一候选证据。专业来源审核、外站全文可用性、真实设备手册与机型适用性属于已明确移交的后续事项，不写成已解决。

## 一、本机依赖与构建权限

**现象**：沙箱中的 Agent 测试提示缺少 `fastapi.testclient`，Go 缓存不可访问，Vite 创建子进程报 EPERM；系统 Node 22.11.0 低于本项目 Vite 要求。

- 原因：原依赖及构建缓存的沙箱访问限制，以及 Node 版本不匹配。
- 影响：不能将环境启动失败计为功能测试失败或通过。
- 解决：使用既有依赖在批准的沙箱外测试；前端采用已安装 bundled Node 24.19.0，不改依赖锁。
- 验证：Agent 最终 49/49、Go 全量、前端类型与构建以及 11 项交互测试通过。
- 状态：已解决；原失败输出与最终通过分开保存。

## 二、服务器 Python 归档兼容

**现象**：发布脚本在解包前报 `extractall() got an unexpected keyword argument 'filter'`。

- 原因：服务器 Python 版本没有新版 tarfile 的 filter 参数。
- 影响：第一次部署在保存源基线之后停止，业务容器未切换。
- 解决：先验证归档成员全部为范围内普通文件，再逐个写入，不提取符号链接；兼容服务器版本。
- 验证：修正后服务器发布完成，知识索引已随 Agent 镜像加载，来源接口可读。
- 状态：已解决；第一次失败批次保留。

## 三、模型供应商联网能力尚未证明

**现象**：供应商首页、文档和 OpenAPI 常见路径返回 404；模型列表可鉴权访问，没有明确搜索模型。

- 原因：目前只取得聊天 API 入口，没有联网协议与可验证来源能力说明。
- 影响：真实联网五例验收缺少前置条件，阻塞 V2-M3 正式签收。
- 解决：保持联网未配置的明确状态；等待供应商接口说明或独立搜索 API 凭据，禁止将模型自述“已搜索”作为证据。
- 验证：已核对模型列表；搜索模拟、未配置及错误降级测试通过。
- 状态：2026-10-02 时未解决；2026-10-03 已用博查独立接口补齐凭据与协议门槛。当前来源支撑及最终复验问题见第八、九节。

## 四、真实模型回答被校验拒绝

最初真实模型批次有文档回答返回 `answer_validation_failed`。文档中的“九十天”转换为阿拉伯数字时，原数字校验只识别数字字符；增加明确计数／时长单位对应的中文数值识别，并验证九十天可接受为 90、不能接受为 91。原失败回答未完整保存，不能断言每次拒绝都由这一原因造成。

后续 `acceptance-r4` 的知识缺口问题再次降级。单独诊断实际取得六条建议，超过 `ModelAnswer` 的五条上限；系统拒绝属于正确安全行为，但该批不能计成功。系统提示补齐数量与长度限制，校验本身保持。最终 `acceptance-r5` 为 54/54，本机真实文档与缺口四例通过。以后模型仍可能生成不合规答案，需要保留明确降级与失败统计。

## 五、通用缺口问题调用不相关工具

浏览器核对“风机覆冰”时，未配置联网后模型尝试读取平台设备列表，不能支撑通用排查结论。增加文档／公开知识与实时业务问题分流：知识问题没有有效证据时直接返回依据不足，有文档证据时不提供业务工具；混合问题仍可取业务数据。真实浏览器和最终问答复测均确认缺口提示、持久记录及零不相关业务证据。关键词分流只覆盖当前约定范围，复杂表达仍需持续补充固定测试集。

## 六、部署与观察批次隔离

一次前端重建与停止 Agent 的故障试验发生重叠，造成临时接口失败与容器操作冲突；恢复后改为严格串行，`fault-agent-down-r3` 与实际回退通过。首次回退脚本尾部存在 CR 空行报错，回退与恢复检查已完成，但其观察启动不作为最终观察证据。

曾发现两个观察进程写同一文件，停止这两个进程并保留中间报告；通用问答和输出提示修正后，最终由单独进程写 `observation-r5.json`。最终报告必须同时满足完成标志、至少 1800 秒和全部样本通过；中断的旧观察不得累计成三十分钟。

一次重新构建命令误用了不存在的 Compose 文件名，在构建前失败，容器未切换；改用源码 README 中原统一 Compose 和 Agent overlay 后正常更新。上述操作失败独立保留，不计成功批次。

首次本机探测在沙箱内无法读取完整 Python 依赖，`httpx.AsyncClient` 不可用；使用已安装依赖的授权执行后，官方接口 HTTP/业务码均 200，返回五条，耗时 1.842 秒。一次编辑脚本未启用 UTF-8，在读取源码前停止；启用 UTF-8 后完成，未覆盖既有工作。

真实本机 r1 的第三题被原校验拒绝，验收脚本又误读取不存在的 `ProviderError.reason` 导致批次中断；改用安全错误字符串，并恢复该批中断报告，剩余两题明确记为未运行。r2 为 4/5，覆冰题被拒绝；服务器 r1 为 4/5，光伏电弧题被拒绝。没有保存这些拒绝的模型草稿，不能断言它们均由同一数字或结构问题造成。

补充诊断脚本只保存安全拒绝原因，不展示被拒绝内容；本机 r3 和服务器 r2 均为 5/5。断连修复后最终服务器批次为 4/5，风机过热题再次被原校验拒绝，不能用较早成功批次替代最终批次结论。保留之前的拒绝批次，不通过删除失败或放宽校验改善统计。

搜索结果包含转载手册、专利预览和题库，不能等同于厂家当前运维手册。抽查能支持部分原理性描述，但部分建议的引用不足以直接支持具体操作，例如从接线表推导断电步骤、从绝缘专利推导不反复启机。该语义问题不会由数字与编号校验自动解决；不能据五题接口通过宣布所有建议可靠。正式签收仍需完成来源支撑审查，后续优先补受控厂家文档与人工审核，不改原防线。

页面来源顾如站点要求合法用户验证，未绕过；同题其他公开专利预览可阅读。豆丁页面加载较慢，读取实际页面后继续核对。浏览器一次按整行文本定位失败，改为查看真实引用面板，未修改产品行为。

## 九、真实取消没有及时传递到服务端（2026-10-03）

浏览器取消后不展示迟到回答，但服务端仍可能完成搜索及模型回答；真实代理取消探测未取得 `cancelled` 缺口记录。此前仅使用任务取消的单元测试，未覆盖实际 ASGI 连接断开。

原因定位到原轮询 `request.is_disconnected()` 的取消作用域接收方式。请求体已经由 FastAPI 消费后，改为独立任务等待 `request.receive()` 的实际 `http.disconnect` 事件；原任务预算、鉴权、回答校验、错误内容清理和审计保持一致。新增真实 Uvicorn 本机 HTTP 连接测试，确认搜索任务取消、缺口只写一次、审计为 `request_cancelled`、会话锁释放且模型与业务工具未调用。

修复后 Agent 回归为 60/60。只重新构建 Agent，旧观察独立保留为 `observation-before-cancel-fix.json`；修复发布、实际取消与回退恢复完成后重新开始完整三十分钟观察，不累计先前时长。

## 十、问答入口分流与验收断言漏检（2026-10-03）

**现象**：“当前有哪些告警，怎么查看？”被判为纯文档题，模拟模型只引用文档却输出“当前没有活动告警”；固定检索集直接调用检索器，二十九道有答案题中十二题不进入聊天入口的知识检索。原服务器混合题允许 `degraded` 仍计安全状态通过，不能用原 49/49 证明混合回答成功。

- 原因：`needs_business` 在识别实时词前用“怎么”提前返回；`needs_knowledge` 只靠狭窄关键词；验收脚本对混合题没有成功及双来源断言。
- 影响：当前状态可由不相关的文档伪装，本地知识命中率不能代表真实问答入口覆盖率，混合回归结论偏宽。
- 解决：实时词与业务对象优先识别，普通知识疑问进入检索；实时结论须取得对应只读业务工具证据且在结论中引用。混合题验收要求 `answered`、预测工具证据进入结论、文档证据进入回答。原 `validate_answer` 与六工具白名单保持。
- 验证：本机新增完整编排入口固定集、恶意模型反例及来源审查门槛测试，Agent 67/67。服务器严格混合题首次复验因原数字校验拒绝而失败，证明原 49/49 宽松断言掩盖问题；取数提示增强后单题 18/18、完整七题 67/67。实时告警专项 16/16，实际取得 `list_alarms` 并在结论引用。审计仅记录允许的校验错误类型，不保存拒绝的模型正文；实际源码与镜像回退恢复均健康。
- 当时状态：入口安全与严格混合题已部署复验；联网五题及人工来源审查仍阻塞该批 V2-M3。当前正式结论见第十一节。

**补充一 · 混合题取数提示**

服务器严格混合题在已有有效文档与预测证据时被原数字校验拒绝，安全审计分类为 `unsupported_numeric_claim`。补充混合问题的取数提示：每条数字只能来自该条引用的本轮有效证据，用户问题里的设备编号不能冒充证据；原数字校验函数、概率阈值规则均未调整。新批单题和完整回归均通过，但真实模型具有波动性，后续仍保留拒绝统计。

**补充二 · 联网语义护栏**

联网验收还存在“有效引用不等于来源支持具体建议”的独立语义问题。程序现拒绝仅凭联网证据提出断电、复位、停机、改线等具体工程操作的建议；服务器五题脚本分别输出协议结果与逐条人工审查模板，审查记录按回答与来源内容哈希绑定。此关键词护栏不能判断所有句子的语义支持，未核对的建议仍不能算正式通过。此前抽查发现的断电、复位建议继续列为不足，需有厂家受控文档直接支持或删去相关建议。这个人工门槛属于用户追加的博查联网范围，归 V2-M3，不把它追溯成原立项大纲条款。

**补充三 · 新五题结果**

新五题批次均成功检索，但逆变器电弧、接地绝缘和风机过热三题的具体工程操作建议被护栏拒绝；覆冰与光伏电弧两题为协议通过、人工来源审查待办。历史 4/5 和本次 2/5 分开保留，不能混成“全部通过”。新 Agent 镜像尚未完成独立三十分钟观察和隔离恢复；先前版本的观察与备份结论不转移为本次验收结果。

**补充四 · 回答文本约束**

随后发现按问题分流仍无法阻止模型在静态知识题中自行写出“当前没有活动告警”。增加回答文本约束后，首版状态识别过宽，误拒绝一条知识库帮助回答；失败批次保留，收窄到明确状态陈述并增加正反例。最终本机 Agent 68/68、服务器严格七题 65/65，文档、混合和当前告警均通过。最终镜像的五题联网为 1/5 协议通过：四题工程操作建议被安全拒绝，覆冰题仍待人工逐条来源审查。实际源码与镜像回退恢复成功；新镜像三十分钟观察和隔离恢复尚未完成。该历史批次 V2-M3 保持未签收；当前正式结论见第十一节，问题详情与镜像指纹见 [[05-V2-M3测试与交付]] 第七节。

## 十一、开发阶段验收口径与旧护栏冲突（2026-10-04）

**现象**：此前最终镜像五题均检索到来源，但四题含设备操作建议而整轮拒绝；逐条专业来源审核也缺少实际机型手册，阶段无法收尾。

- 原因：把“AI 不执行设备操作”扩大为“不允许提出设备操作建议”，并将真实设备适用性审核作为当前开发阶段硬门槛。
- 影响：有来源的参考建议无法展示，当前现实条件下专业审核反复阻塞。旧拒绝仍是当时规则下的真实结果。
- 解决：遵照所有者明确的新口径，允许建议并醒目标注人工实施；每条可展开来源。来源专业审核暂缓，保留授权、哈希及专业复核待办，不伪造人工审查。
- 验证：本机 Agent 71/71、前端 13/13、类型与生产构建、Go 全量均通过；当前服务器新批次尚待执行。
- 状态：实现完成，服务器验收进行中；最终以正式测试页为准。

首次本机测试因依赖路径与 Windows 默认 GBK 读取 UTF-8 日志失败；改用已有 `artifacts/stage7-智能体/pydeps` 和显式 UTF-8 模式后原基线 68/68、新实现 71/71。没有修改锁定依赖；环境失败与最终通过分别保存。

## 十二、加密异地备份自动审批拒绝（2026-10-04）

**现象**：更新前备份命令被自动审批拒绝，脚本没有执行。

- 原因：审核要求明确授权数据库、私有配置与凭据、审计和知识缺口等敏感载荷，以及具体外部接收目标；通用“执行加密备份”授权未获该审核接受。
- 影响：本轮更新前备份、线上部署及后续服务器验收未执行，阻塞当前阶段签收。
- 处理：只读核对既有云服务器专用备份目标及密文包，向项目所有者列出载荷与具体目标请求明确授权；未改目标、未绕过拒绝或上传私有材料。
- 验证：受审源码包已复制并核对哈希及脚本语法；原线上镜像未切换。
- 后续：所有者于 2026-10-04 明确确认敏感载荷、既有专用目标及更新前／最终／隔离恢复用途；更新前备份已执行并核对云端密文校验和。此前自动拒绝仍保留为历史事实。

## 十三、新增公开源码权限导致候选启动失败（2026-10-04）

**现象**：第一批候选构建成功，但非 root Agent 无法导入新增 `advice.py`，健康检查失败。

- 原因：发布脚本沿用私有运行目录的 `umask 077`，新增公开源码写成 `600`，容器 UID 10001 无读取权限。
- 影响：第一批发布失败；自动回退恢复原源码与原镜像，三项业务健康、重启为零，API 未替换。
- 解决：仅为受审公开源码设置 `644`，不改私有配置；构建后、替换服务前增加候选导入预检。恢复当前源码时同样设置公开文件权限。
- 验证：第二批导入检查与健康检查通过；失败目录独立保留。

## 十四、真实模型字段和概念措辞波动（2026-10-04）

第二批联网四题协议通过，过热题因 `schema_extra_forbidden` 被拒绝；严格七题首题因概念说明夹带实时状态断言被拒绝。已保留两个独立失败批次，所有联网缺口照常持久记录。明确模型只输出原三字段及每条的 `text`／`evidence_ids`，概念问答使用规则或条件措辞；没有修改模型结构、数字校验、实时业务取证或工具权限。调整后本机 Agent 71/71，后续明确资料题不使用实时状态措辞，混合题不计算派生数字或复述无必要编号；第六批、最终保守提醒候选各自完整严格七题 73/73、五题 5/5。中间数值拒绝和超时批次保留。

## 十五、浏览器验收账号自动审批拒绝（2026-10-04）

创建随机临时操作员的命令被自动审批拒绝，理由是浏览器验收授权未明确包含新增账号。该命令未执行，没有新增账号或提升权限；已显示既有登录页，请所有者自行登录，继续完成不依赖浏览器的服务器验证。随机测试凭据及未执行脚本仅留在私有运行产物中，不加入知识库或发布包。

## 十六、仅记录镜像 ID 不足以保证实际回退（2026-10-04）

第三批实际回退时，前一候选镜像未加独立保留标签，重建后已不再可寻址；仅记录完整 ID 无法恢复。原 API 与前端仍运行，恢复已审阅 Agent／前端现存镜像后均健康。失败目录与日志独立保留。发布脚本现于构建前给基线镜像添加本轮唯一标签，候选也固定独立标签，并使用 `--pull never --force-recreate` 确保采用本轮实际镜像、禁止错误远端拉取；第六批和最终保守提醒候选各自重新执行实际源码与镜像回退恢复成功，不将本次失败计为通过。

## 十七、资料开头混合设备动作的提醒遗漏（2026-10-04）
