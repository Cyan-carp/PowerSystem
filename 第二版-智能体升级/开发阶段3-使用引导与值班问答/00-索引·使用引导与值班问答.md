## 一、阶段定位

在阶段一的只读工具、用户会话与审计，以及阶段二的模型故障隔离基础上，补齐页面使用引导和有证据的值班问答。本地知识不足时记录知识缺口，适合的通用问题再使用联网搜索。

| 能力 | 实现入口 | 说明 |
| --- | --- | --- |
| 受控文档检索 | `stages/07-agent/knowledge/` | 来源清单、章节资产、哈希版本 |
| 值班问答 | `/agent` | 原聊天接口与只读业务工具 |
| 页面帮助 | 顶部入口 | 六个业务路由，静态指南 |
| 知识缺口 | 持久 JSONL | 脱敏、汇总、独立审核状态 |
| 联网补充 | 博查／原通用适配 | 真实接口已联调；来源支撑仍需独立审查 |

> 不能把“模型 API 可以聊天”当作“已支持联网搜索”。当前里程碑结论必须同时参考实际服务器证据与搜索接入条件。

## 三、与前两阶段衔接

- 实时设备、告警、预测和遥测仍从当前用户 JWT 的 Go API 查询。
