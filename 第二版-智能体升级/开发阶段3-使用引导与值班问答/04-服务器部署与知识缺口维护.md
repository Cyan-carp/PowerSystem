# 04 · 服务器部署与知识缺口维护

> 记录第三阶段在既有统一 Compose 上的增量交付方法。实际上线、备份、恢复和回退结果集中于 [[05-V2-M3测试与交付]]。

> **当前部署状态（2026-10-05）**：最终候选 `runtime/manual-advice-20261005T004409Z/` 已完成增量部署、实际回退、最终加密备份、隔离恢复和独立 1800.52 秒／60 次观察，固定 API、Agent、前端镜像健康且重启为零。知识缺口与历史恢复环境均保留；专业来源审核和补库继续待办。

## 一、部署前提

实施前经穿透 SSH 核对，原 Agent、API、前端均健康，项目目录存在，磁盘有足够空间。私钥只用于 SSH，不读取到日志；公开笔记不新增工作站私钥绝对路径。

发布包只包含受审源码和知识资产，不含 `.env`、凭据、用户问题或运行日志。发布脚本先校验包 SHA256，核对归档成员为项目范围内普通文件，保存被覆盖文件与三种原镜像标识。

## 二、增量上线与持久化

Agent 镜像增加只读知识资产；Go 增加知识来源代理，前端增加问答和帮助。使用既有 Agent profile，三个服务增量构建与启动，不新建业务表，不新增公网端口，不替换私有配置或业务数据卷。

知识缺口挂载到容器 `/knowledge-misses`；默认宿主目录为 `runtime/agent-knowledge-misses`，属主 UID/GID 10001，权限 700。模型审计保持原目录。搜索接口需要独立 `search.compose.yaml` 和私有密钥，未配置时不增加 secret 依赖。

## 三、备份与恢复

统一 `backup.sh` 在原加密包中增加知识索引、知识缺口目录及可选搜索密钥。原异地 SFTP 与加密口令不改。恢复时核对归档清单、知识集合哈希及 JSONL 解析，然后继续原业务数据库与 Redis 隔离恢复。

知识缺口备份以实际容器 `/knowledge-misses` 的 bind source 为准，覆盖私有宿主目录配置；没有对应挂载时使用默认目录。恢复归档保留相同材料结构，重新挂载时按当前私有配置恢复属主与权限。

源文档更新需要重建索引、运行检索测试再随镜像发布。缺口汇总及审核操作只针对私有运行目录；原记录不覆盖，正式知识补充更新受控 Markdown，再重新构建。

## 四、回退与观察

保留阶段二 API、Agent、前端镜像，并使用临时镜像 override 实际回退。回退期间知识挂载仍保留，旧镜像忽略新增能力；恢复第三阶段镜像后核对缺口记录和知识版本。

回退与 Agent 停止测试结束后，需要验证业务接口及原告警解读恢复，再观察不少于三十分钟。观察只读，不反复调用模型，不制造业务通知。

> 通用规则：搜索凭据尚未提供时，可以部署问答与显式降级，但不能签收真实联网验收或整个 V2-M3。本项目当前正式候选已经配置并完成真实联网验收；本条保留给以后新环境部署。
