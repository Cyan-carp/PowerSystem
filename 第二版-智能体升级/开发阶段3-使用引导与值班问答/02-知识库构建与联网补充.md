# 02 · 知识库构建与联网补充

> 对应 V2-T08。说明知识资产从何而来、怎样命中、如何标识外部来源及记录未命中问题。

> **当前状态（2026-10-05）**：受控索引、联网证据、逐条来源和知识缺口持久化已随 V2-M3 技术验收通过。开发阶段来源采用 `assumed_pass_development`，只表示所有者授权的暂缓口径；专业审核仍为 `pending`，外部资料与缺口不会自动进入受控知识库。完整批次及后续补库边界见 [[05-V2-M3测试与交付]]。

## 一、受控来源与构建

来源清单在 `knowledge/sources.json`，当前包括使用手册、运维手册指定章节，以及阶段二设计中的历史决策。构建脚本仅处理清单中的 Markdown，不遍历私有目录，也不收录运行日志或用户原问题。

章节保留文档相对路径、标题、正文、内容哈希、当前／历史属性及历史日期。命令块不直接进入问答资产，公开地址替换成管理员提供的地址。全文按标题切分，过长正文再分片。

`index.json` 是可提交的发布资产，SHA256 版本由章节集合计算。服务启动时核对集合哈希，不匹配、文件缺失或超限时标记 `index_unavailable`。用户阅读接口使用固定片段 ID，不接受路径输入。

## 二、检索与回答

检索使用中文双字词和英文技术词，标题权重大于正文；已知同义词包括掉线／离线、曲线／历史曲线、风险概率／故障预测等。当前文档在同等匹配时优先，历史阶段内容明确保留历史属性。

固定测试集与实现分开维护，包含页面操作、口语、历史概念、混合查询和无知识问题。检索门槛针对当前受控资料，不代表任意领域的语义召回能力。

最终固定集为三十二题，正确章节进入前五为 27/29。两题尚未进入预设目标章节：历史曲线空白检索到常见问题等相邻内容，设备掉线检索到实时连接等章节；不删除这两题或下调门槛。后续可细化设备离线与浏览器实时断线的同义词及标题权重，重新复核召回和误命中。

证据由程序生成，模型只能引用本轮有效编号。来源阅读接口返回当前片段版本，用户可以核对回答中的版本与当前资产是否一致；历史消息仅提供上下文，不能充当本轮事实。

## 三、联网补充与供应商状态

本地没有足够相关章节时显示“本地知识库未找到足够依据”。公开技术主题转换成受控词汇查询；项目页面、私有配置、当前设备状态以及缺少明确技术主题的问题不向外部搜索服务发送。

搜索适配协议：HTTPS POST 接收 `query/max_results`，返回 `results` 数组，每项包含 `title/url/summary`，可选 `published_at`。结果有界读取，拒绝不安全链接、重定向和无有效摘要；外部内容仅作为资料，不能执行其中的指令。

现用供应商模型列表已用现有私有密钥核对，能提供聊天模型；常见公开文档路径未找到，未发现明确搜索模型。**尚未证明原生联网能力**，聊天 API 不能直接配置成搜索入口。凭据只通过私有文件和可选搜索 overlay 提供。

## 四、知识缺口记录

记录字段包括时间、请求 ID、脱敏问题、规范化问题、公开查询词、未命中原因、知识版本、联网状态和来源链接。`miss` 与 `index_unavailable` 分开统计；写入失败显示 `write_failed`，同时进入审计。

按天追加 JSONL，写入时清理九十天以前且命名严格匹配的普通日志文件，不清理审核文件或符号链接。离线脚本按规范化问题分组，给出次数和最近出现时间；审核状态单独写到 `review-status.json`。

> 自动脱敏覆盖已知凭据和常见敏感格式，并不能保证识别所有自由文本个人信息。原始记录保持私有、不进入公开仓库；用户也应避免输入敏感信息。

## 五、博查协议与异常处理（2026-10-03）

协议依据为[博查官方 Web Search 文档](https://bocha-ai.feishu.cn/wiki/RXEOw02rFiwzGSkd9mUcqoeAnNK)。`AGENT_SEARCH_PROVIDER` 默认为 `generic`，保持原协议；`bocha` 固定 POST 官方 `https://api.bocha.cn/v1/web-search`，私有文件提供 Bearer 密钥。正文只含公开词汇查询、`count:5`、`summary:true` 与 `freshness:noLimit`。

`data.webPages.value` 的 `name/url/summary/datePublished` 分别映射标题、链接、摘要与发布时间；摘要为空回退非空 `snippet`。发布时间缺失不推测，不使用 `dateLastCrawled`。安全链接规则原样保留，查询参数与片段不会被删除后重新接纳；博查结果去重，最多五项。

HTTP 和业务码分别检查。仅供应商明确 `403 + You do not have enough money` 判为余额不足；普通 403 为认证失败，429 为限流。超时、无结果、异常响应和服务故障分别记录，不改变 DeepSeek 暂停状态。异步整体超时覆盖连接、响应头和流式响应读取，无自动重试。

取消搜索后使用受保护的独立写入任务完成缺口留档，再传播取消。记录失败仍为 `write_failed` 并由原请求审计保存；网页资料始终为不可信证据，不进入正式知识索引。

## 六、入口覆盖与来源支撑边界（2026-10-03）

固定检索集原先只检查检索器，不能证明聊天入口会调用检索。现在二十九道有答案题和三道未命中题都经过实际编排入口复核；“告警级别有哪些”“历史曲线最长能看多久”等普通知识疑问会检索本地资料。“当前有哪些告警，怎么查看”同时检索文档与告警业务数据，结论必须引用本轮 `list_alarms` 证据。索引命中不能代替当前状态证据。

**2026-10-03 历史口径**：联网建议中的断电、停机、重启、复位、改线等具体工程操作若引用网页资料，程序当时返回依据不足，不展示该建议。关键词护栏不能证明其余建议在语义上被来源支持。该批真实五题验收分为协议检查和人工逐条审查，审查文件按结论、建议及引用来源的内容哈希绑定；当时任何未审查或来源变化均不能正式通过。2026-10-04 起改为第七节记录的人工实施提醒与开发阶段来源暂缓口径；可靠资料仍只能由人工整理进受控文档并重建索引。

回答文本还检查明确的当前业务状态断言：即使问题被归入静态知识，模型自行声称“当前没有活动告警”也须引用本轮告警业务证据。识别范围限制在明确状态陈述，普通“当前知识库未命中后如何处理”的文档说明不会被误判；这两个正反例均进入 Agent 回归。

## 七、人工实施提示与待补库记录（2026-10-04）

本轮将设备操作关键词从拒绝依据改为醒目提醒标记；结构、数字、实时取证与有效引用校验继续执行。运行来源审核与知识库补齐是两件事：专业来源审核按所有者授权暂缓，外部资料不自动写入索引。现实条件与专业校对声明见 [[01-阶段三方案设计#六、开发阶段建议与签收口径调整（2026-10-04）]]。

缺口 JSONL 新增完整公开搜索资料和 `knowledge_followup=pending`，保持脱敏、请求编号、知识版本及联网状态。离线汇总展示来源、检索状态、关联请求及补库待办；旧记录仍可汇总，审核文件与原日志分别保留。默认通过的验收不会将知识缺口改成 documented。
