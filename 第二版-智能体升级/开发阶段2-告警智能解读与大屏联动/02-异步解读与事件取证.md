# 02 · 异步解读与事件取证

> 对应 V2-T05、NFR-14～16。本页说明已进入源码的任务、证据、模型错误与接口机制；参数取舍见 [[01-阶段二方案设计]]，实测结果见 [[05-V2-M2测试与交付]]。

## 一、任务生命周期

Go 每秒扫描已提交的新告警，扫描与建任务使用独立事务，不修改原告警事务和飞书投递表。

1. 首次启用记录基线；基线上方按“尚无任务”反连接扫描，避免较小 ID 晚提交后被游标漏掉。
2. `agent_interpretations` 以事件键去重，同时保存任务状态、证据快照与结果。
3. 工作者在短事务内领取任务，随后释放数据库锁；模型请求不占用领取事务。
4. 60 秒租约配随机令牌，旧工作者不能覆盖新结果；重启后可接管过期任务。

任务状态 `pending/running/completed/degraded` 描述流水线；回答状态 `answered/unable_to_determine/degraded` 描述内容，两者不能混用。

## 二、证据快照

### 2.1 业务告警

- **E1 触发事实**：保存原值、阈值、级别和触发时间，不用后来的确认或恢复覆盖。
- **E2 设备信息**：保存触发时可用的设备标识与归属。
- **E3 历史告警**：触发前 24 小时最近 20 条，并注明查询是否完整。
- **E4 相关曲线**：触发前 30 分钟，最多 100 个实际点，保留统计值、原始点数和压缩说明。
- **E5 触发预测**：仅 AI 风险事件使用；匹配同设备、触发前创建且相距不超过 15 分钟的预测。

### 2.2 平台监控

- 只接收项目已有的 `PowerSystemAPIDown` 与 `PowerSystemDiskHigh`。
- 按 `fingerprint + startsAt` 去重；迟到的 firing 不覆盖已收到的 resolved。
- Agent 验证独立凭据后写 Redis Stream；Go 在 PostgreSQL 提交成功后再确认消费。
- 没有实际指标时，只能陈述“监控观察到什么”，不能推断具体根因。

> 证据快照回答“事件发生时看到了什么”，业务页面回答“现在是什么状态”。二者时间口径不同，不能用当前值改写历史事实。

## 三、模型错误与共享暂停

| 原因码 | 触发条件 | 处理 |
| --- | --- | --- |
| `not_configured` | 功能关闭、模型或密钥缺失 | 不调用模型 |
| `auth_failed` | 认证失败或供应商明确报告过期 | 共享暂停 |
| `quota_exhausted` | 供应商明确额度错误码 | 共享暂停 |
| `rate_limited` | 普通 429 | 有限重试 |
| `unavailable` | 网络、5xx 或未知错误 | 有限重试 |
| `answer_validation_failed` | 格式、引用或数字非法 | 拒绝回答 |

共享暂停保存在 `stage7:model:pause`，供用户问答和事件解读共同读取。供应商原始错误、密钥与账户信息不进入浏览器；永久错误不重试，暂时错误最多三次，数字型 `Retry-After` 上限 60 秒。

管理员检测一分钟最多一次。检测成功后解除暂停，只补最近 24 小时仍活动、因永久配置问题降级的事件；换密钥后须重启 Agent 使配置生效。

## 四、接口与回答校验

**内部接口**

- `POST /internal/agent/interpret`：使用 `X-PowerSystem-Token`，只接收事件键、类别和证据列表。
- `POST /internal/agent/monitor-events`：使用独立 Bearer 凭据，接收 Alertmanager 事件。

**用户接口**

- 列表、详情和已读接口使用用户 JWT。
- 模型状态与检测接口只允许管理员，检测每分钟一次。
- WebSocket 的 `interpretation_updated` 只推送记录标识、状态和更新时间，详情仍经 JWT 获取。

模型输出使用唯一的 `submit_interpretation` 结构。Agent 继续复用阶段一的引用与数字校验，并补充时间等价、混合阈值和平台监控确定根因守卫；任何业务工具调用、任意 URL、用户身份或写操作均拒绝。审计失败时不返回成功。

> 校验可以阻止伪造引用、概率改写和明显无依据根因，但不能证明全部自然语言语义正确；最终建议仍需人工核查。

## 五、持久性边界

Redis AOF `everysec` 存在约一秒的断电窗口，PostgreSQL 与 Redis 备份也不是跨库原子快照。系统依靠事件键去重、任务租约和恢复后补处理收敛，不承诺任意故障下零丢失。
