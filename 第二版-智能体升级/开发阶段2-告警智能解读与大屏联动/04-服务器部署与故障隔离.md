# 04 · 服务器部署与故障隔离

> 记录 V2-M2 在既有 R730xd 上的配置、发布、备份与回退方法。实际测试数字和问题台账集中在 [[05-V2-M2测试与交付]]，本页不重复测试过程。

## 一、配置与网络边界

| 对象 | 服务器位置或约束 |
| --- | --- |
| 服务令牌 | `/etc/powersystem/agent-service-token`，只供 Go 与 Agent |
| 监控令牌 | `/etc/powersystem/agent-monitor-token`，只供 Alertmanager 与 Agent |
| 模型密钥 | `/etc/powersystem/agent-model-key`，不参与业务身份认证 |
| 审计目录 | `runtime/agent-audit/`，由 Agent UID 10001 写入 |
| 公网入口 | Agent 不映射端口；Nginx 明确拒绝 `/internal/` |

模型和服务令牌为只读私有文件；监控令牌通过只读属组同时提供给 Agent 与 Alertmanager。网页不写密钥。模型未配置时 Agent 仍可启动并接收事件事实。

## 二、发布步骤

#### 步骤 1 · 备份基线

记录源码与镜像标识，保存 Compose、Alertmanager 和私有配置快照，再运行既有加密异地备份。保留原数据卷和根 `.env`。

#### 步骤 2 · 校验并构建

```bash
docker compose --env-file .env \
  -f stages/04-frontend/deploy/compose.yaml \
  -f stages/07-agent/deploy/agent.compose.yaml \
  --profile agent config --quiet

docker compose --env-file .env \
  -f stages/04-frontend/deploy/compose.yaml \
  -f stages/07-agent/deploy/agent.compose.yaml \
  --profile agent build api frontend agent
```

> 只检查 `config --quiet` 的退出状态，不把展开后的私有配置写入日志。

#### 步骤 3 · 增量上线

```bash
docker compose --env-file .env \
  -f stages/04-frontend/deploy/compose.yaml \
  -f stages/07-agent/deploy/agent.compose.yaml \
  --profile agent up -d api frontend agent alertmanager
```

迁移只新增任务、解读、监控与已读表。首次启用建立扫描基线，不批量解读历史告警。

#### 步骤 4 · 验收与观察

依次核对真实模型、三类事件、证据展开、人工确认、权限、WebSocket、公网 `/internal/` 拒绝和飞书链路。完成备份恢复及实际回退后，连续观察不少于 30 分钟。

## 三、备份与隔离恢复

`backup.sh` 在原 PostgreSQL、TDengine、SQLite 队列和模型基础上，增加三类 Agent 私有文件、审计目录与 Redis RDB。Redis 快照包含未消费监控 Stream 和模型暂停状态，只进入加密包。

`restore-verify.sh` 使用独立项目和数据卷恢复全部组件。启用 `agent-restore` profile 时：

- API、MQTT、PostgreSQL、TDengine 与 Redis 均不映射公网端口；
- AI 与飞书关闭，模型地址指向拒绝连接的本地端口；
- 使用恢复包内服务令牌，验证 Redis Stream 续消费后再停止隔离容器；
- 隔离卷保留，供后续独立复核。

旧备份没有 Redis 或 Agent 材料时仍走原恢复路径，不伪造新数据。

## 四、故障隔离与回退

- Agent 或模型失败：原告警、预测、飞书、确认和遥测继续工作，解读显示降级。
- Go 暂停：监控先留在 Redis Stream，Go 恢复后提交 PostgreSQL 再确认消费。
- Redis 或主机整体不可用：不能承诺实时解读，由飞书继续承担外部通知。
- 版本回退：恢复发布前 API/前端镜像和 Alertmanager 配置，停止 Agent 并关闭解读开关；保留新增表和业务数据卷。

> 多组件备份不是跨库事务快照，Redis AOF `everysec` 也存在约一秒断电窗口。恢复依靠事件键去重和租约续处理收敛，不承诺任意故障下零丢失。

| 项目 | 实际结果 |
| --- | --- |
| 恢复基线 | PostgreSQL inbox 140,469 条、TDengine 遥测 140,472 条、2 个 SQLite 队列 |
