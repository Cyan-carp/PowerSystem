# 03 · 大屏卡片与证据回链

> 对应 V2-T06～T07。前端沿用第一版阶段四的企业级直角布局、路由和告警状态，只新增解读入口、证据面板与模型状态交互。

## 一、事件进入大屏

原 `alarm_created` 提示保持不变。`InterpretationPanel` 在总览自动打开活动未读事件，在其他页面通过“告警解读”入口查看。

- 首次进入、重连和每 5 秒补查活动事件及最近 24 小时未读结果；分页取全。
- 多事件按级别、触发时间排序；当前会话已展示的记录不重复自动打开。
- WebSocket 只触发刷新，完整详情和证据仍通过用户 JWT 查询。
- 已恢复事件保留查询能力，但不重新自动弹出。
- 等待、模型不可用和校验失败都显示事实卡片，业务确认入口不受影响。

## 二、确认与已读

| 事件状态 | 用户操作 |
| --- | --- |
| 活动业务告警、未确认 | 先调用既有确认接口，再标记解读已读 |
| 已确认或已恢复的业务告警 | 只标记解读已读 |
| 平台监控 | 只标记当前用户已读 |
| 关闭面板 | 不写确认，不写已读 |

确认冲突返回 409 时刷新详情，不覆盖他人的确认。已读用户由后端 JWT 确定，客户端不能提交用户 ID。公网联调中发现确认后的并发补查可能短暂覆盖已读状态，现改为写入成功后主动拉取当前详情。

## 三、证据展示

结论和每条建议都能展开所引用的证据项。面板展示来源、数据时间、取证时间和原始快照；曲线复用 `TelemetryChart`，同时标注是否压缩和原始点数，并提供设备、告警或预测页面回链。

| 展示对象 | 用户应如何理解 |
| --- | --- |
| 事件快照 | 触发时已经固定的事实 |
| 关联页面 | 当前业务状态，可能已确认或恢复 |
| 模型结论 | 对有效引用的受限解释 |
| 人工建议 | 待人工判断的检查动作，不代表已执行 |

> 机械引用和数字校验不能证明真实设备根因。证据面板用于复核模型有没有忠于输入，不替代现场诊断。

## 四、权限与视觉修复

管理员可查看脱敏模型状态并执行“检测并恢复模型”；操作员不能调用管理接口。网页不提供密钥输入，也不自动切换供应商。

公网抽屉颜色和确认后已读状态问题均已修复，并通过类型检查、构建和 8 项前端测试。原因、修改和验证记录见 [[06-问题记录与解决方案]]。
