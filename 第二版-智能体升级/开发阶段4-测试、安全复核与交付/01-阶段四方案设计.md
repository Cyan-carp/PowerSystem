# 01 · 阶段四方案设计

> 说明 V2-T11～T13 的实施基线、接口变化和阶段验收条件；工程约定引用根规范，具体命令只在源码 README 维护。

## 一、基线与可行性

V2-M3 已正式签收。复用 FastAPI、Go、Redis、现有六工具、统一 Compose、加密备份和隔离恢复，不新增数据库迁移或消息组件。R730xd 部署目录没有 Git 元数据，采用固定候选提交、受审文件包、SHA256与独立镜像标签。

## 二、问答调用保护

- Go 鉴权及格式校验后，以 Redis TIME 和 Lua 原子接纳请求。
- 滚动60秒每用户最多10次接纳；同用户并发1，全站并发4。
- 租约50秒，正常、取消、超时及失败均释放；后台释放不复用已取消上下文。
- 超限返回429及 Retry-After，Redis不可用返回503；自动告警解读不占交互额度。

## 三、测试与发布

基础回归、30例真实解读、三类服务器事件、严格七题、联网五题、页面、安全、实际回退、最终加密备份、隔离恢复及最终镜像1800秒观察均为技术门槛。失败保留独立批次。

## 四、签收范围

所有者已确认按合成演示与公开资料辅助建议发布 v2.0.0，来源签收沿用 assumed_pass_development。专业审核 pending；不冒充真实设备操作规程或机型验证。线上通知最多7条，其余故障测试在隔离环境。
