## 一、问题：同一套代码，两块屏看着不一样

打个比方：网页交给浏览器的是一份**印着「13 磅字、版心固定 1440 格」的稿子**，显示器是打印机。1080p 桌面像每英寸只点 92 个点的粗打印机，同样 13 磅的字印出来又大又占地方；2K 笔记本是每英寸约 200 个点的细打印机，同样的字印出来小而精致。Windows 的「放大 125%」等于把纸整体拉伸，版心一撑满，两边的留白就挤没了。

| 比喻 | 技术名词 | 改版前的实际值 |
| --- | --- | --- |
| 稿子上的「13 磅」 | CSS px | `body 13px`、卡片标题 `14.5px`、页边距 `22px` |
| 打印机点距 | PPI | 24 寸 1080p ≈92；14 寸 2K ≈200 |
| 把纸拉伸 125% | 系统缩放 / `devicePixelRatio` | 1080p 的 CSS 视口被压到约 1520px |
| 固定版心居中 | `.page-inner { max-width:1440px; margin:0 auto }` | 视口一窄，两侧留白立刻归零 |

**还有一个容易误判的叠加因素**：所有者提供的三张截图里，第一张是 `www.yancap.top/model-quality`（1900×952，**生产旧版**），第二、三张是同一个文件（MD5 相同）`127.0.0.1:5174/model-quality`（2541×1420，**本地新版**）。所以当时对比的其实是「两个版本的页面 + 两块屏」，不全是屏幕差异；把新版发布到生产后，这个变量才被消掉。

## 二、设计：按物理分辨率分档，不做主观判定

| 决策 | 做法 | 为什么 |
| --- | --- | --- |
| 分档依据 | 屏幕物理像素宽 = `screen.width`(CSS px) × `devicePixelRatio` ÷ 页面缩放；页面缩放用 `outerWidth/innerWidth` 估 | 不随 Windows 缩放、浏览器缩放、窗口拖窄、跨屏拖动漂移，能稳定区分 1080p(≈1920) 与 2K(≈2560) |
| 阈值与档位 | `< 2200` → `compact`，否则 `standard`；只有两档 | 只需抵消低 PPI 的「显大」，不做二次改版 |
| 不做的事 | **不做「健康 / 关注 / 异常」档位** | 所有者 2026-11-08 明确否决；主观判定会变成替业务编规则 |
| 变化时机 | `resize` 与 dpr 的 `matchMedia` 监听都触发重算 | 浏览器缩放不一定触发 `resize`，跨屏拖动只改 DPR |
| 本地对照 | 开发预览 `?density=compact\|standard` 强制覆盖 | 同机同视口截图对照；生产始终自动，不留可改开关 |

## 三、作用范围：只收紧页面内容，不动框架与浮层

- `src/lib/density.ts`（新增）：分档判定、`data-density` 标记、监听；不读写任何业务状态。
- `src/main.ts`：挂载前调用 `watchDensity()`，是登录态之外唯一的全局启动动作。
- `src/styles/shell.css`：页边距由固定 `22px` 改为流式 `clamp(22px, 3.4vw, 60px)`；`--content-scale` 在 compact 档为 `0.9`，**只对 `.page-inner` 应用 `zoom`**。顶栏、图标轨、抽屉、Toast 都在容器外（浮层 Teleport 到 body），定位与字号不受影响。`@media (max-width:1100px)` 内把系数与 zoom 一并复位，交给既有窄屏断点。
- `src/views/AssistantView.vue`：5 处 `calc(100vh - Npx)` 改为 `calc((100vh - Npx) / var(--content-scale, 1))`。`zoom` 会把视觉高度一起缩小，不补偿会让助手页底部空出约 13%。

不碰接口、数据、指标口径、按钮功能，也不折叠或藏起任何功能；图表下移按所有者选定的「压缩并排、往下滚」实现。

## 五、边界与未验证项

| 项 | 边界 |
| --- | --- |
| 双机目视 | **未在真实 1080p 与 2K 两台机器上由所有者目视签收**；截图对照与浏览器模拟不能代替真机观感，需本人打开生产页确认 |
| 判定例外 | `2200` 阈值按常见 1080p / 2K 物理宽设定；带鱼屏、4K 低缩放、多屏混合 DPI 未逐一实测 |
| 页面缩放估计 | `outerWidth/innerWidth` 含边框与滚动条的少量误差，只用于分档，不参与任何业务计算 |
| 兼容性 | `zoom` 依赖 Chromium 系；项目现行验收浏览器为 Chrome/Edge，未覆盖 Firefox/Safari |
| 回退 | 关闭能力只需移除 `watchDensity()` 与 `data-density` 相关 CSS，或直接回退到父版前端镜像 `b7347a58…`；回退后的批次事实按 [[00-当前系统状态]] 回写 |
| 数据一致性 | 本能力纯渲染，任何档位下同一接口返回与指标口径完全相同 |
