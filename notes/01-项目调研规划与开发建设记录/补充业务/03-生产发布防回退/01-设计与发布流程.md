# 01 · 生产发布防回退设计与发布流程

> 针对本项目多阶段叠加编排发生的 API 版本回退与助手配置遗漏，说明既有完整发布入口及门禁设计。归入补充业务只改变笔记归属，已确立的强制发布要求继续生效。

## 一、问题与目标

2026-10-15 使用基础编排重建 API 后，旧镜像缺少历史会话、运维任务路由，同时遗漏助手连接配置，页面出现 404。恢复已验收镜像后，新增统一发布入口，防止后续演示更新再次覆盖已交付能力。

## 二、设计原理

| 控制 | 解决的问题 |
| --- | --- |
| 冻结完整多阶段编排及私有引用摘要 | 防止只用基础编排遗漏助手、搜索及运维配置 |
| 固定实际镜像 ID 和卷身份 | 防止浮动标签、隐式构建或拉取替换已验收内容 |
| 发布锁、备份及非目标漂移检查 | 防止并行发布、恢复点缺失及无关服务被更新 |
| 发布后自动业务/身份/HTTPS/WSS 门禁 | 防止只看容器运行就认定功能已恢复 |
| 上一份已验收版本及未完成事务 | 防止失败候选变成基线，中断后盲目继续发布 |

> 设计理由：发布对象是可追溯的完整“镜像＋配置＋卷身份”，成功条件是业务门禁通过。只有全部通过后才推进当前指针；失败回到已验收版本，回退失败则保留事务并阻止后续发布。

## 三、规范与实现入口

- 强制规则及审查细目：[[02-工程规范边界与验收治理/项目工程规范/08-发布工具与故障恢复说明]]，工程总纲对应章节继续生效。
- 唯一发布入口：`stages/04-frontend/deploy/production-stack.py`；参数和命令仅维护于 [[06-代码工作区导航与链接映射/stages-04-frontend-deploy-README|README；目标章节：生产发布唯一入口（2026-10-15）]]。
- 私有冻结配置、镜像清单、生产指针、未完成事务保存于服务器 `runtime/production-stack/`；公开笔记不保存秘密配置或运行日志。

## 四、配置与发布流程

#### 步骤 1 · 构建并冻结完整候选

> 在获准的维护环境准备；前提是完整阶段编排和私有引用齐备。准备候选不等于已发布，不能直接覆盖生产指针。

核对全部服务、助手连接、生产 R0 和关闭写窗口，固定镜像及卷身份；候选与当前基线绑定，不接受未审查的非目标漂移。

#### 步骤 2 · 使用统一入口发布并自动判定

> 在正式获准的生产变更窗口执行；会更换指定应用容器，并自动运行发布所需门禁。本次文档整理不执行。

先确认排空、密文备份和互斥条件，再按源码 README 发布。核心 API、匿名拒绝、历史会话/任务列表及详情、双入口 WSS、容器与实际环境均按入口执行结果判定。

#### 步骤 3 · 处理失败或中断

> 在同一受控发布流程中处理；存在未完成事务时不得另开候选绕过阻塞。

自动回退只使用上一份已验收完整配置与镜像，再执行门禁；回退仍失败则保留证据和事务，按唯一入口恢复，不手工把候选改记为通过。

## 五、运行与权限边界

基础 Compose 和历史控制器不能作为现网应用更新入口。工具不授予 Agent 生产执行、审批或写窗口能力；主机 root 仍有系统管理权限，因此不声称操作系统层已禁止一切绕过。文档整理遵守“不重复测试”，但未来真实发布时自动门禁仍是必要环节。
