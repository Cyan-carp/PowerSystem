# 模型通道与额度面板

> 所有者诉求：像桌面客户端那样在界面上直接换模型与 API Key，并在屏幕上看到剩余额度。本专题记录这一次做到哪一步、为什么不能全部照搬，以及发布前必须知道的前置条件。**本批只在工作区完成，未发布**；生产指针与开关仍以 [[00-当前系统状态]] 为准。

## 一、结论：拆成两件事，先做只读那件

| 能力 | 本轮 | 原因 |
| --- | --- | --- |
| 查看每条通道的模型、地址、配置状态 | 已做 | 只读，`/agent/model-status` 与新增 `/agent/model-balance` 都已有后端能力 |
| 查看供应商剩余额度 | 已做 | DeepSeek 官方提供 `GET /user/balance`；由各服务用自己的 Key 查询 |
| 测试连接 | 已做 | 复用原 `POST /agent/model-probe`，带原有副作用与限流 |
| 在界面改 Key / 换模型 | **未做** | Key 是 docker secret 文件、进程启动时读一次，改完必须重建容器；运行态覆盖会破坏发布门禁的可追溯性 |

第三列不是暂缓，是设计判断：把「保存成功」和「实际生效」分开显示，会让人以为改完了。换模型属于另一条写路径，见第五节。

## 二、三条通道，Key 各归各的

平台同时存在三条模型通道，互不复用凭据。面板只覆盖前两条——第三条是 09/10 的传统 v6 域，与用户日常看到的能力无关。

| 通道 | 变量 | 生产实际 | 面板是否展示 |
| --- | --- | --- | --- |
| 告警解读（07） | `AGENT_INTERPRET_LLM_BASE_URL` / `MODEL` / `API_KEY_FILE` | 官方 `api.deepseek.com` / `deepseek-flash` / thinking disabled | 是 |
| 主助手（08） | `AGENT_LLM_BASE_URL` / `AGENT_LLM_MODEL` / `AGENT_LLM_API_KEY_FILE` | 官方同上，凭据 `stage8_assistant` | 是 |
| 传统 v6 域（09/10） | `OPS_LLM_URL` / `SEC_LLM_URL` | 兼容网关 `hgapi.dieqiyun.top/v1` | 否 |

**Key 不出各自的服务。** 余额查询由 07 和 08 各用自己的 Key 发起，Go 后端只做转发与合并，不接触密钥。反过来的做法（把两份 Key 挂进 api 容器）改动更小，但会多出一处密钥暴露面，与最小暴露原则冲突，因此没有采用。

## 三、接口契约

| 层 | 方法 | 路径 | 鉴权 |
| --- | --- | --- | --- |
| 前端可见 | GET | `/api/v1/agent/model-balance` | JWT + `requireAdmin` |
| 内部 | GET | 07 `/internal/agent/model-balance` | `X-PowerSystem-Token` |
| 内部 | GET | 08 `/internal/agent/model-balance` | `X-PowerSystem-Token` |
| 前端可见 | POST | `/api/v1/agent/model-probe` | JWT + `requireAdmin`（原有，本轮只接界面） |

单通道返回：

```json
{
  "channel": "interpret",
  "label": "告警解读",
  "model": "deepseek-flash",
  "base_url": "https://api.deepseek.com",
  "supported": true,
  "is_available": true,
  "balances": [{"currency": "CNY", "total_balance": "110.00",
                "granted_balance": "10.00", "topped_up_balance": "100.00"}],
  "fetched_at": "2026-10-31T15:00:00+00:00",
  "error": ""
}
```

`error` 取值与含义，界面逐条翻译成中文：

| 值 | 含义 | 不能混淆成 |
| --- | --- | --- |
| `unsupported_provider` | 该地址不是可查额度的供应商 | 0 余额 |
| `missing_key` | 没读到 Key 文件 | 额度用完 |
| `auth_failed` | Key 无效或已撤销（HTTP 401） | 余额不足 |
| `is_available=false` + `error=""` | 供应商明确表示余额不足 | Key 失效 |
| `timeout` / `unreachable` | 查询没打通 | 通道不可用 |
| `unavailable` | 智能体服务未启动或未启用 | 没有配置模型 |

金额全部按供应商返回的**字符串**透传，前端不做浮点换算，避免精度与四舍五入失真。

## 四、为什么额度只有 DeepSeek 能看

余额是**供应商私有接口**，OpenAI 兼容协议本身没有额度端点：

- DeepSeek：`GET https://api.deepseek.com/user/balance`，返回 `is_available` 与 `balance_infos[]`（CNY/USD，总额/赠金/充值三分项）。
- 其他兼容供应商（含腾讯 Token Plan 一类）：各自有计费控制台，但没有统一的、可被兼容协议描述的额度接口。

所以实现里对非官方域名返回 `unsupported_provider` 而不是去猜别家的接口——猜错会把「查不到」显示成「没额度」，值班员可能去给一个没问题的账号充值。这一点有单元测试守着。

同理，将来真把解读通道换成别家模型，面板会如实显示「这条通道不提供余额查询」，不会变成 0。

## 五、如果以后要支持界面改 Key / 换模型

按现有的实现方式直接改是走不通的，三条硬约束：

1. **`Config` 是 `frozen=True`，启动时读一次。** `07-agent/agent/config.py` 的 `Config.load()` 在进程启动时读环境变量与 secret 文件，运行期不会重读。网页保存后必须 `up -d --no-deps` 重建容器才生效。
2. **解读通道对模型有硬校验。** `AGENT_INTERPRET_LLM_BASE_URL` 必须精确等于 `https://api.deepseek.com`、模型必须 `deepseek-flash`、`AGENT_INTERPRET_THINKING` 必须 `disabled`，三者缺一即 `not_configured`，自动解读全部降级。换供应商必须先改这段校验并重新验证输出 schema。
3. **运行时改 secret 会让运行态脱离冻结基线。** 生产编排由 `artifacts/` 下的脚本生成，手改 secret 后下次 `prepare` 会判 `active_manifest_changed`，`prepare`/`status`/`rollback` 一起失效。

可行的方向是**运行时覆盖层**：DB 表存 override，服务启动时 override 优先于 env，保留审计与一键回滚；同时把覆盖状态纳入发布回执，否则门禁仍会失联。这不是小改动，需要单独一轮设计与授权。

另有一条功能性的前提：代码对模型输出有严格校验（证据引用、数值断言、时间断言），换没针对这套约束调过的模型，多半会批量 `answer_validation_failed`。**能配上不等于能用**。

## 六、界面与交互

- 入口：顶栏时钟右侧的额度胶囊（CPU 图标 + 解读通道余额），**仅管理员可见**；窄屏（≤1180px）只留图标。
- 胶囊颜色：正常为中性；`error` 非空转橙；`is_available=false` 转红。
- 面板：每通道一张卡，显示模型、地址、余额（总额 / 赠送 / 充值分列）、状态胶囊与查询时间。
- 刷新：登录后拉一次，之后每 10 分钟一次；打开面板与测试连接后再刷。**拉取失败保留上一次的值**，不清零——清零会在顶栏显示一个假的 `¥0.00`。
- 退出登录清空余额并停掉轮询：余额是账号资产信息，不留给下一个登录的人。
- 测试连接按钮的确认框写明真实代价：调用一次模型、总预算 40 秒、每分钟限一次；通过后会清熔断标记，并把最近 24 小时内因未配置 / 认证失败 / 额度用尽而失败的解读重新排队。这条只测解读通道，不影响主助手。

## 九、发布前置条件（重要）

本批跨四个镜像：`07-agent`、`08-agent-rag`、`api`、`frontend`。三者有硬耦合：

- **api 与 07/08 必须同批发布。** 若只发 api，新接口会调不到内部路由，两条通道都显示「智能体服务未启动」，但不会 500、不影响告警解读与其他页面。
- 若只发 07/08 不发 api，新接口无人调用，行为与现状一致。

因此建议整批发布，不要拆。发布后按 [[00-当前系统状态]] 第六节在同一批次回写生产快照，并把本页状态从「未发布」改为实际结论。
