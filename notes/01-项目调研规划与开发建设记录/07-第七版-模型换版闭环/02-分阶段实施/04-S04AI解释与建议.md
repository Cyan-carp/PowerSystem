# S04 · AI 解释与建议

> 目标：把「为什么退化、该不该换」用一段人能读懂的话说清楚。LLM 只写结论，不动数据。

## 一、两个入口

| 入口 | 触发 | 输入 | 输出 |
| --- | --- | --- | --- |
| 漂移归因 | 漂移事件出现时手动点「分析」 | 近 24 小时事件、按小时 tp/fp/fn、当前与基线指标 | 「是滞后误报还是真退化」的判断与建议 |
| 换版对比 | 试用期满 | 新旧模型同段指标、按小时误差 | 「建议提升 / 建议回退 / 建议观察」及理由 |

## 二、实现位置

复用平台 agent 网关（`AI_URL`），不新增模型通道。提示词与工具定义放 agent 侧，api 只转发与落库。

输出落 `trial_note` 与新的 `drift_analysis` 文本字段，页面标注「AI 建议」，与规则事件分行显示。

## 三、硬性约束

1. 只读：LLM 只能调只读接口；
2. 不执行：文本输出不能直接变成训练、提升、回退动作；
3. 可降级：LLM 不可用时页面显示原始指标，不阻塞操作；
4. 可追溯：每次输出记 `prompt_version` 与 `model_used`。

## 四、验收标准

| 项 | 判据 |
| --- | --- |
| 归因可读 | 输出包含具体时段、误差类型、建议动作 |
| 与规则不冲突 | 规则事件仍独立显示，AI 结论标明来源 |
| 失败不影响主流程 | 关掉 agent 服务，页面功能完整 |

### 实测输出（drift）

```
conclusion: 当前更像数据不足，尚不足以判定模型退化或形态滞后。
reasons:   漂移仅触发 L1 watch，high_ratio 0.0018 与 0.0215 均远低于阈值 0.25
           漂移记录 baseline 为 null，缺少可对比基线
           分时误差集中在 16 时 tp=6/fn=6 与 15 时 fp=16，整体故障率仅 0.70%
suggestions: 继续观察后续窗口并补齐基线数据，暂不重训
            回放复核 16 时漏报与 15 时误报样本
tokens: 597 + 743（含推理 543）
```

模型正确判断「数据不足」而非「模型退化」，并指出 baseline 缺失——这是规则事件本身表达不出来的。

### 页面

「模型运营」卡片独立于版本表，左右两栏：

| 左栏 | 右栏 |
| --- | --- |
| 重训资格（天数/样本/正样本）+ 开始重训 | AI 解读（分析漂移 / 对比试用）+ 结论、依据、建议、token 用量 |

重训按钮原先挂在版本表 head 上，本批移入卡片，与解读并列。

### 过程中修掉的 bug

首版解析直接 `json.Unmarshal(content)`，开 thinking 时模型偶尔在 JSON 前后加说明，导致 502。改为截取最外层大括号再解析，失败时回显前 180 字便于定位。
