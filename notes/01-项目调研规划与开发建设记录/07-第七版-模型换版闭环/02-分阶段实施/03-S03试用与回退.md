# S03 · 试用与回退

> 目标：候选模型先跑 24 小时再定去留，不行一键退回，全程不重启容器。

## 一、状态机

```
candidate ──trial──▶ trial ──confirm──▶ active
                        │
                        └──rollback──▶ candidate（软链回退 + reload）
```

新增字段（`model_registry`，均可空）：

| 字段 | 用途 |
| --- | --- |
| `trial_started_at` | 试用开始，用于算 24 小时 |
| `previous_version` | 回退目标，回退只认这个字段 |
| `trial_note` | 试用结论（人工或 AI 填写） |

## 二、三个接口

| 接口 | 动作 |
| --- | --- |
| `POST /models/{v}/trial` | 校验版本可加载 → 改软链 → reload → 置 `trial`，记 `previous_version` 与 `trial_started_at` |
| `POST /models/{v}/confirm` | 校验已满 24 小时 → 置 `active`，原 active 置 `retired` |
| `POST /models/{v}/rollback` | 软链改回 `previous_version` → reload → 目标版本置回 `candidate` |

三个接口都是写操作，需管理员权限，且都要有二次确认框。

## 三、试用期满的判定

- 时长：`now - trial_started_at >= 24h`；
- 指标：新模型在试用期内 `precision` 不得低于旧模型试用前 24 小时 `precision` 超过 5 个百分点；
- 优劣只做提示，**不自动回退**——写操作必须人点。

## 四、验收标准

| 项 | 判据 |
| --- | --- |
| 试用切换不中断 | 切换前后连续调 `/predict` 无 5xx，容器 `StartedAt` 不变 |
| 未满 24 小时不能 confirm | 按钮置灰并显示剩余时间 |
| 回退可复现 | 回退后 `/health` 与台账都回到旧版本，试用版本回到 `candidate` |
| reload 失败自动改回 | 故意指向坏目录，软链与台账均不变 |

## 五、实施记录（2026-11-03 04:25 CST）

### 关键前置：`/model` 改可写

S01 验收时发现容器不能改软链（`Read-only file system`）。本批把 `ai-predict` 的挂载从 `:ro` 改为 `:rw`，`/admin/reload` 在传 `version` 时自己切软链——顺序是**先加载成功、再切软链**，失败时两者都停在旧版本。

### 落地

| 项 | 值 |
| --- | --- |
| api | `63f025e1…` |
| frontend | `4a361800…` |
| ai-predict | `f73e1075…`，`/model` 挂载 `rw=True` |
| 台账 | 新增 `trial_started_at`、`previous_version`（手工 SQL 迁移） |

### 验收输出（完整一轮）

```
1. 登记候选     candidate（updated=True）
2. 试用         trial，previous=stage3-xgb-89e6530c9e29，trial_at 17:40:51Z
3. 立刻确认     409「试用未满 24 小时，还需 24.0 小时」
4. 列表         trial 行 prev=89e6530c、trial_at 有值；runtime=ae1f508f
5. 回退         200，rolled_back_to=89e6530c
6. 回退后       runtime=89e6530c，试用版本回到 candidate
```

全程容器 `StartedAt` 未变——切换与回退都是热加载。

### 过程中修掉的 bug

首版列表接口没返回 `trial_started_at` 与 `previous_version`，页面试用行看不到上一版本，回退确认框会显示「恢复 undefined」。已补并在 `63f025e1` 修复。
