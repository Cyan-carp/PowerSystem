# S02 · 重训作业与按钮

> 目标：页面点一下就能用新数据重训，产出候选并落到 `versions/<v>/`，不需要登服务器。

## 一、组成

| 组件 | 职责 |
| --- | --- |
| `ai-trainer` 服务 | 常驻容器，装 xgboost/numpy，暴露 `POST /train`，训练完把文件写到共享卷 `versions/<v>/` |
| 后端接口 | `POST /predictions/quality/models/train`：校验数据量 → 调 trainer → 登记候选 |
| 页面 | 「重训」按钮，显示训练进度与结果 |

## 二、数据口径

严格按 [[01-项目调研规划与开发建设记录/07-第七版-模型换版闭环/01-立项与总体设计/03-训练数据划分与试用回退]]：

- 硬边界 `window_end_ms >= 1793604000000`；
- 训练 / 验证 / 测试三段切分（7 天 / 6 天 / 1 天）；
- 排除未结算、窗口内、非 window 来源样本；
- 真实 : 合成 = 30 : 70 起步。

## 三、准入与拒绝

沿用第六版阈值（5,000 样本 / 50 正样本 / F1 0.5），不足时**不开放按钮**并给出具体差多少：

```
新形态数据仅 6 天，需 10 天；当前正样本 120，已达 50
```

## 四、验收标准

| 项 | 判据 |
| --- | --- |
| 页面可触发 | 点按钮后 trainer 收到请求，日志可追 |
| 产物落位 | `versions/<v>/{model.json,metadata.json}` 存在且可加载 |
| 台账登记 | 训练完成后 `candidate` 出现在版本表，文件位置列正确 |
| 失败可读 | 数据不足 / 训练异常 / 写盘失败，页面显示具体原因 |
