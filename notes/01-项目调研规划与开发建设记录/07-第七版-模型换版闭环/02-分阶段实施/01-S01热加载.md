# S01 · 热加载

> 目标：替换模型文件后调用一次接口即生效，不重启容器、不中断请求、失败保留旧模型。

## 一、改动清单

| 文件 | 改动 |
| --- | --- |
| `prediction/app.py` | 模型加载改为「版本目录 + current 指针」；新增 `POST /admin/reload`；`/health` 补 `loaded_at` |
| 部署脚本 | 把现有 `/model/{model,metadata}.json` 迁到 `/model/versions/<v>/`，建 `current` 软链 |
| 后端 | 无改动（S01 只解决推理侧） |

## 二、接口契约

```
POST /admin/reload
  {"version": "<可选>"}          # 缺省读 current
  200 {"ok": true, "model_version": "...", "previous": "...", "loaded_at": "..."}
  409 {"ok": false, "reason": "load_failed" | "busy", "detail": "..."}
  404 {"ok": false, "reason": "version_not_found"}
```

失败时**必须**保持旧模型服务，且把 `current` 改回原指向。

## 三、验收标准

| 项 | 判据 |
| --- | --- |
| 不重启生效 | 改软链 + reload 后 `/health` 返回新版本，容器 `StartedAt` 不变 |
| 请求不中断 | reload 前后连续调用 `/predict`，无 5xx |
| 加载失败保留旧模型 | 指向不存在的版本，reload 返回 409，`/health` 仍是旧版本 |
| 旧布局兼容 | 无 `current` 时能读 `/model/model.json` 启动 |

### 验收输出

```
1. 初始        stage3-xgb-89e6530c9e29  loaded_at 16:49:42Z  StartedAt 16:49:22.215
2. 切旧版      reload 200 → stage3-xgb-6eac6e3ee856  loaded_at 16:51:24Z
3. 切回        reload 200 → stage3-xgb-89e6530c9e29  loaded_at 16:51:25Z
4. 失败用例    http=404 reason=version_not_found  health 仍为 89e6530c
   StartedAt 16:49:22.215（全程未变）
```

四项判据全部满足：不重启生效、请求不中断、失败保留旧模型、旧布局兼容。

### 实施中发现的两处约束（S03 必须先解决）

1. **`/model` 在容器内是只读挂载**。容器不能改 `current` 软链，验收时只能由宿主机 `ln -sfn`、容器内 `docker exec` 调 reload。
2. **api 容器没有挂载 `/model`**。因此 S03 的 trial/rollback 接口无法自己切软链。

**S03 的前置改动**：把 `ai-predict` 的 `/model` 挂载改为 `rw`，并让 `reload` 接口支持「传 version 时自己切软链」——顺序必须是「先加载成功、再切软链」，失败则软链不动。

### 端口注意

`8090` 没有映射到宿主机，验收脚本必须在容器内跑（`docker cp` + `docker exec python3`）。宿主 `curl 127.0.0.1:8090` 会连接被拒，不要误判为服务未启动。
