# 04 · AI 辅助的边界

> LLM 在本版只做「读数据、写结论」，不做任何写操作。这条边界与平台现有的「只读 + 人工确认」基调一致。

## 一、四种可能的介入形态

| 形态 | 做法 | 结论 |
| --- | --- | --- |
| A 决策辅助 | 读漂移事件与指标，输出归因与建议 | **做** |
| B 替代预测 | 把特征序列喂给 LLM 判断故障 | **不做** |
| C 生成训练数据 | 让 LLM 编造带标签样本 | **不做** |
| D Agent 编排 | 串起「检测→重训→对比→建议」 | **做，但停在建议** |

## 二、为什么不做 B

| 项 | XGBoost | LLM |
| --- | --- | --- |
| 单次推理 | < 1 ms | 数百 ms – 数秒 |
| 成本 | 近似为零 | 按 token 计费 |
| 可解释性 | 特征重要度可读 | 难以核验 |

当前规模：143 台设备 × 每 5 分钟一批 = 每天约 4 万次推理。换成 LLM 是数量级的成本与延迟上升，而准确率未必更好。时序异常检测不是 LLM 的强项。

## 三、为什么不做 C

合成数据现在由物理模型生成（日照曲线、功率-温度耦合、电气一致性校验），可复现、参数可查。让 LLM 编数据，无法验证生成值是否满足热力学与电气约束，等于把「可解释的合成」换成「不可验证的文本」。

## 四、A 与 D 具体做什么

### 1. 漂移归因

输入：`prediction_drift_events` 近 24 小时事件 + 按小时的 tp/fp/fn 分布 + 当前版本与基线指标。

输出（示例）：
> 15 点误报 16 次，集中在 PV-04 窗口结束后 40 分钟。特征窗口 30 分钟仍带高温，判断为滞后误报，不是模型退化。建议观察，不建议重训。

### 2. 重训后对比

输入：新旧模型在同一测试段的 precision / recall / F1、按小时误差分布。

输出：整体更好但单时段更差时明确指出，提示是否需要按时段分模型。

### 3. Agent 串联

每日定时或人工触发，Agent 依次执行：查漂移 → 判断是否重训 → 触发训练 → 出对比报告 → **停在「建议提升」**，等人工点确认。

## 五、硬性约束

1. **不写数据库**：LLM 只能调用只读接口；
2. **不触发训练**：训练由页面按钮或 Agent 的显式工具调用发起，LLM 的文本输出不能直接变成动作；
3. **不解释为事实**：LLM 输出在页面标注「AI 建议」，与规则事件分开呈现；
4. **失败静默降级**：LLM 不可用时，页面显示原始指标，不阻塞任何操作。

## 六、实现位置

复用平台已有的 agent 网关（`AI_URL` / `agent` 服务），不新建模型通道。提示词与工具定义放在 agent 侧，api 只转发。
