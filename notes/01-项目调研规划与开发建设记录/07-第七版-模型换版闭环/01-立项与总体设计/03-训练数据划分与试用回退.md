# 03 · 训练数据划分与试用回退

> 回答两个问题：重训用哪些数据、试用期怎么定义。所有口径都可由 SQL 复核。

## 一、硬边界：按故障形态切段

```
window_end_ms >= 1793604000000   # 2026-11-02T07:20:00Z，即 qualityEpochMS
```

这条线之前，模拟器是「窗口内突变、无前兆」；之后改成「前兆 60 分钟爬到目标 70%」。两种形态的特征分布完全不同，混在一起训练等于让模型同时相信两套规律。

**实现**：训练取数 SQL 一律带 `window_end_ms >= 1793604000000`，不接受参数覆盖，避免手滑。

## 二、三段划分

| 段 | 范围 | 用途 | 是否参与拟合 |
| --- | --- | --- | --- |
| 训练 | `[epoch, now-7d)` | 拟合 | 是 |
| 验证 | `[now-7d, now-1d)` | 调阈值、早停 | 否 |
| 测试 | `[now-1d, now)` | 最终评估，只跑一次 | 否 |

留 7 天验证期的原因：若训练与验证重叠，指标虚高；若验证与测试重叠，选阈值时就偷看了答案。

样本不足时的降级：`now-epoch < 10d` 时不开放重训按钮，页面提示「新形态数据不足 10 天」。

## 三、必排样本

| 条件 | 原因 |
| --- | --- |
| `label_status != 'labeled'` | 窗口未到期，`actual_fault` 还没定 |
| `window_end_ms` 落在故障窗口内 | 特征里已含故障，等于作弊 |
| `source != 'window'` | 补数、回放样本分布不同 |
| `probability IS NULL` | 推理失败的行 |

## 四、合成数据的位置

真实数据当前只有 5 个钟点、143 台设备，覆盖不了「不同爬升速率、不同日照、不同负载」。合成数据补这部分。

| 阶段 | 真实 : 合成 | 触发条件 |
| --- | --- | --- |
| 初始 | 30 : 70 | 真实数据 ≥ 10 天 |
| 中期 | 50 : 50 | 真实数据 ≥ 30 天 |
| 稳定 | 70 : 30 | 真实数据 ≥ 60 天 |

合成数据必须用 `--window-mode --precursor-minutes 60` 生成，与线上形态一致。

## 五、试用与回退

### 状态机

```
candidate ──trial──▶ trial ──confirm──▶ active ──replace──▶ retired
                        │
                        └──rollback──▶ candidate（或 retired）
```

| 状态 | 含义 | 谁进入 |
| --- | --- | --- |
| `candidate` | 已登记未上线 | import |
| `trial` | 已加载、观察中 | trial 接口 |
| `active` | 正式现役 | confirm（试用期满且指标不劣） |
| `retired` | 已下线 | 被新版本替换 |

### 试用期规则

- 时长 **24 小时**，从 `trial_started_at` 起算；
- 期满前不允许 confirm，页面按钮置灰并显示剩余时间；
- 期满时自动对比：新模型 `precision` 与试用前 24 小时旧模型的 `precision` 比较，允许 5 个百分点回退；
- 劣于阈值 → 页面提示「建议回退」，不自动回退（写操作要人确认）。

### 回退

回退 = 软链改回上一版本 + `/admin/reload` + 台账把 `trial` 版本置回 `candidate`。全过程 < 3 秒，不重启容器。

上一版本记录在 `model_registry.previous_version`（新增可空列），回退只认这个字段，不靠猜。

## 六、质量数据的一致性

切换版本后，`prediction_outcomes` 会同时存在两个模型版本的样本。日指标的 SQL 必须按 `model_version` 分组，否则新旧混算会得出「都还行」的假象——这个坑在 [[79-前兆注入与模型切换]] 已经踩过一次。
