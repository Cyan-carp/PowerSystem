# 第七版 模型换版闭环 · 索引

> 第七版的目标是让「换模型」从运维手工操作变成产品内闭环：**热加载不中断 → 页面触发重训 → 试用一天 → 不行回退**，并用 AI 补上「为什么退化、该不该换」的解释。四个阶段已于 2026-11-03 全部发布（api `47317d90…`、ai-predict `f73e1075…`、trainer `2bfb33be…`），生产指针以 [[00-当前系统状态]] 为准。

## 一、这一版解决什么

第六版把「模型可被衡量、可被登记、可被提升」接成了闭环，但换版链路上仍有三个断点（详见 [[01-项目调研规划与开发建设记录/07-第七版-模型换版闭环/01-立项与总体设计/01-换版链路现状与断点]]）：

1. **换文件就要重启**：`ai-predict` 启动时只加载一次模型，替换 `model.json` 后必须 `docker restart`，中断 10–30 秒，网页跟着 502。
2. **重训靠命令行**：`retrain.py` 只能在服务器上跑，页面无法触发，非技术人员做不了一次完整换版。
3. **没有试用期**：候选提升即生效，好坏都得等第二天看指标；想回退还要再走一次手工换文件。

## 四、四条必须记住的边界

1. **热加载必须原子替换**。新模型先完整加载到局部变量，成功后才替换运行时引用；失败保留旧模型继续服务。不允许「边加载边替换」，详见 [[01-项目调研规划与开发建设记录/07-第七版-模型换版闭环/01-立项与总体设计/02-热加载与原子替换]]。
2. **训练数据按故障形态切段**。`window_end_ms < 2026-11-02T07:20Z` 的样本一律不进训练集，旧形态（突变型）与新形态（60 分钟前兆）混训等于教模型两套矛盾规律，详见 [[01-项目调研规划与开发建设记录/07-第七版-模型换版闭环/01-立项与总体设计/03-训练数据划分与试用回退]]。
3. **AI 只出建议，不执行写操作**。提升、回退、改阈值仍由人点按钮；LLM 负责解释漂移与对比结论，详见 [[01-项目调研规划与开发建设记录/07-第七版-模型换版闭环/01-立项与总体设计/04-AI辅助的边界]]。
4. **不采用蓝绿双容器**。热加载已能做到「失败不切、切换不中断」，再叠一套双容器属于过度设计；只有将来单容器扛不住负载再考虑副本。

## 五、与第六版的关系

第七版不替换第六版，是它的延长段：

| 能力 | 第六版 | 第七版 |
| --- | --- | --- |
| 登记候选 | ✅ import 接口 | 不变 |
| 提升台账 | ✅ promote 接口 | 增加 `trial` 中间态 |
| 替换模型文件 | ❌ 运维手工 + 重启 | ✅ 页面触发 + 热加载 |
| 触发训练 | ❌ 服务器命令行 | ✅ `ai-trainer` + 按钮 |
| 回退 | ❌ 手工 cp 备份 | ✅ 一键回退 |
| 退化归因 | ⚠️ 规则事件 | ✅ LLM 解释 + 建议 |
