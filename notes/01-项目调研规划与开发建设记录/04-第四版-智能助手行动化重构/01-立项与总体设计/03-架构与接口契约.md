# 03 · 架构与接口契约

> 冻结版本 assistant/v4-draft1。以下是S02–S08实现契约，不是现有接口。现有 ma/v1 与 ma-review/v1 不原位扩权；兼容适配需单独版本与测试。

## 一、职责与信任边界

前端 → Go鉴权网关 → 阶段8主助手/运行服务 → 普通业务适配器或阶段9运维专家 → 独立安全审查/执行器。阶段2仍是业务权限和指标真相；阶段10提供签名意见而非权限。所有工具从统一能力目录发现，不给模型任意URL、SQL或Shell。

每次执行前核对当前身份、资源范围、能力版本、参数及禁区。模型理解用户问题不由关键词硬拒，但模型请求读取秘密同样是动作，须在读取前拒绝。网页、文档和日志只作为不可信数据。

## 二、公开API与身份

全部位于原JWT鉴权组，身份由Go注入，客户端不能提交user_id/role。用户只读本人运行、产物和批准记录；管理员角色本身不自动授予他人会话访问权。

| 接口 | 冻结行为 |
| --- | --- |
| POST /api/v1/agent/runs | body: message、可选session_id、可选page_context；Idempotency-Key必填UUID；返回202及run_id/turn_id/session_id/status |
| GET /api/v1/agent/runs/:id | 返回状态、阶段、answer_version、turn_id、final_answer（未终结为已持久化正文）、result_refs、动作状态与产物元数据清单、terminal_event、last_seq和脱敏错误 |
| GET /api/v1/agent/runs/:id/events | SSE；Last-Event-ID或after_seq续传，二者同时提供且不一致返回400 |
| POST /api/v1/agent/runs/:id/cancel | 幂等取消请求；返回实际状态及已执行动作，不承诺撤销 |
| POST /api/v1/agent/runs/:id/actions/:action_id/decision | decision=approve/reject，approval_id与plan_hash；有效授权绑定，重复同决定回原结果，冲突409 |
| GET /api/v1/agent/artifacts/:id | 本人产物元数据与可预览信息；download子路由受同一鉴权 |

S05另增 GET /api/v1/reports/energy：start_date/end_date为北京时间日边界、end_date不含；最多31自然日；scope=business/all/baseline，可选station_code/device_id，组合筛选取交集；返回逐日与汇总电量、实际窗口、聚合更新时间、complete/missing信息。无聚合记录不冒充零发电。可用率/时效复用现有31天口径，遥测导出保留7天/200000行上限。

S02补验提前适配上述最小只读JSON查询，文件与完整业务分析仍归S05；窗口默认语义和影响见修订台账C08。知识来源GET可选collection/version固定原物理集合及导入版本，旧无参数链接兼容内容回读，详见C09；这不授予任何知识写权限。

S08增加 /api/v1/agent/schedules 的本人列表、详情和创建/修改接口；修改先生成受审查动作，经批准后生效，暂停/取消为可审计授权缩减，按第五章直接生效。下载不通过模型指定任意路径，预览不执行HTML/脚本；文件名与CSV公式单元格按格式转义。

S06复用既有POST /api/v1/alarms/:id/ack的业务语义，助手只能通过阶段9已消费的一次性动作调用，不向模型开放裸写URL。设备备注新增PATCH /api/v1/devices/:id/remark，body={remark,expected_version}，remark纯文本最多1000字符，expected_version不符409；迁移新增remark默认空、remark_version默认0及remark_updated_by/remark_updated_at（不复用既有Device.updated_at作为备注版本），更新与版本+1同事务，Go依据当前operator/admin权限并核验动作绑定，记录修改前后摘要。人工平台原有确认告警路径不因本版助手审批而偷偷改变，若统一改人工权限须另列契约变更与回归。

S08创建/修改调度返回待批准动作，GET详情含config_version/grant状态；暂停/取消幂等，恢复或扩大范围重新批准。默认grant期限30天，最长90天，到期暂停不自动续批；用户可选择更短期限。有效期/时区/范围必须在批准卡显示。

产物默认7天过期，metadata记录expires_at，下载每次核验当前owner/权限/完整性；流式送文件到浏览器，正文不经模型。过期或损坏返回410且不给存储键，固定后台策略清理到期文件并留元数据/审计；这不授予模型删除生产业务数据的能力。大文件生成设预算与大小上限，S05基于实际性能确定值并留契约变更记录，不默认无限制。

旧 POST /agent/chat 在迁移期间保持旧响应；新页面明确选择runs协议，不能一个请求隐式双发旧/新路径。

## 三、运行与事件

Run状态：queued → running → awaiting_approval → running；终态为succeeded/partial/failed/cancelled。未发出写动作时达到预算记failed且error.code=deadline_exceeded。写已发出时优先适用核查分支，deadline只停止后续计划，不能覆盖reconciling/partial。未知写结果进入reconciling，核实前不能标成功或再次执行；超出核查预算转partial并标requires_manual_reconciliation。

session_id省略时创建新会话并返回ID，不隐式续用最近会话；提供时校验本人所有权。上下文快照在受理事务中固定，记录当时可见turn版本、任务状态及page_context；排队请求不自动吸收之后完成的答案，可明确引用前序run并获取标注时间的当前状态。

先在事务中保存会话（若新建）、用户turn、run、context_snapshot、request_hash和outbox，再返回202；任务创建即绑定turn_id，不等答案结束补绑。幂等唯一键为(user_id,idempotency_key)，同键不同规范化请求409，同键同请求返回原run（不重复模型或动作）。

事件统一包含protocol/run_id/turn_id/seq/type/at/data，seq在run内严格递增且唯一。类型：accepted、progress、text_delta、tool_started、tool_finished、approval_required、action_blocked、artifact_ready、completed、failed、cancelled。终态快照与终态事件同事务保存；客户端按seq去重。业务结论按校验后段落发送，自然解释可增量发送；禁止把内部推理或原始敏感工具响应作为事件发出。

前端使用带Authorization的fetch流，不把JWT写入URL。15秒心跳；事件保留7天，按run判定游标：after_seq小于该run最早保留seq减1、或尚需事件已全部过期时返回410 event_cursor_expired；等于last_seq无缺口，等待新事件；大于last_seq返回400。客户端读取快照完整替换展示，再从其last_seq续传。快照按会话保留规则保存；事件过期不删除最终结果。取消响应丢失可幂等重试。

浏览器断线只停止订阅，不取消运行。后续问题可以独立排队；每次新run锁定本轮上下文快照及实体引用，最近任务ID/状态可检索。用户问过去失败不重新执行；问当前状态不拿旧值冒充新值。默认每用户最多2个运行中非写任务，额外任务排队；状态修改按目标加互斥锁。

### 快照与载荷

GET /runs/:id即为单run快照接口。读取采用一致性事务，使正文、answer_version、result_refs、产物/动作投影、terminal_event与last_seq对应同一已提交事件前缀；未终结时terminal_event=null。返回protocol、owner授权后的session_id/turn_id、status、phase、cancel_requested、requires_manual_reconciliation、final_answer、answer_version、result_refs、actions[]、artifacts[]、last_seq和error。阶段9权威动作尚未同步的项目必须带observed_at/stale=true，批准/取消仍实时核验。

事件过期只重建该run。跨轮会话顺序由既有GET /api/v1/agent/sessions/:id的turn列表提供，S03兼容增加可空run_id（旧客户端忽略）；前端分别恢复各run，不能用单run覆盖整段历史。审批与产物清单包含展示所需元数据，不包含令牌、文件存储路径或正文；失效项目仍可展示状态，但不能产生有效下载/批准入口。

事件data最小字段：

| type | data字段 |
| --- | --- |
| accepted | status、session_id、turn_id |
| progress | phase、message、可选已测percent（未知不传） |
| text_delta | answer_version、offset、text；版本变化先发reset=true并从offset=0重建 |
| tool_started/tool_finished | call_id、capability、status、脱敏summary、result_ref、error |
| approval_required | action_id、approval_id、plan_hash、expires_at、risk_class、effect_summary、target_summary、authority_revision |
| action_blocked | action_id、rule_codes、reason，不含可批准令牌 |
| artifact_ready | artifact_id、name、mime_type、size、sha256、expires_at |
| completed/failed/cancelled | status、answer_version、result_refs、error、requires_manual_reconciliation |

同一次状态变化中快照与事件原子写入；审批投影从阶段9幂等同步后再发布，不抢发虚假“已批准/已执行”。客户端按seq去重、按answer_version/offset应用正文。run→turn为必需外键，子任务创建时即传parent_turn_id与run_id，不能结束时再补绑。

### 取消与核查状态

cancel先持久保存cancel_requested，再报告权威状态。queued与awaiting_approval在撤销未消费审批后进入cancelled；running只读任务协作停止并保存已有结果。写动作尚未发出时以阶段9同一账本事务竞争“消费审批/撤销”，只允许一个成功。

写已发出则进入reconciling，保留cancel_requested，禁止报cancelled或再次写入。阶段9负责查询执行器结果，默认核查预算120秒；确认后保存已发生副作用、停止剩余计划并置partial（有副作用）或cancelled（确认无副作用）；超预算partial且requires_manual_reconciliation=true，后续人工核查只追加动作事实与修订版本，不自动重跑。

cancel及decision响应必须同步查询阶段9权威动作状态；不可达返回202 pending_reconciliation及last_known状态，不能把投影当成已执行动作完整清单。终态后的重复cancel返回原终态，不把成功改成取消。阶段8本地cancel请求、阶段9动作状态和投影更新通过幂等outbox收敛。

## 四、持久化与执行唯一权威

阶段8原RAG库增量维护 assistant_runs、assistant_run_events、assistant_actions、assistant_artifacts、assistant_schedules；保留rag_sessions/rag_turns，turn关联run可为空以兼容旧记录。逻辑结构：

- runs：owner/session/turn、请求摘要、状态、版本、模型配置版本、阶段、截止时间、最终回答与结果引用。
- events：run_id+seq唯一，类型、时间与裁剪后payload。
- actions：run/owner、能力名版本、参数摘要、目标快照、风险/数据分类、策略版本、状态及execution_ref；投影保存approval_id、plan_hash、expires_at、approval_status、consumed_at、authority_revision与observed_at，不能独立改写消费事实。
- artifacts：owner/run、类型、内部存储键、大小/摘要/生成及过期时间；文件正文不进上下文。
- schedules：owner、任务类型及固定参数范围、时区/调度、config_version、启停状态、下次执行时间；schedule_grants保存grant_id、schedule_id、scope_hash、destination_id/version、approved_by、approved_at、expires_at、revoked_at与config_version，并对每次run记grant_id/slot。

ID采用UUID，时间以UTC持久化、界面按用户/业务时区显示；事件seq为64位整数且run内唯一。runs对(owner,idempotency_key)唯一并索引(owner,session,created_at)，events对(run,seq)唯一，actions对action_id唯一且关联run，artifacts按owner/run查；owner/turn外键在受理事务中校验。request_hash覆盖规范化message/session/page_context与协议版本，派生ID不参与；保留会话删除语义，软删除不得删除执行审计。S03迁移先加可空关联、兼容读写，再切开关；回退关闭新受理但保留任务查询/核查与账本，不降级重放到旧chat。

动作审批及执行仍由阶段9控制器账本作为唯一权威；阶段8 actions保存绑定与状态投影，不再消费一套独立审批。审批决定适配器将原始动作绑定转交阶段9并取回权威结果。跨库以outbox和幂等状态同步，不声称跨库原子事务。必须保持当前角色/权限与用户意图绑定。

LangGraph持久检查点放RAG库独立命名空间，thread_id=run_id；会话上下文从受裁剪的turn与任务摘要构造，检查点不能覆盖动作账本。worker恢复先核对动作状态：只读可有界重试；写结果未知先核实，不能因节点重新运行再次写入。模型调用绑定step与预算，记录已完成输出避免无条件重放。

S03内部绑定适配使用独立`ma-run/v1`及`POST /internal/ma/v1/run-tasks`，强制read_only并要求run_id/parent_turn_id；旧ma/v1和旧受理路径保持原语义。阶段9在子任务受理事务写入绑定，同键不同绑定409；此适配不提供新审批或写执行能力，修订理由及回归见C11。

## 五、动作与安全接口

ActionProposal字段：action_id、run_id、capability/version、typed_args、target_refs与target_version、risk_class、data_class、destination_id、expected_effect、recovery_limit、policy_version、plan_hash。风险由能力目录与参数确定，模型不能自行降级。

R0可含敏感数据，是否审查由data_class/destination独立决定；R1为业务修改，R2为受控运维；禁区为deny_rule而非可批准风险等级。ReviewDecision为allow/require_approval/deny/unavailable并附rule_codes、中文解释、绑定摘要、有效期；R1/R2即使模型allow仍须本人且有权限的用户批准。

审批默认5分钟内一次消费；执行前复核参数、资源版本、当前权限、策略版本与目标模型目的地。拒绝后同动作不自动换参数循环求放行。审查不可用阻断所需动作，不能自动放行或中断无关解释。批准只授权本次动作，不转为长期许可。

数据出站前裁剪及检查目的地；安全意见本身不能授予模型秘密访问。服务操作仅固定注册的适配器，不接任意命令。失败/部分成功分别保存已执行事实和后续可选动作，不能承诺不可逆业务修改可撤销。

### 审批绑定与数据分类

阶段9签发approval_id并计算plan_hash：对绑定对象按RFC 8785规范化JSON后取SHA-256；对象包含owner_id、run_id、action_id、capability/version、typed_args、target_refs/version、data_class、destination_id/version、policy_version与expires_at。数字必须为有限JSON数，未知字段拒绝。旧ma协议保留原hash，新版本适配不可混用。

阶段8转交批准，不独立签发/消费；阶段9以条件事务一次消费，重复同决定只返回原execution_ref。过期、参数/目标/权限变化返回409及stable error.code，并发布权威状态事件同步投影；拒绝为终态，重新提议生成新action_id且需明确新用户意图。

数据分类与目的地：

- data_class枚举public/internal/sensitive/secret；destination枚举local/platform_client/registered_model/external。
- public/internal在当前资源权限内的local或本人platform_client读取为R0自动；向登记模型发送须按能力批准的字段白名单裁剪，未知字段或未登记模型不出站。
- sensitive读取或向登记模型出站先审查，可控范围暂停批准；secret读取/出站硬拒。
- external交付需专门审查与批准，第四版不启用对外发送能力。调用模型也是数据出站，目的地变更使旧审批失效。
- 普通读快速路径依赖确定性分类，不因安全模型不可用全部停摆。默认data_class来自能力/字段注册表，模型不得自行降级。

S08区分两类凭证：创建/修改/恢复配置的动作审批仍5分钟一次性；消费后写入有到期时间、任务类型/范围/站内目的地与版本绑定、可撤销的schedule_grant。该配置授权只允许到期前重复触发限定只读任务，每次重验权限，不是可复用动作批准，不能批准R1/R2。暂停/取消本人调度属于缩减授权的幂等控制，鉴权后直接执行并审计，不等待安全模型。

## 六、模型、知识和功能开关

S07内部ma-ops/v1与ma-ops-review/v1按C15独立分域，复用阶段9原批准/执行权威，S06策略不授权运维。固定登记隔离service.diagnose/logs/evidence/restart；R2管理员5分钟一次绑定批准，敏感日志/证据先独立审查且内容只给本人站内。JSON证据包复用产物鉴权/摘要/7天期限，下载白名单增加application/json，禁止HTML。手动核查终态时，GET本人run可只读查询晚到的权威回执并追加动作事实与修订事件，保留原partial/manual终态及终态事件，不重跑图或再次执行。当前实现与适用范围见S07交付页，不授予任何生产写权限。

Provider统一输出正文增量、完整工具调用、usage、finish_reason与错误类别；JSON/SSE兼容，只有完整且校验通过的工具参数才可执行。连接/首响应/总时限分开记录；模型结束前截断不得执行半个工具调用。

模型配置登记provider_id/model_id/endpoint目的地/凭据引用/协议能力/版本；正文不保存秘密。现有生产档绑定不直接删除，以新显式v4档替代并保留旧档验证。候选需真实评测，工具选择与最终结论能力分开判定。

能力目录回答“助手当前能做什么”；知识集合保留版本与源摘要，分卷纳入显式清单，导入完成验证后原子换别名并保留旧引用。实际设备/规则事实优先于文档，文档不改变授权。

配置开关：V4_ASSISTANT_ENABLED、V4_RUNS_ENABLED、V4_ARTIFACTS_ENABLED、V4_ACTIONS_ENABLED、V4_OPS_WRITE_ENABLED、V4_SCHEDULES_ENABLED，默认全部false。测试环境逐阶段开启，生产至S09才按账号灰度登记。部署权限、备份、恢复门禁仍按既有规范；新增SQL必须通过真实启动迁移入口隔离测试。

## 七、S08调度与预演

默认Asia/Shanghai，每日时刻或固定间隔（最短15分钟）；站内交付，不发送邮件或外部消息。配置批准绑定任务类型/范围/期限，调度只执行只读查询和本人产物，不自动批准任何业务/运维写动作。
