# 02 · 需求范围与总体方案

> 冻结本版做什么、不做什么，以及为什么把「自动重训」降级为「自动观测 + 人工提升」。

## 一、所有者诉求（原话口径）

1. 模型要能根据实际情况微调。
2. 要有一个模块，把预测准确率与修正情况展示出来。
3. 精度偏移到一定数值后，模型能自主重新训练。
4. 就用仿真设备，项目价值在流程而不是数据。

## 二、方案选择：B 档

自动重训拆成「训练」与「上线」两个动作。训练可以全自动，上线保留人工闸门。三档对比：

| 档 | 做法 | 结论 |
| --- | --- | --- |
| A | 评估达标自动替换生产模型，7 天恶化自动回滚 | **不采用**。仿真环境真值单薄，坏模型会静默上线，且回滚依据的是同一套可能失真的指标 |
| **B** | 自动训练 + 自动评估 + 自动置为候选，管理员一键提升 | **采用**。与现有「写操作要人工闸门」的纪律一致 |
| C | 只对阈值/校准做自动调整，换权重才要人 | 保留为后续选项，本版不做 |

## 三、范围

### 做

| 模块 | 内容 |
| --- | --- |
| 真值回路 | 4 张表；每小时回填真值；按日聚合混淆矩阵与 ECE |
| 质量看板 | 预测页新增「预测质量」页签：KPI、混淆矩阵、校准曲线、按天趋势、版本表、漂移事件 |
| 版本台账 | `model_registry`；候选登记接口；提升/退回状态机 |
| 训练作业 | `retrain.py`：产出候选目录 + 机器可读报告，带准入判断 |
| 漂移观测 | L1（分布）/L2（校准）/L3（精度）三类事件，只记录不训练 |

### 不做（本版明确排除）

| 项 | 原因 |
| --- | --- |
| 自动拉起训练容器 | 需要调度器与资源隔离，属 S05 以后；本版由运维执行脚本 |
| 自动替换生产模型文件 | 与发布流程冲突，必须走镜像/发布 |
| 自动回滚 | 依赖足够真实的真值，仿真环境不成立 |
| 接 TDengine 导出训练集 | 训练数据管道是独立工程，本版允许用合成数据 |
| 人工标注入口 | 表结构已预留 `label_source='manual'`，界面入口留待后续 |
| 预测页以外的改动 | 不动其它页面与导航 |

## 四、四个阶段

| 阶段 | 内容 | 依赖 |
| --- | --- | --- |
| S01 | SQL 迁移、真值回填 worker、日指标、漂移检测、6 个只读/写接口 | 无 |
| S02 | 前端页签与三个图表组件 | S01 的接口 |
| S03 | `retrain.py` + 候选登记接口 `POST /models/import` | 无 |
| S04 | promote 状态机、版本表交互、漂移事件展示 | S01、S02 |

S01 与 S03 可并行；S02 依赖 S01 的接口形状；S04 收口。

## 五、关键设计取舍（写下来避免以后争议）

1. **真值用规则推导，不用告警反推。** 告警有去重、确认、维护闸，且 `ai_failure_risk` 类告警是模型自己触发的，用它会形成自我印证。规则推导是确定性的，可复算。
2. **指标为 null 而不是 0。** 无样本时 `precision=null`，界面显示 `—`。把「算不出来」显示成 0% 会让人误判模型坏了。
3. **promote 只改数据库。** 台账与容器里的模型文件是两个事实，必须由人同时处理。接口与界面文案都已写明这一点。
4. **漂移只写事件。** 本版不做自动训练，`action` 只有 `watch` 与 `triggered` 两种，后者表示「建议人工介入」。
