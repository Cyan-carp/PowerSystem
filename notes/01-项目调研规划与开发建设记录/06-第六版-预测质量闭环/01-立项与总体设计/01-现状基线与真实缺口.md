# 01 · 现状基线与真实缺口

> 本篇全部数据来自 2026-11-01 对生产环境的只读查询，不是估算。生产指针见 [[00-当前系统状态]]。

## 一、模型与推理

| 项 | 实测 |
| --- | --- |
| 算法 | XGBoost 二分类，预测未来 1 小时故障发生风险 |
| 校准 | Platt，slope 0.9678、intercept -1.4432 |
| 阈值 | 0.35 |
| 现役版本 | `stage3-xgb-6ac6e3ee856` |
| 特征 | 由 `prediction/features.py` 的 `FEATURE_NAMES` 固定顺序定义，含温度/电压/功率等窗口统计 |
| 推理 | `POST /predict` 单次推理；模型在容器启动时从 `STAGE3_MODEL_DIR=/model` 读 `metadata.json` 与 `model.json`，**无热更新** |
| 训练 | 离线。读 `data_dir` 的特征 CSV 与 `fault-events.jsonl`，按日期切 train/validation/test |

## 二、预测记录

| 项 | 实测 |
| --- | --- |
| 行数 | **397,685** |
| 设备数 | 151（含已下线） |
| 时间跨度 | 1790600299122 — 1793519606262（约 2026-09-28 至 2026-11-01） |
| 字段 | id、device_id、window_end_ms、probability、threshold、risk_level、model_version、top_factors、source、created_at |

**关键缺口：表里没有任何「实际是否发生故障」的字段。** 也没有独立的结果表。所以准确率、命中率、漏报率都无法计算，连一条都算不出。

## 三、设备与真值来源

| 项 | 实测 |
| --- | --- |
| 在线设备 | 143 台，`is_simulated` **全部为 true** |
| 模拟器故障模式 | 启动参数 `--fault-mode off`；且代码中 `fault_mode` 已标注为 inert |
| `fault_active` | 代码注释明确「always false」，即模拟器**不再产生故障标签** |
| `fault-labels.csv` | 容器 `/data` 下**不存在**（只有 6.9GB 的 `simulator.sqlite`） |
| 现存注入 | `--window-mode on` 生效：每天固定时刻对固定场站注入 10 分钟遥测越线（见下篇口径） |

也就是说：**「故障」在当前环境里只表现为遥测指标越线，没有任何一行记录说「这台设备此刻故障」**。

## 四、现成可复用的规则

模拟器的窗口注入是**确定性**的，后端已有同源实现，这是本版能低成本补真值的前提：

- `stages/01-data-chain/simulator/simulator.py`：`WINDOW_SCENARIOS` 五个场站（9→PV-01、11→PV-02、13→PV-03、15→PV-04、17→ST-01），`WINDOW_MINUTES=10`，`window_device_code` 按日轮换。
- `stages/02-backend/internal/service/simulation.go`：`SimulationDay`、`SimulationDeviceIndex`、`SimulationSchedule` 等函数与上面的 Python 实现一一对应，注释明确「Mirror service.SimulationDeviceIndex」。

**结论：不需要改模拟器，也不需要复制规则，后端直接复用 `service` 包即可精确推导真值。**

## 五、界面现状

`PredictionsView.vue` 只有设备维度：筛选、风险排行、单设备详情抽屉（含概率、阈值、风险等级、模型版本、`top_factors`）。**没有任何模型维度的质量信息**——看不到命中率、看不到校准、看不到版本对比。

## 六、监控现状

现有 10 条告警规则全部基于容器内指标（`up{job="api"}`、磁盘、遥测水位、覆盖率）。与预测质量相关的**一条都没有**。模型退化、漂移或换坏版本，没有任何机制会发现。

## 七、缺口归纳

| # | 缺口 | 本版是否解决 |
| --- | --- | --- |
| 1 | 没有真值，算不出准确率 | 解决（S01） |
| 2 | 没有模型版本台账，换模型无据可查 | 解决（S03） |
| 3 | 界面看不到质量 | 解决（S02） |
| 4 | 模型漂移无感知 | 解决为「观测 + 事件」（S04），不自动训练 |
| 5 | 仿真数据不能证明真实设备预测力 | **不解决**，属数据问题，后续接真实设备再评估 |
