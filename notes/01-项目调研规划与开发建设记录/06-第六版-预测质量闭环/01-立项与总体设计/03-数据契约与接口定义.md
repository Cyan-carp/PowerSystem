# 03 · 数据契约与接口定义

> 字段名是前后端与训练脚本之间的硬契约。改字段必须同时改这三处并在本篇更新。

## 一、表

迁移文件：`stages/02-backend/deploy/postgres/018_prediction_quality.sql` 与 `019_prediction_outcome_label_rule.sql`，已按顺序追加到 `internal/store/store.go` 的 `MigrationPaths`。全部 `IF NOT EXISTS`，重跑安全。

### prediction_outcomes（真值，一条预测一行）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| prediction_id | BIGINT PK | 与 `prediction_records.id` 一对一 |
| device_id / device_code / station_code | BIGINT / TEXT / TEXT | 冗余，避免指标计算回查 |
| window_end_ms | BIGINT | 预测窗口终点 |
| model_version | TEXT | 冗余，支持按版本分组 |
| probability / threshold | DOUBLE | 冗余 |
| predicted_high | BOOLEAN | `probability >= threshold` |
| actual_fault | BOOLEAN | 真值 |
| fault_onset_ms | BIGINT NULL | 实际注入起点 |
| label_source | TEXT | `window_rule`（当前唯一实现）／预留 `manual`、`alarm` |
| label_rule | TEXT | 真值规则版本：`window_1h`（现行 1 小时口径）／`legacy`（2026-11-04 前旧行，禁止进入主指标） |
| label_confidence | TEXT | `confirmed`／`proxy` |
| labeled_at / labeled_by / note | TIMESTAMPTZ / TEXT / TEXT | 标注元数据 |

### prediction_outcome_label_correction_runs / prediction_outcome_label_corrections（修正审计）

- `runs`：每次显式修正一行，记录 `run_id`、操作者、原因、epoch、成熟边界、扫描/更新/翻转计数、`status` 与错误。
- `corrections`：逐条保留 `actual_fault` 与 `fault_onset_ms` 的旧值/新值；唯一键 `(prediction_id, rule_to)`，重跑幂等。
- 修正入口：`stages/02-backend/cmd/prediction-label-fix`，默认 dry-run，`-apply` 必须带 `-actor` 与 `-reason`。

### prediction_quality_daily（按日聚合）

`day`（上海日历日）为主键；`samples/tp/fp/fn/tn`；派生 `precision/recall/f1/accuracy/ece/prob_mean/high_ratio`（全部可空）；`model_version` 取当日出现最多的版本。

### model_registry（版本台账）

`model_version` 唯一；`status ∈ {candidate, active, retired, rejected}`；`threshold`、`calibration`、`metrics`、`baseline_metrics`（JSONB）、`data_source`、`train_samples`、`positive_samples`、`artifact_path`、`trained_at`、`promoted_at`、`promoted_by`、`rejected_reason`。

### prediction_drift_events（漂移事件）

`detected_at`、`level ∈ {L1,L2,L3}`、`signal`、`observed`、`baseline`、`threshold`、`action ∈ {watch, triggered}`、`detail`（JSONB）。

## 二、接口

全部挂在既有 `a` 分组（Bearer 鉴权）。除标注外均为只读。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/predictions/quality/summary` | 汇总：`from`/`to`（`YYYY-MM-DD` 或 RFC3339）、`station_code`、`model_version`；只统计 `label_rule=window_1h` 且已满 1 小时的窗口；未指定版本时收窄到区间内主导版本 |
| GET | `/predictions/quality/series` | `days`（默认 30）、`station_code`、`model_version`；批次线同样只统计 1 小时、已成熟标签 |
| GET | `/predictions/quality/calibration` | `days`（默认 30）；只统计 1 小时、已成熟标签 |
| GET | `/predictions/quality/models` | 版本台账，按 `promoted_at DESC NULLS LAST, created_at DESC` |
| POST | `/predictions/quality/models/import` | **requireAdmin**，登记候选（训练报告提交口） |
| POST | `/predictions/quality/models/:version/promote` | **requireAdmin**，已停用（409）；候选切换改走 `trial` → `confirm` |
| POST | `/predictions/quality/models/:version/trial` | **requireAdmin**，实际加载并核对运行版本后进入试用 |
| POST | `/predictions/quality/models/:version/confirm` | **requireAdmin**，核对运行版本后转正 |
| POST | `/predictions/quality/models/:version/rollback` | **requireAdmin**，核对后回退到上一版 |
| GET | `/predictions/quality/drift` | `limit`（默认 50） |

### 响应字段

- `summary` → `{ samples, tp, fp, fn, tn, precision, recall, f1, accuracy, ece, prob_mean, high_ratio, model_version, batch: { total, hit, rate, avg_lead_minutes, p50_lead_minutes } }`
- `series` → `{ points: [{ day, samples, precision, recall, f1, accuracy, ece, prob_mean, batch_total, batch_hit, batch_rate }], model_version }`
- `calibration` → `{ buckets: [{ lower, upper, count, predicted_mean, actual_rate }], ece }`
- `models` → `{ items: [{ model_version, status, threshold, data_source, train_samples, positive_samples, metrics, baseline_metrics, trained_at, promoted_at, rejected_reason }] }`
- `drift` → `{ items: [{ id, detected_at, level, signal, observed, baseline, threshold, action }] }`
- `import` → `{ model_version, status, updated }`
- `promote` → `{ model_version, status, promoted_at, promoted_by }`

### 空值语义（重要）

分母为 0 的指标一律返回 **`null`**，不是 `0`。前端据此显示 `—`。把「算不出来」显示成 0% 会让人误判模型失效。

## 三、import 接口细则

训练在容器外执行，本接口只登记台账，不读模型文件。

- 默认登记为 `candidate`；`eligible=false` 时记为 `rejected` 并写 `rejection_reason`。
- 同版本重复提交：可更新，但**若该版本已是 `active` 则拒绝**（409），防止覆盖现役指标。
- `status=active` 仅允许在台账里还没有任何 active 版本时直接登记（首次接入现役模型）；否则必须走 promote。
- 真实模型文件不在这里流转，`artifact_path` 只是记录位置。

## 四、promote 细则

事务内 `SELECT ... FOR UPDATE` 锁目标行：校验 `status='candidate'` → 现役改 `retired` → 目标改 `active` 并写 `promoted_at`、`promoted_by`。非 candidate 返回 409。

**不触碰容器与模型文件**，代码注释与界面确认框都写明：真实切换由运维执行。
