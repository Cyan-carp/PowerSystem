## 二、worker 节奏

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `qualityFirstDelay` | 90s | 启动后等待，避开 api 冷启动与首轮预测 |
| `qualityBackfillDays` | 3 | 每轮回看天数 |
| `qualityRefreshDays` | 10 | 日指标重算天数（3 天近期 + 7 天漂移基线） |

每轮：`backfillOutcomes` → `refreshDailyMetrics` → `detectDrift`。

## 三、回填要点

- 只处理 `window_end_ms + 1h <= now` 的记录。
- 选行条件：时间范围内且 `NOT EXISTS` 对应 `prediction_outcomes`，按窗口升序，`LIMIT 20000`。
- 真值判定复用 `service` 包的 `SimulationDay` / `SimulationDeviceIndex` / `SimulationSchedule`，规则见 [[01-项目调研规划与开发建设记录/06-第六版-预测质量闭环/01-立项与总体设计/04-真值口径与计算规则|真值口径]]。
- 幂等：`ON CONFLICT (prediction_id) DO NOTHING`。

## 四、指标计算

按上海日历日聚合 `prediction_outcomes`，算 `tp/fp/fn/tn` 与 `precision/recall/f1/accuracy`，另算 `prob_mean`、`high_ratio`、`ece`。

ECE 分 10 桶：每桶算 `|预测均值 - 实际正例率| × 该桶样本占比`，求和。空桶跳过。

`model_version` 取当日出现次数最多的版本，便于按日追踪是否换过模型。

## 五、验收

见 [[01-项目调研规划与开发建设记录/06-第六版-预测质量闭环/01-立项与总体设计/06-阶段路线与验收矩阵|验收矩阵]] 第 1–8 项。最小检查：

```sql
-- 有回填且不提前标
SELECT count(*), min(window_end_ms + 3600000) FROM prediction_outcomes;   -- 最小值应 <= now
-- 日指标自恰
SELECT day, samples, tp+fp+fn+tn FROM prediction_quality_daily ORDER BY day DESC LIMIT 5;
```
