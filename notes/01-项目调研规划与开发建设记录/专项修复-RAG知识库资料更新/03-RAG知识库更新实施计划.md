## 一、目标与分工

**Workbuddy 负责实施与自检**：现查生产、整理来源、修复清单、冻结资料、构建候选集合、更新当前生产知识别名、回写文档并交付证据。所有者以本页委派实施时，按此完整范围推进；若转交时收窄范围，以转交指令为准。

**Codex 负责交付后的集中校对**：核对来源取舍、实际改动、集合完整性、历史引用和回执一致性；只对证据缺口补做定向核查。此轮采用所有者指定的先实施后交付方式，不另开并行任务，不持续监视 Workbuddy。

本次属于知识数据更新，不新增智能体能力，不调整问答策略、Embedding 模型、向量维度、分片参数、审批权限或业务数据库。默认不改应用镜像、不重启应用、不改公网端口，不提交或推送。遵守既有生产规则，不把本计划增补为长期工程规范。

### 4.4 混合历史正文的处理

不能把整份 README 或手册视为全部现行。现有提取器会去掉 YAML 元数据，长文分片也可能不包含页首说明，仅添加页首“历史”提醒不足以约束所有片段。

优先采用既有导入器可读取的、按本批冻结的资料快照：

1. 逐份列出保留与排除的章节。明确历史部署命令、旧模型/权限/主机说明、未生效候选与临时测试操作不进入现行操作知识。
2. 完整适用的来源按原文复制；混合来源只摘录现行相关章节，保留必要的条件、限制与日期，不凭印象改写事实。
3. 为摘录记录原文件路径、原文件规范化摘要、章节标题、实际入库快照摘要和摘录原因。`source_hash` 必须对应实际入库文本，不能用原文全文摘要冒充摘录摘要。
4. 每个状态快照片段应可辨认资料时点；依靠同页首段无法传递时，在冻结资料中为相关章节补充简短的适用时点。不得把本轮计划、交付报告反向加入知识源，形成自引用。
5. 不修改正式文档来迁就检索，不开发通用文档平台。确有必要修改导入器时，先说明具体缺口，做最小兼容修复，保持已有引用身份与集合版本约束。

不扫描全仓库；共享记忆、AGENTS.md、私有配置、用户附件、会话、原始日志、备份和审计记录不纳入本轮受控知识源。联网搜索结果不自动入库。

## 五、实施步骤

### 步骤一：现场确认并记录基线

- 保存开工 Git 状态，区分既有改动与本批改动；同文件有并发修改时先协调编辑归属。
- 沿既有严格主机指纹连接链确认实际 VM、主机身份、应用 active/pending、RAG 实例与镜像。只读取必要配置项，不打印 env、令牌或凭据正文。
- 从当前 RAG 实例读取真实 `RAG_COLLECTION`，解析对应物理集合；全量读取必要来源元数据并核对精确计数，保存 `before.json`。

- 现查本批服务器目录、可用空间、现有导入材料/模型挂载及权限，在当月上传定位卡登记；不沿用 10 月批次路径，不覆盖仍在使用的只读挂载源。

### 步骤二：整理来源并冻结资料

- 完成上述 18 来源的取舍表、历史退出表及章节筛选。
- 修复仓库 `stages/08-agent-rag/knowledge/sources.json` 的失效路径与旧摘要；仓库清单用于登记原始受控来源，若生产使用摘录，另生成本批导入清单并记录两者映射，不能让一个 sha256 同时代表两种正文。
- 文本按 UTF-8/LF 规范化，使用既有 `document_sha256` 算法重算摘要；保留旧 title 和设备适用性元数据。
- 冻结本批入库快照、导入清单与来源映射。冻结完成后不再原位修改其中任何字节。
- 先做文件存在性、正文提取、摘要一致性检查。字符回退只用于预检；正式片段数与版本必须使用生产同款本地 E5 模型和实际分片器计算，不把字符回退结果当权威结果。

### 步骤三：构建独立候选集合

- 优先复用现役 RAG 镜像及既有模型，以独立导入进程执行。现有实例挂载只覆盖部分旧资料路径，不能把“仓库文件存在”当作“容器能读取”。
- 本批使用独立冻结目录，显式指定资料根目录、导入清单和可写报告路径，核对容器 UID/读权限；不为临时读取全部新资料而先改生产服务 Compose 或重启服务。
- `scripts/knowledge.py` 实际导入会自动切换它配置的别名，因此候选导入必须显式设置一个本批独立候选别名。此时服务实际使用的生产别名及其他既有别名必须保持原映射。
- 不直接套用 `import-knowledge.ps1` 的旧私有配置，也不直接运行任何默认指向生产别名的导入命令。命令按实际参数与现行 README 整理，不臆造 `--no-switch` 等参数。
- 生成新物理集合，保留导入报告中的版本、逐文档摘要、片段数、跳过项、真实 Embedding 和分片方式。失败报告独立保留，不复用旧成功报告。

### 步骤四：核对候选并晋升生产知识别名

以下是知识数据完整性核对，使用既有只读审查器和导入器，不扩展为全平台发布门禁或业务回归：

- 候选报告、完整扫描与精确计数一致；启用资料齐全，退出的两份历史资料不再出现在候选集合，全部来源 hash/version 与冻结包相符，无混合版本或未登记资料。
- 用真实分片器执行 `audit-v4-knowledge.py`，显式传入本批导入清单、冻结资料根目录、候选别名、真实模型和实际 Qdrant 地址。严格模式 blockers 为 0；不能以 `--skip-qdrant` 的结果代偿集合核对。
- 核对关键更新章节确实进入片段：账号/附件、数据链路/现场记录/预测反馈、home-dev 与生产分界、现行权限和仿真设备边界。以片段内容与来源映射核查为主，不要求消耗回答模型额度。
- 切换前再次读取服务别名，必须仍为开工旧映射；有并发更新则停止覆盖，重新对齐。记录切换时点，使用 Qdrant 已有的原子别名机制只替换实际生产别名。
- 切换后重新解析服务当前配置的别名、全量来源清单与精确计数，保存 `after.json`；核对服务镜像和应用 active 没有被知识操作意外改变。
- 应用 active 代表应用发布，纯知识别名切换不虚构新应用镜像或改写为应用发布成功。知识更新回执单独绑定当时实际 active、镜像、旧/新集合和本批来源。

按现行规则，不为本次知识更新另建全备，不跑整站门禁、发布前后业务测试或长时间观察；如实登记未执行项。用户界面、回答模型质量及真实设备专业审核不在上述来源完整性结论内。

### 步骤五：历史引用与回退准备

- 保留旧集合 `powersystem_rag_79cfcba74b20_a11898f9` 及其他已有历史集合，不做按年龄清理。历史带 collection/version 的引用仍须能在原集合读取原片段。

### 步骤六：回写与收尾

- 同批更新 [[06-当前系统状态/03-运行能力现状]] 中的知识来源口径；如仍有知识缺口，在 [[06-当前系统状态/04-已知限制与未生效改动]] 明确记录。入口摘要只改实际受影响项，应用发布指针不因知识更新而改变。

Codex 收到交付后集中核对以下事项；有既有明确证据的部分不重跑：

1. **来源正确**：18 个候选来源的最终取舍可解释，失效路径已修复；两份历史分卷退出当前集合，混合正文筛选可复核；仿真参考未被升级为真实厂商资料。
2. **内容与版本一致**：冻结原文/摘录映射、清单摘要、导入报告、全量扫描及实际生产别名对应，无缺项、额外资料、混合 hash/version 或伪造分片计数。
3. **实际生效**：交付显示现役 RAG 服务读取的实际别名已指向新集合；应用镜像与 active 的变化均有解释。需要补查时只读现查真实别名和来源元数据。
4. **引用与回退保留**：至少一条旧引用仍可定位原集合/版本，旧集合未删，回退步骤绑定真实映射。
5. **交付真实**：正式记录、状态回写、上传定位、产物登记和对话记忆一致，未执行项如实记录，未混入其他会话改动或秘密。

缺少实际生效、摘要/计数不一致、历史正文冒充现行、旧引用破坏及敏感材料入库，列为阻塞缺陷；额外资料扩充、长期增量自动化及界面管理列为可排期建议，不用建议阻塞已完成的更新。
