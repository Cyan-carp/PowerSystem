# 03 · 高优先级修复与本地验证

2026-10-19 对 FR-10～12 校对发现的三个 P1 问题完成本地修复与自动化验证。本记录不表示已发布生产，也不替代 FR/BND 六项独立验收；原校对报告和失败复现输出保留不改。

## 一、修复结果

| 问题 | 修复后的行为 | 源码 |
|---|---|---|
| F01：TDengine 时间格式不兼容 | 可用率的边界样本、窗口内样本和 CSV 共用既有 `parseTDTime`，支持 RFC3339 带时区字符串及毫秒值；CSV 时间戳列统一输出毫秒整数，北京时间从该值生成 | `internal/api/report.go`、`internal/api/telemetry_export.go` |
| F02：刚收到的旧采样仍获高分 | 先验证必需字段、状态和时间合法性；合法旧接收仍判离线 0 分，接收新鲜但采样超过 15 秒则评分未知；缺字段、零时间和未来接收均不评分 | `internal/api/health.go` |
| F03：确认统计越过报表截止时间 | 只有 `acked_at <= end` 才进入确认耗时；晚于 end 或从未确认均列入确认未完成，即使已自动恢复也不从确认队列消失 | `internal/api/report.go` |

以上源码位于 `stages/02-backend/`。健康评分保留既有最多 60 秒采样时钟偏差容差，同时检查采样不能比接收时间超前超过该容差。接收新鲜度与采样新鲜度的 15 秒边界均包含恰好 15 秒的情况。

报表遇到不能解析的时间、缺失状态或不完整行时返回读取失败，不把解析错误静默变成遥测缺测；导出遇到无效时间返回 HTTP 503，不提供带缺失时间列的“成功”文件。没有数据的合法查询仍沿用既有空结果行为。

告警事件队列仍按 `[start,end)` 的触发时间选择，确认和恢复的生命周期状态按截至 end 计算；本次没有改动恢复原因分类和队列筛选口径。

## 二、回归与证据

- 新增 `internal/api/health_test.go`：固定时钟验证旧采样、离线、缺字段、未来时间、15 秒边界、60 秒时钟容差及正常告警等级评分。
- 新增 `internal/api/report_regression_test.go`：验证 RFC3339/带时区/毫秒格式、边界样本、异常行拒绝、CSV 两个时间列、确认截止时间及未确认已恢复事件的队列完整性。
- 五个新增顶层测试包含 40 个命名子场景，均通过。
- 原校对的三个 P1 对应五个顶层复现测试重新执行，均通过；新增设备窗口、导出硬上限等 P2 复现未纳入本次修复范围。
- 后端 `go test ./... -json`：37 个顶层测试通过，0 失败，3 个需专用服务的集成测试跳过。
- `git diff --check` 通过。

跳过项：`TestRedisChatAdmissionIntegration`、`TestStatisticsPostgresBoundariesAndGroups`、`TestMAC19BusinessContinuesWithOperationUnavailable`。这些测试没有本轮明确配置的专用 PostgreSQL/Redis 环境；本地通过不能写成真实服务集成通过。

新增报表测试用本机临时 HTTP 服务模拟 TDengine REST，并以纯内存 SQLite 执行处理器查询；不访问生产服务。该测试验证 Go 解析、分类与响应行为，不代替真实 TDengine/PostgreSQL 的兼容性和业务验收。

初次全包验证遇到系统 Go 缓存目录访问拒绝，改用项目内独立 `GOCACHE` 后全包通过。验证产物新增于 `artifacts/问答与运维复核-20261019/p1-fix-local/`，旧失败批次保持不变。

在仓库根重放本地验证：

```powershell
$p1FixCache = Join-Path $PWD 'artifacts/问答与运维复核-20261019/p1-fix-local/go-cache'
$env:GOCACHE = $p1FixCache
go -C stages/02-backend test ./...
```
