# 报表快照与首页预加载 · 设计草案（2026-11-24）

> **本文的实施方案已被 [[17-报表快照交接精简设计与验收（2026-11-24）]] 取代。** 第一、二节的业务规范与代码核查仍然有效，第三、四节的实现路径（`seed` 兜底、60 秒一次性定时器、`loadedKeys` 条件映射、`windowPinned` 推进窗口）已按评审删除，改为更窄的单槽交接。两版都未实施。

> **本文只提交设计与最小改动草案，未实施。** 当前 `stages/` 与 HEAD 零差异，生产仍是第二代小时汇总（2.5 秒），第三代补丁未恢复。
> 草案文件在 `artifacts/report-loading-20261123/design-20261124/`，用 `git apply` 可整体应用或整体撤回。

## 一、业务规范变更（本方案的前提）

**旧规范**：统计报表是实时视图，展示中的数据必须满足 60 秒新鲜度。
**新规范（2026-11-24 所有者确认）**：

1. 每次**实际查询**时保证数据新鲜度（后端按 `aggregation_lag_ms` 决定读小时汇总，还是退回原始计算）；
2. 查询结果整体作为一份**统计快照**展示；
3. 明确显示统计区间与报表生成时间；
4. 快照超过 60 秒**照常展示、照常导出**，只提示可手动刷新；
5. 不做周期性自动刷新；
6. 改查询条件或主动刷新才重新计算；
7. CSV 导出等于屏幕上这一份快照。

这条变更的价值不在"换个实现"，而在**消灭了需求本身**：上一版前端缓存有 7 个状态维度，其中"全局代数 / 会话代次 / 60 秒新鲜度判定 / 超龄隐藏"四项只服务于"展示期必须新鲜"。规范一改，它们全部不存在，也就没有 R2、R3 的土壤。

## 二、代码核查：决定设计的五个事实

| # | 事实 | 位置 | 对设计的影响 |
| --- | --- | --- | --- |
| 1 | **首页已经在算这份报表**：场站总览挂载时调用 `api.availability({})`，就是"最近 7 天 + 全部设备"的可用率报表，用来画数据质量卡 | `OverviewView.vue:52` | 预加载**不需要新增任何查询**，只需把已经付过成本的结果留下。新增数据库负载 = 0，而不是"每会话一次" |

## 三、最小实现路径

```
场站总览 mount ─→ api.availability({}) ─→ putSnapshot(报告)
                                              │ 单槽，按 token+id+role 归属
统计报表 mount ─→ takeSnapshot() ─命中──→ 直接渲染（0 请求）
                              └─未命中─→ 照旧 api.availability()
```

四处改动，后端 0 行：

1. **新增 `lib/report-snapshot.ts`（45 行）**：模块级单槽，只存一份默认窗口报表。无 LRU、无过期清理、无在飞合并、不落 localStorage。
2. **`OverviewView.vue` +8/−1**：拿到结果顺手写进槽里。首页自身行为不变（仍是它自己的 `quality` 请求、仍显示"统计更新于"）。
3. **`ReportsView.vue` +163/−66（净 +97）**：
   - `seed` + `availability = computed(请求结果 ?? seed)`——快照不进 `useLatestRequest`，公共 hook 一行不改；
   - 快照信息条：统计区间 / 报表生成时间（精确到秒）/ 超龄提示；
   - 60 秒：进入时算一次剩余时间，一个 `setTimeout`，不轮询；
   - 页签：`loadedKeys` 记住每组条件对应哪次结果，切回来不重算；
   - 导出：改用 `lib/report-csv.ts` 从当前快照拼 CSV，0 次查询。
4. **新增 `lib/report-csv.ts`（159 行）+ 单测（115 行 / 4 例）**：列序、BOM、`\n` 结尾、Go 引号规则、公式注入前缀、浮点最短表示，逐条对齐 `report_export.go`。

## 五、关键取舍：与老师方案的 4 处偏离

**1. 预加载不新增请求，复用的是首页那一次。**
老师写的是"每个符合权限的登录会话至多一次默认报表查询"。核查后发现首页本来就要算一遍（事实 1），所以边际成本是 **0 次**，不是 1 次。副作用也要说清：首页每次挂载都会重算（既有行为，本方案不改），因此严格意义的"每会话只预加载一次"并未实现；若要实现，得让首页也改成消费快照，那是更大的改动（且首页会出现"数据不是此刻"的观感），不建议在本批做。

**2. "预加载还未完成时等待已有请求"——没做。**
这条与"不引入在飞合并"直接冲突。默认不做的代价是：用户在场站总览挂载后 2.5 秒内点进统计报表，会并发两条 143 台查询，各自约 2.5 秒。后端有 3 路并发上限兜底，不会打挂；而"共享同一个 Promise"正是上一版 R1 的土壤。若评审认为必须严格单飞，可以加 12 行 `inFlight` 字段，但需要同时定义"共享 Promise 的失效规则"——这正是复杂度回升的入口。

**3. 刷新会推进默认窗口。**
"最近 7 天"是相对窗口，若刷新只按旧快照的绝对区间重算，报表会永久停在第一次查询那天。规则：**没手动改过起止 → 刷新把窗口推到此刻；改过起止 → 只按输入框的字面值重算**，用一个 `windowPinned` 布尔区分（6 行）。这是原方案没覆盖的语义，需要确认。

**4. 导出改成前端生成，服务端导出接口保留但界面不再调用。**
好处是"所见即所得"且 0 查询；代价是失去三个响应头（`X-Rule-Version`、`X-Computed-At`、`X-Data-Complete`）——CSV 正文里的"规则版本 / 开始 / 结束 / 计算时间 / 归组依据"五列全部保留，且"计算时间"就是页面上那个 `computed_at`，两份文件可以逐字节对照。若审计明确要求"文件必须由服务端生成"，那就只能回到后端导出（+2.5 秒，且可能与页面不一致），二者不可兼得。

## 六、权限与安全

- `/reports/*` 只校验登录，预加载不改变任何角色的可见范围；
- 快照只在内存：不写 localStorage / sessionStorage，刷新页面即失效，不会把上一个账号的数据留在磁盘；
- 归属指纹 = `token | 用户 id | 角色`，写入与读取全等才命中：登出、401、换人登录、改密码后重新登录，都会自动失配，无需在 `auth.ts` 里加回调；
- 前端导出不扩大数据可见范围（用户本来就能看到全部 143 台），但**审计口径变了**：文件不再经过服务端，没有响应头可验。这是第 5 节第 4 条的代价。

## 七、边界条件

| # | 场景 | 行为 |
| --- | --- | --- |
| 1 | 深链直接进 `/reports`，无快照 | 照旧发请求，无提示条中的"历史快照"字样 |
| 2 | 场站总览请求失败 | 槽为空，报表照旧请求，不报错叠加 |
| 3 | 2.5 秒内从首页点进报表 | 两条并发的 143 台查询；见第 5 节第 2 条 |
| 4 | 快照已 10 分钟 | 照常展示，进入即显示"当前展示历史统计快照，如需最新数据请手动刷新" |
| 5 | 页面停留超 60 秒 | 一次性定时器到点显示提示；之后不再重复，无轮询 |
| 6 | 快照的窗口 vs "最近 7 天" | 输入框填快照的绝对起止，标签显示同一区间 |
| 7 | 改条件后切页签 | `load('query')` 同时作废两个页签的结果，不会闪出旧数据 |
| 8 | 同一条件来回切页签 | 命中 `loadedKeys`，不重算、不发请求 |
| 9 | 请求失败 | 清除该页签的 key，下次切入会重试 |
| 10 | 页面内 401 | `notifyUnauthorized` → `clearSession` → token 变空 → 快照失配，不会带到下一个账号 |
| 11 | 导出时无数据 | 按钮禁用，函数内再判一次空 |
| 12 | CSV 字段含逗号/引号/换行 | 按 Go `encoding/csv` 规则加引号、内部引号翻倍 |
| 13 | CSV 字段以 `=` `+` `-` `@` 开头 | 前置单引号，与后端 `csvCell` 一致，防公式注入 |
| 14 | 比率极小（< 1e-6） | 定点兜底，避免 JS 输出 `1e-9` 与 Go 的 `0.000000001` 不一致 |
| 15 | 时区 | 输入框按 +08:00 解释（`toLocalInput` / `parseInput` 既有逻辑），后端一律 UTC |

## 九、未做与明确不做

- 不恢复第三代补丁，不碰 `availability_rollup.go`、`availabilitySums`、降级链；
- 不改并发度（15 号实测结论：单人快、多人不快，且挤压 Worker 余量）；
- 不做服务端分页（指标卡与场站表必须全量累加）；
- 不做 LRU、不做多键缓存、不做在飞合并、不做后台轮询、不做定时预加载；
- 不改 `useLatestRequest`（公共 hook 被 20 多个视图使用）；
- 不顺手重构报表页其它部分（`.table-note` 缺样式只记录不修）。

## 十、需要拍板的三点
