# 10 · 报表加载提速实施计划

> 本页是交给 Workbuddy 的本轮实施任务书：优化可用率首次查询以及两个报表页签的重复查看，完成本地实施、自检与交付后，由 Codex 集中复核。当前系统状态见 [[00-当前系统状态]]。本页的“目标”不代表性能已经达标，也不构成已部署结论。

## 一、目标、分工与交付边界

### 1. 已确认的用户意图

- 首次进入、换日期/场站/设备查询，以及切换页签、离开再返回，都需要提速。
- 保持现有一分钟内的统计更新约束，不采用三至五分钟结果缓存，也不默认先展示过期结果。
- 本轮按用户最新安排顺序交接：Codex 提供任务书；用户交 Workbuddy 实施；Workbuddy 完成交付；Codex 再复核。该安排不要求 Codex 同时实施另一条代码线，不更改长期协作规范。
- Workbuddy 的交付止于待 Codex 复核的代码、证据和文档。本轮不自行上传生产、换镜像、发布、推送 Git 或修改生产数据；此边界来自本次“实施后交付给 Codex”的任务范围，不撤销既有后续发布授权。

### 2. 目标与验收层级

| 项目 | 本轮目标 |
| --- | --- |
| 可用率首次查询 | 汇总就绪、143 台、7 天非整点窗口，接口完成时间小于 2 秒 |
| 缓存命中查看 | 切换页签/返回页面，200 毫秒内显示对应完整结果 |

| 兼容性 | 既有路由、字段、设备范围和统计规则不变 |

性能目标是本轮设计默认值，并非新生产承诺。执行分层交付：代码正确性、开发环境性能、实际143台环境性能分别给结论。环境缺失可以交接未验证项，但不得把缺证据或未达标写为完成验收。

### 3. 不扩大的范围

不新增服务、依赖库、分钟级汇总表、数据库迁移、全站缓存或后台预热平台；不改变告警及时性后端算法、权限、能源数据、采集链路、原始遥测与汇总写入/CAS协议；不为追求2秒把默认7天改成1天、非整点改成整点，或减少设备数。

## 四、工作包B：减少首尾扫描请求

### 1. 保留独立正确性对照

保留原始 loadAvailability/scanAvailability 与 computeAvailability 对照路径。新增内部专用补算入口，不全局替换TD客户端通用方法；小时后台重建仍走既有实现。这样新路径可以与未改变的原算法交叉对照。

### 2. 新补算入口的精确语义

对于输出区间 [lo, hi)：

1. 空区间直接跳过，不发TD查询。
2. 从 lo - 15,000 毫秒开始读取有序状态点，右边界仍为 hi 的开区间；游标初始化应保证恰好位于 lo - 15,000 的样本可被读取，并遵守底层正时间参数限制。
3. 复用 StatusAfter 的键集分页及5000条上限，保留跨页前一个样本、时间单调检查、状态合法性检查、上下文取消和TD响应错误处理。
4. 折算器的输出起点仍是 lo，前15秒仅提供边界上下文，不得计入 WindowMs 或重复累计。
5. 扫描更早于 lo - 15,000 的数据没有覆盖贡献，因此省掉单独 BoundarySample。15秒恰好边界、无样本及缺口必须用测试证明。
6. 在本次报表每台确需补算的设备执行一次 EnsureDevice，之后所有补算区间复用；纯完整小时命中时不确认TD表。采用请求内状态，不使用跨请求永久“已建表”缓存。

正常非整点窗口且每个边界区间不到一页时，原路径约为每设备两次“确认表+边界+扫描”共6次TD请求；新路径目标为一次确认加两次扫描共3次。该数字是特定输入下的请求数断言，分页增加时按实际计数，不保证所有数据均为3次。

### 3. 错误与并发

沿用最多3个设备工作者；不增加每设备内部并行区间任务。任一TD读取失败取消同批其余工作，不能返回半份成功或导出残缺CSV。不把缺表、超时、坏状态值当作无数据；EnsureDevice失败直接沿用错误路径。

## 五、工作包C：局部脏桶与缺桶补算

### 1. 在单次数据库读取中生成计划

保持完整小时范围计算：lo取查询开始与设备创建时间的较晚值，hi取查询结束；完整小时为 [ceilHour(lo), floorHour(hi))。

一次SQL/同一语句快照同时返回有效小时汇总与需要补算的小时列表，避免先读总和、再读脏桶而出现不同快照。可用选中设备范围与 generate_series 生成预期小时，LEFT JOIN 现有小时表：

- computed_at非空、generation等于computed_generation、规则版本匹配且时长字段有效的小时，进入有效汇总。
- 缺失、未计算、脏桶、错误版本或时长字段不完整的小时，不进入有效汇总，记录为补算区间。
- 校验 CoveredMs等于RunningMs+StoppedMs+FaultMs，UnknownMs等于小时长度减CoveredMs。不能将异常字段coalesce为“已计算的0”。
- 返回结果必须能核对全部选中设备及预期小时覆盖；结构不完整或SQL失败按既有整请求降级原始路径处理。

### 2. 构造互不重叠的补算区间

每台设备把“开始零头、需补算的完整小时、结束零头”放在同一列表，按时间排序并合并相邻/重叠区间。

- 没有完整小时的短窗口，只补算整个 [lo, hi)，不能把首尾各算一次。
- 全部小时不可用时，合并成一个完整窗口原始扫描；多个离散脏小时只扫描对应区间。
- 每个合并区间按工作包B读取前15秒上下文，但仅累计区间自身时长。
- 有效小时总和加补算结果后，只在最终设备结果上计算一次比率、空值和insufficient_data；场站继续按时长相加再计算比率。
- 不按百分比平均，不修改设备排序、设备创建时间裁切、当前台账归属或15秒规则。

### 3. 汇总状态与降级保持兼容

- 未安装/关闭/心跳过期仍使用既有 raw、warming、degraded 路径与语义。
- 单纯首尾补算不构成warming；存在预期完整小时缺失或脏桶时标warming。
- 统计更新时间、延迟及响应头沿用现有字段。响应完成前继续检查60秒阈值，不能把已超期的汇总标ready。
- 本轮只改变查询规划，不修改 dirtyAvailability、确认CTE、后台周期、generation CAS或数据写入；迟到与重算并发测试必须继续通过。
- SQL层读失败可降级；已经进入TD补算后的失败整份报错，不用二次大扫描掩盖错误。

## 六、工作包D：前端会话缓存与请求管理

### 1. 模块边界与数据结构

新增报表专用轻量模块 stages/04-frontend/src/lib/report-cache.ts，管理成功结果、会话代次和正在进行的请求。不要改变全站 useLatestRequest.cancel() 的默认语义，避免总览等页面受影响。

每份完成记录至少包含：规范化查询键、会话代次、页签、不可变查询参数、响应、规则版本、请求起点/接收时刻、新鲜度上界。两个页签各自保存最后一次成功查询描述；表单草稿与已提交参数分开。

规范化键包含：会话代次、报表类型、UTC ISO精确开始/结束、空字符串归一化后的场站、数字设备ID。不能把场站省略与全平台范围改成别的scope；不向接口添加当前不支持的scope参数。结果记录保存rule_version并核对本模块支持的版本，规则版本不匹配不缓存。JSON结果缓存不混入CSV响应。

缓存采用最多20份成功结果的LRU，淘汰只作用于完成记录；失败、不完整响应不入缓存。仅内存保存，不写localStorage/IndexedDB。api.ts可补齐服务端已存在的complete可选类型字段，不改变服务端契约；缓存要求complete明确为true。

### 2. 新鲜度算法

全部复用同时满足：自请求开始经过时间小于30秒；响应完整；会话与查询键一致。

可用率仅缓存ready、statistics_updated_at可解析、aggregation_lag_ms为有限非负数的响应。保守年龄计算为：

    统计年龄上界 = 响应aggregation_lag_ms + 自该请求开始至当前经过的时间
    可用率缓存有效 = 统计年龄上界 <= 60,000毫秒 且 请求年龄 < 30,000毫秒

这里额外计入整个请求耗时是有意保守，避免把返回途中的耗时漏掉。不要直接用浏览器当前时间减服务器时间戳计算年龄，避免机器时钟偏差。

经过时间以performance.now为主，并结合本地Date.now正向经过时间取较大值，防止休眠后单调计时停顿使缓存复活；本地时钟回拨时直接使该条缓存失效。任何元数据异常均不复用，仍允许显示本次刚取得的实际响应及其真实状态。

告警及时性没有aggregation_lag_ms，只按请求起点最多30秒复用。computed_at保留原值，命中时不伪造新的统计时间。

### 3. 查询、刷新与页签行为

- 初次进入无已保存条件时，仍按北京时间输入生成近7天窗口，只查询激活页签；场站/设备列表继续独立加载。
- 输入条件变化先作为草稿；点击“查询”或切换页签时沿用当前已有行为提交并校验草稿。校验失败显示错误，不发请求，不把上次结果贴到无效新窗口。
- 相同键重复点击“查询”，复用当前进行中的Promise；有有效完成缓存则直接显示。
- 不同键查询取消被替代请求，使用请求代次保证旧响应即使晚到也不能显示或写回有效缓存。
- 切换页签取消离开的未完成请求，但保留该页签已成功且仍有效的缓存；新页签独立查询或命中，不等待旧页签完成。
- “刷新”校验当前表单并强制发请求，绕过完成缓存及旧同键请求；旧同键请求取消，强制刷新结果为权威。
- 离开页面取消未完成请求并移除页面定时器，只保留成功缓存与会话内查询条件。返回时恢复上次已提交条件；已有合法URL tab优先，否则恢复上次页签。返回恢复不重新生成now窗口。
- 未提交草稿不跨页面保存。新登录会话重置默认近7天；用户需要更新窗口结束时间时仍通过现有时间输入操作，本轮不新增自动滚动窗口语义。

### 4. 显示、过期与导出一致性

窗口标题、规则版本、统计时间、图表/表格、本地CSV兜底都从同一个成功记录读取。请求中的新条件不得与旧结果混排；加载时展示既有加载提示。

缓存30秒到期只是“不可再次命中”，不要求正在阅读的报告每30秒自动刷新。可用率可见结果达到保守60秒年龄上限时，隐藏数值、禁用导出并提示刷新；本轮不增加持续轮询。告警及时性结果显示生成时间，按请求起点60秒执行同样显示过期处理。过期检查在一次性定时器、页面重新可见、切换/返回、用户交互与导出前执行；移除页面时清理监听与计时器。

导出仅在当前成功记录有效且没有替代查询时可用，绑定该记录参数；开始导出时冻结记录和参数，失败后的本地兜底也使用冻结记录，不使用正在变化的页面computed。后端CSV仍按相同查询重新计算，因此迟到数据存在时不承诺和较早JSON完全同快照；静态夹具上的JSON/CSV必须等价。

### 5. 登录会话与失效

模块单例订阅auth.ts公开的authToken、currentUser身份/角色变化；同步清空缓存、保存条件，取消所有未完成请求并递增会话代次。401沿用现有clearSession入口。缓存键、日志、证据中不放真实token，旧会话响应不得写入新会话。

不要从业务模块直接读localStorage；不要为此重构鉴权或引入API/auth循环依赖。只在模块内部保留必要的会话失效订阅，测试必须有明确reset/dispose入口。

| B06 | 全有效、全不可用、错误版本/异常时长 | 有效桶不扫TD，其余正确降级 |
| B07 | 迟到、重算中generation变化、心跳过期 | 原CAS语义及新鲜度不弱化 |
| B08 | TD错误、非法状态/时间、取消 | 取消同批工作且无部分成功 |
| B09 | JSON/CSV、设备/场站汇总 | 业务字段逐项等价，顺序稳定 |
| B10 | 正常双边界小于一页的夹具 | 每台最多一次EnsureDevice及两次扫描，无BoundarySample |

小时SQL需真实PostgreSQL集成覆盖，不能全部以SQL字符串mock代替。原始路径和新路径在同一冻结夹具对比；比较时排除computed_at等本就不同的生成元数据，但逐项单独验证其合法性与状态。保持设备并发不超过3，不通过放宽错误断言让测试“通过”。

### 前端行为

| 编号 | 场景 | 必须证明 |
| --- | --- | --- |
| F01 | 首次进入、选项加载失败 | 只请求激活页签且结果独立展示 |
| F02 | 两页签往返、卸载再进入 | 有效缓存命中，查询条件不漂移 |
| F03 | 不同日期/场站/设备 | 键隔离，不展示别的查询结果 |
| F04 | 同键重复查询、手动刷新 | 前者合并请求，后者真正重发 |
| F05 | 慢请求切换、不同条件替换、离开后晚返回 | 取消/代次生效，旧结果不回写 |
| F06 | 缓存年龄29.999/30秒、统计年龄60秒边界 | 超期即不复用，未叠加一分钟 |
| F07 | metadata缺失/非法、warming/degraded、不完整结果 | 不缓存且不伪造正常ready |
| F08 | 休眠、重新可见、本机时钟回拨 | 超期不复活，显示过期处理正确 |
| F09 | 退出、切账号、角色变化、401 | 缓存和在途请求均隔离 |
| F10 | CSV过程中改条件、CSV失败 | 参数与本地兜底始终绑定导出快照 |

复用现有Vue测试渲染器，补充可控时间与延迟Promise。旧“同键再次查询会取消”用例需按新约定拆成“同键合并”“不同键替换”“刷新强制替换”，保留旧响应隔离覆盖；不直接删除测试消除失败。

### 构建与定向运行

在阶段四运行 npm run typecheck、npm run build，并执行受影响的loading与新增报表缓存测试；改动共享模块时扩展其现有相关回归。

在阶段二运行受影响api/tdengine包的报表定向Go测试与构建；精确列出运行命令、环境变量名（不含秘密值）、通过/失败/跳过数量。PostgreSQL集成测试因未配置而skip，不能记成通过。不要不经检查直接运行会重置依赖或停止Broker的旧全量脚本。

提供本人手动界面检查步骤：首次进入、切两个页签、改条件、返回、刷新、等待过期、导出。自动模板测试不能代替真实浏览器200毫秒实测；没有浏览器计时证据时明确待本人反馈。

## 八、性能判断、风险与停止条件

- 在等价143台、7天非整点、ready环境中，第一次请求与随后5次顺序请求均需小于2秒，才能给出该环境的“达到目标”；5次中位数、最大值仍全部报告。
- 缓存命中计时从点击/路由激活到对应结果实际渲染完成，至少5次；不能只量Map读取或Promise返回。浏览器运行环境、CPU/网络条件随证据登记。
- 冷结果查询、缓存命中、CSV、并发、warming/degraded分别报告，不能合并成一个“平均提速”。
- 3个不同键并发短测要求无错误/取消串扰；比较TD请求数量、API耗时和已有遥测积压指标。若采集积压持续增加或负载明显恶化，停止压力短测，保留证据，不提高并发补救。
- 目标未达时先按实际分段耗时定位；本轮允许优化既定范围内的SQL、区间合并和请求数量。不得直接新增分钟表、改变统计规则或扩大生产操作。
- 数据不等价、跨账号命中、错误结果当成功、过期数据标新鲜、导出混条件，均为阻塞缺陷，必须修复后交付。
- 环境不足或性能未达必须列为未完成验收/性能待办，不能以“正确性通过”宣称整个提速目标完成。额外外观优化、跨页面通用缓存属于可排期建议，不阻塞本轮代码交接。

## 十、Workbuddy交付模板与Codex复核

### 必须交付的材料

- **结果摘要**：分别说明后端提速、前端复用、正确性、新鲜度及性能目标的结果。
- **代码来源**：实施起止HEAD、实际修改文件、已有差异排除说明；未提交则写未提交，不能用HEAD冒称包含未提交代码。
- **设计偏差**：逐项对照B/C/D，说明未做、替代或新增内容及原因。
- **测试清单**：实际命令、环境、通过/失败/跳过数、证据相对路径；明确真实PG集成与真实浏览器验证是否执行。
- **性能对照**：窗口、设备数、汇总状态、新鲜度、首次/5次顺序/3并发、TD调用数、缓存命中耗时，列基线与候选原始样本。
- **数据等价证明**：比较字段与差异数，JSON/CSV结果；动态生成元数据的单独校验。
- **风险与待办**：分阻塞缺陷、未完成验收、可排期建议，不把三类混写。
- **复现与记忆**：最短复现步骤、手动检查步骤、正式交付页、当前对话记忆增量、临时资源留存清单。

建议证据文件包括 baseline.json、candidate.json、equivalence.json、test-summary.md、manual-check.md；记录实测结果，不预填passed。不要提交原始秘密响应、配置文件或令牌。

### Codex收到交付后的复核重点

集中查看整体差异和已有证据，重点审查：15秒上下文等价性、小时区间不重不漏、SQL快照及脏桶处理、会话隔离、取消/同键合并、新鲜度时钟算法、导出参数绑定。只对缺证据、失败或高风险交叉点补测，不重复完整已通过测试。

只有证据支持时，分别签收源码正确性、性能与可发布性；生产实际生效继续以发布回执与唯一状态入口为准。发布实施另按现行上传规范、阶段四deploy README与当月定位卡执行，本计划不复制服务器命令或旧批次目录。
