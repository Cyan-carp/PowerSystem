# 01 · 方案与实现

2026-10-09，本地候选将运行问答入口改为 `Orchestrator → NaturalAgent`。此前的关键词路线仅作为归档测试夹具保存，不进入 Agent 镜像。

## 语义计划与设备定位

主模型通过 `submit_plan` 返回受 Pydantic 严格校验的范围、意图、业务/资料需求、设备指代、时间窗和分组；拒绝额外字段、字符串布尔值、任意 SQL 和未允许的维度。语义规划最多占十五秒，供应商临时不可用只向同一主模型重试一次，仍受总时间预算限制；失败时只对已知业务问法使用保守识别器，不接备用模型。

状态、指标、设备列表、告警、预测和排名意图均有强制业务取证契约，即使模型将 `live` 错写成 false 也必须查数。资料解释独立处理，“如何”不关闭实时工具。范围外返回 `out_of_scope`，只说明服务范围，不展示技术或生活答案。

范围判定也执行服务契约校验：语义模型误将明确新能源技术主题（如钙钛矿组件衰减）判为范围外时予以纠正，继续执行已校验意图；含生活、娱乐等混合请求仍拒绝。此校验不使用技术词决定状态/资料/排名路线。

设备编码和 ID 使用本轮台账校验；序数按 ID 升序，并检查分页前缀是否有序及去重。第二台定位结果和采用的顺序进入答案提示。会话只存设备指代元数据，不把旧回答作为证据；“它”“刚才那台”会重新校验台账和采集数据。缺少唯一指代时说明原因。

设备状态强制查询最新遥测与未确认/已确认未恢复告警。告警数量使用带条件接口的全量 `total`，不从返回的一条列表记录推断总量。采样时间和接收时间都必须在允许的新鲜窗口内；缺失、过期或设备不匹配不会生成状态正常/故障结论。预测保留原概率和阈值。

“还有告警吗”按当前未恢复状态核查，不用近 30 天触发事件替代当前数量；明确问过去事件数才按时间窗聚合。事件筛选了状态时，答案准确标明筛选口径。

## 告警全量统计

新增认证 GET `/api/v1/alarms/statistics`，允许 `group_by=device|metric|level|status`、`start/end`、`device_id` 和受限 `status`。时间必须带时区、左闭右开，单次最长 366 天。所有分组表达式由服务器固定，参数不能进入 SQL 语法。

数据库单条聚合语句返回完整分组，响应包括起止时间、`total_events`、`groups`、`complete`、统计口径和设备可见范围。默认按近 30 天 `triggered_at` 触发事件计数，包含已恢复和未恢复；只统计本轮可见且未删除设备的告警。总数来自同一聚合结果，避免计数和分组读取不同快照。新增时间/设备复合索引和幂等 006 迁移。

Agent 的 `get_alarm_statistics` 校验时间、维度、筛选条件及分组总和。排名列出所有并列第一；零记录明确回答“该范围内无告警记录”。不完整、接口错误或条件不一致时拒绝排名，不退回单页告警推断。

## 资料与来源

知识检索使用语义计划中的技术问题，再由主模型检查候选章节相关性；设备编码命中或泛泛页面介绍不足以回答技术问题。已定位设备的型号不匹配时，不接纳手册章节。业务证据、项目规则、型号手册和网页分别保留来源类型。

知识未命中时沿用已配置的受控公开搜索；未得到有效来源仍可使用主模型知识，逐项标为“未核验”，不能写成本站配置、现场事实或确定根因。索引故障与缺口分别显示。缺口进入既有持久目录，不自动入库。

模型资料陈述经过独立逐条来源核对：引用必须有效，审核须确认问题相关且所有分句得到支持，并提供能在对应章节/摘要中逐字找到的短摘录。数字、时间、概率和阈值仍执行原护栏；伪造摘录或只引用无关编号不能获得支持覆盖率。审核未通过的通用解释显示为未核验；现场断言直接拒绝。此检查是技术来源校验，不是专业工程师签字。

答案先给结论，再分别列出 `verified_facts`、`unverified_explanations`、人工建议和缺失项。覆盖率按得到支持的独立事实/建议条数除以全部事实/建议/未核验解释条数计算，结论只是这些陈述的摘要，不重复计数。总处理超时仍保留本轮已取得的业务事实；开放式问题在主模型故障时显示服务故障。
