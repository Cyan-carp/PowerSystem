# 06 · 审查协议、外发与审计

> 2026-10-14当前：SEC-M4本机限定签收及r6追加准入通过；MA-C32～C35和最终文档门槛已完成，MA-M4及联合阶段四在声明范围正式技术签收。服务器r6/v5、恢复维护修订3；本机唯一批准动作保留，写窗口关闭，生产仅登记R0。

> 当前强制门禁与公开报告已经接入；SEC-M2实现补充节为当前契约。第一至十节保留建设前规划与SEC-M1历史；其中“未来/未接入/待补查”均为当时状态。

## 一、服务与协议

安全源码已归stages/10-security-agent/；实际本机端口8100，运行命令由源码README维护。安全服务仅本机回环/项目内网可达，独立凭据、签名受众、模型配置和预算，不新增公网端口。本机端口已经预检并验证服务启动；尚未发布内网服务器。

规划内部接口POST /internal/ma-review/v1/reviews；只接受可信程序控制层的严格结构输入。没有公共自由载荷创建或审批接口，健康检查仅证明进程/配置。继续沿用现有技术栈，不增加通用Agent框架。

## 二、请求与结论

| 请求字段组 | 内容与来源 |
| --- | --- |
| 协议与关联 | protocol=ma-review/v1；review_id/task_id/trace_id/step_no |
| 审查类别 | sensitive_read、data_egress、write_plan、write_preflight、post_execution、inspection_report |
| 执行上下文 | user_id/当前role、execution_epoch；由程序赋值 |
| 不可变计划 | 注册tool/version、规范化args_hash、plan_hash |
| 目标与策略 | asset_id/version、目标身份摘要、policy_version |
| 安全材料 | 最小脱敏上下文、evidence_refs、实际时间与完整性 |
| 外发材料 | 目的地别名、许可范围版本、字段清单、payload_hash |
| 截止时间 | 程序生成的审查请求截止，不超过父任务剩余预算 |

返回严格限制为protocol、review_id、decision、reason、rule_hits、evidence_refs。decision只允许allow、deny、needs_clarification。模型不生成可修改的执行计划、身份、签名、有效期或授权标记；程序保存原始合法决策后生成带摘要绑定和有效期的审查记录。

未知版本、额外字段、非法枚举、伪造引用、错误关联均拒绝。needs_clarification停止动作并给出具体缺项，任务保留诊断澄清并以failed/security_clarification_required结束；用户补充后新建任务，不复活原终态。

## 三、绑定、有效性与资源

未来审查记录绑定请求摘要、计划/参数、工具版本、目标/资产/策略、任务/步骤/所有者、执行代次和外发范围/载荷摘要；每次执行前程序重新比对。签名使用独立key_id与受众，私有头传输，审查模型及公开响应不接触签名材料。

首期配置默认：安全功能false；模型型号显式配置，无自动备用模型；单次模型审查30秒、有效期最多300秒，均不得超过父任务剩余预算。每用户1项、全局2项审查并发，超限停止受审动作并记录依赖故障；不创建第二个运维任务绕开原名额。单次审查自动重试0次，每次调用计成本。上述参数只为待实现设计，不改现有配置文件。

审查进度在现有planning/executing状态内以事件表达，不新增任务终态。审查记录保留pending、completed、unavailable、invalid四类程序状态；已执行动作的后审超时仅表示复核不可用，不改动作事实。

## 四、外发前程序投影

先以许可范围与字段白名单投影，再脱敏和限长，随后安全模型接收必要摘要。凭据、原JWT、签名、私钥、原始日志、业务原文及未授权数据不得送审查模型。“安全模型也需要看秘密才能判断”不构成例外。

安全模型自身外发使用预先明确许可的最小审查字段范围，由程序校验；不递归调用安全模型审查自己。内容不满足这个范围时在本地阻断。安全allow不能批准新供应商、目的地或扩大用户的数据授权。

模型输出继续视为不可信文本；资料、工具结果和网页指令不能改变审查任务。reason不得重现原始敏感值，记录规则编号与证据引用足够表达拒绝原因。

## 五、持久化与兼容

程序控制层未来在ma_ops追加审查记录及事件迁移，不改历史行；模型不直连数据库。记录包括关联、请求/计划/载荷摘要、策略版本、程序签名验证结果、决策/规则命中、有效期和失效原因；JWT、密钥、签名原文和原始生产日志不入库。

未来ResultEnvelope增加security_reviews默认空数组；当前严格Schema与前后端需同批适配，新字段缺失按旧历史处理。报告分区标识工具事实、运维诊断、安全审查、人工审批；不覆盖原轮次。任务详情仍经Go读取本人记录，admin无跨用户例外。

## 六、失败恢复与观测

固定错误包括security_denied、security_clarification_required、security_unavailable、security_invalid、security_review_stale；都不产生写重试授权。恢复出的审查和批准仅供证据查询，没有临时可信身份或有效执行上下文不能续跑。审计或持久化失败停止受审动作。

监测审查耗时、拒绝/澄清/不可用、失效、模型预算与审计失败；指标标签用类别/状态/规则，不用问题、用户或资产地址。私有审计用task/trace/review关联。正式发布时审查记录、策略和配置引用纳入MA-M4加密备份及隔离恢复，恢复副本禁写且不自动执行。

## 七、SEC-M1当时契约与显式接入（历史）

阶段10源码已创建，回环8100独立服务已实际启动验证；阶段9新增reviews程序模块与005迁移仅由专用验收入口加载，现有Worker和公开ResultEnvelope尚未接入。Schema以阶段10review_contract.py为实现真相；下文所述强制门禁/公开报告仍待SEC-M2。

**输入与投影**

- 顶层严格字段：protocol、review_id/task_id/trace_id、step_no、execution_epoch、kind、actor、tool、可空asset、policy_version、scope_version、normalized_intent、evidence、可空egress、deadline。六kind沿规划；所有层额外字段拒绝。
- actor包含正整数user_id及operator/admin；tool含name/version/risk_class/args_hash/plan_hash；asset含别名/version/identity_hash/project_scope/criticality/verified。身份、注册工具、角色、当前资产和参数摘要先由程序校验，模型不生成这些值。
- evidence包含ref、program/synthetic来源、带时区时间、complete/filtered/truncated、许可事实key/value；untrusted_excerpt仅在明确synthetic来源允许。egress绑定目的地别名、scope_version、许可字段清单、payload_hash。原始日志/业务原文/未知字段及凭据阻断。
- 当前scope仅sec-m1-synthetic/v3、policy为sec-m1-policy/v6。控制器只受理独立合成任务；模型投影排除user_id及任务认证材料。事实键仅允许状态/范围/关键性/明确执行/审批及动作状态/时效完整性所需合成标量，不能透传任意dict。

**认证、响应与存证**

- X-SEC-Service-Token和X-SEC-Request私有头；规范UTF-8 JSON摘要，独立kid=sec-m1、受众ma-review-request/v1。响应正文仍严格六字段；X-SEC-Metadata保存请求/决策摘要、耗时和token计数，X-SEC-Result以独立结果密钥和ma-review-result/v1受众签署元数据。
- 程序验证签名、引用、规则、关联及当前任务代次后事务保存ma_security_reviews和ma_security_review_events。原签名/令牌不落库；binding_hash绑定整个请求及其计划/目标/策略/外发摘要。valid表示记录绑定和期限有效，deny/needs_clarification也可为合法记录，**valid不能代替decision=allow，更不代表执行授权**。
- 同review_id同摘要读原记录，不重复请求；不同摘要冲突。服务进程内短期拒绝重放，持久化真相归程序库。未完成记录仅在确认本批次没有活跃控制器后由单一启动者恢复为unavailable，不能自动续跑。
- 单次30秒、有效期≤300秒、每用户1/全局2、零自动重试，均受父任务预算约束。模型/格式/审计故障不返回有效allow。数据库验证尚未执行，不宣称恢复或事务实测通过。

当前模型按所有者指令换回deepseek-v4-flash-0731与新独立密钥，30秒、例外false；GPT为历史；原404历史、当前0731/v6真实存证10样例及常规签收，原GPT例外历史见[[01-项目调研规划与开发建设记录/第二版-智能体升级/多智能体协作建设/05-安全审查模型/05-功能开发与阶段交付/01-独立审查闭环/03-SEC-M1测试与交付]]。

## 八、模型意见与程序关联（0731验收候选）

外部请求及六字段响应保持ma-review/v1。模型内部Opinion严格四字段decision/reason/rule_hits/evidence_refs，未知字段一律拒绝；protocol/review_id在合法意见校验后由程序固定绑定当前请求，签名仍覆盖请求及决策摘要。模型无关联标识生成权限，不把错误输出改成合法结论。

模型投影排除review/task/trace/user标识及认证材料；保留kind/role/tool/asset/最小证据、当前epoch及程序reviewed_at。许可v3事实增加身份/归属、注册/参数/审计核对、审批当前有效/代次/期限和计划是否旁路的合成标量。source=synthetic明确为虚构条件，不是实际Go/资产/审批验证。真实数据接入仍待SEC-M2单独设计与许可。

策略v5明确write_plan审能否进入人工审批，pending可为正常状态；write_preflight已知未批准应deny，未知条件才澄清。旁路和注入等已知违规优先判定；allow仍不产生执行授权。真实样例结果由正式页维护，不复制通过数。

## 九、临时性能例外的程序绑定（2026-10-13）

默认30秒保持。本批只有所有者批准的gpt-5.6-sol合成验收可显式启用120秒；服务与程序控制器双重校验，父任务剩余预算继续取最小值，有效记录最多300秒不延长。health及专用验收摘要标明例外，外部六字段协议不变；默认配置与无例外代码路径不放宽。格式/引用错误的稳定类别白名单事务写入审查事件，不保存非法正文或私有签名。常规30秒签收须更换API后独立补查。

## 十、回切后常规配置与策略版本（2026-10-13）

当前策略sec-m1-policy/v6、许可sec-m1-synthetic/v3；请求结构与六字段响应不变。恢复新独立凭据/0731、30秒、例外关闭并独立补查通过；旧策略、旧有效期及审计不改写。不同摘要分别绑定其参数/计划/载荷，不以跨对象摘要相等作为签署依据；v6模型理由约束归安全策略专题。运行命令仅源码README维护。

## SEC-M2本机建设增量（2026-10-13）

当前运行许可sec-m2-local-drill/v1与策略sec-m2-policy/v5显式匹配，M1合成许可/控制器/专库保留。服务请求六字段响应和模型四字段意见不变；模型固定0731、30秒、TTL≤300、并发1/2、零自动重试，受父任务预算限制。v5按kind隔离提示，合法已消费审批以approval_consumed标量表示，后审不改变动作事实。

运行请求来自已保存任务、当前身份、规范参数、Manifest、登记目标和程序证据。白名单投影、秘密检查、限长在审查前；两条外发路径绑定现有网关、operation/supervisor指定型号及实际payload_hash，发送前再核对。Supervisor完整敏感报告用于本人页面，模型仅得到受审摘要；只有审查记录、还未采集事实的拒绝报告也按受审任务处理；可重放历史移除敏感报告，再次解释重新审查。审计失败停止受审动作。第七至十节保留SEC-M1当时事实，不能用于判断现有Worker是否接入。

## SEC-M3现行契约与规则（2026-10-14）

- ma-review/v1复用inspection_report，模型四字段意见及服务六字段签名响应不变；M3仅R0。许可sec-m3-local-inspection/v1，当前sec-m3-policy/v3；旧v1/v2和失败不覆写。
- 最小摘要使用固定状态、资产别名/版本、枚举检查项和程序绑定事实；秘密、原文、未知字段及超限材料在本地阻断。发送前再次核对当前身份、资产、epoch、许可、摘要及期限。
- 完整敏感报告不重放；再次解释新审查。独立Security不递归自审，接收许可内安全包，无执行或数据库凭据。
- 30秒/TTL≤300秒/并发1与2/零自动重试受父任务预算限制。运行档严格配对本轮专库和地址；实际证据见[[01-项目调研规划与开发建设记录/第二版-智能体升级/多智能体协作建设/05-安全审查模型/05-功能开发与阶段交付/03-项目只读巡检/03-SEC-M3测试与交付]]。
