### 0.3 旧统计的更正

上一版正文中的部分数字与因果表述不成立，保留更正如下，避免继续被引用：

1. **27% 是调用占比，不是失败任务占比。** `answer_validation_failed` 214 次是调用数；同一任务可产生多次调用。任务数与调用数必须分开统计。
2. **小样本不能排除高峰限流。** 探针在某一时段连续成功，只能证明该时段该路径可用，不能排除其他时段的限流或网关异常。
3. **194 次调用 / 2 次成功不证明重试风暴是因果。** 只说明该小时调用量远高于成功量，缺少到达率、排队与上游状态对照，不能断言重试导致塌方。
4. **同端点主备模型不是高可用。** 同一端点、同一凭据下的两个模型共享故障域，不能作为供应商冗余；现行方案已删除该设计。
5. 有效安全边界仍保留：原始证据快照、事件身份绑定、禁止编造概率/阈值、供应商失败不伪装成解读成功、审计不记录密钥与推理原文。

## 二、目标架构：四层职责

Go 在业务事务提交后创建持久化任务；worker 取固定事件快照后调用阶段 7 v2。模型只提供受约束的解释与候选原因，不决定阈值、不改状态、不查业务库、不执行操作。

### 2.1 Go 事实层（权威）

- 保留原始 E1–E5 快照，并计算 `evidence_hash` 绑定本次输入；哈希不等即拒绝，防止跨事件或跨版本复用。
- 为每个可展示值生成 `fact_id`（`F1…`），携带：来源证据 ID 与路径、原始值、**单位**、精度、**UTC 时间**、展示时区、角色（告警值 / 阈值 / 测量值 / 概率 / 标识 / 时间）。
- 当前生成同指标触发值与阈值的差，并复用后端曲线统计；派生事实记录公式和输入引用。时长、倍率、变化率在缺少明确公式或完整输入时不生成，不交给模型自行计算。
- 不猜测未知时区；标识类与数值类分角色建模，避免把设备编号当测量值。

### 2.2 模型侧：模板占位，不算数

- 模型输出固定结构：`findings / hypotheses / suggestions / limitations`，每项为 `{template, fact_refs}`。
- `template` 中只允许 `{{F1}}` 形式的占位符引用本次请求内的事实；模型**不写具体数值、单位与时间**。
- 校验：占位必须存在于本次 `facts`；占位引用必须包含于 `fact_refs`，定性条目允许只有来源引用而无数值占位；不得引用未提供的事实；不得新增字段。
- 角色约束：概率、阈值只能由对应角色事实渲染，禁止模型改写；定性因果与操作建议仍受来源与边界校验。
- **否定句处理**：已修复"建议确认是否故障"等否定/条件表达被误判为确定性因果断言的问题，补了正反单测；不得因此放宽对实质编造的拒绝。

### 2.3 渲染与展示层（Go 确定渲染）

- 服务端将模板占位替换为事实值 + 单位 + 时区，生成最终文本；前端不再二次拼接数字。
- 页面分层：**事件事实**（快照，供应商故障时仍展示）与**模型分析**（成功 / 证据不足 / 校验拒绝 / 供应商不可用）分开呈现。
- 不得把模板事实标成"AI 已成功解读"；无模型结论时明确显示降级状态。

### 2.4 供应商适配层（独立）

- 解读专属 provider：`POST https://api.deepseek.com/chat/completions`。
- 请求固定：`model=deepseek-flash`、`thinking={"type":"disabled"}`、`response_format={"type":"json_object"}`、`stream=false`、`max_tokens=4096`、**不带 tools**。
- 不发送 `tool_choice`，不做 auto 兼容，不强制函数调用。
- 只解析 `choices[0].message.content`；保留 allowlist 元数据（HTTP 状态、内容类型、finish reason、token 计数、耗时），不保存推理原文与密钥。
- 独立密钥文件、独立暂停键、独立健康探针；阶段 8 问答与阶段 9 运维智能体仍走原通道，**完全不变**。

## 三、调度、重试与熔断

### 3.1 每任务持久预算

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `model_calls` | 每任务上限 **2** | 持久化在任务行，跨进程、跨重启有效；不是内存计数器 |
| 租约 | **60 s** | 取任务即续租；过期可被重新领取，但预算不重置 |
| 任务截止 | 创建后 **15 min** | 超时直接终态 `retry_deadline_exceeded` 或 `call_budget_exhausted` |
| 重试间隔 | **30 s ± 20%**（24–36 s） | 仅 Go 单层；Agent 内层**不重试** |
| worker | 暂沿用 2 | 补齐排队指标后再评估扩容 |

- 每次实际调用前用条件更新预占 `model_calls`（`lease_token` 匹配、租约未过期、`model_calls < 2`、未超 15 min），保证并发下不超发。
- 失败分类：传输/结构类可重试一次；schema 类可重试一次；**数字/时间/预测改值等业务拒绝不重试**；认证、额度、永久配置错误直接暂停。
- 重试仍失败即终态，不做第三次调用。

### 3.2 熔断

- 连续 **3** 次供应商故障 → 开路；冷却期 **60 s** 起，逐级 **120 → 240 → 300 s** 封顶。
- 冷却期内不发起模型调用，直接按 `circuit_open` 降级，任务保留可重试状态。
- 半开只放行**单个**探测请求；成功闭合并重置计数，失败继续加倍冷却。
- 熔断是临时态，**不写永久暂停键**，不影响阶段 8/9。
- **结构与 schema 类失败计入熔断计数**（用户冻结策略），不用放宽 schema 或删除该保护来换取成功率；恢复仍受 15 分钟窗口与调用预算约束。
- 无同端点备用模型、无自动换模型；供应商失败单独呈现，不伪造成功。

## 四、内部接口 v2

在阶段 7 内新增 `POST /internal/agent/interpret/v2`；旧 `/internal/agent/interpret` 迁移期保留但不作为新任务路径。**不新增服务、公开端口或中间件。**

| 对象 | 关键字段 | 作用 |
| --- | --- | --- |
| 协议 | `protocol_version=2`、`event_key`、`category` | 版本与事件身份 |
| 证据 | `evidence_version`、`evidence_hash`、`evidence[]` | 绑定固定快照，哈希不符即拒 |

### 5.1 规模与节奏

## 六、旧业务告警清理（已执行）

用户最终要求是**删除全部旧业务告警及其解读与通知记录**，从零开始，而不是保留旧历史继续补跑。执行顺序固定，任一步失败即停止：

1. **候选门禁**：候选镜像通过六例真实模型短门禁与离线故障注入；未通过不得进入清理。
2. **维护冻结**：停止新告警写入与解读领取，排空在途任务；记录冻结时刻。
3. **备份**：更新前加密备份，核对大小与 SHA256；未备份不得删除。
4. **固定高水位**：冻结后记录`MAX(alarm_records.id)`和关联记录计数，按这些告警ID确定关联解读、已读与通知删除范围；不把不同表的ID混作同一个水位。
5. **单事务删除**：在同一事务内按高水位删除旧业务告警、关联解读与通知记录；失败整体回滚。
6. **保留项**：告警序列（不自增归零）、设备台账、规则、遥测、预测、监控、审计记录。
7. **禁止项**：不得 `Redis FLUSH`、不得清空全部键、不得撤回已发送的飞书历史消息、不得删除 08 中的容量与长测证据。

> 删除工具与发布工具已实现并保留分步门禁。`r1` 发布门禁失败、`r2`/`r3` 因私有 env 路径适配缺陷（`FileNotFoundError`）及随后的版本跳号受阻，均由专用恢复器恢复 `pending=false`，三次均未执行删除；`r4` 修正私有布局后于 2026-10-21 23:59:36 发布成功。删除前 GPG 快照首轮因 `pg_restore --list` 提前退出产生 `broken pipe`，被严格校验阻断；修正为完整排空流后生成新密文并完整验证，first-attempt 快照与日志保留。**2026-10-22 00:01:33 单事务删除成功**：业务告警 728→0、关联解读 711→0、已读 20→0、通知 outbox 1449→0；保留平台监控 16 条及解读 16 条、设备/规则/遥测/预测/监控/审计；序列与扫描 cursor 仍为 728，维护 false。删除后保留项校验通过；若校验失败，是**有意维持维护冻结**的安全策略，必须人工确认并清除标记后才恢复，不能用无条件 `finally` 放开。实际发布、冻结、删除前后行数与保留项校验以 [[04-系统部署发布备份与变更记录/部署与运维日志/30-官方独立告警解读与每日五次演示|部署日志30]] 为准。

## 九、风险与回退

| 风险 | 处置 |
| --- | --- |
| 熔断阈值过激，健康期误开路 | 半开单请求 + 冷却封顶 300 s；当前按冻结策略实现，调整需另行复核 |
| 模型仍生成非法结构 | 安全子码 + 单层重试一次；连续失败熔断，不放宽校验 |
| 模板占位被滥用 | 只允许引用请求内事实；角色与集合一致性硬校验 |
| 演示被误读为真实告警 | 全链路 `simulation_scenario` 标记 + 10 min 自动结束 |
| 清理误删 | 冻结、备份、高水位、单事务、保留项清单；未备份不删 |
| 发布失败 | 先暂停演示/解读并保留自然告警门控；不得直接回退旧API造成模拟告警回潮；数据库恢复单独处理 |
