## 三、容量环境设计

**规模与时长**

- 200 台设备，5 秒采样，360 轮，合计 **72000 条**，持续约 30 分钟。
- 72000 条是端到端对账基数：发布、接收、处理、入库四个环节都应按此核对。

**隔离方式**

- 独立 Compose 项目：实际容量使用 `powersystem-capacity-20261021-r4`；r1～r3 为未发压的初始化尝试，证据保留，不作为容量实测。
- 独立 MQTT、PostgreSQL、Redis、TDengine 实例，独立网络与独立数据卷。
- 复用当前生产 API 与 gateway **镜像**，保证被测代码与线上一致。
- 不挂载任何生产数据卷，不读写生产台账，不复用生产 Broker 或数据库。
- 私有 compose 内含随机测试凭据，只存在于 Git 忽略的证据区，不写入本页或任何笔记。

> 复用镜像是为了“测同一份代码”，隔离数据与网络是为了“不碰生产”。两者必须同时成立，缺一不可。

**资源配额口径**

- CPU 配额合计 **2.0**、内存 **4096MB**，指各容器**分配上限**之和，不是整机规格。
- 该配额不等价于完整 20 服务拓扑或裸机硬件的非功能验收。
- 负载发生器（模拟器侧）资源预算单独计算，不计入被测服务配额。
- 仅隔离容量环境关闭 AI、Agent 与飞书相关服务；生产上述服务保持原状。

## 四、生产长时间只读观察

- 对象：现有生产车队 143 台（业务 140 + 基线 3）。
- 窗口：7200 秒；每 60 秒采样一次 `dashboard/overview` 的 `all`、`business`、`baseline` 三档。
- 方式：只读 HTTP 采样，只记录计数、延迟与短错误标签，不写生产库、不触发写接口。
- 采样本身不增加生产压力数据：不注入消息、不模拟设备、不改配置。
- 记录字段与判定沿用已复核采样器：期望/登记/已观测、`partial`、延迟、错误标签。

## 五、安全停止条件

出现下列任一情况，**只停止隔离项目**，不动生产：

1. 主机可用内存低于 **2200MB**；
2. 连续 **3 轮**生产 `ping`/健康探测失败；
3. 生产指针或 `pending` 状态发生变化。

- 停止动作限于本批精确的隔离项目负载和容器；结束后移除测试容器和网络，保留测试卷与证据，不删除卷。
- 生产服务、生产指针与生产台账不在停止动作范围内。
- 触发停止须记录触发时刻、指标值与当时隔离项目状态，作为证据保留。

> 第三条尤其重要：容量测试不应引起任何生产指针变化，一旦变化即视为越界，先停再查。

## 六、判定口径

**容量测试（隔离环境）**

- MQTT `published`、PG `received`、PG `processed`、TDengine `rows` 四项均应为 **72000**。
- 四项一致才说明端到端无丢失、无重复放大。
- 同时检查 `late cycles`（超时轮次）、容器 `OOM`、容器 `restarts`。
- 任一项缺失或不等，先定位环节，不直接判“通过”或“失败”。

**长时间观察（生产只读）**

- 实际运行时长是否覆盖完整 7200 秒；
- 错误样本数与错误类型分布；
- 覆盖不足次数（登记或观测低于期望）；
- 接口延迟 `p50` / `p95`；
- 三档范围容器与服务状态是否稳定。

## 八、明确不外推的边界

- 本轮**无断网注入、无故障注入**，不验证断网缓存与补传行为。
- **无浏览器完整验证**，不覆盖页面交互、多浏览器兼容与前端性能。

- 因此不能外推 NFR-02（页面响应）、NFR-03（告警延迟）、NFR-04（数据完整率）、NFR-05（断点续传）通过；NFR-01 也只在“本隔离环境、本配额、本规模”内成立，不等于裸机或完整拓扑验收。
- 无故障、无断网条件下拿到的完整率，不能替代弱网与恢复场景的完整性结论。

> 四项数字对齐只证明“这条隔离链路在 30 分钟内收全了 72000 条”，不证明任何非功能需求整体达标。
