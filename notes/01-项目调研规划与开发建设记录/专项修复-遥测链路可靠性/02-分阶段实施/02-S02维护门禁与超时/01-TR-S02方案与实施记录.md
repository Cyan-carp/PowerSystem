## 二、冻结预算与状态

| 范围 | 预算 |
| --- | --- |
| 队列轮次 / 单项 | 30秒 / 5秒 |
| 业务事务 / 维护读 | 3秒 / 1秒 |
| TD / Redis单次 | 1秒 / 1秒 |
| 依赖/schema初始化 | 共30秒，PG连接最多5秒，Redis连接最多3秒 |
| MQTT连接 / 订阅等待 | 10秒 / 2秒，跟根取消 |
| 每次恢复 / 每台设备 | 30秒 / 2秒，最多3候选 |
| 恢复失败重试 | 5秒间隔，保持未就绪，不自解维护 |
| 退出 | HTTP、worker、MQTT和WS共5秒 |
| 通知派发 | 总10秒，原HTTP最多8秒，根取消可提前退出 |

轮次先建立context，再读门禁和队列。事务/单项继承父deadline；failure元数据用单项剩余预算，不用脱离根取消的后台context。数据库、TD、Redis、ProcessSample、规则/告警/outbox/dirty贯通context；生产Redis启用ContextTimeoutEnabled。轮次保留既有每设备一条与固定顺序，公平性另属S03。

维护分disabled/enabled/sql_error/missing四态，只有disabled准入。空db也失败闭合；普通读取不缓存false。日志按原因每真实分钟最多一次，TD探针有state 0未初始化/1成功/2错误/3超时/4跳过及固定计数/最近时间；watchdog的maintenance_known、maintenance_missing、maintenance_sql_error分别表达，新增gate_*计数。既有S01八种业务失败原因保持，取消和未知提交使用独立计数/日志。

## 三、冻结、排空与只读边界

现有运维协议是先UPDATE单例enabled=true，等待/检查在途解读任务排空，再取冻结快照；全备对RAG/Ops的既有停复流程保持。历史维护工具只作为协议证据，本轮不执行其清理或解锁命令。

新增业务事务先`SELECT ... WHERE id=1 FOR SHARE`，持锁至提交/回滚；原UPDATE需要冲突行锁，提交返回即表示已准入遥测事务排空。更新后新事务看到enabled=true便拒绝。删除单例也受在途锁制约，缺行仍拒绝。

- 遥测事务涵盖TD确认、派生缓存、ProcessSample与失败元数据；锁读inbox后才有副作用。恢复SET/DEL同样持门禁锁。
- HTTP设备/规则/确认/归档使用请求局部事务、同一门禁锁和context，不复制Server及互斥锁。响应和广播在提交后才释放；失败提交提示只读核查并令WS刷新。
- 预测保存、演示关闭、解读扫描、通知派发与energy重建补同一门禁；现有在途解读租约仍按原排空协议等待，不能单凭本锁声称所有外部任务已经停止。
- MQTT接收inbox及网关TD原始写按原协议继续；维护暂停业务消费与派生写，不是停原始接收。没有自动解除门禁。

实际GET设备、告警、规则、电量和解读在PG只读会话执行通过。普通GET不触发重建/确认/归档；metrics与ready只读内存。WebSocket升级GET有一次性Redis GETDEL票据与连接登记，明确不属于“无副作用业务查询”；只读刷新不调用批准、历史重放或通知接口。

## 四、取消、提交与快照语义

事务体失败或提交前已取消：回滚，单项剩余预算允许时记retry和原低基数原因；父context已取消时不另起后台SQL。业务成功时间只在COMMIT确认后刷新。

调用COMMIT后的不确定错误保守归commit_unknown，不写失败/隔离状态，不立即重放，触发WS刷新。后续轮次必须先锁读同一持久inbox：终结行跳过；未提交行才重新执行。database/sql明确自动回滚的ErrTxDone且context已取消可归已知取消；不能把任意驱动context错误推断成肯定回滚。

Redis与PG不承诺跨库原子事务。沿用S01“TD确认”与“业务成功”两维，缓存新增`snapshot_source=td_confirmed`与`business_commit=not_asserted`。后续业务回滚不把已经验证的TD样本伪装为业务成功，PG状态/成功指标仍保持未成功；缓存先成功也不能代替告警提交。单调原子最新值与更完整补偿留S03/S04，不提前引入新队列权威。

## 五、有界广播与启动

广播只序列化并尝试入全局64条队列，单载荷上限16KiB；最多128连接，每连接8条和独立writer，单次写1秒。保留队列内FIFO，遥测后同事务告警按调用顺序入队，不承诺不同并发事务的全局提交顺序。

队列满/超长不静默继续：递增epoch、旧代队列失效、断开受影响连接。单连接满或写超时关闭该连接，不等待每个慢客户端。新代连接不会收到旧队列事件。退出停止准入、关闭连接并等待reader/writer，late hijack不能留下协程。

现有前端connected事件触发设备详情、总览、告警、预测与解读的只读刷新，断线重获一次性票据；没有重放WS历史或外部通知保证。T06使用真实loopback握手加专用慢写连接故障夹具，不把OS缓冲未满当慢客户端通过。

启动阶段created/subscribing/restoring/restore_failed/running/stopping可见。恢复按实际部分索引取每台最多3个success/legacy候选，先清该派生键，再重验所需TD来源；依赖失败返回错误并保持恢复未完成。维护也阻止恢复的SET/DEL。

`/ready`只有恢复完成、running、最近15秒内probe、PG/Redis/TD可用、维护明确关闭、分类已知、登记预期设备非空且采样/接收年龄从探针测量时刻持续增长仍全部新鲜时200，否则503。旧ping在实际Run时同步强制ready并增加telemetry_ready/telemetry_phase，防止原容器healthcheck提前200；独立/live只表示存活。启动未恢复时业务读入口503，不能把旧缓存当恢复成功。实际发布门禁如何消费ready由S04统一核对，不放宽现行门禁。
