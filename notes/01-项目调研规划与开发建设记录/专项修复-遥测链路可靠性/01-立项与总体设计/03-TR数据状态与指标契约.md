# TR · 数据状态与指标契约

> 本页是S01必须落实并冻结的语义约束；以下名称表示逻辑概念，不预设最终列名、枚举或SQL。schema在S01依据实际迁移器/查询计划定案。

## 一、处理状态与成功定义

| 逻辑状态 | 含义 | 能否当成功快照/业务处理 |
| --- | --- | --- |
| 待处理/待重试 | 尚未成功、失败可恢复 | 否 |
| TD已确认但业务未完成 | 允许解释缓存与告警进度不同 | 只按明确快照契约，不算业务成功 |
| 业务成功 | 事务含告警/outbox与必要dirty已提交 | 是 |
| 隔离跳过 | 坏行或经策略判定不可正常处理 | 否，保留原因与原始行 |
| 历史无法判定 | 旧processed_at无法区分成功与人工跳过 | 不推定成功，单独兼容策略 |

- 分开事件接收时间、失败首次发生时间、下一重试时间、最终业务成功时间。不能把旧received_at当依赖故障已持续两分钟。
- 持久原因使用稳定低基数代码；日志不记payload、密钥或原始依赖响应。记录inbox ID/次数/阶段足够定位。
- 数据库成功、Redis成功与广播成功不构成跨库原子事务；明确先后、补偿和幂等。不为追求表面一致性重放未知提交结果。
- 所有旧读者先登记：worker、restoreLatest、energy重建/dirty/历史SQL、报表/助手读取、回填脚本。新状态引入时必须一起处理，禁止只改worker。
- 迁移不扫描清洗或猜测重分类所有历史行。明确保留原字段和索引的兼容窗口、旧二进制限制与回退方式。

**S01必须闭合的运行语义**

- TD确认是验证维度，业务待处理/成功/隔离是处理维度，不互作排他枚举；TD已确认但业务失败仍属于可重试业务行。
- S01必须使现有单worker继续消费新待重试状态：可暂用当前轮询加最小重试，不等待S03才出现消费者。临时依赖失败保持可消费，不能为避免挂起而改成隔离成功。S03只扩展分类退避、熔断与补偿调度。
- legacy旧行不批量重分类。最新快照仅取有界候选并重新确认TD来源，无法确认则返回未知；不能作为已验证新鲜数据。既有电量历史不擅自删除或重算，涉及legacy的重建结果须标明来源不确定/完整性暂定，不冒充验证成功。S01实现前冻结对应接口/读者改动和dirty策略，未能落地这套兼容读语义即阻塞签收。
- Codex在S01负责形成逐读写者清单与检索依据，Workbuddy复核覆盖完整性；迁移后旧镜像写入窗口必须实测，不兼容则明确只允许前滚并演练，不能仅宣称镜像可回退。

## 二、指标语义与探针边界

| 信号 | 必须表达什么 |
| --- | --- |
| inbox最近接收年龄 | 原始接收持续性；DB历史恢复与未初始化可区分 |
| worker最近业务成功 | 真实成功提交；队列跳过不能刷新此时间 |
| worker循环/推进 | 存活、游标推进、隔离计数分别记录 |
| Redis写成功时间 | 操作成功，不等于内容新鲜 |
| 缓存接收/采样年龄 | 使用值内原始received_at/ts，不能用SET时刻代替 |
| 设备覆盖/最差年龄/缺键 | 预期活动设备集合下的部分失效，不用全局max掩盖 |
| 依赖/维护/探针状态 | 成功、失败、未初始化、主动维护、单例缺失可区分 |

watchdog独立协程、探测限时；metrics handler优先读取受同步保护的快照，不让Prometheus抓取触发全库重扫。结合现有索引选择有界查询；大表上不得每次MAX/COUNT全扫，不能用设备ID/原始错误作为无界标签。

**预期设备集合的唯一口径**：以业务库未软删除的devices为登记权威；主动停用/计划静默必须通过可审计显式配置排除，不从“最近是否上报”倒推预期集合。fleet.json只提供合成车队身份及all/business/baseline分类，不替代数据库登记。清单缺失或登记冲突时覆盖率显式未知/异常，不能把期望数清零变成全健康；各阶段复用S01冻结的同一选择器。

## 三、告警及维护契约

- 阈值建议值是待验证初值；包含15秒抓取、15秒求值、for、group_wait、探针周期及接收器耗时后再承诺发现时间。
- 预期输入停止、积压增长、处理无成功、缓存失鲜、覆盖不足及probe自身停止各有可解释规则。
- 主动维护显示maintenance并压制预期遥测噪声，保留维护超期/查询失败告警；不自动解除门禁。
- 正常idle且没有预期输入时，不把“无业务成功”单独判故障；有预期输入但全断流仍必须报警。
- 新metrics和日志不等于已接通知；规则、路由、触发和恢复分别验收，实发外部通知只按实际授权。
- S01最低通知证据为隔离Prometheus/Alertmanager到本地假webhook的真实触发、路由、去重与恢复闭环，记录从失鲜发生到接收器到达的时延并不超过测试前冻结的预算。只做规则语法检查或dry-run不够；生产飞书未实发时另标未验证，不阻塞隔离范围签收，也不冒充生产通知保证。

## 四、恢复、时钟与接口约束

- 服务器赋值received_at保留实际接收语义，补传不得重写为当前处理时刻。
- Redis原子更新以可比较的可信接收顺序为依据；不能只按可能偏移的sample.ts，也不能只按跨run会重置的seq。
- 当前未来样本60秒容差与接收/采样15秒规则是核查基线；S04统一新旧接口前先明确兼容影响，不能无声扩大阈值。
- 电量允许的数据来源、隔离数据是否纳入、dirty触发、缺口完整性和回填重建必须一起冻结；健康未知不得解释为硬件故障。

## 五、S01实际字段与兼容冻结

- `business_state`使用pending/retry/success/quarantined；迁移前行保留NULL。NULL且processed_at非空为历史无法判定；NULL且processed_at空仍可被当前worker消费。processed_at只是兼容终结标记，成功必须同时满足business_state=success。
- `td_confirmed_at`独立于业务事务；first_failed_at记录首次实际失败时刻，next_attempt_at只对retry有意义，attempts记录已持久失败次数。原因限定为稳定代码；观察到的失败计数与持久终态分开。
- 014整份事务执行，保留旧部分索引并增加接收、成功、恢复和电量来源索引；NOT VALID约束不猜测校验旧行，仍约束后续写入。迁移后仅前滚，旧worker须先停止；历史NULL豁免不构成旧二进制可安全运行的承诺。
- 恢复每台最多3个候选，总预算30秒；仅success或历史NULL终结行可入候选。legacy或缺TD确认的候选重新查TD；无法确认则缺键/unknown，删除的仅为派生缓存，不是原始行，不推断TD确定缺失或硬件故障。
- 电量来源为业务success加历史NULL终结行，隔离/重试不积分；legacy或窗口内非成功行使重建source_quality=provisional。已有日表默认legacy_unknown，迁移不改数值；成功、重试和隔离状态写入同时标dirty。003启动迁移不再扫描历史播种dirty，显式回填脚本保留人工入口。
- 报表JSON/CSV、日/组/总计均传播source_uncertain与complete=false，保留数值。complete表示所选设备日聚合有有效段且来源可信，不表示全天连续覆盖；15秒以上间隔仍不积分。summary区分today_energy_provisional与retained_energy_provisional，旧energy_provisional为保留历史口径；overview标今日来源。
- watchdog预期集合选择器只认未软删除devices；silence窗口须有actor/reason和起止时间。fleet身份冲突或缺失单独未知，不改变登记数。当前新鲜度固定15秒，输入停止30秒、队列/无成功/无Redis写60秒，维护观察超期1800秒；不扩展真实长周期设备支持。
- 维护查询成功、配置单例是否存在和enabled分开。仅enabled=1抑制预期遥测噪声；未知配置继续报警，缺单例门禁本身的失败闭合由S02实施。
- watchdog每5秒、单轮总预算4秒；抓取/求值15秒、for15秒、group_wait5秒、group_interval15秒、repeat5分钟。启动宽限输入/worker30秒、probe15秒；缺指标按instance检测。
- 事前发现预算：断流120秒、覆盖105秒、worker/积压/无成功/无Redis写150秒、probe90秒，恢复75秒。实测与复核处置见S01测试页；不承诺20–30秒通知或生产飞书必达。

## 六、S02追加冻结（不改S01状态与预期集合）

- 维护写准入四态：disabled准入，enabled/sql_error/missing保守停写；事务持单例共享锁，原UPDATE提交为已准入业务事务的排空边界，原在途解读协议继续执行。
- S01八种业务失败reason不扩为动态错误标签；取消、COMMIT未知、门禁原因、WS丢弃/慢写及TD探针使用固定计数与最近时间。未知提交不得改为失败后直接重放，必须先锁读持久inbox终态。
- 新TD探针为只读、单次1秒，仍受原probe4秒总预算；probe_td_ok表示操作成功，probe_td_state为0未初始化/1成功/2错误/3超时/4跳过，不把未跑当成功。ready的新鲜年龄从实际测量起点持续增长，不冻结快照年龄；存活接口不代替ready。
- 缓存新增snapshot_source=td_confirmed/business_commit=not_asserted，明确TD验证与PG业务成功维度分离，不承诺Redis/PG原子事务。恢复清理仅派生键，依赖不可用保持恢复未完成/不就绪；完整实现、预算与GET副作用边界见[[01-项目调研规划与开发建设记录/专项修复-遥测链路可靠性/02-分阶段实施/02-S02维护门禁与超时/01-TR-S02方案与实施记录]]。

## 七、S03追加冻结

- telemetry_scheduler.last_device_id仅持久调度位置，inbox为唯一队列；每页≤500设备队头，键集跨轮/回绕，先保存调度访问再派发。按inbox ID跨run有序，事务内再验头/终态/到期。调度访问与业务尝试/成功/隔离分开，不以500为通用故障阈值。
- retry同原因1秒指数至60秒，TD查无5秒起。连续成功查无≥6次且10分钟，相邻≤2分钟，才确认隔离；依赖错误或未观察超窗清连续证据。payload同原因≥3次且30秒；确证身份/删除立即隔离；依赖/lookup/业务不按原接收年龄丢弃。首次实际失败与累计attempts保留。
- 两个固定依赖熔断器连续2失败打开，1—30秒指数冷却、单个半开探测；跳过不增加行失败。已知context取消只记取消信号，不冒充失败；未知提交先锁读持久结果。
- 补偿默认锁读单ID；显式回队仅精确隔离库，保存原状态/actor/reason/请求键，重试窗口清零但保留累计次数和首次失败。设备锁防后继并发重排，已有终结后继拒绝；默认不回队历史告警/通知，无自动生产入口。
- 生产默认S02预算/登记预期集合及广播/ready边界不变；公平窗口/实际证据及容量扫描限制见[[01-项目调研规划与开发建设记录/专项修复-遥测链路可靠性/02-分阶段实施/03-S03公平调度与可重试机制/01-TR-S03方案与实施记录]]，不能外推任意规模20秒SLA。015仍前滚，旧worker不得混跑。

## 八、S04追加冻结（当前两通道契约）

本节扩展S01恢复候选与S03串行实现限制，保留其登记/审计、失败分类、同设备持久ID队头和未知提交锁读规则；不改变生产授权。实现/读写者兼容清单见[[01-项目调研规划与开发建设记录/专项修复-遥测链路可靠性/02-分阶段实施/04-S04容量恢复与实时通道/01-TR-S04方案与实施记录]]，同候选实际结果见S04测试页。

- inbox仍为唯一持久队列。历史默认8个有界跨设备槽，阀门1—8或暂停；递归索引跳到下一设备，不以旧DISTINCT扫描性能外推容量。实时独立按设备页128/每设备3候选，以精确device/ts/seq核验TD并在维护SHARE/设备锁下提交telemetry_snapshots引用；TD-only pending也可成为实时来源，但不等于业务/告警/outbox成功。
- Redis为派生缓存，在相同维护/设备锁下重读已提交来源，按20位十进制inbox接收ID Lua原子比较；seq/run不作大小，采样时间倒退不能推进。数据库恢复后按其可信引用校正残存高ID/损坏内容，运行期Redis重启亦重建；固定10分钟TTL、原始时间保留，不把SET时间当采样/业务成功。不宣称跨库原子事务。
- UTC毫秒；received_at与TD确认用服务器数据库时钟。入库48小时容差不变，候选以原接收时刻判断采样过去15秒/未来60秒。summary/overview/health/watchdog统一：异常或未来接收、无效采样/未来超过60秒、接收新但采样旧均unknown；合法接收已过15秒为offline；快30秒兼容，慢30秒/停滞/补传不自动fresh。unknown不推断硬件故障，新增telemetry_unknown与原offline区分；旧消费者须读取unknown/partial/原时间。
- 历史/乱序样本整次告警评估含恢复默认抑制，alarm_evaluation与单设备评估水位保存空档；JWT只读progress以64条before_id页呈现，不补发历史通知。成功历史可积分；TD-only pending/quarantine不积分，存在非成功/legacy或>15秒缺口使来源provisional。
- 电量流式保持最后ID同时间样本，covered_ms/gap_count/max_gap_ms与coverage_known/coverage_complete区分有效段、来源和全天完整。dirty_pending使旧verified聚合在重建前仍complete=false，summary/overview亦暂定；不改旧kWh/接收时间或猜测完整覆盖。
- 所有持久确认/业务/Redis写仍经维护四态SHARE排空，TD只读可在门外但提交重验；全备须另停网关并等SQLite/TD协程退出。历史暂停阀不替代全备门。016整体事务仅前滚，旧worker不混跑；实测旧API缺审计/无序缓存不能回退，可退冻结止写再同schema恢复，可用性兼容回退镜像另列生产前门禁。
- 143/5秒实际140+3全供数，286仅隔离2倍余量；四规则、watchdog/energy竞争、固定资源/窗口、8580积压及净消费ETA的范围只见S04交付，不承诺生产SLA或任意长积压。全部原始/隔离/缺口保留，无生产部署或外部通知。
