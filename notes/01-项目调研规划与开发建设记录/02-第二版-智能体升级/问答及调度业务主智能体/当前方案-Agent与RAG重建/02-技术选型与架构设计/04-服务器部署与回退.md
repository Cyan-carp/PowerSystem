# 04 · 服务器部署与回退

2026-10-11，按用户指定的新公网入口 `https://8.138.42.212/agent` 发布。既有架构中该云机运行入口，业务及数据库仍在同一R730XD `/opt/powersystem`；不向另一台公网服务器部署业务。本轮状态以服务器正式交付页为准。

独立Agent采用Python 3.12 Linux CPU镜像，本地开发环境为Python 3.13；版本锁与本地已验收环境对齐，Windows专属依赖附平台条件。服务器镜像使用本地E5模型、内部Qdrant、独立PostgreSQL数据库和既有认证Redis。阶段7告警解读容器保留原镜像及权限。

生产编排按顺序叠加阶段4主编排、阶段7 Agent与搜索编排、阶段8 `deploy/production.compose.yaml` 及本次固定镜像文件；显式使用私有 `compose.env`，不覆盖原 `.env`。新Agent密钥采用UID10002可读的专属副本；模型及资料只读挂载，审计目录单独持久化。Qdrant不映射公网端口。业务代理超时135秒，Go125秒，Agent单轮120秒。

发布材料存于服务器 `runtime/rag-release-20261011/`：原源码快照、基线镜像标签、候选源码包及文件摘要、固定镜像配置、私有环境与验收证据。该目录不得进入公开仓库。回退使用 `switch-release.py rollback --release <发布目录>`；恢复候选使用 `activate`。两者只重建API与前端，不删除新会话数据库、向量卷和旧告警模块。

原 `backup.sh` 增加`POWERSYSTEM_BACKUP_LOCAL_ONLY=1`和`POWERSYSTEM_BACKUP_SKIP_SECONDARY=1`：前者生成本地密文不上传，后者仅上传显式指定目标；不改变既有定时备份配置。RAG备份范围包括独立会话库、各向量集合一致性快照及别名、E5模型、私有配置与审计。新格式已在隔离PostgreSQL/Qdrant恢复、比对会话正文并执行语义检索；不是仅检查压缩包存在。新机恢复私有配置时须按实际路径重新准备密钥文件及UID10002权限，不直接复用旧机器绝对路径。

公网故障排查先区分入口与业务：本轮R730XD出口变化导致FRP来源白名单失效。用户明确允许后备份旧值并更新单一7000来源；其他端口及另一台公网机未修改。
