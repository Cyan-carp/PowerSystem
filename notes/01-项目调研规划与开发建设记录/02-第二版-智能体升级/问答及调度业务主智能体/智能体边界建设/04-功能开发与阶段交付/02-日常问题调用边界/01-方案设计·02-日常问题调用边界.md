# 01 · 日常问题调用边界方案设计

> 记录本轮用户决定及已实现契约；功能状态见[[01-项目调研规划与开发建设记录/02-第二版-智能体升级/问答及调度业务主智能体/智能体边界建设/04-功能开发与阶段交付/02-日常问题调用边界/03-阶段2测试与交付]]。本方案为BND-M1之后新增的入口边界，不改写此前自由问答验收。

## 一、目标与用户决定

面向平台用户和运维人员，减少明确生活与闲聊请求的模型调用，保留普通技术、新能源设备及平台问答。

- 生活问题不回答内容，返回固定服务范围提示并保存会话。
- 纯问候、感谢、告别使用预设短句，不调用模型，保存会话。
- 分类过程使用本地规则，不增加分类模型或Embedding判断。
- 不确定时放行；明确混合生活与技术请求时整条拦截，要求分开发送。
- 先交付代码、笔记和本地验收；用户后续明确授权同步R730XD，指定公网入口8.138.42.212，新增服务器完整回退、恢复与固定镜像观察验收。

> 零调用保证针对命中拦截规则的请求。选择“不确定放行”意味着新表达可能漏拦，不能承诺识别所有生活问题。

## 二、判断流程与例外

身份、参数、会话归属检查及会话锁 → 读取历史 → 本地分类 → 程序答复或现有模型/工具循环 → 脱敏、持久化和审计。程序分支不创建Engine任务，不执行知识库、网页或业务工具。

规则版本bnd-m2-v1，日常子规则D01至D05覆盖食谱餐饮、旅行度假、娱乐陪聊、部分个人生活建议及日常天气问法；S类规则处理纯礼貌用语。规则包含具体短语及组合，不以“日常”“推荐”单个词作为拒答条件。

| 输入 | 行为 |
| --- | --- |
| 你好、谢谢、再见、你好谢谢 | 预设程序答复 |
| 炒蛋怎么做、推荐晚饭、讲个笑话 | 固定范围提示 |
| 解释Redis，再推荐晚饭 | 提示分开发送 |
| 你好，解释TCP | 正常模型问答 |
| 设备日常巡检、推荐数据库 | 正常问答 |
| Python字符串中的“炒蛋” | 技术例子不触发生活拦截 |
| 推荐一下、怎么处理 | 不确定，放行 |

输入仅为分类进行Unicode规范化、大小写及零宽字符处理，持久化问题仍沿用原脱敏文本。引号和代码片段先保护再分句，仅在所在技术子句中作为例子忽略；“解释TCP，再回答‘炒蛋怎么做’”仍按混合请求拦截。

## 三、多轮与历史

“具体步骤呢”“继续说”等明确延续，回溯本会话最近实质主题；礼貌用语及独立核验不重置主题。生活主题的延续仍拦截，明确技术主题恢复模型问答；没有可判定主题时按不确定放行。

程序答复保存空model_messages；构建模型上下文时排除程序记录及明确命中生活规则的旧问答和延续轮次。显示历史完整保留，不删除、改写旧生活答案。普通技术记录、历史只读核验及原资源预算保持。

## 四、接口与页面

公共POST /api/v1/agent/chat的输入不变。响应兼容增加可选字段：

- response_mode：model、preset或boundary。
- model_called：在Provider.complete实际被调用前记录；调用失败也为true，程序答复为false。
- boundary：action、reason、rule_id、rule_version；配置关闭时不产生该字段。

礼貌答复status=answered，生活/混合/延续拦截status=out_of_scope，正文为固定Markdown，model为空字符串，sources及tool_calls为空。Go原代理已支持该状态，只新增透传回归测试。新增字段写入现有response JSON，不增加数据库迁移。

页面显示“固定回复”或“服务范围提示”并标未调用模型；不显示为模型故障，不提供补查按钮，也不展示指向补查的取证面板提示。历史接口不能重新打开这些记录的verification_available；直接以新程序记录作为核验父轮次返回400。旧记录缺字段按原逻辑显示，不反推历史调用次数。

## 五、开关、故障与兼容

BND_DAILY_GATE_ENABLED默认true，集中由Config读取；关闭恢复原模型入口和历史上下文行为，已有程序记录继续显示。开关不关闭JWT、会话隔离、只读工具、脱敏和接纳限额。

分类或历史筛选异常返回503，不静默调用模型；存储失败不返回已保存成功。沿用会话409、跨用户404、接纳429及并发控制。模型故障仍degraded，独立主动核验维持BND-M1契约。

服务启动原有本地Embedding预热仍存在；本规则不使用该模型分类，也不在被拦截请求中执行Embedding。配置关闭属于功能停用，不等于已验证完整源码回退。
