# 03 · 项目只读巡检方案

> 2026-10-14归属：本目录维护本模型职责、规则与前三阶段；联合第四阶段由[[01-项目调研规划与开发建设记录/02-第二版-智能体升级/多智能体协作建设/06-联合发布验收/00-索引·联合发布验收]]统一维护，正式签收见[[01-项目调研规划与开发建设记录/02-第二版-智能体升级/多智能体协作建设/06-联合发布验收/03-联合第四阶段测试与交付]]。

> SEC-F04/F05、SEC-T09～T12；首期用户主动、只读，已在SEC-M3本机实现。当前签收：[[01-项目调研规划与开发建设记录/02-第二版-智能体升级/多智能体协作建设/05-安全审查模型/05-功能开发与阶段交付/03-项目只读巡检/03-SEC-M3测试与交付]]。

## 一、发起与数据流

用户需求 → Supervisor澄清范围 → 程序建立本人read_only任务并选择固定检查项 → 现有受控R0采集 → 必要敏感读取/外发审查 → Security依据安全摘要研判 → 程序保存报告 → 本人任务卡展示。

沿现有ma/v1受控任务创建流程，规划intent=security_inspection，不增加公共自由载荷创建接口。程序路由该类任务到固定巡检编排；模型不能自建后台任务或跳出当前身份/任务预算。无明确项目资产范围先澄清。

## 二、检查清单与覆盖限制

| 类别 | 首期证据 | 不能据此宣称 |
| --- | --- | --- |
| 主机与服务 | 在册服务状态、资源和安全事件摘要 | 全物理机、全部云资产安全 |
| 容器 | 在册身份、安全inspect字段、状态和事件摘要 | 完整daemon配置或所有镜像无漏洞 |
| 数据库 | 已有固定健康/连接聚合 | 全部角色授权、数据或SQL已审计 |
| 权限与暴露 | 经核对的脱敏配置/审计摘要 | 当前公网端口已现场验证 |
| 凭据与外发 | 私有配置引用及许可范围证明 | 密钥正文可发送给模型 |
| 审计与恢复 | 对应版本正式页和受控摘要 | 新版本恢复、灾难切换已测试 |

现有R0工具不能取得的网络规则、权限明细、证书、备份新鲜度或完整配置，只能使用经核对的限定材料，或者标未检查。旧正式页提供历史证据，不等同实时现场检查。新增采集器/联网扫描/系统配置读取须另行定义Manifest、最小权限和验收，不在本轮自动开放。

## 三、报告结构

程序报告包括：已请求与已检查范围、每项状态、证据引用/时间/视角、confirmed_findings、hypotheses、unchecked_items、recommendations及完整性说明。

检查状态限定passed、finding、inconclusive、not_checked；passed必须有对应规则及充分证据，仅表示该项在限定时点/范围满足条件。截断日志、空摘要、健康200和缺少异常事件都不能推出全项目无风险。

建议标明需专业人工、新增采集能力或另行授权，不将建议包装成已修复。报告不生成可自动执行的生产修复指令。

## 四、失败与取消

必要采集失败保持失败和已取得事实，模型不可用保留程序清单/缺项；取消停止后续采集，已返回证据保留。过期、失效身份、未核验/跨项目资产和超预算零后续采集。报告归任务所有者，admin不能自动读取他人报告。

## 五、首期不建设

不自动定时、不创建系统级长期身份、不新增飞书通知、不尝试漏洞利用、不扫描其他服务、不安装插件或开启生产日志。定时/持续监控与自动处置单独立项。

## SEC-M3现行契约与规则（2026-10-14）

- 当前任务语义为security_inspection，通过task_kind独立路由固定清单；具体字段由程序控制任务协议维护。
- 六类清单按现有能力执行，未开放工具逐项not_checked；本轮实际仅容器inspect，其余工具测试层和现场覆盖分账。
- 程序范围/版本固定、证据规则与故障处理见[[01-项目调研规划与开发建设记录/02-第二版-智能体升级/多智能体协作建设/05-安全审查模型/05-功能开发与阶段交付/03-项目只读巡检/01-方案设计·03-项目只读巡检]]；实现及分层签收见[[01-项目调研规划与开发建设记录/02-第二版-智能体升级/多智能体协作建设/05-安全审查模型/05-功能开发与阶段交付/03-项目只读巡检/03-SEC-M3测试与交付]]。
- 旧规划中没有覆盖的配置/网络/备份/权限采集继续未开放，不安装新采集器、不自动修复。
