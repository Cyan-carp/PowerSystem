# 01 · 交接模板与接续规则

> 沿用第五版的四件套与八项交接。每阶段独立对话、完成交接后停止，不自动推进下一阶段。

## 一、新对话读取顺序

1. `notes/00-当前系统状态.md`（唯一事实源）。
2. `AGENTS.md` 与 `shared-memory/workbuddy-collaboration.md`、`shared-memory/project-memory.md`。
3. [[01-项目调研规划与开发建设记录/08-第八版-移动端与安卓客户端/00-索引·第八版-移动端与安卓客户端]]。
4. [[01-项目调研规划与开发建设记录/08-第八版-移动端与安卓客户端/03-跨对话交接/00-V8当前接续入口]]。
5. 上阶段的正式交接与直接相关的源码 README（前端或安卓）。

核对实际工作区后，在 `shared-memory/conversations/<日期>/` 新建独立记忆，不复用他人文件。

委派 Workbuddy 时须先让它读协作规范、项目公共记忆与当前记忆，再读直接相关正式材料；
明确独占文件与验收范围。涉及生产发布时按上传规范核对真实门禁与备份条件，未执行项不得记成通过。

## 二、八项交接

1. **阶段结论**：完成 / 部分完成 / 阻塞；分别说明已实现、已测试、已验收、真实环境验证。
2. **工作区基线**：分支、HEAD、提交或未提交清单，与原有未提交改动如何区分。
3. **实现结果**：改了哪些文件、新增什么能力、依赖与配置变化、文档位置。
4. **实际验证**：环境、步骤、结果、失败或跳过项与证据位置；命令只在源码 README。
5. **冻结决定**：断点位置、导航形态、外壳选型、`targetSdk`、签名方式与理由；变更时受影响的范围。
6. **风险遗留**：阻塞与非阻塞分开列，注明归属阶段与回退限制。
7. **下一起点**：先读材料、第一项动作、范围与准入门槛。
8. **协作复核**：Workbuddy 实际返回、采纳或纠正理由、剩余问题与记忆增量。

## 三、验收与停止点

每阶段四件套为方案与实施记录、测试与交付、独立问题记录、正式阶段交接，阶段目录另有索引。

- 必须明确「能否进入下一阶段」，未清阻塞不得签收，失败批次不得覆盖成通过。
- 阶段交接控制在约 1500 中文字，长证据通过正式页导航。
- 完成后停止，不自动进入下一阶段。

## 四、四类证据不互相代偿

| 证据 | 含义 |
| --- | --- |
| 代码完成 | 文件改完、类型检查与构建通过 |
| 本地实测 | 浏览器视口 / 模拟器 / 假后端上的实际行为 |
| 可安装包 | APK 产出并签名，能装能跑 |
| 生产上线 | 上传、active 指针变化、定位卡登记、本人确认 |

> 本轮只做到前两类 + 内部包；生产上线未做，因此本版不得在状态页标为「已上线」。

## 五、版本与生产边界

- 本版不改后端、接口、数据库与权限，也不改变既有批准权与运维写限制。
- 安卓包的签名密钥与口令属私有资产，不进 Git、不写进笔记；丢失即视为该包身份失效。
- 生产发布单独走 S03，需所有者授权，并在当月定位卡登记实际路径。
