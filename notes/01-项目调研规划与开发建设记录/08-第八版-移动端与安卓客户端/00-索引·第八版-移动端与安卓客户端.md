# 第八版 移动端与安卓客户端 · 索引

> 第八版把「只能在电脑前看的控制台」变成「手机上也能用的平台」：网页补手机端适配，安卓端出一个把**同一套页面**装进 WebView 的安装包。生产指针、发布批次与已知限制以 [[00-当前系统状态]] 为唯一事实源。

## 一、这一版解决什么

前七版把数据链、模型闭环和发布链都做齐了，但入口始终是一块按 1440px 设计的桌面控制台：

1. **手机上勉强能开、没法用**：左侧图标轨固定占 52–64px，390px 的屏上正文只剩一半；顶栏搜索、时钟、快捷胶囊互相挤压；顶栏弹层 340px 直接溢出到屏幕左外侧。
2. **没有「像 App 一样打开」的入口**：手机浏览器每次要输网址、重新登录，告警来了也不会停留在会话里。
3. **桌面客户端只覆盖 Windows**：第五版 Electron 客户端解决的是 Win10/11，与手机无关；重写一套原生界面既贵又与网页两套口径。

缺口基线与取证见 [[01-项目调研规划与开发建设记录/08-第八版-移动端与安卓客户端/01-立项与总体设计/01-现状基线与移动端缺口]]。

## 四、四条必须记住的边界

1. **一套页面，不做第二套**。手机端沿用阶段四同一份 Vue 代码与同一份接口，只加壳层断点；不新建 m 站、不复刻业务页面，避免两套口径长期分叉。
2. **App 不打包网页**。安装包只提供壳层与系统能力，页面永远从服务器加载；网页更新后 App 不需要重新发版。这与第五版桌面客户端同一思路，见 [[01-项目调研规划与开发建设记录/08-第八版-移动端与安卓客户端/01-立项与总体设计/03-安卓外壳选型与安全边界]]。
3. **手机端不是缩小版桌面**。九枚图标平铺在 390px 上每枚只剩 43px，必须按使用频次重排成「底部四格 + 更多」，而不是把图标轨压窄了事。
4. **发布不等于验收通过**。前端已于 `mobile-ui-20261108-r1` 上线并完成公网资产核对，但本批未跑完整门禁与发布前测试，也未做真实手机实装；不得用「已发布」代替体验确认，状态页按「已上线、真机未验」登记。

## 五、与第七版的关系

第八版不替换第七版，是同一平台的新入口：

| 能力 | 第七版（起点） | 第八版 |
| --- | --- | --- |
| 网页入口 | 桌面浏览器控制台 | + 手机浏览器（≤900px 壳层） |
| 客户端 | 第五版 Windows 桌面（Electron） | + 安卓 WebView 安装包 |
| 页面口径 | 单一份前端 | 不变，仅增加断点 |
| 接口与数据 | 现行 51 条接口 | 不变，无新增接口 |
| 登录态 | JWT + localStorage | 不变，WebView 内持久化 |
| 生产发布 | 前端/API 双服务批次 | 仅前端镜像 `mobile-ui-20261108-r1`，手工接受激活 |
