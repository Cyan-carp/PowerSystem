# 03 · 安卓外壳选型与安全边界

> 回答「为什么是裸 WebView」「外壳给了哪些系统能力」「哪些权力坚决不给」。工程结构与本机构建命令见 `stages/12-android-client/README.md`，本页只写判断与边界。

## 一、四条技术路线的取舍

| 方案 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| **裸 WebView（选定）** | 零第三方依赖、包体 29 KB、离线也能构建 | 系统能力要自己写（下载、返回、错误页） | ✅ |
| Capacitor / Cordova | 插件生态现成 | 需要 Gradle + 联网拉依赖，本机构建链不可控 | ❌ |
| Tauri 2 mobile | 体积小、Rust 安全模型 | 需要 Rust 工具链与 NDK 交叉编译 | ❌ |
| React Native / Flutter | 原生渲染 | 等于重写一遍界面，与「一套页面」原则冲突 | ❌ |

决定性理由不是体积，而是**构建可重复**：本仓库的发布纪律要求「源码 → 构件」有据可查。
裸 WebView 只用 SDK 自带工具（`aapt2`/`javac`/`d8`/`zipalign`/`apksigner`），
不联网、不引入 AGP 版本漂移，任何一台装了 Android SDK 的机器都能复现同一个包。

## 二、为什么不把网页打进安装包

| 做法 | 后果 |
| --- | --- |
| 打包 `dist/` 进 APK | 页面与 App 版本绑死，前端每次改动都要重新发版；接口域名写死；登录态与资源缓存跨版本失效 |
| **从服务器加载（选定）** | 前端发布即生效；同一份页面在浏览器与 App 里表现一致；代价是无网时只能显示错误页 |

因此 App 里**没有任何业务代码**，只有一个 Activity 与系统能力适配。
这也意味着：手机端布局改动不需要动 App，App 的升级只跟外壳能力有关。

## 三、外壳给了哪些能力

| 能力 | 行为 | 边界 |
| --- | --- | --- |
| 站内链接 | 留在 WebView | 保留会话与历史；首次加载时用配置入口判断同源 |
| 站外链接 | 交给系统浏览器 | 不在无壳窗口里打开第三方页面 |
| 返回键 | 先退网页历史，退到底连按两次退出 | 覆盖层（错误页/设置页）直接交给系统退出 |
| 下载（报表 CSV） | 系统 `DownloadManager`，落公共「下载」目录 | 带登录 Cookie 与 UA；不静默存到应用私有目录 |
| 软键盘 | `adjustResize` | 助手页输入框不被键盘遮挡 |
| 旋转屏幕 | `configChanges` 接管 | 不重建 WebView，不丢会话与网页历史 |
| 缩放 | 关闭手势缩放 | 布局交给网页 viewport 与断点，避免两种缩放叠加 |
| 服务器地址 | 首启确认 + 长按图标可改 | 默认生产入口；改地址不重新打包 |

## 四、安全边界（本版硬性）

1. **混合内容禁止**：`MIXED_CONTENT_NEVER_ALLOW`。生产是 HTTPS，不允许 https 页面混载 http 资源。
2. **本地文件不开放**：`allowFileAccess=false`、`allowContentAccess=false`，网页读不到设备文件。
3. **第三方 Cookie 关闭**：`setAcceptThirdPartyCookies(false)`，登录态只在本站内。
4. **明文流量开关显式**：`usesCleartextTraffic="true"` 是为了能连内网 http 测试环境，
   这是本版唯一的放宽项；确定只连生产时应改为 `false`。
5. **权限只留三项**：网络、网络状态、以及 API ≤28 的写外部存储（CSV 落盘用，`maxSdkVersion="28"`）。
   不申请相机、定位、通讯录、后台定位。
6. **签名密钥就是身份**：包名 `com.powersystem.mobile` + 密钥共同决定能否覆盖升级；
   密钥在 `build/keys/`（git 忽略），**丢失后只能卸载重装并清掉本地登录态**。
7. **不代持凭据**：App 不保存账号密码，不内置任何 token；登录仍走网页自己的登录页与 JWT。

> 不做的两件事：一是不在 App 里做「记住密码/自动登录」的旁路，二是不同步任何业务数据到本地。

## 五、版本与兼容口径

| 项 | 值 | 理由 |
| --- | --- | --- |
| `minSdkVersion` | 24（Android 7.0） | 覆盖老值班机；WebView 自动更新机制在 5.0+ 已成熟 |
| `targetSdkVersion` | 34（Android 14） | 不触发 35+ 的强制 edge-to-edge，系统栏由主题配色控制，行为可预期 |
| `compileSdkVersion` | 36 | 跟随本机 SDK 平台；不引入运行时依赖 |
| 应用名 | 源网智联 | 与网页标题一致 |
| 包名 | com.powersystem.mobile | 不含版本号，换版本不改包名 |

> `targetSdk 34` 是有意为之：35 起系统强制全屏边到边，WebView 内容会压到状态栏与手势条下面，
> 必须额外做 inset 补偿；本版不做这一步，等真正需要上架时再单独评估。
