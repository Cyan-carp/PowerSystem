# 03 · V8-S02 问题记录与解决方案

> 构建链上的五个坑，均为「不解决就出不了包」的阻塞项，状态全部已解决。留档是因为它们会在换机器、换路径、换 PowerShell 版本时复现。

## 问题 1 · `.ps1` 里的中文提示变乱码，脚本直接语法报错

**现象**：`build-apk.ps1` 报 `Unexpected token 'C:\Program'`、`The string is missing the terminator`，
报错行内容显示为「apksigner 楠岀澶辫触」这类乱码。

**原因**：Windows PowerShell 5.1 读取**无 BOM** 的 `.ps1` 时按系统 ANSI 代码页（本机 GBK）解码，
UTF-8 中文被拆成非法字节，字符串引号配对被破坏。

**影响**：脚本完全无法执行。

**解决**：两个 `.ps1` 一律保存为 **UTF-8 with BOM**（`EF BB BF`）。已在 README 中写明，避免有人用编辑器重新保存时丢掉 BOM。

**验证**：加 BOM 后脚本正常解析并跑完全流程。

## 问题 2 · aapt2 打不开仓库目录：`failed to open directory`

**现象**：`aapt2 compile --dir <仓库>/app/res` 报「系统找不到指定的文件」，但目录确实存在。

**原因**：`aapt2`、`zipalign` 是原生 Windows 程序，参数经窄字符转换后无法解析含中文的路径；
仓库绝对路径含「新能源设备智能运维平台」，因此必失败。

**影响**：资源编译与对齐两步都跑不了。

**解决**：把所有中间产物放到纯 ASCII 的 `%TEMP%\powersystem-apk-build`，先把 `app/` 整个复制过去再编译；
`javac`/`d8`/`apksigner` 是 Java 工具（Unicode 安全），最终 APK 仍由它们写回仓库 `build/out`。

**验证**：迁到临时目录后 aapt2 与 zipalign 均正常；APK 正常落在仓库内。

## 问题 3 · `ZipArchiveMode` 类型找不到

**现象**：`Add-Type -AssemblyName System.IO.Compression.FileSystem` 之后，`[System.IO.Compression.ZipArchiveMode]` 仍报 `TypeNotFound`。

**原因**：`ZipArchiveMode` 枚举在 `System.IO.Compression.dll`，不在 `FileSystem` 程序集里。

**影响**：`classes.dex` 写不进 APK，出的是没有 dex 的空壳包（装上就崩）。

**解决**：两个程序集都加载：`System.IO.Compression` + `System.IO.Compression.FileSystem`。

**验证**：`classes.dex` 13,980 字节出现在包内；`aapt2 dump badging` 与实装均正常。

## 问题 4 · 多出一个 `.idsig` 文件

**现象**：签名后 `build/out` 里除 APK 还有 `PowerSystem-Android-1.0.0.apk.idsig`。

**原因**：新版 `apksigner` 默认开启 v4 签名，额外产出 `.idsig`（供 `adb install --incremental` 使用）。

**影响**：不影响安装，但产物目录多一个容易被误发的文件。

**解决**：签名命令加 `--v4-signing-enabled false`，只留 APK。

**验证**：重建后产物目录只有 APK。

## 问题 5 · 模拟器里页面一直跳回登录页

**现象**：用 CDP 预置 `ceoc.token` 后导航到首页，仍被重定向到 `/login`，且 `localStorage` 里的 token 被清空。

**原因**：假后端对 token 做形状校验（`/^mock_[0-9a-f]{16,}$/`），非法形状直接回 401；
前端 401 的唯一出口是清会话并跳登录页。手工写的 `dev-preview-token` 正好不合规。

**影响**：只影响本地验证脚本，不影响产品代码。

**解决**：验证脚本改用合规形状的 token（`mock_` + 32 位十六进制）。

**验证**：注入后 9 个页面全部正常渲染，不再跳转。
