# 02 · 技术选型与总体架构

> 定义在线桌面客户端与现有平台的连接方式及代码边界。

## 一、选型与取舍

Electron 复用现有 Web 技术和 Chromium 渲染环境；TypeScript 维护桌面主进程及 preload；electron-builder 生成 NSIS 安装包。依赖在 S01 选取实施时受支持版本并提交锁文件，本轮不虚构已安装版本或构建结果。Electron 包含浏览器运行时，安装体积和更新维护成本纳入候选实测，不预先承诺数值。

首版加载线上页面，维持业务请求、WebSocket 与助手事件流的同源关系。若以后改成本地打包业务页面，必须另行评估来源校验、跨域、路由和接口兼容，不直接沿用本版验收。

## 二、进程与数据流

| 部分 | 职责 | 数据边界 |
| --- | --- | --- |
| 主进程 | 单实例、窗口、托盘、通知、保存与设置 | 不持有业务密码或模型凭据 |
| preload | 向固定页面提供版本化窄桥接 | 不暴露 Node、文件路径或通用 IPC |
| 远程业务页面 | 现有登录、业务、助手与批准交互 | 使用现有 sessionStorage 与鉴权接口 |
| 本地失败页 | 页面加载失败提示与重试 | 不加载业务数据，不获得业务桥接 |
| 现有服务端 | 数据、身份、助手、批准及定期任务 | 保持原有权限与执行权威 |

业务请求和 WSS 仍由远程页面直连既有 HTTPS 入口；仅桌面动作经过 preload 和主进程。通知点击由主进程构造固定告警路由，不接受任意跳转地址。文件先经过现有鉴权与校验链，再由下载管理进入保存对话框。

## 三、工程归属

桌面工程归 `stages/11-desktop-client/`，至少包含源码 README、package/锁文件、TypeScript 主进程与 preload、受控本地错误页及打包配置；这些实现由 S01 实际创建，本轮只建立 README。业务 UI 继续维护原阶段四，桌面适配采用可选能力探测，不复制整个前端。

配置和非敏感偏好保存在当前 Windows 用户的应用数据目录；使用独立非持久会话分区，不保存登录凭据。窗口位置恢复时检查仍处于可见屏幕范围，多显示器变化时回到可见位置。

隔离联调用独立测试构建登记精确回环来源与端口，仅限本机夹具；测试配置不得进入团队安装包，不开放运行时任意地址或跳过证书检查。S03以实际分发候选和固定HTTPS来源复核，不用测试构建代替最终包。

## 四、生命周期与连接恢复

重复启动只唤起已有窗口，不额外建立实时订阅。隐藏到托盘保留页面与会话；显式退出销毁窗口和会话。启动失败由打包本地页显示原因分类和重试入口，不通过关闭证书校验解决。

S02 对断线和系统恢复事件触发现有重连/快照机制，不自动重提业务请求、任务或批准。不能以整页自动刷新作为所有断线恢复办法，以免丢失草稿和会话；必要刷新前保留用户选择。客户端关闭不会取消服务端任务。

## 五、发布与兼容

桌面原生能力和网站页面分别版本化。页面缺少桥接或协议不支持时保持网页行为，不阻断登录和普通业务。S01/S02 先在本地与隔离入口验证，涉及线上前端适配的发布集中 S03，仍走原统一门禁。内部安装包手动覆盖升级，保留非敏感设置；登录重新建立。
