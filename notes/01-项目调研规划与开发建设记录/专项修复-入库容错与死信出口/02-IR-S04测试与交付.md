首轮观察到 143 个队头/500ms 的结构上界约 286 行/s，游标推进在该夹具内约占运行时间 13.6%；TD/PG 每项 CPU 约 4.3/2.9ms。以上都是隔离特定输入下的诊断线索。首轮**未覆盖**实际持续 API 接收与实时 TD 确认、energy worker、真实生产 TD 大表/磁盘条件；20 个 tick 的 P99 接近最大值，稳定性样本不足。这些首轮缺口由后续混合夹具补了一部分；真实 TD 延迟可见、生产等价性和同输入改后对照仍待验证。

Workbuddy 后续混合夹具完成 22 个正式轮次，143 台、24/s 输入叠加历史积压时测得历史排水约 257.95/s，真实 `srv.worker` 对照约 262.70/s；24/s 与 48/s 无初始积压稳态的成功量分别约 23.80/s 与 47.60/s，接收至成功 P99 约 520ms。**Codex 原始 JSON 复核发现容量组测量窗口内 `fresh_success_in_window=0`、480 条新接收样本全在队头之后 pending；257.95/s 仅为历史积压排水率，不能当作新输入的接收至成功 P99 或生产净余量。**该夹具 TD 行预写、无 retry；与本轮生产大量近期重试也不等价。Codex 正在一次性隔离环境补 TD 延迟可见场景，结果尚未签收。

Codex 补测的 `mixed-delay-143-24` 在同一 `ir_s04` 夹具增加**排定接收后 800ms 才向一次性 TD 子表写样本**；先仅建空子表，让查无返回 `(false,nil)`，使用真实 API 接收、历史/快照/energy worker，3 轮各 30 秒。测试本身 `PASS`，总耗时 134 秒，未超过所有者的 10 分钟上限。每轮接收/TD 写入均为 720/720，零写入错误；窗内成功 675/676/676，剩余 45/44/44 条在短暂 drain 完成；TD 真查无各 708 次、retry 各 708 次，最终 720 条均成功，完整性/FIFO 检查通过。TD 写入返回滞后 P99 约 818–821ms，接收至成功**窗内** P99 1.855/1.882/1.863s，through-drain 全部 720 条 P99 1.866/1.899/1.888s；上述为固定 800ms 一次性 TD 写入模拟，未启动真实 gateway/MQTT/SQLite，不能当生产写入时延。窗内 success 22.5/s 对 24/s 输入的差值是固定时延造成的边界截断，不能写成负容量余量。

首次运行忘建空 TD 子表，HasSample 的表不存在错误触发原错误熔断；Codex 在第 2 轮后中止并作废该运行，修正后重新编译和完整三轮。无效运行保留日志、不得并入结果；TD 表预建只创建一次性夹具子表，不预写待测样本。

`mixed-delay-backlog-143-24` 在上述延迟条件下每台先放 3 条真实 TD 命中的旧样本，共 429 条小积压，另 720 条新接收；3 轮各 30 秒 `PASS`，429 条历史均在窗口内成功，新样本窗口内成功 676/675/676，剩余 44/45/44 条 drain 完成。新样本接收至成功窗内 P99 2.273/1.973/1.953s，3 轮中位 1.973s；无积压档的中位约 1.863s。TD 真查无 663/673/672 次、retry 同数，TD 写入均 720/720 且零错误，所有轮次 0 FIFO 队头越位、完整性通过。首轮 P99 波动较大，不能宣称固定增量；两档都是隔离短测，且无真实 gateway/生产重试分布。原始 JSON 与日志位于 Git 忽略的 `artifacts/ir-s04/2026-11-07/`。
