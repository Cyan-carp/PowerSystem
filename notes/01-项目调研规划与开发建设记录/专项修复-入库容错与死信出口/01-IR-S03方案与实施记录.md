# IR-S03 · 方案与实施记录

> 本阶段只处理「TD 查询成功但系统性查无」的识别与熔断，不重做旧 TR-S03 已签收的公平调度、分类重试、错误熔断和容量工作。生产状态只认 [[00-当前系统状态]]；本地候选不等于上线。核心隔离验证及 Codex 定向复核通过，S03 本地候选已签收，生产未签收。

## 一、起点与分工

- S02 本地候选已由 Codex 复核签收，生产仍为唯一状态页所列批次；从 [[04-IR-S02阶段交接]] 接续。本轮没有生产发布、生产故障注入、生产只读查询或 S04 授权。
- Workbuddy 负责系统性缺失识别、开路/半开/恢复核心及定向测试，编辑 `telemetry_scheduler.go`、`server.go` 和独立核心/测试文件。
- Codex 负责 `telemetry_monitor.go` 的固定指标导出、独立指标测试、本专题四件套、索引与状态页同步；两线不并发编辑同一文件。阈值与结果以实际隔离测试交接为准，不能由文档预填。

## 二、现行证据与风险

- `tdengine.Client.HasSample` 在 SQL 成功而结果为空时返回 `(false,nil)`；现有 `dependencyCircuit.finish` 仅对 `err != nil` 累计失败，因此这种查无不会打开原错误熔断。
- `server.processInboxItem` 将 false 记录为 `td_missing`。单行持久连续证据由 `recordInboxFailure` 维护：10 分钟、至少 6 次、相邻核查至多 2 分钟，满足后隔离。全局系统性缺失与此单行终态是两个判据，不能共用计数器。
- 96 批次的三条实查样本随后均可在 TDengine 查到，说明近期 false 可能只是 TD 写入时间差。该历史反证不能当作本轮延迟分布实测。

## 三、实现边界

1. 单独维护有界的系统性缺失状态，不改变已有 TD 错误熔断、Redis 熔断和快照 TD 熔断实例。
2. `HasSample` 的命中、成功查无、查询错误分别计数；取消/预算截止不计为成熟查无。近期接收样本的 false 保持待核，不直接作为系统性故障证据。
3. 开路须有跨设备、连续且成熟的查无证据；单设备空洞不触发全局开路。当前候选参数见下表；生产真实 TD 写入延迟尚未实测，不能把隔离阈值说成生产上界。
4. 开路只限 TD 确认路径的尝试频率，不伪造业务成功，不越过同设备未终态队头，不启动第二个历史 worker。其他业务路径及 S02 过期出口保持独立。
5. 半开探测必须实际核查目标样本；只有命中才可证明该探测恢复，false 不能被 `err==nil` 误读为恢复。查询错误仍服从原错误熔断。
6. 不删数据、不 `VACUUM FULL`、不碰 `owner_abandoned`、不改 TDengine 或 `energy_daily` 历史值；无迁移时明确零 schema 变更。

### 3.1 核心候选与阈值

- 独立 `tdMissingCircuit` 不复用原 `dependencyCircuit` 的错误状态；`Server` 在 TD 确认前查询独立开关，之后按命中/成功查无/错误调用不同观察入口。新状态只在进程内，有界证据表最多 1024 台，无设备 ID 指标标签。
- `TD_MISSING_CIRCUIT_ENABLED=false` 为默认值；关闭时查询仍照常执行，原错误熔断与单行缺失证据照常工作。开启后才可能出现新的全局限流。

| 参数 | 候选值 | 依据与限制 |
| --- | --- | --- |
| 接收成熟线 | 2 分钟 | 大于单次 TD 查询预算、小于原单行 10 分钟宽限；**没有生产延迟分布可证明 2 分钟足够** |
| 证据窗 | 最近 3 分钟 | 设备首次观测超过窗口时重置次数与起点；恰等于窗口仍计入，超过 1ns 重置；单测覆盖 |
| 单设备持续性 | ≥2 次成熟查无、跨度 ≥30 秒 | 排除单次 false；隔离测试验证门槛两侧 |
| 跨设备门槛 | ≥16 台 | 状态页记录 143 台（非本轮生产复测）中的约 11%；站级缺失仍可能触发全局限流，生产误开率未知 |
| 冷却/半开 | 30 秒/一次探测 | 半开 false 或错误重新开路；只有真实命中关闭；失败设备轮转防止单设备独占 |
| 内存上限 | 1024 台证据 | 固定上限，超过时淘汰最久未见设备 |

2 分钟成熟线和 16 台门槛是隔离候选假设，不是从 96 历史数据实测出的安全值。生产灰度前需读取真实 TD 写入延迟分布并核误开风险；此项在本阶段未授权执行。

## 四、可观测合同

| 指标 | 口径 | 成本与窗口 |
| --- | --- | --- |
| `td_query_hit_total` | `HasSample` 成功且命中次数 | 进程计数，重启归零；单次调用 |
| `td_query_missing_total` | SQL 成功但结果为空次数 | 同上；不等于确证缺失 |
| `td_query_error_total` | SQL 报错次数 | 同上；取消需单独处理，不能冒充缺失 |
| `td_missing_mature_total` | `received_at` 至查询时已满 2 分钟的成功查无次数 | 进程计数；单次成熟不等于系统性缺失 |
| `td_missing_circuit_{open,skip,half_open,recovered}_total` | 状态转换与开路跳过次数 | 固定标签/键，低基数，重启归零 |
| `td_missing_circuit_state` | 0 关闭、1 开路、2 冷却已过可半开或正在半开 | 即时进程状态；无设备 ID 标签 |

指标导出不执行数据库或 TDengine 查询。开路状态与业务成功、队龄、窗口外滞留须组合看；开路次数单独不能证明数据真的缺失。

## 五、回滚与保留

- 默认关闭的 `TD_MISSING_CIRCUIT_ENABLED` 是灰度和回滚点；关闭或回退镜像停止新的系统性开路，不回写单行失败证据。进程重启清空独立熔断内存状态；不影响 PG 已提交的终态。
- 隔离证据覆盖近期 false→true、单设备空洞、16 台门槛、半开 false/true、错误熔断、取消、重启、并发与 S02 共存。Codex 发现的证据窗/取消边界已定向修订并复测：首次观测滑出 3 分钟即重置；父/事务取消及单次 TD 查询预算截止均不将 `(false,nil)` 计作查无。详见 [[02-IR-S03测试与交付]]。
- 生产发布和生产故障注入仍分别需要当轮明确授权；本阶段文档与隔离测试不构成授权。
