# IR-S04 · 问题记录与解决方案

> 施工中。下列项按本轮只读证据与源码列出，待隔离基线判定优先级；单点观察不当作瓶颈结论。

> 下表部分行是 S02 上线前的历史问题记录；现行生产和新容量分档分别见 [[00-当前系统状态]]、[[08-IR-S04容量余量分档实测]]。

| 编号 | 问题 | 当前证据或假设 | 验证/处置 |
| --- | --- | --- | --- |
| IR-S04-Q01 | 流量平衡不等于余量 | 生产近 1 小时接收/success 接近、pending 很短；没有压力斜率 | 隔离固定输入测最大稳定 success 速率与 P99，再冻结净余量目标 |
| IR-S04-Q02 | 近期 TD 查无重试成本 | 69.277 秒中 retry +1,312、success +1,657；大量 success 的 attempts>0 | 核 TD 确认/重试/实时确认交互，隔离量重试写入与调度访问成本，不提前改宽限 |
| IR-S04-Q03 | P99 来源不等价 | 生产 PG `processed_at-received_at` P99 是端到端代理，当前 metrics 只有路径 sum/count | 隔离夹具记录逐项 P99；前后同口径，不能拿生产代理当单条执行 P99 |
| IR-S04-Q04 | PG WAL/锁争用未证明 | 单次 `docker stats` PG CPU 106.21%，一次 `pg_stat_activity` 见 WALWrite/WalSync | 隔离多轮资源/等待与查询计划；单点不触发索引或事务重写 |
| IR-S04-Q05 | 8 路上限与旧 TR-S04 边界 | 016 CHECK 与代码均限 1..8，旧专项已签收 8 槽/实时通道 | 不直接改并发上限、第二历史 worker、PG 池；先证明具体瓶颈 |
| IR-S04-Q06 | S02/S03 候选未上线 | 本轮生产仍为 96 批次，两个候选默认关闭 | 隔离矩阵分开标开关；不把候选能力写成当前生产 |
| IR-S04-Q07 | 容量测试与数据边界 | 8,809,844 条 `owner_abandoned` 不得碰，历史 TD/energy 值不动 | 只用一次性隔离库，生产只读；不删行、不 VACUUM FULL |
| IR-S04-Q08 | 生产发布门禁 | 备份目标从 VM117 不可达为既有记录，本轮未重测备份路径 | 发布前另行核链路/备份；无授权不 prepare/publish 或手工激活 |
| IR-S04-Q09 | 纯历史夹具的高吞吐不可外推 | 首轮 143 台、500ms ticker 的纯历史上界约 286 行/s，实测 274.7 行/s；未有持续接收/energy/真实 TD 大表 | 补混合负载、重复轮次和资源观察，再定数值目标；不得以“无退化”替代净余量提升 |
| IR-S04-Q10 | 快照 worker 的容量竞争 | 首轮同一纯历史夹具加连续快照，成功吞吐由 274.7 降至 246.0 行/s，tick P99 由 538.8 升至 770ms，均仅 n=20 | 混合场景复核真实争用及 P99；未证明可通过调 PG 池或关闭快照解决 |
| IR-S04-Q11 | 游标写入优化可能损害公平恢复 | 首轮夹具中每 8 条派发前写一次持久 `last_device_id`，360 次约 1.42s；旧 TR-S03/S04 的预算截断、重启续扫与新增设备测试依赖可观测的持久游标推进 | 若混合量测仍指向该成本，先做语义保持方案及慢队头/预算截断/重启/500 设备边界回归，再比较；不能直接改成整页末写游标 |
| IR-S04-Q12 | 历史排水与新样本时延混淆 | 混合 capacity 原始 JSON 窗内新样本成功 0/480；258/s 只来自历史积压 | 净余量仅按该历史场景标注排水率；TD 延迟可见场景独立报告新样本 P99、retry 和队头影响，不外推生产 |
| IR-S04-Q13 | 近期 TD 查无测试须先建空子表 | 首次延迟场景未建 TD 设备子表，HasSample 走错误熔断而非 `(false,nil)`，结果无效 | 作废首次运行；仅在一次性 TD 建空子表后重跑两档各 3 轮，真查无/重试与最终成功均有证据 |
| IR-S04-Q14 | 容量倍数须按可靠边界签收 | 48/s 三轮稳定；72/s 尾部等待波动；96/s 第三轮 TD 写入 7 条失败 | 只签隔离 2 倍短时输入下界；保留 96/s 失败回执，不把 3/4 倍或隔离值写成生产承诺，见 [[08-IR-S04容量余量分档实测]] |
