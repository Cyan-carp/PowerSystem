# 告警智能解读模型返回兼容修复（2026-10-18）

> 2026-10-18 13:04:55（北京时间）已正式上线，随后线上合成解读返回 answered 且正确引用 E1。本次不补记此前已按所有者要求免写日志的页面框架调整。

## 一、现象、原因与影响

- 告警 #289 的五份事件证据均为 `ok`，解读三次尝试均以 `model_invalid_response` 降级。排查时近24小时同类失败50条；首次同类失败发生于2026-10-17 20:44，最后成功记录为当日19:44，均为北京时间。
- API、Agent、PostgreSQL 和 Redis 健康，相关服务未重启；Agent未因今日界面发布被替换。故障不由历史列表或页面滚动样式造成。
- 经所有者批准，使用现有授权模型接口发送一次合成协议请求，不携带真实告警或设备数据。上游 HTTP 200，响应正文可解析为 JSON，含一条工具调用，但 `message.role` 为 **空字符串**；当前解析器只接受 `assistant` 或字段缺失，因此拒绝响应。该次响应头为 `text/event-stream`，正文实际仍为单个 JSON 对象；本次不为该头部实现任意流式容错。
- 前端和解读服务的提示表缺少该错误码，因而显示“原因尚无法判断”等通用文案。

## 二、修复及安全边界

- 仅将模型完成响应中的空角色兼容归一为 `assistant`；显式 `user/system/tool/developer`、非字符串角色、无效消息和异常工具调用结构仍拒绝。
- 不修改模型、密钥、工具权限、提示词、证据编号、数字与因果判断校验；规范化后仍走原有完整回答校验及审计。
- 补充返回格式、超时和不可连接的中文错误说明。历史失败保留其真实失败身份，不批量重试、不覆写已恢复告警的记录，不人为插入业务告警。
- 本轮生产候选基于正在运行的 Agent 固定镜像，只叠加解析器与错误文案；不整包覆盖服务器。既有本地与运行镜像的工具选择条件差异不借本轮一并发布，修复片段与本地一致。
- 源码入口：[[06-代码工作区导航与链接映射/stages-07-agent-README|事件解读服务]] 的 `agent/llm.py`、`agent/interpret.py`、`tests/test_provider_response.py`；[[06-代码工作区导航与链接映射/stages-04-frontend-README|前端]] 的 `src/lib/interpretations.ts`。
