# 81 · 漂移事件基线补全

> 修 [[01-项目调研规划与开发建设记录/07-第七版-模型换版闭环/02-分阶段实施/04-S04AI解释与建议]] 实测中暴露的问题：AI 解读说「漂移记录 baseline 为 null，缺少可对比基线」。

## 一、问题

`prediction_drift_events` 有 `baseline` 列，但 L1 的 `high_ratio` 信号写入时没传值：

```go
// 修改前
Level: "L1", Signal: "high_ratio", Observed: &recent.HighRatio,
Threshold: ptrFloat(driftL1HighRatioMax), Action: "watch",   // 没有 Baseline
```

其余信号（`probability`、L3 的 `precision`、`ece`）都传了基线，只有这一处漏了。

后果有两层：

1. 漂移事件读起来只有「观测值 0.0215、阈值 0.25」，看不出「正常该是多少」；
2. AI 解读每次都把「基线缺失」列为一项依据，占掉了本该用来分析误差分布的篇幅。

## 二、改法

基线取**此前 7 天的日均高风险占比**，与 `probability` 信号的口径一致：

```sql
avg(CASE WHEN predicted_high THEN 1.0 ELSE 0.0 END) AS daily_high  -- 按天聚合后再取均值
```

新部署没有历史时（`baseline.Days == 0`）退化到经验区间中点 `(0.02+0.25)/2 = 0.135`，并在 `detail.baseline_source` 标为 `range_midpoint`；有历史则为 `trailing_7d`。

标注来源是为了让读的人区分「实测基线」和「兜底值」——两者混在一起等于又制造一次「说不清数据哪来的」。

## 三、验证

| 项 | 结果 |
| --- | --- |
| 编译 | `go build ./cmd/... ./internal/...` 通过 |
| 部署 | api `d2f1187b…`，healthy，`/ping` 200 |
| 存量事件 | 两条旧 `high_ratio` 事件仍为 null，属历史数据，不回填 |
| 新事件 | 次日同信号检测时带上基线（当日已有记录，`recordDrift` 按「同日同信号」去重，不会重复写） |

存量不回填是刻意的：当时的 baseline 已经查不到（预测数据已随时间变化），用今天的 7 天窗口去补昨天的基线属于伪造。

## 四、回退

api 镜像回 `47317d90…` 即可；本次只改了检测逻辑，未动表结构。
