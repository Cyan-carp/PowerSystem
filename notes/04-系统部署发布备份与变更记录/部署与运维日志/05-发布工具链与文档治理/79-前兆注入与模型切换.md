# 79 · 前兆注入、质量归档与模型切换

> 所有者决策：**项目定位是预测故障概率，不改**；告警频率与时段变化无所谓（有自动告警证明链路活着即可）；质量页历史断层直接归档，从新形态数据重新开始。

## 一、模拟器加前兆

`simulator.py` 的窗口注入原本是突变：窗口内 10 分钟直接抬到目标值，窗口前毫无征兆。这是为「稳定触发告警规则」设计的测试手段，不是对真实故障的建模。

改动：

| 项 | 内容 |
| --- | --- |
| 新参数 | `--precursor-minutes N`（默认 0 = 保持原行为） |
| 前兆形态 | 窗口前 N 分钟内线性爬升到目标的 70%，`shape_value()` 保证不超过目标值 |
| 兼容 | `window_phase()` 在 N=0 时返回与原 `window_active()` 完全相同的判定 |
| 生产配置 | `--precursor-minutes 30`，通过 compose overlay 的 `command` 覆盖，未改原编排文件 |

实测曲线（PV-03，target 82 / 阈值 80，前兆 30 分钟）：

```
12:29  none           45.0
12:40  precursor/0.33 53.6
12:55  precursor/0.83 66.6
13:00  active/1.00    82.0
13:10  none           45.0
```

前兆期温度已越过 55/80 阈值以下的部分会提前触发告警——所有者已确认接受。

## 二、质量数据归档

切换故障形态后新旧数据混算会让指标失去意义，按「历史归档、从新开始」处理：

| 表 | 归档表 | 行数 |
| --- | --- | --- |
| `prediction_outcomes` | `prediction_outcomes_archived_20261102` | 137,218 |
| `prediction_quality_daily` | `prediction_quality_daily_archived_20261102` | 4 |
| `prediction_drift_events` | `prediction_drift_events_archived_20261102` | 2 |

线上表已清空。

**关键配套**：回填 worker 按 `qualityBackfillDays=3` 回看，会把归档前的预测重新算出来。新增 `qualityEpochMS = 1_793_604_000_000`（2026-11-02T07:20:00Z），`backfillOutcomes` 的 `cutoff` 取 `max(3天前, epoch)`，早于此刻的预测不再回填。

## 三、模型切换

用窗口注入 + 前兆数据训练出的候选 `stage3-xgb-89e6530c9e29`（F1 0.943，见 [[78-窗口注入训练集改造与重训结论]] 的对照组）：

| 步骤 | 结果 |
| --- | --- |
| 备份旧模型 | `/opt/powersystem/runtime/model/{model,metadata}.json.20261102-bak` |
| 覆盖文件 | bind mount 直写宿主目录，无需 docker cp |
| 重启 | `docker restart powersystem-stage4-ai-predict-1`，容器内确认版本正确 |
| 台账 | import → promote，`promoted_by=p0-admin`；旧版本置 retired |

现役：`stage3-xgb-89e6530c9e29`，阈值 0.325，15 特征。

## 四、首批实测（14:34 批次）

| 检查 | 结果 |
| --- | --- |
| 模型切换生效点 | 14:34 批次开始 `model_version=stage3-xgb-89e6530c9e29`；14:29 及之前仍是旧版本 |
| 推理服务自检 | `/health` 返回 `stage3-xgb-89e6530c9e29`，容器 06:30Z 启动 |
| 前兆期概率 | PV-04（15:00 窗口，前兆 14:30 起）：`INV-19` 概率 **1.000**、`INV-13` 0.664、`INV-20` 0.164，同场站其余设备 < 0.01 |
| 旧模型对照 | 同时段平均概率 0.115，最高仅 0.97 且不集中在窗口设备 |

前兆期设备被高置信度命中，说明模型确实识别到爬升过程，而非随机给分。

## 五、待观察

- 17:00 窗口（ST-01，温度 82）是首次带前兆的完整窗口，前兆应自 16:30 开始；
- 质量页需等新预测到期（窗口结束 + 1 小时）才有首批真值，预计 18:00 后出现第一条日指标；
- 新模型上线后 1 小时内产生的预测仍可能混有旧模型结果（模型替换在 07:20 完成，之前的预测已落库）。
