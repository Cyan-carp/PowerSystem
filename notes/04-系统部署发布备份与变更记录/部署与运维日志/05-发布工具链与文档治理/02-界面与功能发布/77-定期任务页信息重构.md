# 77 · 定期任务页信息重构

> 所有者反馈：该页面对非开发者难以理解，看不出用途。本批只改前端信息结构与文案，**不动后端契约、审批流与任务逻辑**。

## 一、诊断

原页面把三件事混在一屏，且大量规则引擎术语：

| 问题 | 具体表现 |
| --- | --- |
| 用途不明 | 页面只有按钮，没有一句话说明「这页是干什么的」 |
| 起点太高 | 空状态只有「还没有定期任务」，用户不知道从哪开始填 |
| 术语堆叠 | 方案预演、基准阈值、候选阈值、比较符、授权到期、配置审查、run_id |
| 主次颠倒 | 「方案预演」（辅助工具）占主区一半，任务列表反而在上方且常为空 |
| 两件事混淆 | 「定期任务」是定时执行；「方案预演」是改阈值前试算，二者无直接关系 |

## 二、改动

| 位置 | 改前 | 改后 |
| --- | --- | --- |
| 顶部 | 只有刷新/新建 | 标题 + 一句用途说明 + 审批提示 |
| 空状态 | 一行「还没有定期任务」 | 三个模板卡片，点击直接带出预填表单 |
| 方案预演 | 标题「方案预演」，副标题术语化，默认展开 | 「改报警线前，先试算」，一句话说明，**默认收起** |
| 试算字段 | 设备 / 指标 / 比较符 / 基准阈值 / 候选阈值 / 假设采样间隔 | 选一台设备 / 看哪个指标 / 判断方式 / 现在的报警线 / 想改成 / 设备多久上报一次 |
| 试算结果 | 预演结果、基准命中、候选命中 | 试算结果、现在会触发、改完会触发 |
| 任务类型 | 定期巡检 / 定期日报 | 自动巡检 / 每日报告 |
| 范围 | 全部场站 / 业务场站 | 所有设备 / 业务设备 |
| 触发 | 每日 09:00 / 每 30 分钟 | 每天 09:00 / 每 30 分钟一次 |
| 授权 | 授权 30 天 / 授权到期 | 有效期 30 天 / 到期 |
| 提交 | 提交审批 | 提交给管理员批准 |
| 侧栏 | 授权与边界 | 使用说明（三条白话） |

三个模板：每天 09:00 检查全部场站、每 30 分钟检查业务场站、每天 18:00 生成日报。均走既有 `openForm` 路径，仅预填字段，不新增接口。

## 四、布局调整（同日 12:30 CST）

首版只是把试算工具改名收起，但它仍占主栏一半宽度，与任务列表并排，视觉上仍是并列关系。

调整为：

- 试算卡从 `.sc-main` 移出，成为 `.sc-grid` 的最后一项，`grid-column: 1 / -1` 跨两列，落在页面最底部；
- `previewOpen` 初始值由「非 '0' 即展开」改为「等于 '1' 才展开」，**默认收起**；
- 收起时卡片只剩一行标题（连同展开按钮），展开才渲染说明与表单（`v-show`）。

现在页面自上而下：用途说明 → 概览 → 我的任务 + 侧栏 → 试算工具（一行）。frontend 镜像 `7448c186…`。
