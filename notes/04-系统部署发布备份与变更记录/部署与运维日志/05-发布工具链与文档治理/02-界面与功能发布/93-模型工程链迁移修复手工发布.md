## 八、后续加固：020 迁移改为可重复安全（2026-11-05，Workbuddy）

> 本批不动线上镜像，只改仓库文件与迁移语句；生效时间见本节末。

`store.Migrate` 没有版本表，每次 api 启动都会重跑全部迁移，020 的「DROP 主键 + ADD 主键」因此每次启动执行一遍。原实现有两个可改进点：

1. **重复数据会让启动失败**：若 `(day,label_rule)` 出现重复行，`ADD PRIMARY KEY` 报错，`main.go` 里是 `logger.Fatal`，容器会反复退出。已加 `ctid` 去重语句（正常路径下删除 0 行）兜底。
2. **DROP 与 ADD 之间没有事务**：原 `Migrate` 仅对 014–017 包事务，中间存在「表暂时没有主键」的窗口。已把 019/020 登记进新增的 `store.atomicMigrations`，两条语句同事务生效。

**生产库演练（只读回滚）**：在 powersystem 库执行 `BEGIN … ROLLBACK`，五条语句合计约 15 ms，回滚后主键仍为 `(day, label_rule)`，未产生任何持久变更。

**生效时间**：下一次 api 镜像重建时随镜像内的 `deploy/postgres/020_*.sql` 生效。当前运行镜像 `f6a130d3` 内的 020 仍是旧版——可正常启动，只是每次重启会重建一次主键（当前表十几行，毫秒级）。
