# 72 · 演示告警台网页与直接发布

> 本页记录把「登业务机敲 `demo-alarm.py`」换成网页操作台的实现与三批直接发布（后端接口 + 静态页 + 两次前端修正）。功能语义见 [[01-告警固定解读与手动演示]]，当前生产状态见 [[00-当前系统状态]]。

## 一、为什么要做这个页面

原来的演示流程是：`ssh` 进业务机 → 记路径 → 敲 `python3 /opt/powersystem/runtime/production-stack/demo-alarm.py create --device ... --level ... --analysis ...` → 手动 `read` 回填 alarm_id → `status` → `set-state`。这套东西对当场演示太笨重，而脚本本身只是把容器内的 Go 命令包了一层，业务逻辑都在 `service.CreateManualDemo` / `AckManualAPIDemo` / `EndManualAPIDemo` 里。

所以页面不是重写业务，而是给这三个函数加一层 HTTP 入口：脚本能做的一模一样，只是把「进容器敲命令」换成「点按钮」。

## 二、后端：一个口令、六个接口

新增 `stages/02-backend/internal/api/demo_console.go`，路由挂在 `/api/v1/demo-console/` 下：

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | `/login` | 单一口令换 8 小时令牌（`scope=demo-console`） |
| GET | `/devices?keyword=` | 设备搜索，供下拉（直连 `devices` 表，不复用列表接口的分页参数） |
| GET | `/alarms?scope=recent\|active` | 最近 20 条演示告警 / 当前活动 |
| POST | `/alarms` | 创建（body: `device_code`、`level`、`analysis`、`request_id`） |
| GET | `/alarms/:id` | 单条状态 + 解读 |
| POST | `/alarms/:id/ack` | 确认 |
| POST | `/alarms/:id/recover` | 恢复 |

口令不进环境变量、不改 compose：文件在 api 容器的 `/data/demo-console.json`（`api-state` 具名卷），内容 `{"enabled":true,"password_hash":"<bcrypt>","actor":"p0-admin"}`。这样发布时不需要动编排，也不必因为「配置变更」去走 full 档全备那条路。

鉴权用与平台同密钥签的 JWT，但带 `scope=demo-console`：平台 `authorize` 要求 `sub` 是真实用户，演示台令牌没有 `sub`，两个方向都进不去。失败限速是进程内的 5 分钟窗口、8 次上限，没有引入 Redis 计数。

几处刻意的细节：

- **写入同闸**：`alarmMaintenanceGuard` 的 `affected` 前缀加了 `/api/v1/demo-console/alarms`，于是告警维护开关打开时页面写入同样 503，事务与「提交后再广播」的缓冲逻辑也一并复用。
- **广播复用现有通道**：写成功后 `broadcastAfterWrite(service.AlarmEvent{...})`，与网页「确认」走同一条 WS 事件，主站打开的告警面板会同步变化；没有再往 `powersystem:manual-alarm-events:v1` 里发一份，避免重复广播。
- **返回的是提交后的那一行**：写操作不做乐观更新，重新查一次库再回给页面。
- **解读结果服务端拉平**：`result` 有 v1/v2 两套结构，页面是原生 JS，不引入工程里的 `lib/interpretation.ts`，改在 Go 里把 `conclusion.text`、`findings`、`analysis.findings`（模板占位用 facts 的 `display_value` 替换）、`suggestions`、`limitations`、`facts` 拉成字符串数组，页面只负责渲染。`reason` 码翻译成中文也在这层。

## 三、前端：独立静态页

`stages/04-frontend/public/demo/index.html` 单文件（Vite 会把 `public/` 原样拷到 `dist/`），零构建依赖、零 Vue 代码。因为落在 `dist/demo/index.html`，`try_files $uri $uri/` 直接命中，**nginx 配置一行没改**。

页面结构：顶栏（产品名 + 操作账号 + 退出）→ 左卡片（设备搜索、级别、解读方式、request_id、创建）→ 右侧当前告警（徽章、时间线、解读结论/事实/建议/局限、确认/恢复/主站查看）→ 底部最近 20 条。

入口改的是主站左侧栏底部那颗按钮：`App.vue` 里 `RouterLink to="/assistant"` 换成 `<a href="/demo/">`（整页跳转，不进 SPA 历史栈），图标 `help` → `bolt`，文字「使用说明」→「演示台」。`/assistant` 本身仍在导航的「助手」项里，没有丢入口。

两处交互是为演示现场改的：

- **设备下拉**：进页面不铺开整张设备表，点进输入框或开始搜索才展开；点空白处收起。第一版一进来就展开 20 条，把级别、解读方式全顶下去了。
- **不要原生 confirm**：`window.confirm` 会阻塞整个标签页、在演示时弹出系统框，而且被浏览器「阻止此页面创建更多对话框」静默拦掉时返回值是 false ——恢复按钮会变成点了没反应。改成按钮两步确认：恢复按钮文字变「再点一次确认恢复」5 秒，创建按钮在 model 模式变「确认消耗 1 次模型额度 · 再点一次」6 秒，超时自动还原。

父版链条 `health-rows-20261030-r1` → `demo-console-20261030-r1` → `-r2` → `-r3`。r1 时 api 与 frontend 一起 `up -d --no-deps --force-recreate --wait`（先 api 后 frontend，避免 nginx 起在 api 前面），之后两批只重建 frontend，api 容器 ID 保持 `5c0fd03b4cdd` 不变。

口令文件是在 r1 激活后写进容器的：

```sh
docker exec powersystem-stage4-api-1 sh -c \
  'echo <base64> | base64 -d > /data/demo-console.json; chmod 600 /data/demo-console.json'
```

（base64 包一层是为了绕开 `$` 与引号在三层 shell 里的转义。）文件落在 `api-state` 卷里，r2/r3 只重建 frontend，所以口令一直有效；将来重建 api 容器也不会丢。

## 六、已知边界与后续可做

- 口令是**单一口令**，没有独立账号；确认动作的 `acked_by` 统一记为配置里的 `actor`（现为 `p0-admin`）。这是「谁有口令谁就能演示」的取舍，审计上不能区分具体人。
- 页面不防重放也不做 CSRF 令牌：写操作要 `Authorization: Bearer`，浏览器跨站请求拿不到 sessionStorage 里的令牌，实际风险低；但如果将来改成 Cookie 会话，必须补 CSRF。
- 「当前告警」只按 `scope=active` 自动带出最新一条；如果要一次看多条活动演示（多设备并行演示），需要再加多选/列表区。
- `pageSize` 类的自适应、暗色主题、手机端细节都没做；手机上左卡片与右侧会堆成一列，够用但不精修。
