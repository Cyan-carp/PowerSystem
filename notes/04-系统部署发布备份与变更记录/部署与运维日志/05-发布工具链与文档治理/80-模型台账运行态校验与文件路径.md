# 80 · 模型台账：运行态校验与文件路径

> 补 [[79-前兆注入与模型切换]] 暴露的三个断点中的前两个：**提升只改台账、不换文件**，以及**候选文件位置在前端不可见**。

## 一、问题

模型换版有四段：训练产出 → 登记 → 页面提升 → 运维换文件。页面只能完成第三段，于是存在两个静默风险：

| 断点 | 后果 |
| --- | --- |
| 提升 ≠ 生效 | 台账显示 A 现役、容器里跑 B，质量指标按台账版本归类，统计全错 |
| 文件位置不可见 | 非技术人员不知道候选文件在哪，换版必须问运维 |

## 二、改动

### 后端（`prediction_quality.go`）

| 项 | 内容 |
| --- | --- |
| 新增 `runtimeModelVersion()` | 带 2 秒超时请求 `AI_URL/health`，取 `model_version`；任何失败返回空串，不拖垮列表 |
| 列表响应 | 增加 `runtime_version` 字段 |
| 列表项 | 增加 `artifact_path`（此前只存不返回） |

### 前端（`PredictionQuality.vue`）

| 项 | 内容 |
| --- | --- |
| 版本表 | 新增「文件位置」列（16% 宽，`word-break` 换行），空值显示 `—` |
| 不一致提示 | `runtime_version` 与台账 active 版本不同时，表格上方琥珀色告警条：「台账现役为 X，推理服务实际加载的是 Y」 |

前端不改任何写操作，提示只做告知。

## 三、验证

接口实测（`p0-admin`）：

```
runtime_version = stage3-xgb-89e6530c9e29
  stage3-xgb-89e6530c9e29  status=active   artifact=/opt/powersystem/runtime/v6-quality-20261101/train/out4/stage3-xgb-89e6530c9e29
  stage3-xgb-6eac6e3ee856  status=retired  artifact=ai-predict:/model
```

台账现役与运行态一致，告警条按预期不显示。此前 `artifact_path` 存的是 `precursor-20261102` 这类短标识，已用 SQL 更新为完整目录。
