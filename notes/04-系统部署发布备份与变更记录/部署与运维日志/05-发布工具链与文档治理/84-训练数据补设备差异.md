# 84 · 训练数据补设备差异（B 方案第一步）

> 承接 [[83-真值容差试验失败与回滚]]：口径改不动，问题在模型学错了特征。这条记录改的是**训练数据的分布**，不是模型结构。

## 一、根因

对比两侧的温度公式，其实完全一致：

```python
temperature = 25.0 + 0.25 * power + 3.0 * max(0, sin(π*(hour-7)/12)) + 噪声
```

差别在**参数**：

| 项 | 生成器（训练） | 模拟器（线上） |
| --- | --- | --- |
| 设备功率 | 三台完全相同 | 143 台各不相同 |
| 设备温度偏移 | 无 | 每台 ±1.5℃ 固定偏移 |
| 噪声 | ±0.7 | ±0.35 |

后果：训练集里「功率 90 的设备 51℃」和「功率 82 的设备 47℃」从未同时出现，模型只学到「51℃ 算热」，没学到「功率高所以热是正常的」。

线上 PV-02 场站六台设备同处一片日照，功率都在 80–90，温度都在 47–52，模型把这些全部判成高风险。

## 二、改动

`generate.py` 加两个系数：

```python
DEVICE_EFFICIENCY = {"INV-1001": 1.00, "INV-1002": 0.93, "INV-1003": 0.86}
DEVICE_TEMP_OFFSET = {"INV-1001": 0.0, "INV-1002": 1.3, "INV-1003": -1.2}
```

功率乘效率，温度加偏移。生成后同一时刻：

```
INV-1001  power 89.8  temp 51.0  residual 28.6
INV-1002  power 86.9  temp 51.2  residual 29.5
INV-1003  power 82.1  temp 47.0  residual 26.5
```

温度差 4.2℃，残差只差 3℃——这正是线上该有的形态。

## 三、重训结果

| 项 | 老模型 `89e6530c` | 新模型 `9d5056e4` |
| --- | --- | --- |
| 训练样本 | — | 97080 |
| 正样本 | — | 7200 |
| precision | 0.943（F1） | 0.963 |
| recall | — | 0.992 |
| F1 | 0.943 | **0.977** |
| threshold | 0.325 | **0.225** |

候选已登记为 `candidate`，未切现役。

## 四、必须提醒的两点

1. **合成数据的 F1 不能直接外推**。上一个模型合成 F1 0.943，线上 precision 只有 15.6%。同一个坑不能踩第二次。
2. **阈值从 0.325 降到 0.225**，意味着更容易报警。如果设备区分度没真正建立，误报只会更多。

上线前必须在真实数据上验证，方式见下。

## 五、验证计划

用 15:00 的 PV-04 窗口做一次试用：

1. 试用前记录 14:30–15:00 的 high 预测数（旧模型基线）；
2. 切到 `9d5056e4`，观察 14:30–15:10；
3. 对比：新模型是否只对 PV-04 的目标设备报警，其他设备是否安静；
4. 不满意可在 10 秒内回退（`/rollback` 已上线）。

风险可控：试用不重启、可一键回退，最坏情况是半小时内多几条误报。
