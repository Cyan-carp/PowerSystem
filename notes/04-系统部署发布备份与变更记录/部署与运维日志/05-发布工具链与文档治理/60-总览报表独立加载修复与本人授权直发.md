# 60 · 总览报表独立加载修复与本人授权直发

> 本页记录本次无数据现象排查、前端修复和所有者明确免门禁/免新备份的实际发布。当前状态见 [[00-当前系统状态]]。

## 一、现象与原因

- 用户反馈刷新后总览与报表看不到数据。旧页面通过`Promise.all`等所有请求成功后才统一赋值，可用率历史扫描会拖住其他已成功接口；任一失败还会阻止其余结果显示。
- 生产旧版访问记录可见summary、overview、alarm-timeliness及availability的200响应，也存在availability的499。不能将该现象认定为数据库清空。
- 独立复核确认旧前端上传完整、镜像来源有效，既有全备密文实哈匹配；但旧门禁未覆盖两个报表接口，状态页顶部还残留旧指针。本批仅修前端及发布登记，不修改后端查询或备份选库算法。

## 二、修复范围

1. 总览各区域分别提交结果，历史曲线并行开始；数据质量慢查询不阻塞指标、场站或告警。刷新期间保留上次结果。
2. 报表只查询激活页签；场站、设备选项独立加载。切页或重查取消前轮可取消请求，忽略晚到响应。
3. 加载、接口失败、真实空结果分别表达；移除生产页面的`npm run mock`提示。导出查询使用已提交的窗口/筛选，窗口标签对应实际提交范围。
4. 新增轻量`useLatestRequest`及页面级回归检查；不改变API契约、生产依赖、权限、三库或遥测写者。
