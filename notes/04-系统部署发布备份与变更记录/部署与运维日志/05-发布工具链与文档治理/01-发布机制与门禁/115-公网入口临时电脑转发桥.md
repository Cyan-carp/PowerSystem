# 115 · 公网入口临时电脑转发桥

> 记录本地服务器出网异常时，将现有云 Nginx 回源临时接到所有者电脑，再经内网回到原 VM117 的一次性处置。当前生产事实仍见 [[00-当前系统状态]]；本页不新增长期部署规则。

## 一、故障与决策

- `www.cyancarp.cn`、新云 IP 与旧云备用入口均返回 502。新云 Nginx 与 FRPS 在运行，但主端 `3667` 和管理端 `7070` 无监听；VM117 的两条 FRPC 分别连接两台云主机超时。
- VM117 原网页 `127.0.0.1:18080/`、API 和相关容器仍健康；active 为 `user-management-20261109-r1`、pending=false、镜像匹配接受清单。PVE/R730XD 可达内网网关，外部 HTTP/HTTPS 与两云入口超时；本机电脑 WLAN 可连接新云。
- 所有者选择“电脑只做转发桥”，不复制或启动另一套业务、数据库或模拟器。暂不改变 active、镜像、卷、私有配置与写者身份。此举只恢复公网到 VM117 的入口，不修复 VM117 自身的互联网出口。

## 二、临时链路与现场范围

```text
浏览器 → 新云 Nginx:443 → 新云 127.0.0.1:3667
       → 本机 CYAN-CARP SSH 反向隧道（WLAN 出网）
       → 本机以太网 192.168.111.235 → VM117 192.168.111.153:18081
       → VM117 127.0.0.1:18080 → 原 frontend/API 与 21 服务
```

- VM117 新增**临时运行态** `powersystem-temp-web-relay.service`：`systemd-run` 启动非 root 的 `socat`，仅绑定 VM 内网 `192.168.111.153:18081`，只接受电脑 `192.168.111.235/32`，转发到原回环 `127.0.0.1:18080`。PVE `.3` 请求该端口得到空响应，电脑请求首页/API 均为 200。
- 本机以现有 SSH 公钥认证到新云，`-R 127.0.0.1:3667:192.168.111.153:18081`；云端只在回环监听 3667，现有 Nginx 配置未修改。电脑初始 `ssh.exe` PID 29200；隐藏 PowerShell 守护 PID 39184 只在该精确隧道进程退出后重连。PID 是本次现场记录，重连后以完整进程命令行识别，不沿用旧 PID。
- 测试端口 `13667` 曾以独立 SSH 隧道验证云回环到 VM 首页/API 均 200，随后已停止并复核云端该端口无监听。没有上传项目文件、安装软件、改云防火墙或重建容器；未生成本批备份，未执行发布门禁或功能测试。

## 三、验证与限制

- 新云 `127.0.0.1:3667/` 返回 200；公网 `https://www.cyancarp.cn/`、`/api/v1/ping` 和 `https://8.138.42.212/` 均返回 200；ping 业务体 `code=0`、`telemetry_ready=true`。匿名无效 ticket 的 WSS 升级请求返回预期 401，只证明请求已到鉴权层，不代表带真实 ticket 的 101 已验。旧云入口现查 502。原发布指针、pending 与接受镜像保持不变。
- 原 `powersystem-web-primary-frpc` 仍每约 30 秒报连接 `8.138.42.212:7000` 超时，因此此时不能撤掉电脑桥。旧云备用入口没有接到本桥，仍需另行核实。
- 电脑必须同时保持 WLAN、以太网、供电和用户会话在线；断电、休眠、重启或有线内网故障会令网页再次不可用。守护可在电脑在线时重连 SSH，但不保证电脑重启后自动启动；VM 临时 unit 也不随重启恢复。此次只核匿名首页/API HTTP 200，未凭此签收登录、WebSocket、写入或长期稳定性。

## 四、恢复原链路与清理

1. 先从 VM117 现查到新云 `7000` 可达，并核两侧 FRP、Nginx、生产 active/pending；不能仅凭电脑可上网判定本地服务器出口恢复。
2. 在电脑上先停止本批隐藏守护，再按精确 `-R 127.0.0.1:3667:192.168.111.153:18081` 命令行停止该批 SSH 隧道。不要按进程名结束其他 SSH 会话。云端 3667 释放后等待原 FRPC 自动注册，实核监听来源为 FRPS 而非 SSHD。
3. 复测主域名首页、API、必要的 WSS 与备用入口；若原 FRP 未恢复，可重新启用本批电脑隧道。原链路稳定后停止 VM `powersystem-temp-web-relay.service`，复核内网 18081 关闭、无残留 SSH 守护与测试端口，再更新唯一状态页和本日志。

## 五、2026-11-11 原链路恢复与临时桥清理

- 切回前现查 VM117 两条 web FRPC 与临时 unit 均 active；主 FRPC 已连新云并每约 30 秒重试网页代理，失败码 `port unavailable`，因为电脑 SSH 正占云端 3667。云端 7070 已由 `frps` 监听、来源对账 `pending=false, ready=true, sources_match=true`；旧云入口已恢复 200。VM 本机网页 200，生产 active 仍 `user-management-20261109-r1`、pending=false、21 镜像匹配接受清单。
- 按精确进程身份先停电脑守护 PID 39184，再停带本批 `-R` 映射的 SSH PID 29200；电脑复核两个进程均不存在。短暂返回 502 后，原 FRPC 于北京时间 2026-11-11 19:39:39 记录 `start proxy success`。云端 3667 与 7070 均由 `frps` 监听，不再由 `sshd` 占用。
- 公网主域名、两个 IP 首页均 200；主入口 ping HTTP 200、业务 `code=0`、`telemetry_ready=true`；VM 出网访问新云 ping 200，R730XD 来源维护 timer active、最近 service success、客户端 `entry_recovered=true`。无登录态或有效 ticket 的 WSS 101 验证，本次不将匿名短查记为完整功能验收。
- VM 停止 `powersystem-temp-web-relay.service`，确认 18081 不再监听。`socat` 退出曾使临时 unit 留下 `failed/exit-code` 状态，随后 `reset-failed` 清零；最终 `inactive/dead`、`Result=success`、`ExecMainPID=0`、`FragmentPath` 为空。测试端口 13667 在前一日已清，无本批临时文件或目录需删除。
- 本轮只恢复网络入口，未修改应用镜像、数据库、发布指针、云 Nginx 配置或云防火墙；没有新上传、备份和发布门禁。出网中断的上游具体原因尚未取证，不能把一次恢复视为长期稳定性证明。
