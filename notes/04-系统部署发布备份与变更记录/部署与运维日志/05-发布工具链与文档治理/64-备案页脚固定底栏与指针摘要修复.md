# 64 · 备案页脚固定底栏与指针摘要修复

> 本页记录域名入口注入的备案页脚造成整页滚动的原因、最小改动，以及同批修正上一批手工激活写错的指针摘要。当前状态见 [[00-当前系统状态]]。

## 一、定位

现象：滚轮在内容区滚到底再滑一下，顶栏、侧栏和卡片整体上移半格；页脚是一条深色横条，与浅色控制台不协调。

先确认归属：`curl` 业务机 `127.0.0.1:18080` 的首页尾部没有页脚，`curl https://www.cyancarp.cn/` 的响应在 `</div>`（`#app`）之后、`</body>` 之前多出一行：

```html
<footer class="icp-footer" style="padding:12px 16px;text-align:center;font-size:12px;line-height:20px;background:#0c1118;color:#9fb0c3;border-top:1px solid #24303f">
  <a href="https://beian.miit.gov.cn/">粤ICP备2026158345号-1</a>
</footer>
```

即：页脚由域名入口在边缘侧拼进 HTML，不在前端代码里，业务机 IP 入口没有。

布局成因三条叠加：

1. 该 `footer` 是 `#app` 的兄弟节点，无定位，参与文档流；
2. 内联样式定死高度 = 12 + 20 + 12 + 1 = **45px**；
3. `.app { height: 100vh; overflow: hidden }` 已把内容区写死满屏。

文档总高 = 100vh + 45px，滚轮在 `.page` 滚到头后冒泡给文档，整页位移 45px。

## 二、改动

- `tokens.css` 增 `--icp-h: 26px`。
- `shell.css` 末节以 `!important` 覆盖内联样式：`position: fixed`、`inset: auto 0 0`、高 26px、去 padding、浅色半透明底（`#fbfcfef0`）配 1px `--line` 上边线、10.5px `--ink-placeholder` 灰字、链接 hover 转品牌蓝；`z-index: 35` 保持低于抽屉（80）与 Toast（400）。
- `main.ts` 在挂载前探测 `document.querySelector('.icp-footer')`，命中才写 `document.documentElement.dataset.icp = '1'`；`shell.css` 据此把 `#app` 收为 `calc(100% - var(--icp-h))`、`.app` 由 `100vh` 降到 `100%`。登录页 `.login { min-height: 100% }` 随之同降，不需要单独改视图。
- 不做全局 `overflow: hidden`：登录页仍依赖文档流，一刀切会裁内容。
- 备案号常驻可见、可点进工信部（法规要求），只压缩高度与配色，不做隐藏或 hover 才显。本机 `vite build` 通过；未新增单测。

## 三、同批修复：父版指针摘要错位

`prepare` 首次返回 `{"completed": false, "blocked": "active_manifest_changed"}`。查因：上一批（63）为手工激活，`active.json` 与接受回执里的 `manifest_sha256` 写成了 `f31e65a7…`，而该版本 `manifest.json` 的真实摘要（`sort_keys` 序列化后 sha256，见 `production-stack.py` 的 `digest()`）是 `d6ecd779…`。`accepted()` 比对不一致，`status`/`publish`/`rollback` 都会判错。

处置：只改这两个文件的该字段，镜像、容器、发布内容一律不动；`immutable()` 已逐个校验 `manifest.files`，文件未变是前提。修复记录写在该版本目录下 `pointer-digest-repair-20261030.json`，含原值、真值、原因与证据。修复后 `prepare` 正常完成（`completed: true`，`freeze.frontend_chunks` 通过）。

## 四、发布与核验

- 快照：591 文件，sha256 `eba5fb4d…1086`，revision `6e1ecf2` + 14 项显式增量（仅 `04-frontend`，不含其他会话的后端未提交文件）；上传后服务器 `verify` 通过。
- 构建：`powersystem-frontend:ui-icp-footer-20261030-r1`，镜像 `sha256:0d6f6e82…1c0b`。
- 激活：沿用 63 的手工路径——用候选 `private/compose.json` 只重建 frontend（`--no-deps --force-recreate --wait`），采集 20 容器投影写入接受回执，再同步 `active.json`（原指针存 `previous-active.json`）。这次摘要按 manifest 现算，`status` 复检 `pending: false`。
- 上线事实：20 服务运行、frontend healthy、重启 0；公网入口 `index-BBFNE7uC.js` / `index-Czy5ELVM.css`，样式内含 `.icp-footer` 覆盖与 `html[data-icp]` 两条规则，入口 JS 含页脚探测；域名首页仍带注入页脚且已指向新分块。
- 未执行项如实登记：gate_executed=false、gate_passed=null、tests_executed=false、new_backup_created=false；本轮没有新恢复点，页面实际观感由本人查看后判定。

## 五、回滚依据

旧容器 `8680728f9ea3`、旧镜像 `sha256:a490a2ed…` 与父版冻结编排均在，一条 `docker compose ... up -d --no-deps` 可换回；数据层未动，风险只在前端静态资源。
