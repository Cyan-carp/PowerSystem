# 助手报表回答渲染修复发布（87）

> 活动指针与门禁状态只写 [[00-当前系统状态]]。本批只换 agent-rag 一个镜像。

## 一、问题

11-03 14:53 提问「哪个场站今天出力下降最明显？」，助手把查询参数和后端 `energy_summary` 用 `json.dumps` 原样贴进正文，正文里出现 `"kwh": null`、`"complete": "false"` 等原始字段，没有任何结论。根因在 `rag_agent/v4.py` 的 `finish()`：只要本轮 `result['reports']` 非空，就用固定模板整体覆盖回答，且模板直接字符串化了汇总字典。

数据侧的成因（当天日聚合未产出、入库积压）见 [[85-遥测入库积压与发电量归零排查]]。

## 二、改动

只动 `stages/08-agent-rag/rag_agent/v4.py`，新增三个渲染辅助函数，替换报表分支：

- `_energy_body()`：全部缺失时输出「本轮没有取得任何有效发电量」+ 缺失设备日数 + 窗口 + 替代方案（改查最近 7 个已结束自然日或看实时功率）；有数据时按场站输出 Markdown 表格（场站 / 发电量 / 是否完整）与合计，不再出现 JSON。
- `_report_body()`：非发电量报表改为自然语言描述范围、窗口、数据行数。
- `_query_window()` / `_scope_text()`：把 `query` 字典转成「北京时间 … 至 …（右端不含）」「全部场站 · 按场站分组」这类可读文本。

同时补口径：`business_report` 的工具提示里加一句「energy_daily 只覆盖已结束的自然日，问『今天发电量』时不要查当天窗口，直接说明当天尚未结算并建议近 7 天或实时功率」。

提交 `f7bc408`，源码快照 `9295b106…`（635 文件）。

## 三、发布方式

`prepare` 会因容器启动时间变化判 `running_baseline_drift`，按授权手工激活：

1. 复制 `model-features-20261103-r1` 候选目录为 `answer-render-20261103-r1`；
2. 覆盖文件只含 `agent-rag` 一项；
3. 用**基线镜像 + COPY 单个 py** 构建（`d05f9e13` + `1f5…`），不走完整 `pip install`：完整构建会重装 torch 196 MB，实测卡在下载十几分钟没进展。

构建时踩到一个坑：`FROM sha256:<64位>` 会被 Docker 当成仓库名去 pull 而失败，报 `invalid repository name`；必须先把基线 `docker tag` 成普通名字再 `FROM`。
