# IR-S02 过期通知、演示台与批量探针手工激活（98）

> 生产当前指针以 [[00-当前系统状态]] 为准。本批承接 [[97-IR-S02过期收尾手工激活]]，所有者本轮要求把过期飞书提醒写入、在左下角演示台展示积压/S02/S04 状态，并在测试阶段生产服务器做大量过期样本试验。S03 缺失熔断和 S04 容量后端没有随本批上线。

## 一、改动与数据边界

- API：S02 更新原行与业务通知 outbox 同事务；正式样本与 `ir_s02_probe_` 受控演练样本按事件键和指标分开。飞书卡片明确“异常留档不等于成功”；演练卡片明示受控测试。演示台只读接口复用现成队列探测快照，不因网页刷新扫描大表。
- 前端：`/demo/` 增加 7 天窗内/窗外待处理、S02 开关、正式样本在本次 API 启动后的过期累计；观测失败显示未知。S04 明示“未上线，接口待接入”，不造处理速度或余量。
- 监控：基于线上实哈一致的原 10 条 Prometheus 规则，追加正式频繁过期、受控演练频繁过期、过期出口停摆三条规则；原遥测空接收器和 Agent 路由保留，新过期规则走 `feishu-expiry`。演练探针从正式频繁过期表达式扣除。
- 数据：本批无 schema/索引迁移，不删除任何一行，不碰既有 881 万 `owner_abandoned`、TDengine 历史或 `energy_daily` 历史值。批量探针只新增独立 `run_id` 的 8 天前 inbox 行，正常 FIFO 7 天窗不会取它们；S02 处理后保留原行终态，不当作业务成功。演示台正式过期累计排除这类探针。

## 四、1 万条受控过期探针

主动试验硬上限 8 分钟；专用 `run_id=ir_s02_probe_bulk_20261107_b` 一次新增 **10,000 行** 8 天前 inbox 样本，均引用原有设备但只在 inbox 留档，不写 TDengine 或业务告警。原行保留；正常 FIFO 只选 7 天内行，因而本批样本只由 S02 过期出口处理。试后只读核对如下：

| 项 | 本轮结果 |
| --- | --- |
| S02 排水 | 10,000 行全部自动变为 `quarantined/window_expired`，pending **10,000→0**，人工补收尾 **0**；轮询记录在第 14.1、45.0、75.9、96.7、127.8 秒分别看到每批累计 2,000、4,000、6,000、8,000、10,000 行。总脚本 130.2 秒，未超过 10 分钟上限。单次 1 万行突发通过，**不能外推长期持续输入能力**。 |
| 非正式数据隔离 | 本批 TD 确认 0、业务成功 0；目标设备该历史日 `energy_daily` 有 1 行且摘要前后相同。旧 `owner_abandoned` 固定两段各 1,000 行的 count/max/hash 前后相同；不是全量 881 万行指纹。没有删行、清卷或改 TD 历史。10,000 条测试原行保留终态并带独立 run_id，后续不再进入正常处理；演示台正式累计以 `expiry_rows_total - expiry_probe_rows_total` 计算，试后两者均为 10,000，正式累计为 0。 |
| 飞书业务通知 | 本批独立 `inbox-expiry-test:` outbox 事件 **1 条**，`sent_at` 已写、重试次数 0。既有通知 worker 只有收到适配器 HTTP 200 才写 sent_at；适配器仅在飞书 webhook 返回成功码后给 200。2026-11-08 所有者提供群内截图，确认“入库过期受控演练”卡片及两条对应监控消息显示。正式事件键与演练键分开，不会吞掉同一刻的真实过期提醒。 |
| 监控升级告警 | `PowerSystemInboxExpiryProbeBurst` 在 Prometheus 为 firing；Alertmanager webhook 成功次数 **0→1**、失败仍 0；专用飞书路由生效。正式频繁过期表达式扣除探针计数，演练不会被当作真实批量故障。 |
| 队列指标刷新 | 试验脚本结束瞬间，60 秒队列快照还显示窗口外 pending 2,000，故保存的自动汇总 `passed=false`。随后**独立只读复核**：数据库本批 pending=0、终态=10,000；下一次队列探测 `known=1`、窗口外 pending=0，API/前端/适配器仍 healthy、Prometheus 13 条规则仍载入。原 `passed=false` 回执不改写；本项属于观测刷新延迟，不是 S02 留有 2,000 条。 |

本批只证明 1 万条突发样本可自动收尾、飞书接口及监控路由接受了演练消息；不能据此说正常入库处理余量已解决，S04 仍为网页占位。演练数据在数据库中以终态和专用 run_id 留作审计，**不删除**；普通演示告警列表、TDengine 和日发电量不接收它们。Prometheus 的演练历史和飞书演练消息会保留，不能把它们称作正式故障。
