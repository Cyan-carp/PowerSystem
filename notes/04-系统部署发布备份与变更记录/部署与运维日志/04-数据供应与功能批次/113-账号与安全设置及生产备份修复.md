# 113 · 账号与安全设置及生产备份修复

## 范围与授权

所有者要求将网页与手机页「账号与安全」部署生产，先立即备份，明确跳过技术发布门禁。功能仅展示本人账号、姓名、角色，支持核旧密码后修改本人密码；新密码 8–72 字节且不得与旧密码相同，成功后旧 JWT 后续请求失效，页面退出到登录页。Windows 客户端托盘偏好不变。所有者未要求在生产修改任一账号密码，本批未做此操作。

## 备份与修复

首次全备 `powersystem-20261109T151552Z` 在 `queues_snapshot` 失败、无密文；模拟器队列 SQLite 已约 12 GB，旧快照预算 600 秒。旧包装脚本没有保留助手原始错误，因此预算不足是依据队列大小和近期同阶段失败作出的判断，不称精确异常已被取证。第二轮 `powersystem-20261109T154828Z` 延长队列预算后通过该阶段，却在 `release_assets` 失败、无密文：现行 API `19c12fd7…` 原是手工构建，没有受控 `source-build` 回执，其余四个应用镜像来源正常。未补造回执。

第三轮版本化备份助手把队列快照预算增至 2400 秒、错误输出显式保留；针对该确知手工 API 镜像，归档实际镜像 tar、现存完整源码/二进制及逐文件摘要，其余四个应用仍按原受控回执核验。独立预演的采集与离线核验通过。正式全备 `powersystem-20261109T163520Z` 在当前父版上成功：密文 **4,635,269,717 字节**，SHA-256 **`ff92359f8a96cc48ee53f2790a236d210ffd9cfdbc05ec8747de10345c018790`**；主、副目标上传阶段均成功，控制器 `verified_full_baseline()` 复核本地密文摘要与回执通过。只读内容检查解密、内层 SHA、必备私有文件、PostgreSQL TOC 和两份队列快照，共核 4,898 文件，`status=ok`；这不是完整隔离恢复演练，也未从两个远端分别回读整包重算摘要。

三轮备份的维护停复均只造成已登记 RAG、Ops、gateway 写者的 StartedAt 改变；每次确认 ID、镜像、重启数及全体健康后按所有者免门禁授权重签运行基线，没有把失败轮次写成成功。定时器原仍指向旧脚本；本批独立 systemd drop-in 将其 `ExecStart` 指向已实际成功的版本化 r3 脚本。当前 timer `enabled/active`、服务旧 failed 状态清零，切换后下一次定时全备尚未实际执行，不能预称成功。来源与路径见 [[02-工程规范边界与验收治理/项目工程规范/07-历史记录与上传定位卡/2026-11-09-备份队列快照预算修复上传定位卡]]、[[02-工程规范边界与验收治理/项目工程规范/07-历史记录与上传定位卡/2026-11-09-备份发布材料兼容手工镜像上传定位卡]]。

## 来源、迁移与激活

前端以现行 `mobile-ui-20261109-r3` 的 `a4714285…bafa` 完整快照为基；API 以现行手工镜像留存源码树 `a42c4fe1…a9a9` 为基。本地 Git HEAD 比生产 API 多 13 个文件、11 个同名文件内容不同，因此没有从工作区整树重建。两份现行源树拼接后只应用本次账号补丁与新文件，统一 LF；现行 API 原无 021 迁移，`store.go` 只增加 `022_user_session_version.sql`。生产旧质量分析手工修复三文件与原件按 LF 规范化后逐字节等价。完整复合快照 `9e65f27db470595d04b4278f6cc151c7d5d23e6c210aeaede03c1ce64e211828`（655 文件）由服务器 `source-build.py verify` 通过；单一 revision 标签沿前端 df54 基底，后端现役手工来源及补丁摘要另记独立 `provenance.json`，不误称后端整体来自 df54。

新 API 已有受控构建回执，版本化备份助手在已激活版本上再次做独立发布材料采集与离线核验：`manual_images_verified=0`、`frontend_image_verified=true`，预演目录已直删。现有成功全备是**发布前父版恢复点**，不是新 API/前端生效后的全备；下一次定时备份须以其实际回执再确认。上传与激活定位见 [[02-工程规范边界与验收治理/项目工程规范/07-历史记录与上传定位卡/2026-11-09-账号与安全设置上传定位卡]]。

## 临时物与保留

PVE 三轮备份脚本及账号发布包的上传暂存、本机对应 `artifacts/` 暂存均按实查归属直删并复核不存在；VM117 三个发布材料预演目录同样直删核不存在。VM117 r1/r2 失败候选备份工具确认无定时任务引用后直删核不存在。现用 r3 版本化备份工具、账号批次源码/镜像/构建回执、候选与接受回执及成功密文刻意保留，作为当前运行和恢复依据；失败备份时序与维护回执保留，不将失败记作可恢复密文。
