## 原日志 32 · 设备编码与名称视觉区分（2026-10-22 13:55）

### 背景

设备管理、健康排行、统计报表三页的设备列高度相似：同一场站 143 台设备的编码只有末尾两位序号不同（`PV-01-INV-01`…`48`），名称同样只有序号不同（`示范园区 A 屋顶光伏片区 01号逆变器`）。扫读时每行都是同一串字符，缺少锚点。

改动方向是**弱化常量、强调变量**：把不变的部分压到次要层级，唯一变化的部分提到前面。

### 变更内容

| 文件 | 作用 |
|---|---|
| `src/lib/device-code.ts` + `.test.ts` | 编码分段解析、名称分段解析、场站色映射（新增 8 项单测） |
| `src/components/DeviceCode.vue` | 编码渲染：`PV-01-INV`（弱化灰 12px）+ `01`（等宽 13.5px 加粗亮色） |
| `src/components/StationCode.vue` | 场站编码带色点渲染 |
| `src/components/DeviceName.vue` | 名称渲染：前缀弱化 + 序号强调 + 后缀弱化 |
| `src/styles.css` | `:root` 新增 `--st-0`、`--st-t1`…`--st-t5` 及 `.dev-*` / `.station-*` 分段样式 |
| `views/DevicesView.vue`、`HealthRankingView.vue`、`ReportsView.vue` | 接入组件，三个长列表加 `stripe` |

场站色由 `station_code` 经哈希（`hash×33 % 5`）映射到 5 色，低饱和且避让红黄绿状态色，颜色只承载场站、不承载状态。实测 PV-01/02/03/04 + ST-01 恰好各得一色；新增场站自动分色，无需维护映射表。

色点取台账的 `station_code` 字段，不从编码文本推断——否则 `INV-M4-AI-…` 这类历史设备会算出与所在场站不符的颜色。

### 本次新踩的坑

1. **`production-stack.py status` 的指针可能已被他人更新**。上次记忆里的 `assistant-ui-20261019-r1` 与本次记录的 `ui-paging-20261022-r1` 都说明：发布前必须现查 `status`，不要依赖记忆中的指针。
2. **直接 md5 比对会把换行符差异全部报成内容漂移**。84 个文件里 24 处告警，实际全是 CRLF/LF。正确判法是 `diff <(tr -d '\r' < A) <(tr -d '\r' < B)`，确认后再决定是否需要同步。
3. **`grep -c -F --st-t1` 会被当成选项解析**（前导双横线）。须写 `grep -c -F -e "--st-t1"`。
4. **后端验证路由分块时，公网 HTML 里看不到分块引用关系**（压缩后 `__vite__mapDeps` 在本次构建中不可见）。直接用 `docker exec <frontend容器> ls/grep /usr/share/nginx/html/assets` 更可靠，且不需要逐个 curl。
5. **Vite 会把小组件合并进其他分块**，按文件名 `DeviceCode-*.js` 去找会 0 命中。找不到的特征应改为全局扫 `assets/*.js` 再定位实际所在分块。
