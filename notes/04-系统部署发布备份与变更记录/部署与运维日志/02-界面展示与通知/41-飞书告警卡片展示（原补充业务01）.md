# 41 · 飞书告警卡片展示（原补充业务 01）

> **版本归属**：V2 · 智能体升级（阶段五通知展示，2026-10-15—16）。

> 用于本项目完整演示告警状态及关键字段；记录既有卡片实现与展示边界，不新增通知目标或执行入口。2026-10-16 按源码及既有记录补写，未重新发送消息。

## 一、问题与目标

原阶段五已有业务告警、监控告警及飞书投递链路。本补充项把设备越限和 AI 故障风险事件以中文卡片展示，便于演示中快速辨认设备、场站、指标和状态；原通知链路仍归第一版阶段五，卡片样式及字段说明集中在本页。

## 二、设计原理

适配器将合法业务事件转换为飞书 `interactive` 消息；监控告警继续使用既有文本消息。卡片只呈现上游已确认的事件，不计算阈值、预测结果或告警状态，也不提供确认按钮、审批或设备控制。

| 事件状态 | 卡片表现 |
| --- | --- |
| triggered | 红色“触发告警”，突出触发值 |
| acknowledged | 橙色“已确认” |
| recovered | 绿色“已恢复” |
| closed | 灰色“因配置变更关闭” |

卡片包含设备、场站、中文级别与指标、触发时记录值、触发阈值、事件 ID 和北京时间。数值显示三位小数；恢复/关闭卡片仍是触发时记录值，不应解释为当前遥测值。时间转换失败保留输入原文。

> 设计理由：将展示转换放在适配器，保留原事件 ID、状态机和投递重试语义；颜色帮助阅读，但状态文字及事件身份才是核对依据。

## 三、实现与配置入口

- 卡片构造及签名发送：`stages/05-feishu-notification/feishu-adapter/app.py` 的 `business_message`、`send`。
- 输入校验：事件 ID 必须与告警 ID/状态一致；只接受已支持的业务类别和状态，校验字符串长度、级别及有限数值，拒绝布尔值冒充数值。
- 配置及运行命令唯一见 [[06-代码工作区导航与链接映射/stages-05-feishu-notification-README|README]]。沿用已有受限配置中的群机器人地址、签名和内部认证，不写入本页，不新增公网适配器端口。

## 四、配置流程

#### 步骤 1 · 核对既有通知链路

> 在维护环境核对；前提是阶段五基础链路和原通知目标已配置。本步骤只读，不向群发送消息。

按源码 README 核对业务事件入口、适配器版本和私有配置引用，不复制机器人地址到截图或笔记。

#### 步骤 2 · 通过统一发布入口更新适配器

> 仅在确有代码变更且获得发布授权时执行；会更新指定适配器容器，自动门禁仍必须运行。本次文档整理不执行发布。

候选、固定镜像及完整编排要求见 [[01-项目调研规划与开发建设记录/补充业务/03-生产发布防回退/01-设计与发布流程]]；具体命令见源码 README 和发布 README。

## 五、运行与回退

投递失败保留原失败/重试记录，不能因卡片漂亮而宣称告警已送达。卡片或展示异常时按统一发布入口回到上一份已验收适配器及配置，不清空告警、outbox 或重放历史通知。业务告警确认仍在平台原入口进行。
