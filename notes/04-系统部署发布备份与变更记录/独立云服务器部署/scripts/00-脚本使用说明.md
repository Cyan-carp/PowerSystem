# 独立云部署脚本 · 运行入口

> 本页集中维护可选动态来源恢复脚本及管理来源工具的命令。FRP 自动维护只适用于本项目 R730XD 动态出口等相同环境，是基础部署完成后的附加流程，不是通用安装前提；设计与配置过程见补充业务专题。

FRP 动态来源更新实现版本 **1.1.1（SAS）**，依赖 Linux、Python 3.10+ 标准库、systemd、iptables/ip6tables 和新云已有 Nginx；无 pip/npm 运行依赖。设计、控制台流程和实际状态见 [[01-项目调研规划与开发建设记录/补充业务/04-FRP动态出口自动维护/01-FRP动态出口自动维护]]。本文件是新增脚本命令的唯一维护入口。

## 一、接口与权限

- `POST /_ops/frp-source/v1/challenge`：JSON 仅含 `client_id`；返回 `client_id`、`challenge_id`、`nonce`、`source`、`expires_in=120`。`source` 来自 Nginx 原始 TCP 对端，不接受客户端指定。
- `POST /_ops/frp-source/v1/refresh`：JSON 严格限定 `client_id`、`challenge_id`、`nonce`、`signature`；签名为 HMAC-SHA256，小写十六进制。签名原文依次为 `frp-source/v1`、`POST`、完整 refresh 路径、client_id、challenge_id、nonce、source，以单个 LF 分隔，无末尾 LF。
- 成功返回 `allowlist_updated`、`changed`、`recovered`；客户端另外检查 HTTPS ping，将 `entry_recovered` 单独保存。失败对公网只返回通用拒绝或不可用信息；细分原因仅进入 root 私有状态。
- HTTPS 接收器只监听 Unix socket，限制 Nginx UID；特权执行器只接受接收器 UID，独立校验签名。接收器不持设备密钥、云凭据或防火墙权限。Nginx 须有 realip 模块，以 `$realip_remote_addr` 覆盖来源头。
- 仅支持单一公网 IPv4。设备密钥为 32 个随机字节的 64 位十六进制文本，双端 root:root 600。云身份只读取新云 root:root 600 的专用 RAM 程序用户凭据文件，不读取环境变量、CLI profile 或 ECS 元数据角色。此长期 AccessKey 仅获指定 SAS 规则写权限，须定期轮换。SAS请求使用ACS3-HMAC-SHA256 签名，所有 HTTPS 校验证书、无代理、无重定向。
- 云端配置必须登记 SAS 实例 ID 与唯一目标 RuleId；自动程序拒绝其他覆盖 7000 的放行、目标来源非单个公网 /32、实例不匹配及非目标规则漂移。合法运维导致基线变化时先停 timer、人工审查，再另存旧基线并重新初始化，不自动“接受”变化。

## 二、准备安装

#### 步骤 1 · 核对安装包

> 在两台 Linux 主机上使用已核验 SSH 通道传输整个专项目录；不得把本机 SSH 私钥复制到服务器。下面的相对路径以专项目录为工作目录。

```bash
cd /path/to/独立云服务器部署
sha256sum -c SHA256SUMS
bash -n scripts/install-source-refresh.sh
```

#### 步骤 2 · 仅安装停用的模板

> 新云执行 cloud，R730XD 执行 client。安装器会核对主机身份、安装独立文件及 unit、创建专用目录，并 daemon-reload；不会启用服务、改防火墙、配置云资源或 reload Nginx。已有私有配置不覆盖，运行中的本套服务拒绝直接覆盖安装。

```bash
# 新云
bash scripts/install-source-refresh.sh cloud
# R730XD
bash scripts/install-source-refresh.sh client
```

若主机无 systemd、iptables 或原有项目目录，不自行扩大安装范围；修复前提后再继续。

## 三、控制台完成后的激活

#### 步骤 3 · 完成云资源与私有配置

> 先按专题笔记第四章完成 SAS 防火墙目标规则和专用 RAM 程序用户。本步是前置条件；SSH root 不能替代云控制面授权。所有真实 ID 和出口地址只保存在服务器受限文件。

在新云编辑 `/etc/powersystem-edge/source-refresh-cloud.json`，填写 provider=swas、SAS实例ID、地区、目标防火墙RuleId及client_id，本步骤保留enabled=false。目标规则必须是允许TCP 7000、来源为当前allowed-client-ipv4的单个/32。SAS使用SWAS-OPEN 2020-06-01，不能填写ECS的i-/sg-/pl-资源ID。

在 R730XD 编辑 `/etc/powersystem-edge/source-refresh-client.json`，client_id 与云端一致，保留enabled=false。两份配置均为 root:root 600；云端到步骤5前、客户端到步骤7前才分别开启。RAM策略写权限只能指向指定SAS防火墙RuleId；ListFirewallRules只读权限按官方资源模型需覆盖该账号该地域的firewallrule/*，程序请求始终固定本实例。它不是按实例限定的RAM读取授权。

### 云API凭据文件（仅新云）

> 所有者在RAM控制台创建并授权专用程序用户后，自行将AccessKey写入下面的服务器文件。不要发送到聊天、命令参数或仓库。此文件只给云端执行器，R730XD和HTTPS接收器均不持有云凭据。

本次r3-console批次已将经所有者审查、替换真实账号和目标规则ID的策略保存到新云root私有文件。控制台仅开一个页面，先核对/创建专用程序用户（建议名`powersystem-frp-source`；本次本人实际创建的是`powersystem`，显示名称为“FRP动态出口白名单”，不再重复建号），不启用控制台登录，再创建自定义策略`PowerSystemFrpSourceRuleOnly`并绑定。遇到安全验证由本人完成；超时后先核对实际结果，不能重复提交。复制本次策略的命令只读取权限JSON，不含云凭据：

```bash
cat /etc/powersystem-edge/source-refresh-ram-policy.json
```

上述私有文件仅由本批准备，不是通用安装器的自动产物；重新安装或其他环境应仍从公开模板逐项核对后生成。不要将其他账户的现成JSON直接套用。

首次填写时可使用本次r4批次已安装的新云root辅助工具；须在配置尚未开启、凭据文件尚不存在时执行。它核对新云主机指纹，使用隐藏输入收集ID与Secret及二次确认，仅原子写入root:root 600凭据文件，不调用云API、不启用服务，已有文件拒绝覆盖：

```bash
python3 /root/powersystem-frp-configure-credentials.py
```

此辅助工具是本批私有操作产物，源码与摘要保存在r4证据，不是通用安装器自动安装项。其他环境可在新云root使用受限编辑器准备`/etc/powersystem-edge/source-refresh-cloud-credentials.json`，先以umask 077创建，内容字段严格只有`AccessKeyId`和`AccessKeySecret`，填写后核对root:root 600。模板不含真实值：

```json
{"AccessKeyId":"REPLACE_IN_PRIVATE_FILE","AccessKeySecret":"REPLACE_IN_PRIVATE_FILE"}
```

轮换时在控制台创建同一专用用户的新密钥，原子替换私有文件后检查只读API正常，再禁用旧密钥；不同时扩大RAM策略。不得使用主账号AccessKey或FullAccess。

#### 步骤 4 · 私下建立并传输专用密钥

> 仅在新云生成一次；已存在则拒绝覆盖。通过已核验的管理员 SSH/SFTP 通道，将该文件原样安全传输到 R730XD 同一路径，两端均设 root:root 600，不输出内容、不复制到仓库。不得使用备份口令、FRP token 或聊天中出现的密码充当设备密钥。若尚无经过验证的跨主机文件通道，先由管理员建立通道，不能关闭主机指纹检查绕过。

```bash
python3 -B /opt/powersystem-edge/source-refresh/frp-source-refresh.py make-key
```

密钥轮换先停 R730XD timer 和云端 web 服务，再双端替换；重启 executor 会清除内存中的旧密钥。失败批次保留，禁止把旧密钥写回公开材料。

#### 步骤 5 · 初始化并启动云端服务

> 在新云 root 执行。先确认云凭据与设备密钥已就绪，将云端私有配置enabled改为true；initialize 只读取云规则/主机规则，写本套私有基线，不修改云端或主机防火墙。已有baseline.json时只执行check，不能覆盖或删除基线。失败必须先查明具体原因。

```bash
python3 -B /opt/powersystem-edge/source-refresh/frp-source-refresh.py initialize
python3 -B /opt/powersystem-edge/source-refresh/frp-source-refresh.py check
systemctl enable --now powersystem-source-executor.service powersystem-source-web.service
systemctl is-active powersystem-source-executor.service powersystem-source-web.service
```

#### 步骤 6 · 接入独立 HTTPS 路径

> 在新云 root 执行。先备份当前 Nginx 生效文件；仅在现有 IP HTTPS server 中添加下列 include，不能复制模板覆盖整个现网站点。3667 故障时该路径仍须能到达本机 Unix socket。

```bash
install -o root -g root -m 644 /opt/powersystem-edge/source-refresh/templates/source-refresh-rate.conf /etc/nginx/conf.d/powersystem-source-rate.conf
install -o root -g root -m 644 /opt/powersystem-edge/source-refresh/templates/source-refresh-location.conf /etc/nginx/powersystem-source-location.conf
```

在 IP HTTPS server 的 `location /` 前加入一次：

```nginx
include /etc/nginx/powersystem-source-location.conf;
```

```bash
nginx -t
systemctl reload nginx
```

若 `nginx -t` 失败，恢复本次备份及 include；不得继续 reload。保留既有 IP Host 隔离、证书路径、WSS 配置及 ACME 路径。

#### 步骤 7 · 单次核对后启用 timer

> 在 R730XD root 执行；先将客户端私有配置enabled改为true，不断网或重启业务容器。客户端将白名单已更新和入口已恢复分开报告，FRP自然重连尚未完成时入口可能稍后才恢复。

```bash
systemctl start powersystem-source-refresh.service
systemctl show powersystem-source-refresh.service -p Result -p ExecMainStatus
cat /var/lib/powersystem-source-client/status.json
systemctl enable --now powersystem-source-refresh.timer
systemctl list-timers powersystem-source-refresh.timer
```

每次执行完成后 60～65 秒再次检查，网络故障自动等待下个周期，不重叠执行。一次执行硬超时 220 秒；正常条件下以分钟级恢复为目标，不承诺网络或云 API 故障期间的恢复时限。

## 四、诊断与回退

#### 步骤 8 · 查看脱敏状态

> 云端 root 查看详细代码；R730XD 查看两层更新与公网 ping 结果，不输出私有配置或完整规则。

```bash
# 新云
python3 -B /opt/powersystem-edge/source-refresh/frp-source-refresh.py check
journalctl -u powersystem-source-executor.service -n 30 --no-pager
# R730XD
cat /var/lib/powersystem-source-client/status.json
journalctl -u powersystem-source-refresh.service -n 20 --no-pager
```

`non_target_host_change` / `non_target_cloud_change`：人工核查新增规则或合法维护，不删除基线绕过；`sas_credentials_unavailable`：检查专用RAM用户凭据文件权限和格式；`other_rule_allows_7000` / `other_rule_blocks_7000`：核查SAS防火墙覆盖7000的放行或拒绝策略。不能把禁用宽范围规则视为移除重叠；处置须先保存原规则并经所有者确认，程序不会启停或删除非目标规则。`cloud_readback_pending`：保留 pending.json，后续认证周期先读实际状态再恢复。现有规则不因挑战过期或网络失败被清空。

#### 步骤 9 · 停用并按目标回退

> 先在 R730XD 停 timer 和当前客户端执行，再停云端 web。pending.json 存在且需撤销时，root 执行本地定点回退；它只恢复本次旧 /32，不恢复整表。云权限失效时由所有者在控制台恢复该目标SAS规则，不能扩大来源。

```bash
# R730XD
systemctl disable --now powersystem-source-refresh.timer
systemctl stop powersystem-source-refresh.service
# 新云
systemctl disable --now powersystem-source-web.service
python3 -B /opt/powersystem-edge/source-refresh/frp-source-refresh.py rollback-pending
```

无 pending.json 时不运行 rollback-pending。已提交事务需要回到历史来源时，人工选定 history 文件中旧地址，在SAS控制台与主机目标规则分别恢复并重新核验；不得直接使用整个 iptables-before 规则覆盖共享主机。完成后停用 executor，移除本次 Nginx include 和 rate 文件，经 `nginx -t` 后 reload，保留基线、历史和密钥直到交接完成。

## 五、仅验证新增逻辑

#### 步骤 10 · 运行隔离检查

> 从专项目录执行。全部测试使用虚构云响应、模拟适配器和独立临时目录，不调用真实云 API、不执行真实防火墙修改、不主动断网，不重跑业务全套验收。

```bash
python3 -B -m unittest discover -s scripts/tests -p test_frp_source.py -v
```

Linux 接收器 UID/Unix socket 的隔离检查另见 `tests/test_frp_source_linux.py`，仅 Linux 可执行。真实云端权限、SAS防火墙API修改及公网换址恢复必须待前置配置后分开登记，不能把隔离测试写成已上线。

## 六、7070管理来源维护

#### 步骤 11 · 通过新云22核对管理来源

> 在 Windows 管理电脑的 PowerShell、仓库根目录执行。前提是新云 22 可直连、现有公钥有效且主机指纹已核验；不经跳板。本命令默认只读，不修改规则。

新云 22 的可信 ED25519 指纹为 `SHA256:PUS6mFBOfwdsITlg6Wxl0PP5FYg9wo/4pqrxADeJsyQ`，7070 的 R730XD 为 `SHA256:oRSd9R+Emma9+GXS2WRhv5ztzZQpaqto5frq8iSnAaI`；不能互换。其他电脑先经可信渠道复核，不关闭主机校验。

```powershell
Get-Content -LiteralPath 'deploy/edge-server/独立云服务器部署/scripts/refresh-ssh-admin-source.py' -Raw -Encoding utf8 | ssh -o StrictHostKeyChecking=yes root@8.138.42.212 'python3 -'
```

#### 步骤 12 · 定点应用并核对7070

> 从同一管理电脑直连新云 22；确认检查差异后才应用。`--apply` 备份并替换主机 7070 单一来源及持久文件；其他规则变化时回退，已经匹配时不重载。SAS 云规则须另行核对，本脚本不修改。

```powershell
Get-Content -LiteralPath 'deploy/edge-server/独立云服务器部署/scripts/refresh-ssh-admin-source.py' -Raw -Encoding utf8 | ssh -o StrictHostKeyChecking=yes root@8.138.42.212 'python3 - --apply'
ssh -o StrictHostKeyChecking=yes -p 7070 root@8.138.42.212 hostname
```

22 不可达时先用云控制台恢复可信通路；不放宽为全网。原始来源、完整规则和回退副本仅存私有位置。测试资产为 `scripts/tests/test_refresh_ssh_admin_source.py`；仅在代码变更需要验证时运行对应测试，本次文档整理不执行。
