## 一、版本、场景与结论的边界

**发布范围**

- 当前事实：`v1.0.0` 是六阶段合成演示系统；`v2.0.0` 在此基础上完成 V2-M1～M4 的限定范围技术验收。
- 协作要求：对外写明版本、环境、测试日期和范围；不把某阶段本机通过写成整版服务器验收。

**数据与效果**

- 当前事实：公网演示使用模拟设备和合成遥测；预测模型为合成数据训练，公开数据审计不等于外部事件级效果验证。
- 协作要求：不宣称真实场站预测准确率、提前量、误报率、稳定性或常态时效；取得真实测点定义、遥测及可信故障/恢复账本后另做独立验证。

**智能体建议**

- 当前事实：告警解读和问答是辅助研判，来源可能是事件快照、受控项目文档或公开网页；公开网页、专利原理和事件值不自动成为具体机型操作规程。
- 协作要求：专业来源审核、厂家手册、机型适用性和现场条件仍为待办。任何实际设备操作由专业人员核对并实施；不得把开发阶段的 `assumed_pass_development` 写成专业签字。

**验收证据**

- 当前事实：V2-M4 的最终完整批次、实际页面、回退、最终加密备份/隔离恢复和固定镜像观察有独立记录；旧失败与中断批次保留。
- 协作要求：不能拼接不同镜像或批次的成功项，也不能用协议通过代替来源语义支持、用机器人 HTTP 成功代替群内可见、用旧观察代替新发布观察。详见 [[01-项目调研规划与开发建设记录/第二版-智能体升级/问答及调度业务主智能体/废案-旧智能体方案/02-功能开发与阶段交付/04-测试、安全复核与交付/05-V2-M4测试与交付]]。

**合规**

- 当前事实：公网鉴权、端口收敛、仓库扫描和备份恢复是项目技术复核。
- 协作要求：不称为等保认证、渗透测试通过或真实灾难下新机生产切换已演练。

## 二、身份、权限与智能体能力

- 交互问答使用**当前登录用户 JWT** 访问 Go 的只读业务接口；既有角色权限生效，跨用户会话和伪造身份应拒绝。当前登录用户可读全部演示设备，**没有逐设备授权**。不得把角色权限描述成租户或设备级隔离。
- 自动告警解读由 Go 提供**受限事件证据包**，不是借用某位用户的会话；Agent 不任意读取数据库。平台监控事件通过独立接入进入解读，不把 Alertmanager 飞书通知误认为业务 WebSocket 事件。
- 智能体不确认/恢复告警、不改阈值、不写业务库、不创建工单、不远程控制设备，也不改写模型给出的概率、阈值或既有告警状态。只读问答中的“建议检查”属于文字建议，**不是执行授权**。
- 告警主链路、WebSocket、人工确认及飞书通知不等待模型或搜索。模型认证、余额、限流、超时、无数据或证据不足时，应显示可核对的失败/无法判断状态，不能编造结论；问答失败不算成功回答。
- 交互问答当前受 Redis 原子接纳控制：
  - 每用户滚动 60 秒 10 次、同用户并发 1、全站并发 4、租约 50 秒。
  - 超限 429，接纳存储故障 503。
  - 自动事件解读不占该交互额度。
  - 数值是当前版本配置与验收口径，变更时须更新代码、测试和手册。
- 本地知识库只从受控来源构建，缺口记录不自动入库；公开问题未命中且符合条件才可调用独立博查搜索。搜索来源需保留实际 URL、时间和引用，联网结果不能证明本项目当前设备状态。专业审核仍 `pending`；后续改知识、提示词或来源时重建索引并重跑对应验收。

## 三、数据、隐私与公开仓库

- Git 只放受审源码、配置模板和可公开笔记。`.env`、SSH 私钥、模型/搜索密钥、飞书机器人地址与签名、JWT、备份口令、数据库转储、运行日志中的原问题、缺口 JSONL、审计 JSONL、截图和 `artifacts/` 不进公开仓库或公开知识索引。发布前扫描跟踪文件、构建产物与拟提交内容；零命中仅对当次规则和范围有效。详见 [[02-工程规范边界与验收治理/仓库公开与服务器安全要求]]。
- 值班问答与自动解读的证据、审计、来源哈希分开保存。删除或改写失败批次会破坏验收可追溯性；维护知识缺口只用脱敏汇总，人工补库必须审查来源、版本与内容。
- PostgreSQL 保存业务和通知投递，TDengine 保存遥测，Redis 保存临时状态，网关和模拟器 SQLite 保存待处理队列。克隆仓库不会获得这些数据或模型；不能因服务重启而删除卷，也不能把 Redis 当历史真相。上线迁移要区分初始化 SQL 与已部署库演进。
- 备份密文可放既有**专用**异地目标；解密口令须在 R730xd 外有所有者离线副本，口令与介质位置不写笔记或聊天。每次备份核对两端密文摘要，恢复仅在隔离项目演练；未经单独方案不得回灌生产库或清理历史恢复卷。详见 [[04-系统部署发布备份与变更记录/部署与运维日志/04-备份口令离线交接与整机恢复步骤]]。

## 四、服务器、网络与访问归属

- 项目运行于 R730xd `/opt/powersystem`。不在内网时，已核验的穿透入口是 `root@8.138.10.222:7070`，使用本机 SSH 配置解析的既有私钥（默认相对用户目录为 `%USERPROFILE%\.ssh\id_ed25519`）和已知主机密钥；内网入口 `192.168.111.2:22` 仅在有内网路由时适用。笔记不得写死具体用户名或本机绝对目录。不要关闭主机密钥校验、把私钥上传云端或把连接方式等同于新增服务器权限。
- 云服务器通过原有独立 SSH 入口管理。云主机有其他 FRP/服务；只改**本项目明确归属**的配置。当前项目 Web 链路为 R730xd 回环 `18080` → 云端回环 `3667` → 云 Nginx `443` 的 HTTPS/WSS；旧公网 HTTP `:3667` 外部直连应被 IPv4/IPv6 规则阻断。端口号相同或一次 TCP 探测成功不足以判定服务归属；先核对进程、FRP 映射、监听和防火墙。共享 `19090` 不按号码推定为本项目服务。
- 数据库、Redis、MQTT、模型、Agent、监控与 Docker 服务不应新开公网端口；项目前端及监控访问保持既有回环/代理设计。新增端口、云安全组、FRP、证书或 Nginx 变更后需从外部独立验证 HTTPS/WSS、旧端口、IPv4/IPv6 与鉴权。仓库中的地址和配置样例不是给新部署者复用作者凭据的许可。
- 动态出口恢复是独立基础设施维护身份，不能据此扩大Agent的R0权限或生产写窗口。只允许经设备认证更新新云7000单一IPv4来源。新云为SAS，云侧使用指定防火墙RuleId，不使用ECS前缀列表或实例角色；恢复路径独立于FRP，保留TLS、防重放、非目标规则停止写入与私有事务。7070、其他服务规则及业务镜像不随此任务改变；启用前核实SAS实例与规则归属、重叠规则及专用RAM程序用户授权，隔离测试不代表真实换址通过。总则见[[02-工程规范边界与验收治理/项目工程规范/01-目录边界与笔记治理#三、文件放置规则]]，流程与当前状态见[[01-项目调研规划与开发建设记录/补充业务/06-FRP动态出口自动维护/01-FRP动态出口自动维护]]。
- 运行主机也承载其他容器与历史隔离恢复卷。检查或发布时只定位本项目服务及本轮隔离项目；不重启、清理、改权限或迁移无关服务。服务器连通只证明可访问，`/health` 只证明进程/配置状态，不能代替真实模型、搜索和业务回归。
