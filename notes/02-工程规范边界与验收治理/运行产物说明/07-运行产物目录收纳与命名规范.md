# 运行产物目录收纳与命名规范

> 状态与发布结论只认 [[00-当前系统状态]]；本页只规定 `artifacts/` 里**怎么放、怎么命名、怎么登记、怎么清理**。产物用途索引见本目录 `00-索引·运行产物说明`，实际文件在 Git 忽略的 `artifacts/`。

> **2026-11-22 所有者决定**：登记前置、到期复核**已生效**；空目录与嵌套、新增批次目录命名作为**轻量收尾约定**。不做全库改名、不自动删除历史目录、不安排持续监视。决定记录见 [[02-工程规范边界与验收治理/运行产物说明/10-产物登记与留存建议（2026-11-22）|产物盘点页第六节]]。

## 一、顶层只允许三类条目

`artifacts/` 顶层（2026-10-30 起）：

| 类型 | 形态 | 例子 |
| --- | --- | --- |
| 阶段根 | `stageN-<主题>` | `stage1-数据链路`、`stage8-agent-rag` |
| 专题根 | 多阶段成套证据，内含 `S01`/`S02` 子批次 | `v4-智能助手`、`v5-桌面客户端`、`遥测可靠性` |
| 批次包 | `<主题>-<YYYYMMDD>-rN`（主题中文或英文） | `告警链路-20261030-r1`、`备案页脚-20261030-r1` |

**禁止**：为每次小改动在顶层新增一个英文缩写目录。同一专题的连续批次必须落在同一专题根下，用 `rN` 区分轮次。缓存类固定使用 `go-cache`、`go-mod`、`mermaid-cli`、`runtime` 等稳定名，不随时间改名。

## 二、命名标准

- **新增批次目录采用 `<主题>-<YYYYMMDD>-rN`**：阶段根（`stageN-<主题>`）、专题根（含 `S01`/`S02` 子批次）、固定缓存目录（`go-cache`、`go-mod`、`mermaid-cli`、`runtime`）及批次包内部子目录沿用各自结构，不套这一格式。主题段以中文为主，也允许英文或中英混写；英文要能看出用途（`telemetry`、`quality`），不建议新用不可读缩写（`bnd`、`tr`）单独作主题段。专有名词（`SAS`、`MQTT`、`TDengine`）可作中文主题后的限定语。
- **历史目录保持原名**：不为“看起来整齐”批量改名，`model-quality-20261104` 这类既有英文名继续沿用。历史目录与新约定不一致不算缺陷，不因此断链。
- **日期用 `YYYYMMDD`**，放在主题之后；轮次用 `r1`、`r2`，不带前导零。
- **同一主题的新批次用词一致**：2026-10-30 已把 `telemetry-` 统一为「遥测」、`interpretation-` 统一为「告警解读」、`ui-` 统一为「界面」、`frp-source-` 统一为「来源自动维护」。后续新增沿用同一词表，不中途换叫法。
- **改名即改引用**：`artifacts/` 不在 Git 里，确需改名时必须先出映射表，再按「旧名长度降序 + 边界匹配」批量替换全仓引用，最后核 `check_notes.py` 与旧名残留为 0。2026-10-30 的映射存于 `artifacts/_改名映射-20261030.json`（含反向回滚依据）。本条规定的是“改名要付清代价”，不是要求为统一命名去改历史目录。

## 三、登记前置

每个新增批次要在两处留登记，都只写一行，不另写独立报告：

1. **当批日志页**：`产物目录` + `一句话用途` + `保留依据或期限`。保留依据是必填项，例如“发布回执的可复核来源，保留至引用结束”“临时校验脚本，可重跑”。
2. **`00-索引·运行产物说明` 的对应分卷**：`批次目录 → 一句话用途 → 结论指针`。这里只管导航，不重复记保留期。

未登记的批次不算交付完成，也不得在笔记里被当作证据引用。两处的用途可复用同一句；登记不复制运行结论，结论仍以对应笔记为准。2026-11-22 起保留依据为必填；此前批次按盘点页补登时逐步补齐，不追溯重写历史日志。

## 四、容量与到期复核

- 新增批次前先看 `artifacts/README.md` 的现状表。
- 顶层条目超过 100 个必须做一次归档复核，不得无限平铺。
- 单批次体量异常（如单目录超过 1 GB）时，先判断是「证据本身大」还是「混进了依赖/缓存」，后者按第五节清理。

### 到期复核

- “保留至某日”到期**只触发复核，不自动删除**。复核三项：① 是否仍被现行笔记按路径或批次引用；② 是否为本机唯一副本；③ 能否由训练脚本、构建或原始数据重建。
- 复核结论写回该批登记行或批次页，三选一：继续保留（写新期限）、转历史归档、列入清理候选。没有结论就维持原状。
- 不设定时任务，也不要求 AI 持续监视；由下次接触该目录、批次复盘或阶段盘点时执行。到期未复核不等于可删。

## 五、清理边界

**只删可再生**：go 构建缓存、go module、`venv`、`node_modules`、`__pycache__`、`pytest-cache`、PyInstaller `build/`。

**永不删**：`runtime/`（MA 证据，笔记明确「不移动、不删除」）、批次回执与日志、生产快照与数据库导出、已交付的安装包、正式冻结或在役的模型权重（生产指针引用、唯一副本、无可重建脚本）。

**模型权重按状态分三类**：

- **正式冻结 / 在役**：永不删；替换或迁移前保留原文件与摘要。
- **失败 / 被否候选**：默认作为批次证据保留；只有同时满足「非唯一副本 + 可由训练脚本重建 + 有摘要」才可列入清理候选，且须所有者授权。
- **可再生的临时候选**（训练中间物、回放缓存）：按「只删可再生」处理，删除前核对引用。

裁定前一律不清理；本页只界定规则，不构成删除授权。

**删前三核**：① 归属哪个批次；② 笔记是否按路径引用；③ 所有者是否已授权。**删后记账**：写进 `artifacts/README.md` 的清理记录（日期、动作、依据）。

**缓存会自己长回来**：`go-cache` 清理后若再跑 Go 构建会重新生成，属正常，不必视为清理失败；复核时以「是否还有人为堆积」而非「是否为零」为准。

### 任务收尾检查（空目录与嵌套）

- 执行过程中允许临时建空目录（脚本工作目录、占位、待写入），不必边跑边清。
- 任务收尾时检查本批新增的 `artifacts/` 目录：是否遗留空目录、是否误建 `artifacts/artifacts` 或同类重复嵌套。有就本批内清掉或写明保留原因。
- 历史遗留的空目录与嵌套目录**不自动删除**，只登记在盘点页候选清单，待单独排期；检查动作不扩展到他人批次或历史归档。
