# 运行产物目录收纳与命名规范

> 状态与发布结论只认 [[00-当前系统状态]]；本页只规定 `artifacts/` 里**怎么放、怎么命名、怎么登记、怎么清理**。产物用途索引见本目录 `00-索引·运行产物说明`，实际文件在 Git 忽略的 `artifacts/`。

## 一、顶层只允许三类条目

`artifacts/` 顶层（2026-10-30 起）：

| 类型 | 形态 | 例子 |
| --- | --- | --- |
| 阶段根 | `stageN-<主题>` | `stage1-数据链路`、`stage8-agent-rag` |
| 专题根 | 多阶段成套证据，内含 `S01`/`S02` 子批次 | `v4-智能助手`、`v5-桌面客户端`、`遥测可靠性` |
| 批次包 | `<中文主题>-<YYYYMMDD>-rN` | `告警链路-20261030-r1`、`备案页脚-20261030-r1` |

**禁止**：为每次小改动在顶层新增一个英文缩写目录。同一专题的连续批次必须落在同一专题根下，用 `rN` 区分轮次。缓存类固定使用 `go-cache`、`go-mod`、`mermaid-cli`、`runtime` 等稳定名，不随时间改名。

## 二、命名标准

- **主题段用中文**，能让人不打开就判断用途。纯英文缩写（`bnd`、`frp`、`pve`、`tr`）不得单独作主题段；确需保留的专有名词（`SAS`、`MQTT`、`TDengine`、`RAM`）可作为中文主题后的限定语。
- **日期用 `YYYYMMDD`**，放在主题之后；轮次用 `r1`、`r2`，不带前导零。
- **同一主题的用词必须一致**：本次已把 `telemetry-` 统一为「遥测」、`interpretation-` 统一为「告警解读」、`ui-` 统一为「界面」、`frp-source-` 统一为「来源自动维护」。后续新增批次沿用同一词表，不要中途换叫法。
- **改名即改引用**：`artifacts/` 不在 Git 里，改名必须先出映射表，再按「旧名长度降序 + 边界匹配」批量替换全仓引用，最后核 `check_notes.py` 与旧名残留为 0。2026-10-30 的映射存于 `artifacts/_改名映射-20261030.json`（含反向回滚依据）。

## 三、登记前置

每个批次必须在 `00-索引·运行产物说明` 的对应分卷登记三项：**批次目录 → 一句话用途 → 结论指针**。

未登记的批次不算交付完成，也不得在笔记里被当作证据引用。登记只写用途与指针，不复制运行结论，结论仍以对应笔记为准。

## 四、容量复核

- 新增批次前先看 `artifacts/README.md` 的现状表。
- 顶层条目超过 100 个必须做一次归档复核，不得无限平铺。
- 单批次体量异常（如单目录超过 1 GB）时，先判断是「证据本身大」还是「混进了依赖/缓存」，后者按第五节清理。

## 五、清理边界

**只删可再生**：go 构建缓存、go module、`venv`、`node_modules`、`__pycache__`、`pytest-cache`、PyInstaller `build/`。

**永不删**：`runtime/`（MA 证据，笔记明确「不移动、不删除」）、批次回执与日志、生产快照与数据库导出、已交付的安装包、模型权重。

**删前三核**：① 归属哪个批次；② 笔记是否按路径引用；③ 所有者是否已授权。**删后记账**：写进 `artifacts/README.md` 的清理记录（日期、动作、依据）。

**缓存会自己长回来**：`go-cache` 清理后若再跑 Go 构建会重新生成，属正常，不必视为清理失败；复核时以「是否还有人为堆积」而非「是否为零」为准。
