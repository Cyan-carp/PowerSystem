# 运行产物说明 · artifacts 文件索引 · 第一版阶段一至阶段六运行产物

> 本页由 [[02-工程规范边界与验收治理/运行产物说明]] 分卷维护，原有事实、编号和验收边界保持不变。

## 一、阅读与保留原则

`artifacts/` 被 Git 忽略，存放编译缓存、运行日志、测试结果、模型、截图和临时脚本。它不是部署服务器的数据卷，也不等于每日加密备份。目录里大量 Go/Python/npm 依赖和缓存以哈希或包路径命名，功能相同且会重复生成；下文逐一说明有稳定文件名的产物，并按生成规则归类这些缓存文件。带时间戳的运行目录代表不同测试批次，同名文件用途相同、内容随批次变化。

**保留与处理原则**

- `stage3-AI预测/model/model.json`、`metadata.json`：当前预测服务的运行资产；重建/换模型前保留，并与部署版本一起核对。
- `stage1-数据链路/`、`stage2-后端主体/`、`stage3-AI预测/integration-*/`、`stage4-前端上线/`、`stage5-飞书通知/` 记录：验收或部署复核证据；需要追溯时保留原批次，**失败批次也不覆盖**。
- `stage3-AI预测/external/`：外部数据原件、来源许可与审计结果；本机留存，不随 Git 发布，分享和使用须遵守来源许可。
- SQLite 主文件及 `-wal`、`-shm`：同一运行状态的一组文件；运行中不要单独拷贝或删 WAL/SHM，需用在线快照。
- `go-*`、`go-audit-cache`、`npm-cache`、`mermaid-cli`、`pydeps`：本机工具缓存/依赖；通常可重新下载或编译，不是业务数据。
- 本机临时脚本、日志、归档：可能包含测试地址、账号或连接信息；分享前检查并脱敏。

> `artifacts/` 不是部署服务器的数据卷，也不等于每日加密备份。服务器持久数据在 `runtime/` 与异地加密备份，不在本目录。

## 二、根目录的工具与构建目录

**本机可执行文件**

- `bin/gateway.exe`：阶段一网关的本机 Windows 编译产物。
- `bin/stage2-api.exe`：阶段二 Go API 的本机 Windows 编译产物。
- `bin/stage2-gateway.exe`：阶段二网关的本机 Windows 编译产物。
- `legacy/gateway.exe`：更早期的网关可执行副本，命名上属于历史保留；与 `bin/gateway.exe` 同源但不再用于当前部署。

> 这些 `.exe` 均是本机辅助构建；服务器以 Dockerfile 构建 Linux 镜像，不上传 Windows 可执行文件。

**工具缓存与配置对照**

**Go 编译缓存**（不同阶段或命令产生，哈希子目录、`trim.txt`、`README` 由 Go 工具维护，单个哈希文件无独立业务含义，均可再生）

- `go-build/`、`go-cache/`
- `stage3-go-cache/`
- `go-audit-cache/`（模块审计场景）
- `stage4-前端上线/go-cache/`、`stage4-前端上线/go-cache-publish/`（发布候选场景，与 `go-build/` 同类）
- `go-mod/`：下载的 Go 模块包、版本元数据和校验文件；源码依赖缓存，不是本项目手写代码。
- `mermaid-cli/`：渲染架构图时使用的 Mermaid CLI 与 Node 依赖；`node_modules` 下成千上万文件按上游包命名。
- `npm-cache/`：npm 的下载/校验缓存；按内容哈希组织，可由 npm 重建。
- `tdengine-config-backup/taos.cfg.original`：修改 TDengine 本机配置前保存的原始版本。
- `tdengine-config-backup/taos.cfg.updated`：修改后的配置副本，用于对照参数差异。

## 三、`stage1-数据链路/`：数据链路批次

`stage1-数据链路/` 下各时间戳/运行 ID 文件夹是一次独立采集、故障注入或恢复核对。以下文件名会在多个批次重复；表中的说明适用于每个同名文件。某批次少一项通常表示该测试未启用对应组件或未生成该证据。本目录共 20 个批次目录。

**批次结果文件**

- `run.json`：本次运行的标识、参数和时间等元信息。
- `environment.json`：本次测试环境及依赖版本/连接信息的快照。
- `events.jsonl`：测试过程事件流，一行一个 JSON 事件。
- `telemetry.csv`：设备上报的遥测样本明细。
- `fault-labels.csv`：合成故障区间/标签，供注入或结果比对。
- `metrics.csv`：吞吐、时延或其他运行指标的逐条记录。

**对账与审查文件**

- `reconciliation.json`：MQTT、网关、TDengine 等环节的样本对账结果。
- `isolated-reconciliation.json`：隔离条件下的补充对账结果；只在相关批次出现。
- `summary.md`：本批次面向审查的文字摘要。
- `review-bundle.zip`：将该次关键报告和证据打包供复查。

**进程日志**

- `simulator.jsonl`、`simulator.stderr.log`：模拟器结构化输出与标准错误。
- `gateway-1.jsonl`、`gateway-1.stderr.log`：第一网关进程输出与错误。
- `gateway-2.jsonl`、`gateway-2.stderr.log`：双网关/接管测试时第二网关的输出与错误。
- `emqx.log`、`emqx.stderr.log`：MQTT Broker 标准输出与错误。
- `tdengine.log`、`tdengine.stderr.log`：TDengine 标准输出与错误。

**待处理消息与持久状态**

- `gateway.sqlite`、`gateway.sqlite-wal`、`gateway.sqlite-shm`：网关持久待写队列及 SQLite WAL/共享内存配套文件。
- `simulator.sqlite`、`simulator.sqlite-wal`、`simulator.sqlite-shm`：模拟器待发 outbox 及 SQLite 配套文件。
- `i.135.msg`～`i.144.msg`：特定批次 MQTT 持久消息存储的单条消息文件，数字是消息文件标识；不是手工编写的业务配置。

> 阶段一正式 M1 与目录迁移短测的运行编号见 [[01-项目调研规划与开发建设记录/第一版-平台主体/05-功能开发与阶段交付/01-数据链路/05-阶段一目录迁移记录]]。`review-bundle.zip` 便于复核，但不包含私有 `.env`、完整 TDengine 数据库或 Docker 卷；如需保留旧环境，应另行备份所需的整个运行目录和卷。阶段一当时的 `powersystem_emqx-data`、`powersystem_emqx-log`、`powersystem_tdengine-data`、`powersystem_tdengine-log` 由 Docker 管理，不在 `artifacts/`，克隆仓库不会恢复它们。运行中的 SQLite 请使用在线快照，不单独复制主文件；迁移操作顺序见 [[03-平台使用运维与二次开发手册/平台运维与二次开发手册]]。
