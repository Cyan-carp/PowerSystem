# 提交与公开仓库规范

目的：让提交可追溯、公开仓库不混入私有运行材料。

## 上传远程仓库规范

远端：`origin = https://github.com/Cyan-carp/PowerSystem.git`，公开可见。

### 分支约定

| 分支 | 用途 |
| --- | --- |
| `main` | 阶段验收及正式发布版本 |
| `dev` | 各阶段集成开发 |
| `codex/stageN-*` / `codex/<主题>` | 新建协作功能分支的默认前缀，完成审阅后合入`dev`；用户指定名称时遵从用户要求 |

> 既有`feature/stageN-*`属于历史命名，不为统一前缀而改名或重写历史。功能分支不作为远程长期分支；`main`只在对应范围正式验收及发行审阅完成后合并，服务器发布与仓库合并分别记录。

### 提交规范

- **提交身份**：仅在此仓库配置为 `Carp <2310314536@qq.com>`。
- **提交信息**：`类型(范围): 说明`，如 `feat(stage1) / fix / docs / test / refactor / merge`。
- **阶段里程碑**：验收通过后打附注标签，如 `stage1-m1-passed`、`stage1-data-chain`。
- **发布**：阶段里程碑通过后在 GitHub 建 Release，附对应 M1/M2/M3 等验收结果、故障恢复验证、代码目录说明和未验证边界。

### 提交范围

**绝不提交**（已被 `.gitignore` 覆盖）：

`.env`、`.venv/`、`__pycache__/`、`*.exe`、`*.test`、`artifacts/`、`artifacts/历史归档/`、`.obsidian/workspace.json`及备份目录中的同名文件、`.workbuddy/`。Obsidian工作区备份保留本机原件，但不进入版本控制。

**必须提交**：

源码、脚本、`go.mod`/`go.sum`、依赖锁定文件、`compose.yaml`、`deploy/*.sql`、全部 `.md` 笔记、`README.md`、`.env.example`、`.gitignore`。

直接复制到 Linux 主机运行的部署配置与脚本由 `.gitattributes` 固定 LF 换行；Windows 检出后仍须核对目标主机上的配置语法再 reload 服务。

### 安全检查（每次提交前）

公开仓库和服务器的完整发布门禁见 [[02-工程规范边界与验收治理/项目工程规范/02-仓库与前端质量/00-索引·仓库与前端质量]]。

1. 不含真实密码、token；检查新增文件是否意外写入本机绝对路径或内部地址，并用本机 `.env` 的值扫描待提交内容（扫描结果只报告命中，不打印密钥）。阶段一目录整理的历史路径和运行编号见 [[01-项目调研规划与开发建设记录/01-第一版-平台主体/05-功能开发与阶段交付/01-数据链路/05-阶段一目录迁移记录]]，不作为后续文件模板。
2. `review-bundle.zip` 等审查包不进公开仓库。
3. 未误提交 `artifacts/` 下的日志/账本。
4. 提交后核对 `git status` 无意外文件。

## 仓库公开与服务器私有材料

- 提交前核对拟提交源码、图像、归档与日志；不提交.env、私钥、令牌、数据库密钥、Webhook、备份口令、生产数据或可还原这些值的截图。忽略规则不能替代对拟公开内容的判断。
- 服务器秘密放受限目录，不写入可公开Compose模板、命令回显、CI日志、issue、PR、README或录屏。误提交先吊销/轮换并核影响，再处理仓库历史，删最新文件不代表秘密失效。
- 仓库写权限与部署权限分开，最小协作者权限、双因素认证；实际分支保护和协作者状态按当次账号现查，不沿用历史快照。固定提交/镜像来源不能赋予额外服务器权限。
- 数据库/MQTT/Redis/模型/监控/Docker接口不直接公开。管理员与演示账号分离；注册、登录或网络相关变更才针对该路径核对，普通发布不因这条重复全套安全测试。
- 创建备份时保持加密、专用接收目录和SSH指纹；修改目标或密钥先核已有任务。公开笔记使用占位符描述私有入口，历史公开信息的影响按实际资产处理。
- 具体命令仍在阶段源码README维护；未登录服务器不把源码检查写成在线验收。历史安全审查数字和分支/账号快照归 [[02-工程规范边界与验收治理/项目工程规范/07-历史记录与上传定位卡/05-工程边界与发布历史记录]]。
