## 一、目标、分工与基线

目标是让使用说明跟上功能、版本和规则不冲突、检查器发现真实断链、索引能够持续增长，并让产物登记可追溯。保留现有六分区，不全库改名，不重写历史验收，不清理实际证据。

本任务分工按所有者本次安排：**Workbuddy负责第二至四批具体实施与自检；Codex收到所有者转交的结果后集中复核。** 不要求Codex同时另开实施线，不主动联系或持续监视其他会话，不把本次分工改成新的永久规则。

第一批事实见 [[125-文档现状与链接修正]]。截至该批终检：755篇笔记；严格及本地CI模式通过；37个笔记章节双链、131份库外Markdown的271个本地文件链接无断链。以上仅为交接基线，实施时重新测量，不固定最终篇数或链接数。全库其余内容未被逐条业务验收。

第一批已改正状态与旧主机说明、11处文件断链、7处笔记章节断链及部署README的额外引用。不得恢复这些旧错误。总日志索引当时14,987字符，不能继续靠挤字数容纳新批次。

- 先记录实际工作区、Git HEAD、标签、`git status`与本任务涉及文件的开工内容/摘要。已有大量未提交代码和文档迁移，不以HEAD恢复文件，不使用reset/clean/stash或整库格式化覆盖现场，不把既有删除误记成本次操作。

## 二、顺序与停止条件

按 **B2 → B3A → B3B → B4 → 总交付** 实施。每批完成最小变更记录、定向验证与增量清单后，范围内无阻塞即可继续，不逐文件反复请求确认。可以用一份交付页分批登记，无需每个小修复生成四件套。

- 发现他人同时修改同一文件，先保留双方内容、核对差异；无法安全合并时停止该文件，继续不依赖它的工作。
- 缺乏生产证据时标为未核实，不猜测、不开服务器补验，不将未知升级为通过。
- 超出本计划的业务修复、生产操作、实际证据清理或全库迁移不执行；交付具体建议及影响。既有技术缺口不阻塞与其无关的文档治理，但会阻塞相应技术签收。

主要文件：`notes/03-平台使用运维与二次开发手册/平台使用手册.md`、同目录运维手册及其分卷；必要接口说明只更新对应`stages/*/README.md`。

| 功能 | 必须讲清楚 |
| --- | --- |
| 本人会话归档、恢复、删除 | 入口、三种操作区别、是否影响历史/任务，移除过时批量管理说明 |
| 助手附件 | 六类允许文件、实际限制、上传/解析/检索/引用步骤、失败与取消、隐私提示；限制必须以代码和专题为据 |
| 现场记录 | 设备/告警详情入口、可写角色或开关、保存结果、只读与不可用状态 |
| 预测反馈 | 绑定对象、记录与统计口径，不冒称模型自动学习或线上精度提升 |

每项采用“在哪里 → 谁能用 → 怎么做 → 预期结果 → 限制”的简短说明，引用专题，不复制部署摘要。源码能证明的是本地实现，是否上线看发布回执，是否通过生产体验看对应验收证据，三者分开。

| --- | --- |

| 章节与块引用 | Markdown按实际渲染的标题锚点，Obsidian按对应标题/显式块ID；识别重复标题、同页锚点、别名；代码块/行内示例不当正文链接 |

| 迁移残留 | 按迁移表核现行导航旧路径，已删除旧源出现在迁移映射或历史解释不算错误；已合并文件允许多对一，映射链需可解释 |

CI触发范围与说明对齐，纳入所检查入口；只改文档工作流，不扩展业务构建。没有检查远端分支保护时，只称“工作流失败”，不宣称“已强制阻断合并”。保留现有受影响范围之外的工作流。
