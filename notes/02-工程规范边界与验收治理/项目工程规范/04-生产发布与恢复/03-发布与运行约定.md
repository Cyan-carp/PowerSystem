# 发布与运行约定

目的：集中长期发布边界；具体命令与本批状态分别看部署 README 与唯一状态页。

## 发布与运行的长期约定

### 已批准模型与性能例外

所有者明确批准的临时型号/性能例外，必须限定环境、字段许可、实际上限和补查归属；独立保存配置/候选及失败，不扩大默认预算或权限，不自动换回型号。功能签收与常规性能签收分开声明，未执行的常规检查保持待办。更换API、型号或关键调用参数后新建真实验收批次，不能直接复用旧质量/性能结论。具体本轮例外与命令分别归SEC正式交付页和源码README。

### 联合发布与运行上下文

- 扩展环境权限必须使用显式运行档及版本化策略/许可，保存任务私有配置摘要；旧任务不自动取得新增权限，配置变化使旧审查或审批失效。
- 本地集成与服务器发布使用独立批次，签收不得跨环境代偿；观察方式见 [[02-工程规范边界与验收治理/项目工程规范/03-协作联调与验收/03-开发测试与运行观察规范]]；开发阶段不以固定镜像长观察阻塞发布；观察期间文档增量单独核对摘要，不改冻结包。观察不调用模型时必须明确其不证明模型连续可用性。
- 备份记录实际私有配置引用及摘要；隔离恢复关闭Worker、投递及执行入口，不带生产执行凭据，不重放排队任务或批准记录。

### 生产发布防回退与自动验收门禁

> 独立专题见[[02-工程规范边界与验收治理/项目工程规范/04-生产发布与恢复/02-发布工具与故障恢复说明]]：按PUB-01～09解释设计原理、代码定位及边界；档位范围只在[[02-工程规范边界与验收治理/项目工程规范/04-生产发布与恢复/01-上传服务器与分级发布规范]]维护，不另设相反要求。

每次把文件上传服务器及后续发布，都必须按 [[02-工程规范边界与验收治理/项目工程规范/04-生产发布与恢复/01-上传服务器与分级发布规范|上传服务器规范]] 现查指针、定位目标、核对 LF/摘要与档位，并在当次更新服务器目录定位卡；不得为节省查找时间沿用旧批次路径。**档位以候选冻结时确定并按上传服务器规范判定为准**：本页不预设默认档、不复制档位参数，也不记录某档是否已在生产启用——启用状态、耗时、RPO 与命令只认上传服务器规范与 [[00-当前系统状态]]。走哪一档都不裁剪下列九项中的来源可核、部署锁、服务与卷身份、权限与数据边界、真实记录与兼容恢复边界；本人明确免门禁时按上传服务器规范的直接接受方式登记。

- **唯一生产更新入口**：既有生产环境的应用容器发布、配置更新及回退统一由阶段四`production-stack.py`管理。基础Compose仅用于初装和既有备份/只读维护；禁止以单份基础Compose、临时`docker run`或历史发布脚本直接覆盖现网应用。历史命令保留取证，不能作为当前发布入口。操作命令只在阶段四部署README维护。
- **完整编排冻结**：每个候选必须按顺序包含阶段4基础、阶段7 Agent、阶段7搜索、阶段8 RAG及阶段9多智能体编排，使用实际集成私有环境；导出为独立私有配置快照，并校验Compose解析前后语义一致。不得依赖操作者当前目录、默认`.env`或隐式叠加文件。冻结后禁止原位修改，变更必须生成新候选。
- **全部镜像与数据卷锁定**：锁定全部生产服务的实际镜像ID及所需本地镜像，覆盖未变更应用，禁止使用浮动标签作为最终运行依据；发布禁止构建、拉取和自动处理依赖服务。现有命名卷和镜像自带匿名卷均绑定实际卷身份，不得在应用发布中更换持久卷、清卷或改公开端口。
- **配置完整性门禁**：API必须同时具备旧事件Agent、交互RAG及Ops连接、服务令牌与Actor签名挂载、聊天超时/输入/并发限额。生产能力档、角色审查和写窗口以当前系统状态及版本化配置为准，流程简化不自动扩权或公开内部端口。配置、验收脚本、镜像和私有引用摘要变化时旧候选失效，不可仅凭健康检查放行。
- **候选与现网绑定**：候选绑定上一份已验收清单及准备时的全部容器ID、镜像、启动时间和重启计数。并行发布、过时候选、实际基线漂移、未排空任务、未获豁免的恢复材料缺失或未完成事务须先接续处理；本人明确暂不备份、直接接受时按05记录授权收尾。每次只重建显式指定的应用；Nginx上游与已登记资产按既有受控维护方式更新，不新增模型权限、资产或写窗口。
- **发布接受与真实记录**：默认工具执行冻结档位的登录、匿名401、业务/会话/任务、ticket/WSS后登记；所有者明确免门禁/测试时，记录授权及未执行项，用所有者接受回执更新实际版本并归档事务。缺失、异常和404/503不能伪记技术通过。受影响模型、容量、可靠性等专项按实际变更执行，短验不外推长期稳定。
- **失败停止与回退**：兼容发布失败恢复直接已验父版的配置和镜像，按其冻结档位重验；schema不兼容或未知时冻结前滚，不启动旧worker。中断、回退失败保留事务及失败证据，沿原事务显式恢复，不删标记强行续发；不自动降schema或覆盖业务数据。
- **私有产物与恢复**：完整配置可能含秘密值，仅存服务器私有运行目录，清单、指针、门禁日志与必要私有配置纳入现有加密备份；公开Git只保存工具及脱敏说明。恢复副本中的生产指针不自动激活，不带生产执行能力、不重放任务或批准。
- **已有证据与按范围验证**：未受影响且依赖、配置、来源一致的专项证据可复用，注明原编号、摘要与未重测事实；新改动须有对应证据，是否本次执行门禁按05及所有者明确授权决定。成功定时备份的精确状态重核继承原功能验收，不冒称新HTTPS通过；首次基线登记和历史发布按其原记录保留。

**按已冻结档位执行（2026-10-28）**

- 普通发布可执行与变更范围匹配的冻结档位及其对应备份，包括“有效全量基线＋本批小包”这类不新建全量的组合；档位名称、备份条件、有效期与当前启用状态只引用 05 和 [[00-当前系统状态]]，本页不另设开关、默认值或耗时基线。
- 默认门禁范围按05档位执行；所有者明确豁免时如实登记，身份、配置、权限及原始数据边界仍保留，不另加长观察。
- 发布控制器、备份脚本等**普通发布器修改**不自动触发完整隔离恢复演练；恢复演练按 05 的触发条件执行，周期演练与日常上线解耦。
- 不兼容 schema 的候选**禁止回切旧 worker**：只能按冻结现场、前滚修复或另行批准的方案处置，不把回退写成数据已恢复。
- 任何档位都不免除来源可核、部署锁、服务与卷身份、权限边界、数据边界与失败可回退；本地实现或工具改动未经真实发布验证前，不得写成生产已启用。
