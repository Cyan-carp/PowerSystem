## 一、发布与运行的长期约定

### 已批准模型与性能例外

所有者明确批准的临时型号/性能例外，必须限定环境、字段许可、实际上限和补查归属；独立保存配置/候选及失败，不扩大默认预算或权限，不自动换回型号。功能签收与常规性能签收分开声明，未执行的常规检查保持待办。更换API、型号或关键调用参数后新建真实验收批次，不能直接复用旧质量/性能结论。具体本轮例外与命令分别归SEC正式交付页和源码README。

### 联合发布与运行上下文

- 扩展环境权限必须使用显式运行档及版本化策略/许可，保存任务私有配置摘要；旧任务不自动取得新增权限，配置变化使旧审查或审批失效。
- 本地集成与服务器发布使用独立批次，签收不得跨环境代偿；观察方式按03第五章；开发阶段不以固定镜像长观察阻塞发布；观察期间文档增量单独核对摘要，不改冻结包。观察不调用模型时必须明确其不证明模型连续可用性。
- 备份记录实际私有配置引用及摘要；隔离恢复关闭Worker、投递及执行入口，不带生产执行凭据，不重放排队任务或批准记录。

### 生产发布防回退与自动验收门禁

> 独立专题见[[02-工程规范边界与验收治理/项目工程规范/08-发布工具与故障恢复说明]]：按PUB-01～09解释设计原理、代码定位及边界；档位范围只在05维护，不另设相反要求。

每次把文件上传服务器及后续发布，都必须按 [[02-工程规范边界与验收治理/项目工程规范/05-上传服务器规范|上传服务器规范]] 现查指针、定位目标、核对 LF/摘要与档位，并在当次更新服务器目录定位卡；不得为节省查找时间沿用旧批次路径。**档位以候选冻结时确定并经 05 判定为准**：本页不预设默认档、不复制档位参数，也不记录某档是否已在生产启用——启用状态、耗时、RPO 与命令只认 05 与 [[00-当前系统状态]]。走哪一档都不裁剪下列九项中的来源可核、部署锁、服务与卷身份、权限与数据边界、真实记录与兼容恢复边界；本人明确免门禁时按05的直接接受方式登记。

- **唯一生产更新入口**：既有生产环境的应用容器发布、配置更新及回退统一由阶段四`production-stack.py`管理。基础Compose仅用于初装和既有备份/只读维护；禁止以单份基础Compose、临时`docker run`或历史发布脚本直接覆盖现网应用。历史命令保留取证，不能作为当前发布入口。操作命令只在阶段四部署README维护。
- **完整编排冻结**：每个候选必须按顺序包含阶段4基础、阶段7 Agent、阶段7搜索、阶段8 RAG及阶段9多智能体编排，使用实际集成私有环境；导出为独立私有配置快照，并校验Compose解析前后语义一致。不得依赖操作者当前目录、默认`.env`或隐式叠加文件。冻结后禁止原位修改，变更必须生成新候选。
- **全部镜像与数据卷锁定**：锁定全部生产服务的实际镜像ID及所需本地镜像，覆盖未变更应用，禁止使用浮动标签作为最终运行依据；发布禁止构建、拉取和自动处理依赖服务。现有命名卷和镜像自带匿名卷均绑定实际卷身份，不得在应用发布中更换持久卷、清卷或改公开端口。
- **配置完整性门禁**：API必须同时具备旧事件Agent、交互RAG及Ops连接、服务令牌与Actor签名挂载、聊天超时/输入/并发限额。生产能力档、角色审查和写窗口以当前系统状态及版本化配置为准，流程简化不自动扩权或公开内部端口。配置、验收脚本、镜像和私有引用摘要变化时旧候选失效，不可仅凭健康检查放行。
- **候选与现网绑定**：候选绑定上一份已验收清单及准备时的全部容器ID、镜像、启动时间和重启计数。并行发布、过时候选、实际基线漂移、未排空任务、未获豁免的恢复材料缺失或未完成事务须先接续处理；本人明确暂不备份、直接接受时按05记录授权收尾。每次只重建显式指定的应用；Nginx上游与已登记资产按既有受控维护方式更新，不新增模型权限、资产或写窗口。
- **发布接受与真实记录**：默认工具执行冻结档位的登录、匿名401、业务/会话/任务、ticket/WSS后登记；所有者明确免门禁/测试时，记录授权及未执行项，用所有者接受回执更新实际版本并归档事务。缺失、异常和404/503不能伪记技术通过。受影响模型、容量、可靠性等专项按实际变更执行，短验不外推长期稳定。
- **失败停止与回退**：兼容发布失败恢复直接已验父版的配置和镜像，按其冻结档位重验；schema不兼容或未知时冻结前滚，不启动旧worker。中断、回退失败保留事务及失败证据，沿原事务显式恢复，不删标记强行续发；不自动降schema或覆盖业务数据。
- **私有产物与恢复**：完整配置可能含秘密值，仅存服务器私有运行目录，清单、指针、门禁日志与必要私有配置纳入现有加密备份；公开Git只保存工具及脱敏说明。恢复副本中的生产指针不自动激活，不带生产执行能力、不重放任务或批准。
- **已有证据与按范围验证**：未受影响且依赖、配置、来源一致的专项证据可复用，注明原编号、摘要与未重测事实；新改动须有对应证据，是否本次执行门禁按05及所有者明确授权决定。成功定时备份的精确状态重核继承原功能验收，不冒称新HTTPS通过；首次基线登记和历史发布按其原记录保留。

**按已冻结档位执行（2026-10-28）**

- 普通发布可执行与变更范围匹配的冻结档位及其对应备份，包括“有效全量基线＋本批小包”这类不新建全量的组合；档位名称、备份条件、有效期与当前启用状态只引用 05 和 [[00-当前系统状态]]，本页不另设开关、默认值或耗时基线。
- 默认门禁范围按05档位执行；所有者明确豁免时如实登记，身份、配置、权限及原始数据边界仍保留，不另加长观察。
- 发布控制器、备份脚本等**普通发布器修改**不自动触发完整隔离恢复演练；恢复演练按 05 的触发条件执行，周期演练与日常上线解耦。
- 不兼容 schema 的候选**禁止回切旧 worker**：只能按冻结现场、前滚修复或另行批准的方案处置，不把回退写成数据已恢复。
- 任何档位都不免除来源可核、部署锁、服务与卷身份、权限边界、数据边界与失败可回退；本地实现或工具改动未经真实发布验证前，不得写成生产已启用。

## 三、前端实现与界面准则

> **2026-10-29 起重写本节**：旧版（Element Plus + `styles.css` + 深空值班台/浅色云控制台的 statusbar + 检视栏 dock 骨架）随整站覆盖一并失效，本节只描述 `stages/04-frontend` 当前实现，不再保留旧版条款。实现细节（目录、路由、组件清单、令牌取值）见 [[01-项目调研规划与开发建设记录/01-第一版-平台主体/05-功能开发与阶段交付/04-前端、上线与沉淀/09-当前前端工程说明（2026-10-29）]]；历史视觉批次留在 [[04-系统部署发布备份与变更记录/部署与运维日志/02-界面展示与通知/00-索引·界面展示与通知]]，只作追溯，不构成回退依据。

### 3.1 技术边界：没有组件库

- 运行时只用 Vue 3 + vue-router + marked + dompurify。**不得引入 UI 组件库或图表库**替代现有自研组件（`Drawer` / `StatusChip` / `ToastHost` / `PowerChart` / `DonutGauge` / `Icon`）；需要新交互先看现有组件能否组合。
- 图标只用 `src/lib/icons.ts` 的本地 SVG 集；缺图标补在该文件，不从外链 CDN 取。
- 依赖变更须单独说明理由与替代范围，不为单个页面引入整套库。

### 3.2 样式入口与设计令牌

- 样式入口只有 `src/styles/tokens.css`（令牌）与 `src/styles/shell.css`（壳层与通用类）；页面内一律 `<style scoped>`，覆写子组件用 `:deep()`。
- 颜色、圆角、间距、壳层尺寸一律取令牌；新增硬编码色值视为缺陷（图表与个别语义色除外，改动时逐处核对）。
- **语义固定、色值不写死**：主色=交互与选中，红=告警/危险，橙=警示/阈值，绿=正常/成功；状态不得只靠颜色承载，必须配文字或形状。
- `.card` / `.btn` / `.chip` / `.kv` / `.page-head` / `.error-box` / `.empty` 等通用类跨页复用，不在页面里重造同类样式。

### 3.3 骨架与导航

- 骨架固定为「左侧 64px 图标轨 + 顶栏 + 页面主区」：图标轨保留 8 个一级入口（总览/告警/设备/健康/预测/报表/任务/助手）与底部使用说明；顶栏保留页名、搜索（Ctrl/⌘+K）、实时灯、时钟、告警解读、活动告警、账号菜单。
- 功能入口以用户能理解的中文呈现，不留无功能装饰图标或伪搜索框；退出登录等关键操作显式可见，不藏在头像菜单里。
- 页面级详情用 `Drawer` 抽屉，弹窗只用于审批（`ActionApproval`）；弹层不叠层，点外部关闭。
- 断点以页面实际样式为准（常见 1240/1180/1100/900/760/680），收窄时依次收主辅列、详情区与统计带；桌面导航保留文字，隐藏文字的入口必须补 `aria-label`/`title`。

### 3.4 内容与读数

- **总览**：紧凑统计带 + 功率曲线（可选时段）+ 场站/设备概览；发电监测必须写清时间范围与数据来源，不用浏览器打开后的短样本冒充全天。
- **列表**：关键字与状态筛选进 URL、可回放；分页排序不改服务端口径；设备编码带场站色标。
- **抽屉与证据区**：按「主读数 → 阈值/状态 → 时间/编号 → 解释 → 原始依据」分层；原始取证值不改写，仅显示层保留小数。
- **空值与数值**：空值/无效值显示 `—` 或明确状态；有效零值显示 0，不以零补缺失；数值用 `tabular-nums`，单位与数字分开对齐。
- **时间**：统一 `src/lib/format.ts` 按北京时间展示；相对时间必须区分过去与将来（`across()` 输出「N 前 / N 后」，不能把将来算成「刚刚」）。
- **告警解读**：按「状态胶囊（已解读/生成中/未完成/证据不足）→ 结论 → 关键事实 → 建议动作 → 尚未解释的部分 → 证据快照」呈现；结论与事实必须来自后端 `result`，事实标注「取自证据快照，非模型生成」；模型不可用时退回按指标与级别的模板，并明确标注「非模型结论」。
- **严格任务回答**：程序事实从工具实际返回投影，结论短段、研判与建议编号，独立安全意见分区；不将模型推测提升为事实，不因排版改权限、许可摘要或审批。

### 3.5 异步与四态（硬要求）

- 后端存在异步任务的（运行、方案预演、告警解读），界面必须区分**排队/生成中、已完成、失败或降级、没有记录**四态，不得把「还没算出来」显示成「没有数据」。
- 等待可用轮询或 WS，但轮询必须有次数上限；收到 WS 进度帧要立即回读，不干等定时器。
- 失败要说清原因：配置、鉴权、额度、超时、熔断等原因码翻成中文，认不出的原样给出，不编造结论。
- 写操作**不做乐观更新**：成功后回读服务端结果；冲突或失效给出中文提示并要求刷新核查。

### 3.6 修改边界与单一来源

- 视觉事实只认当前源码与 [[00-当前系统状态]]；本页、历史批次与旧截图不覆盖现行实现。
- 允许改模板、样式、组件与展示辅助函数（日期、单位、精度、文案）；涉及 `src/lib/` 须说明影响范围，不得扩成业务改动。API 请求、鉴权、路由权限、订阅与历史补查、统计口径、原始时间戳、模型计算的变化须单独说明并按其范围验证。
- 改完至少跑 `vue-tsc --noEmit` 与 `vite build`；动过假后端再跑 `node --check dev/mock-server.mjs`，并按页面实际渲染核对（截图或页面走查），不以「编译通过」代替界面验收。
- **纯前端排版的免重复测试偏好（2026-10-16 保留）**：所有者未另行要求时，不主动重跑业务测试、模型测试或故障/恢复演练；前端构建与正式发布入口自带门禁，并展示实际页面效果。免重复测试不等于绕过发布门禁，也不自动扩展到鉴权、API、模型或业务数据变更。

## 四、验收清单的持续维护

[[02-工程规范边界与验收治理/项目验收与收尾清单/00-索引·项目验收与收尾清单]]是项目级状态入口，必须随项目推进更新。先写当前跨版本判定，再依次保留第一版阶段一至六与项目总结，随后按日期记录第二版 V2-M1～M4、历史批次和现行长期待办；阶段内写清已完成内容、可复核证据、验收结论和未覆盖边界。历史未勾选项必须标明当时日期，不能误作当前阻塞。阶段五是第一版业务能力，阶段六是第一版公网安全与恢复亮点，二者均纳入 M4，不另设 M5/M6。项目总结不把部分功能上线、单次冒烟或合成数据指标外推成全项目验收；视频复盘与对外材料不属于第一版发布门槛。

**更新时机**

- 每完成一个阶段里程碑、关键功能、联调或部署验收，即更新对应阶段和项目总结；失败后的修复与补测也要更新，保留旧失败证据。
- 日常修复不走本节的全链回写：只留一份变更记录，涉及生产变化时同批更新 [[00-当前系统状态]]；只有接口、用法或资产变化才更新对应手册与台账。分档见 [[02-工程规范边界与验收治理/项目工程规范/01-目录边界与笔记治理|目录边界与笔记治理]] 第六章。
- 需求范围、FR/NFR 实现、公开数据适用性、服务器状态或发布范围改变时，同步更新受影响的阶段结论和当前待办。
- 每次新增或改变 `artifacts/` 中的长期保留证据、模型、外部数据目录时，同步更新 [[02-工程规范边界与验收治理/运行产物说明/00-索引·运行产物说明]]；原始大文件、密钥和运行账本仍由 Git 忽略。

**填写与复核规则**

- 每条"已完成"须指向笔记、源码、测试结果或具体运行编号，并记录核对日期；"已实现""已测试""已验收""真实环境已验证"分别表述，不互相替代。
- 本机证据未入库时标明 `artifacts/` 路径与复现入口；远端服务器未复测时写明最后实测日期，不能默认为仍在线。
- 现行未完成项单列并按 P0/P1/P2 或明确后续归属排序；历史未完成项保留批次日期与后续结果链接。完成后勾选并归入对应阶段的证据与结论，新增由本轮工作暴露的风险。
- 更新清单时同时核对根 README、阶段索引、运行产物说明和相关双链；阶段发布时核对 `main`、标签及 GitHub Release 的准确提交范围。
- 阶段收尾前必须核对独立问题记录页：已解决项附验证结果，未解决项附后续归属和阻塞判断；不得只在聊天、终端日志或测试交付表格中临时描述。

## 五、仓库公开与服务器私有材料

- 提交前核对拟提交源码、图像、归档与日志；不提交.env、私钥、令牌、数据库密钥、Webhook、备份口令、生产数据或可还原这些值的截图。忽略规则不能替代对拟公开内容的判断。
- 服务器秘密放受限目录，不写入可公开Compose模板、命令回显、CI日志、issue、PR、README或录屏。误提交先吊销/轮换并核影响，再处理仓库历史，删最新文件不代表秘密失效。
- 仓库写权限与部署权限分开，最小协作者权限、双因素认证；实际分支保护和协作者状态按当次账号现查，不沿用历史快照。固定提交/镜像来源不能赋予额外服务器权限。
- 数据库/MQTT/Redis/模型/监控/Docker接口不直接公开。管理员与演示账号分离；注册、登录或网络相关变更才针对该路径核对，普通发布不因这条重复全套安全测试。
- 创建备份时保持加密、专用接收目录和SSH指纹；修改目标或密钥先核已有任务。公开笔记使用占位符描述私有入口，历史公开信息的影响按实际资产处理。
- 具体命令仍在阶段源码README维护；未登录服务器不把源码检查写成在线验收。历史安全审查数字和分支/账号快照归 [[09-工程边界与发布历史记录]]。
