# 项目工程规范 · 目录、界面、协作与发布约定 · 发布仓库与界面验收规范

> 本页由 [[02-工程规范边界与验收治理/项目工程规范]] 分卷维护，原有事实、编号和验收边界保持不变。

## 一、发布与运行的长期约定

### 已批准模型与性能例外

所有者明确批准的临时型号/性能例外，必须限定环境、字段许可、实际上限和补查归属；独立保存配置/候选及失败，不扩大默认预算或权限，不自动换回型号。功能签收与常规性能签收分开声明，未执行的常规检查保持待办。更换API、型号或关键调用参数后新建真实验收批次，不能直接复用旧质量/性能结论。具体本轮例外与命令分别归SEC正式交付页和源码README。

### 联合发布与运行上下文

- 扩展环境权限必须使用显式运行档及版本化策略/许可，保存任务私有配置摘要；旧任务不自动取得新增权限，配置变化使旧审查或审批失效。
- 本地集成与服务器发布使用独立批次，签收不得跨环境代偿；实际回退及同一候选恢复后才进入最终固定镜像连续观察，候选改变或观察中断重新计时；观察期间文档增量单独核对摘要，不改冻结包。观察不调用模型时必须明确其不证明模型连续可用性。
- 备份记录实际私有配置引用及摘要；隔离恢复关闭Worker、投递及执行入口，不带生产执行凭据，不重放排队任务或批准记录。

### 生产发布防回退与自动验收门禁

> 独立专题及审查说明见[[02-工程规范边界与验收治理/生产发布防回退与自动验收门禁规范]]：按PUB-01～09逐条对应下列九项总则，解释设计原理、执行流程、代码定位和未覆盖边界。以下总则原文保留，专题不另设相反要求。

每次把文件上传服务器及后续发布，都必须按 [[02-工程规范边界与验收治理/项目工程规范/05-上传服务器规范|上传服务器规范]] 现查指针、定位目标、核对 LF/摘要与档位，并在当次更新服务器目录定位卡；不得为节省查找时间沿用旧批次路径。工作区的前端快路径代码尚未在生产启用，当前服务器仍执行既有全量规则；启用后也不裁剪本节自动验收与回退门禁。

- **唯一生产更新入口**：既有生产环境的应用容器发布、配置更新及回退统一由阶段四`production-stack.py`管理。基础Compose仅用于初装和既有备份/只读维护；禁止以单份基础Compose、临时`docker run`或历史发布脚本直接覆盖现网应用。历史命令保留取证，不能作为当前发布入口。操作命令只在阶段四部署README维护。
- **完整编排冻结**：每个候选必须按顺序包含阶段4基础、阶段7 Agent、阶段7搜索、阶段8 RAG及阶段9多智能体编排，使用实际集成私有环境；导出为独立私有配置快照，并校验Compose解析前后语义一致。不得依赖操作者当前目录、默认`.env`或隐式叠加文件。冻结后禁止原位修改，变更必须生成新候选。
- **全部镜像与数据卷锁定**：锁定全部生产服务的实际镜像ID及所需本地镜像，覆盖未变更应用，禁止使用浮动标签作为最终运行依据；发布禁止构建、拉取和自动处理依赖服务。现有命名卷和镜像自带匿名卷均绑定实际卷身份，不得在应用发布中更换持久卷、清卷或改公开端口。
- **配置完整性门禁**：API必须同时具备旧事件Agent、交互RAG及Ops连接、服务令牌与Actor签名挂载、聊天超时/输入/并发限额。生产R0、关闭写窗口、安全门禁及内部服务不开放公网端口是硬条件。配置、验收脚本、镜像和私有引用摘要变化时旧候选失效，不可仅凭健康检查放行。
- **候选与现网绑定**：候选绑定上一份已验收清单及准备时的全部容器ID、镜像、启动时间和重启计数。并行发布、过时候选、实际基线漂移、未排空任务、缺少有效更新前密文备份或未完成事务均必须停止。每次只重建显式指定的应用；Nginx上游与已登记资产按既有受控维护方式更新，不新增模型权限、资产或写窗口。
- **自动验收后生效**：未来每次发布自动核对目标镜像、实际环境及健康、未变更服务身份、新旧HTTPS入口真实操作员登录、匿名访问401、核心业务、历史会话与任务列表及非空列表详情、一次性ticket和WSS101。全部通过并将结果绑定同一冻结清单后，才原子更新当前生产版本指针；缺失、异常和404/503不得记为通过。该门禁不等于真实模型质量、容量或长期观察验收，受影响专项仍按原工程要求另行完成。
- **失败停止与回退**：门禁失败自动恢复上一份已验收的完整配置和镜像，并重新执行对应自动门禁。回退失败或进程异常中断时保留未完成事务和失败证据，阻止后续发布，必须先显式恢复该事务；不得删除标记后强行续发。正常人工回退也只能指向直接上一份已验收版本，不自动降级数据库、不覆盖业务数据。
- **私有产物与恢复**：完整配置可能含秘密值，仅存服务器私有运行目录，清单、指针、门禁日志与必要私有配置纳入现有加密备份；公开Git只保存工具及脱敏说明。恢复副本中的生产指针不自动激活，不带生产执行能力、不重放任务或批准。
- **已有证据与本次免重测**：仅首次登记已运行、已验收的基线时，允许将现有完成记录和逐容器一致的运行快照绑定为“沿用既有验收”，明确原证据摘要、范围及未重测事实；不得伪造为新门禁通过。2026-10-15首次登记按所有者要求未重复测试，仅安装入口、冻结配置和登记既有基线；2026-10-16真实前端发布已按入口执行自动门禁，不以“不重复测试”跳过门禁。实际回退、模型及专项验收仍按真实记录区分；后续新发布没有跳过门禁开关。

## 三、前端界面视觉规范（深空值班台 · 深色运维控制台）

> 2026-10-18现行。适用于`stages/04-frontend/`及后续前端维护，依据当前`styles.css`、布局和组件更新。10月8日浅色SaaS、钴蓝大圆角和Icon Rail要求已被本节替代，`05-设备知识设计素材与历史归档资产/UI-redesign-mockup/`仅作历史参考。工作区新增展示与已发布版本分开记录，不能仅因源码存在而宣称上线。

### 3.1 骨架与信息层次

- **整体方向**：低亮度灰蓝背景、青蓝主色、细边线分层、小圆角；面向长时间值班阅读。常规面板以边线区分层级，投影主要用于浮层，避免装饰性渐变、发光边框和重阴影。
- **文字侧栏**：桌面侧栏188px，中文文字导航、选中态浅青背景和左侧指示条；底部显示用户及明确的“退出”按钮。品牌使用文字标识，不恢复闪电渐变图标、头像退出入口或伪搜索框。
- **顶栏**：54px深色顶栏，保留位置上下文、帮助/解读入口、明确的实时连接状态、时钟和提示音开关。功能入口以用户能理解的文字或可访问名称呈现，不添加无功能的搜索框及英文营销式kicker。
- **总览**：紧凑运行统计带、发电监测、最新告警和设备速览。发电监测上方单列全站当前功率与当日累计发电量，均显示整数；下方`DashboardTrend.vue`展示北京时间当天0–24点的全站功率折线（5分钟均值）和每小时发电量柱状图。两图横轴每4小时标注、纵轴使用整数刻度，缺测及未到时段留空。全天图使用历史采样，每5分钟增量刷新；发电量在原始采样上积分，超过15秒缺测不跨段补算，不使用浏览器打开后的短时样本冒充全天。总览不再单独展示实时功率曲线；设备详情仍保留原有实时与历史查询。早先`MetricGauge.vue`仪表盘与短时累计趋势仅作历史实现。
- **列表与详情**：设备、告警、预测列表使用`.page-narrow`，最大1080px居中；抽屉和证据区域按主读数、阈值/状态、时间/编号、解释和原始依据分层，不能只用颜色区分状态。

### 3.2 配色与组件

主题入口为`styles.css`的`:root`与`html.dark`，同时使用Element Plus官方深色变量。新增样式优先复用主题变量；现有图表和少数局部背景仍有直接色值，修改主题时一并核对，不宣称已全部变量化。

| 用途 | 当前基准 |
| --- | --- |
| 页面/面板/次级底色 | `--bg: #0c1118`、`--card: #131a24`、`--card-2: #18212d` |
| 三级文字 | `--ink: #c8d2df`、`--ink-2: #9fb0c3`、`--ink-3: #8a9bb0` |
| 常规/强调边线 | `--line: #24303f`、`--line-strong: #32435a` |
| 品牌与主按钮 | `--brand: #34c9c0`、深阶`#23a19a`，主按钮文字`--on-brand: #06201e` |
| 告警/警示/成功 | `--danger: #f26d64`、`--warning-dot: #f0b44d`、`--success: #3ecf8e` |
| 面板/控件/小元素圆角 | `--r-lg: 4px`、`--r-md: 3px`、`--r-sm: 2px` |

主色表示交互和选中；红色用于告警或危险，金色用于警示和阈值，绿色用于成功/正常。告警级别用小方块，连接信号保留圆点；两类状态组件按用途维护，不再要求所有状态点统一形状。深色浮层、帮助面板和来源块复用面板变量，避免遗留白底。悬停变色等过渡保持克制，不增加妨碍读数的动画。

### 3.3 文本、数据与图表语义

- **聊天首页与任务历史分离（2026-10-18）**：首次进入及新会话主区只显示欢迎区和输入框；未完成任务仅以简短提醒引导至独立“任务记录”，不自动展开全局报告。历史会话严格按会话编号恢复并去重任务；未绑定对话轮次的任务保留独立访问入口。任务详情按点击读取，打开历史不重新执行；会话切换须取消旧读取并防止迟到响应串入新会话。发布事实见 [[04-系统部署发布备份与变更记录/部署与运维日志/16-智能助手首页与任务记录分离]]。

- 中文正文使用现有中文无衬线字体栈；数值启用等宽数字，编码/特征值按需使用等宽字体。单位与数字分别对齐，长标识可缩写但须保留完整值的查看方式。保留足够的小字、坐标轴和按钮文字对比度。
- **长时间阅读与会话导航（2026-10-18）**：全站主文字采用柔和灰蓝 `#c8d2df`，Element Plus 与图表高亮文字同步；次级文字保留分层。智能助手历史会话采用 13px 标题、紧凑单行和右侧最后对话时间，悬停时删除图标原位覆盖时间，保留键盘与触屏可访问性。历史面板受视口高度约束，标题与刷新固定，列表独立纵向滚动；滚轮停留在列表时不串联外层页面、不干扰对话跟随。新消息、回答及任务结果在跟随模式下自动定位末尾；用户向上阅读时暂停跟随，并提供返回最新入口。历史批次见 [[04-系统部署发布备份与变更记录/部署与运维日志/15-智能助手会话导航与低亮度阅读优化]]；独立滚动发布状态见 [[04-系统部署发布备份与变更记录/部署与运维日志/17-智能助手历史会话独立滚动]]。
- 空值、无效值和无数据显示“—”或明确状态；有效零值必须显示为零，不以零补缺失，也不因格式化改变原值。日期时间由现有`format.ts`统一按北京时间展示，原始取证值和接口时间戳保持原样；具体格式变更注明工作区及发布状态。
- 告警详情按原始数值比较，仅对显示保留小数；阈值、触发值、当前值与历史恢复值不得混用。预测特征值、单位和模型贡献分列，模型贡献不当作故障概率或真实故障原因。
- **告警智能解读**：采用事件与触发读数、分段解读要点、历史记录、模型因素、走势与统计、编号建议、适用边界及证据快照的阅读模板。常规数值和模型贡献均保留两位小数，数量/编号/时间保持原格式；原始文本、证据及判断精度不改写。已知模型特征以中文名称呈现，原始标识仍可核对。来源跟随结论和建议，不能因排版隐藏失败取证或消除人工核查要求。
- **历史曲线时间轴**：完整日期范围单独显示，同日刻度优先用时分，跨日才附日期；根据图表宽度限制刻度数并隐藏重叠标签，完整时间与两位小数读数置于提示框。抽屉展开及尺寸变化后应重新计算图表宽度，不能把每个采样点的完整日期都铺到横轴。
- 青蓝曲线用于常规遥测，高风险用红，过期/缺失用中性颜色及文字提示。功率演示参考区间不是告警阈值，浏览器累计趋势不是服务端完整历史；来源与时间范围必须写清。
- 模型解释、程序事实、历史证据、审查意见及人工批准保持原有区分；视觉优化不能把“受理/排队”展示成“执行成功”。
- **严格任务的回答模板**：程序事实从工具实际返回投影，结论短段、研判与建议编号，独立安全意见分区；原始回执标明历史身份，原文与审计依据可展开。只可默认折叠已完成且allow的审查，其余否决、澄清或异常保持突出；不将模型推测提升为事实，不因排版改权限、许可摘要或审批。补充维护归[[01-项目调研规划与开发建设记录/第二版-智能体升级/问答及调度业务主智能体/当前方案-Agent与RAG重建/04-增量优化与补充交付/01-回答可读性与任务结果展示/00-索引·回答可读性与任务结果展示]]，不并入原需求/架构主流程。

### 3.4 响应式与可访问性

- 1200px附近总览主辅列转单列；900px附近详情和监测区域进一步收为单列、隐藏时钟，桌面导航仍保留文字。监测布局另有850px断点，具体以样式实际规则为准。
- 640px附近侧栏收为64px图标条、统计带两列、工具栏换行、列表适应可用宽度；隐藏文字的入口必须保留`aria-label`/`title`。登录页改为单列。移动端精细适配仍未完整验收，不将基本可用写成全端完成。
- 图表、关键状态与无文字控件提供可访问名称；加载、错误、空数据和过期提示必须可辨认，键盘焦点与已有交互不能因样式改动失效。

### 3.5 修改边界与单一来源

- 样式/布局以本节与当前源码为基准，历史样稿和旧截图不覆盖现行设计。已删除的阶段性 UI 优化草稿不再作为依据，实施状态以当前源码为准，发布事实归部署记录；本页维护长期规则，不重复堆叠每一轮验证数字。
- UI优化允许修改模板、主题、组件和展示辅助函数，包括日期、单位、显示精度和说明文案；涉及`src/lib/`时明确影响范围，不能扩大为任意业务改动。API请求、鉴权、路由权限、订阅/历史补查、统计口径、原始时间戳和模型计算变化须单独说明、审阅和按影响验证。
- 后续主题改动同步检查Element Plus、图表、抽屉、助手消息/代码块、告警和来源面板。生产发布统一走前述防回退入口，不因视觉改动重新构建或覆盖无关API和智能体服务。

## 四、验收清单的持续维护

[[02-工程规范边界与验收治理/项目验收与收尾清单]]是项目级状态入口，必须随项目推进更新。先写当前跨版本判定，再依次保留第一版阶段一至六与项目总结，随后按日期记录第二版 V2-M1～M4、历史批次和现行长期待办；阶段内写清已完成内容、可复核证据、验收结论和未覆盖边界。历史未勾选项必须标明当时日期，不能误作当前阻塞。阶段五是第一版业务能力，阶段六是第一版公网安全与恢复亮点，二者均纳入 M4，不另设 M5/M6。项目总结不把部分功能上线、单次冒烟或合成数据指标外推成全项目验收；视频复盘与对外材料不属于第一版发布门槛。

**更新时机**

- 每完成一个阶段里程碑、关键功能、联调或部署验收，即更新对应阶段和项目总结；失败后的修复与补测也要更新，保留旧失败证据。
- 需求范围、FR/NFR 实现、公开数据适用性、服务器状态或发布范围改变时，同步更新受影响的阶段结论和当前待办。
- 每次新增或改变 `artifacts/` 中的长期保留证据、模型、外部数据目录时，同步更新 [[02-工程规范边界与验收治理/运行产物说明]]；原始大文件、密钥和运行账本仍由 Git 忽略。

**填写与复核规则**

- 每条"已完成"须指向笔记、源码、测试结果或具体运行编号，并记录核对日期；"已实现""已测试""已验收""真实环境已验证"分别表述，不互相替代。
- 本机证据未入库时标明 `artifacts/` 路径与复现入口；远端服务器未复测时写明最后实测日期，不能默认为仍在线。
- 现行未完成项单列并按 P0/P1/P2 或明确后续归属排序；历史未完成项保留批次日期与后续结果链接。完成后勾选并归入对应阶段的证据与结论，新增由本轮工作暴露的风险。
- 更新清单时同时核对根 README、阶段索引、运行产物说明和相关双链；阶段发布时核对 `main`、标签及 GitHub Release 的准确提交范围。
- 阶段收尾前必须核对独立问题记录页：已解决项附验证结果，未解决项附后续归属和阻塞判断；不得只在聊天、终端日志或测试交付表格中临时描述。
