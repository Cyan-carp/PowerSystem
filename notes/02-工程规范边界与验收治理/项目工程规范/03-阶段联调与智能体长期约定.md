# 项目工程规范 · 目录、界面、协作与发布约定 · 阶段联调与智能体长期约定

> 本页由 [[02-工程规范边界与验收治理/项目工程规范/00-索引·项目工程规范]] 分卷维护，原有事实、编号和验收边界保持不变。

## 一、跨阶段联调的环境前提与复现边界

### 环境前提与复现边界

**环境前提**

- 依赖：Docker Desktop Engine、Go 1.24+、Python 3.12+；端口 `1883`、`18083`、`6041`、`5432`、`6379`、`8080` 不应被其他服务占用。
- 仓库根目录 `.env` 为本机私有文件；新环境按 `.env.example` 准备，已有 Docker 卷必须使用与该卷匹配的密码。
- 四个基础容器（EMQX、TDengine、PostgreSQL、Redis）端口均映射到 `127.0.0.1`，仅供本机程序连接；数据库密码保存在被 Git 忽略的 `.env`，不写入笔记。

**复现边界**

- `artifacts/`、`.env`、Docker 数据卷不随 Git 迁移；换机器必须重新准备环境与生成数据，旧运行编号不会自动出现，以新运行编号保存证据。
- Docker CLI 未在 `PATH` 中不能直接判定 Docker Engine 不可用，应检查安装路径、服务端和容器状态；阶段一脚本的 `Get-DockerExe` 会尝试查找用户目录的 Docker Desktop 安装路径。
- Compose 容器与本机启动的 API/网关进程不要混为一谈；`ping` 只说明 API 接口可达，四容器状态、进程启动结果和烟测全通过，才能证明基础链路就绪。
- 烟测会在指定数据库创建测试账号、设备和遥测；完整 M2 两小时注入故障属于历史里程碑证据，后续开发按本页第五章做受影响短测，不自动重跑。
- 停止服务分别用 `stop-ai.ps1` 与 `stop-stage2.ps1`；两者不会删除数据库卷，勿用 `docker compose down -v` 清理历史数据。
- 阶段一新建验收库报 `954 Vnodes exhausted` 时，既有 TDengine 容器 vnode 已满；不要删除 M1/M2 库或卷，短回归用 `stages/02-backend/scripts/regress-stage1-isolated.ps1` 的临时容器。
- `.venv` 启动器在含中文的仓库路径下可能失效：不删除既有 `.venv` 或验收数据，改用可工作的 Python 3.12 执行脚本。
- 若当前环境没有可用的 Docker Engine：只做离线单测、代码审查和文档，将该环境的 M3 复验记为未完成，转到有权限的主机重跑；这不改写已保存的 2026-09-29 M3 验收结论。

> **不能只凭模型离线成绩或 `/health` 判定 M3 通过**，需在故障点发送前记录：
>
> - 预测产生时间
> - PostgreSQL `prediction_records` 入库
> - 带 JWT 的 `GET /api/v1/devices/{id}/prediction`
> - AI 告警及 WebSocket 推送
>
> 故障后还需记录恢复、重复窗口去重，并检查重启后的行为。验收结论必须对应具体证据，原始失败报告应保留。

## 二、智能体职责与笔记结构

**职责分工**：阶段 8 Supervisor 负责问答、RAG/搜索与会话；阶段 9 Operation 负责平台与在册资产的只读委派；阶段 10 Security 提供独立审查与程序门禁。能力边界以 [[02-工程规范边界与验收治理/项目工程规范/07-能力数据与服务器边界]] 为准。

**笔记结构**：智能体专题按「索引 → 方案设计 → 实现记录 → 测试与交付 → 问题记录与解决方案」五页组织；多智能体专题分 00 程序控制层、01 基础运维模型、02 安全审查模型、03 联合发布验收。规则用 BND 编号，需求/任务/用例用 MA-F/MA-NFR/MA-T/MA-C，安全审查用独立 F/NFR/T/C/R 编号，原 MA/BND 编号不改。

**状态口径**：文档建档、实现、测试、验收、发布五个状态分开写；建档通过不等于功能验收，历史失败证据不得改写，未执行项不得用健康检查、fixture 或模拟事件代偿。

## 三、只读运维与受控执行

### 基础设施只读运维

资产公开投影与私有连接映射分开维护；导入复核管理员当前身份并保留不可变版本快照，未核验、禁用、跨项目或版本不符的目标零采集。模型进程与凭据执行层分离，固定工具、参数和已知主机密钥，模型不能获得自由Shell、SQL、Docker管理或账号配置入口。

日志在采集端按安全字段/已知事件先投影，再传输、存证或送模型；未知文本和用户内容过滤，保留时效、视角、过滤和截断说明，空摘要不代表完整日志或没有异常。外发范围和目的地仍须按实际阶段确认，不从旧问答授权推导。

测试使用独立专库、账号、认证Redis及回环端口，停止辅助进程核对本批次PID与启动时间；当前既有服务和历史证据保持。远端防重缓存仅属短期传输防重，任务/审计状态真相仍由ma_ops维护。具体契约、连接、工具和命令由建设专题及源码README维护。

### 受控执行

审批与执行必须区分模型提案、程序决定和真实动作；写能力默认关闭，临时演练说明明确对象、窗口和影响。阶段签收与执行窗口开放分开记录，不把文档同步视为生产执行授权。

新审批认证上下文与原规划上下文按实例归属清理；审批等待、规划和批准执行分别计时。审批消费后的不确定结果保留原失败，禁止自动补执行。写前审计不可保存则阻断；程序、模型、容器与页面证据分别登记，fixture不得代偿真实模型。

审批绑定程序保存的计划、目标身份、资产及策略版本；批准后不得由模型替换参数。一次消费与执行尝试同事务，受限broker发出动作前另持久防重；结果丢失也不得再写。本机演练只使用明确归属的隔离无状态对象和独立写签名，与服务器只读传输分开配置；验收外发工具范围按用户授权由程序限制，参数与命令归建设专题及源码README。

## 四、安全门禁与只读巡检

### 安全模型关联字段

服务协议的关联字段、身份、期限与签名由程序拥有；模型意见Schema与外部服务响应分开维护，未知模型字段拒绝，不对错误身份或关联标识自动修补。内部意见契约变动必须版本化策略/许可并独立回归，外部协议兼容单独判定。0731是所有者明确调整，原型号失败和旧候选保留；具体职责与Schema引用程序控制层。

### 安全运行门禁

运行许可与合成验收许可分离，版本显式匹配，不通过删除旧限制接入真实任务。审查记录/事件/门禁关联同事务存证；受审动作先保存计划，最后领取及一次消费再次核对。外发先程序最小投影再审查，实际发送前核对当前绑定；再次解释重新获许可，敏感报告不进入可重放模型历史。已执行事实独立于后审结论，恢复不授予续跑。第四阶段仍先本地集成后发布。

### 项目只读巡检

用户主动巡检以程序固定清单、登记范围/版本和当前身份为边界，task_kind独立标记且只读；逐工具缺能力与缺证据分开，资源观察不自行新增阈值。程序事实/确认发现与模型意见分别存证，报告意见不授权修复。新增许可与策略版本独立保留；模型、工具、程序、页面fixture及实际恢复分账，依赖恢复与专库回归串行，不拼接中断批次。完整敏感报告不进入可重放模型历史，再次解释重审最小摘要。具体契约与证据见[[01-项目调研规划与开发建设记录/02-第二版-智能体升级/多智能体协作建设/05-安全审查模型/05-功能开发与阶段交付/03-项目只读巡检/03-SEC-M3测试与交付]]及程序控制层，命令仅源码README维护。

## 五、发布与观察

交互问答采用按用户、全站及滚动时间窗的独立接纳额度，不与自动事件解读共享。发布保留受影响功能短检、镜像与实例身份核对；观察方式按下节执行。证据账本以本轮文件摘要绑定，未完成、取消或缺失证据不计为通过。

### 开发效率与所有者授权（2026-10-29确认）

- 当前开发阶段以功能落地与恢复供数为先，网页未公开使用、可接受短时停摆。不为假设风险反复加门禁、扩建发布工具或重跑无关测试。
- 已授权任务直接推进；出现可能长耗时的问题，停下该分支，给现状、选项和估时，由所有者判断，不自行无限排障。
- 不重复未受影响且已有明确证据的测试。验证范围按实际改动和已有授权决定；所有者明确免门禁、免测试、暂不备份时，按05登记直接接受，不先修一套门禁或补全测试来阻塞授权操作。
- 所有者接受、实际部署、技术测试分别记录；取消或未执行的事项不写成通过。一次性免备份不自动停用既有定时备份，流程简化不自动删除程序的鉴权、事务和业务数据校验。
- 历史积压可按所有者明确决定设一次固定截点，标记放弃并停止重试；保留原始载荷、缺口和理由，不统一改success，不自动延后截点。规则与运行错误定位见07及部署日志57。
- 笔记、共享记忆及时同步，实际变更一份日志，潜在错误及对应功能集中登记，不重复建立多套验收账本。

### 开发阶段真实服务器观察（所有者2026-10-29确认）

- 当前开发阶段网页尚未公开使用，所有者接受短时停摆。取消两小时稳定性待办；后续不安排AI驻守或发布前长时间稳定性测试，不因等待这类观察阻塞开发、修复和上线。既有带日期的历史结果保留追溯，不补签为通过。
- 长周期表现交给真实服务器自然运行。所有者遇到真实问题后，按 [[57-开发阶段运行错误与功能定位清单]] 提供时间、功能和现象，再定向修复；AI不为假设错误预先扩建系统。
- 需要本轮短时验收观察时，先交付可由本人启动、自动记录日志和摘要的脚本；本人运行后交回日志，Codex核对实际镜像、采样范围、失败和未覆盖项。默认五分钟，不由AI持续盯守，不自动延长到长时间测试。
- 原始记录、权限、来源和迁移兼容性边界保留；具体测试按实际影响与所有者授权决定。允许停摆不等于伪造成功、新鲜度或完整电量；历史数据处理按明确授权的截点与政策执行。
- 脚本仅观察，不自动重启、改配置、修数据、清pending或移动验收指针。取消长观察不自动完成原未验事务；实际修复、观察待反馈与正式签收分别记录。
- 可能长耗时的排障先停止相应分支，说明已取得证据、具体选项及预估范围，由本人判断；无依赖的脚本、记录和修复继续推进。

含中文路径的阶段脚本使用现有PowerShell7及显式UTF-8。停止命令成功后必须实测服务不可达，恢复后必须实测健康，不能把退出码单独当作故障注入证据。源码服务器没有Git时采用固定提交公开包和文件摘要；运行资产不变的测试/状态文档增量只核对摘要，运行代码、配置或知识变更按实际影响和所有者授权安排受影响验证，不自动追加最终长观察。

### 变更风险分档与按范围验证（2026-10-28）

> 文档同步义务见 [[02-工程规范边界与验收治理/项目工程规范/01-目录边界与笔记治理|目录边界与笔记治理]] 第六章；本小节规定档位与验证深度。

| 档位 | 判定 | 最低要求 |
| --- | --- | --- |
| **日常本地** | 只改本机代码、脚本或笔记，不触生产、共享状态与对外接口 | 按影响验证；一份变更记录；更新对话记忆 |
| **兼容普通发布** | 只换入口支持的服务，无迁移、卷、端口、服务集合、权限与私有配置变化，数据接口兼容 | 受影响测试、一次构建、来源与摘要、发布后短检；档位与备份按 [[02-工程规范边界与验收治理/项目工程规范/05-上传服务器规范|上传服务器规范]] |
| **高风险变更** | 迁移、持久化可靠性/写链路、权限与身份、持久卷、恢复链、不兼容 schema | 专项隔离验证；新备份或明确只能前滚；写清回退边界 |

档位依据是“可能丢失或改变什么”（数据、身份、权限、配置、兼容性），不看文件大小、行数或是否含 SQL。

- **范围由影响面决定**：前端展示只跑类型检查、展示相关单测和路由/分块核对；API 与业务逻辑跑对应包测试和真实入口短核对；智能体、RAG、运维、安全按各阶段既有专项执行。不为“保险”整仓重跑。
- **证据可复用**：依赖、配置、源码未变且无新疑点（无新增失败、无异常日志、无契约调整）时，不重跑已完成的业务测试、故障注入、容量或恢复演练；引用时写明原运行编号、摘要与复用理由，不把复用写成“本次通过”。
- **扩大范围的触发**：出现失败、结果与预期不符，或改动触及共享底层、跨版本契约时才扩到相邻路径，并说明触发原因。
- **隔离环境对齐生产关键配置**：durable 会话、消息确认与顺序、超时、并发与限额等直接影响链路行为的配置，必须在隔离环境保持与生产同构；只对齐版本号、端口或容器数量不算对齐。此前隔离环境未覆盖生产 durable 会话，导致漏掉线上乱序 ACK 问题，属于必须优先补齐的配置一致性，而非增加通用验收项。
- **专项只按触发条件执行**：迁移、持久化可靠性/写链路、权限与身份、备份恢复链变化才触发专项短测或恢复演练；普通发布器修改不自动触发完整隔离恢复，周期演练与日常上线解耦。
- **档位与门禁只引用 05**：快慢档位、备份条件、RPO 与当前启用状态只在 [[02-工程规范边界与验收治理/项目工程规范/05-上传服务器规范|上传服务器规范]] 与 [[00-当前系统状态]] 维护，本页不复制参数，也不把本地实现写成生产已启用。
- **失败先诊断，不扩建平台**：上线短检或验收失败先判断业务缺陷、配置漂移还是门禁本身的问题，不以新增发布子系统、脚本或门禁分支代替定位与修复；确需扩建时单独立项并经所有者确认。
