# 项目工程规范 · 目录、界面、协作与发布约定 · 阶段联调与智能体长期约定

> 本页由 [[02-工程规范边界与验收治理/项目工程规范]] 分卷维护，原有事实、编号和验收边界保持不变。

## 一、跨阶段联调的环境前提与复现边界

### 环境前提与复现边界

**环境前提**

- 依赖：Docker Desktop Engine、Go 1.24+、Python 3.12+；端口 `1883`、`18083`、`6041`、`5432`、`6379`、`8080` 不应被其他服务占用。
- 仓库根目录 `.env` 为本机私有文件；新环境按 `.env.example` 准备，已有 Docker 卷必须使用与该卷匹配的密码。
- 四个基础容器（EMQX、TDengine、PostgreSQL、Redis）端口均映射到 `127.0.0.1`，仅供本机程序连接；数据库密码保存在被 Git 忽略的 `.env`，不写入笔记。

**复现边界**

- `artifacts/`、`.env`、Docker 数据卷不随 Git 迁移；换机器必须重新准备环境与生成数据，旧运行编号不会自动出现，以新运行编号保存证据。
- Docker CLI 未在 `PATH` 中不能直接判定 Docker Engine 不可用，应检查安装路径、服务端和容器状态；阶段一脚本的 `Get-DockerExe` 会尝试查找用户目录的 Docker Desktop 安装路径。
- Compose 容器与本机启动的 API/网关进程不要混为一谈；`ping` 只说明 API 接口可达，四容器状态、进程启动结果和烟测全通过，才能证明基础链路就绪。
- 烟测会在当前数据库创建测试账号、设备和遥测；需重跑完整 M2 时按阶段二 README 执行 `run-stage2-test.ps1`（约两小时并注入故障），短测不代替 M2。
- 停止服务分别用 `stop-ai.ps1` 与 `stop-stage2.ps1`；两者不会删除数据库卷，勿用 `docker compose down -v` 清理历史数据。
- 阶段一新建验收库报 `954 Vnodes exhausted` 时，既有 TDengine 容器 vnode 已满；不要删除 M1/M2 库或卷，短回归用 `stages/02-backend/scripts/regress-stage1-isolated.ps1` 的临时容器。
- `.venv` 启动器在含中文的仓库路径下可能失效：不删除既有 `.venv` 或验收数据，改用可工作的 Python 3.12 执行脚本。
- 若当前环境没有可用的 Docker Engine：只做离线单测、代码审查和文档，将该环境的 M3 复验记为未完成，转到有权限的主机重跑；这不改写已保存的 2026-09-29 M3 验收结论。

> **不能只凭模型离线成绩或 `/health` 判定 M3 通过**，需在故障点发送前记录：
>
> - 预测产生时间
> - PostgreSQL `prediction_records` 入库
> - 带 JWT 的 `GET /api/v1/devices/{id}/prediction`
> - AI 告警及 WebSocket 推送
>
> 故障后还需记录恢复、重复窗口去重，并检查重启后的行为。验收结论必须对应具体证据，原始失败报告应保留。

## 二、智能体职责与笔记结构

**职责分工**：阶段 8 Supervisor 负责问答、RAG/搜索与会话；阶段 9 Operation 负责平台与在册资产的只读委派；阶段 10 Security 提供独立审查与程序门禁。能力边界以 [[02-工程规范边界与验收治理/项目边界与协作红线]] 为准。

**笔记结构**：智能体专题按「索引 → 方案设计 → 实现记录 → 测试与交付 → 问题记录与解决方案」五页组织；多智能体专题分 00 程序控制层、01 基础运维模型、02 安全审查模型、03 联合发布验收。规则用 BND 编号，需求/任务/用例用 MA-F/MA-NFR/MA-T/MA-C，安全审查用独立 F/NFR/T/C/R 编号，原 MA/BND 编号不改。

**状态口径**：文档建档、实现、测试、验收、发布五个状态分开写；建档通过不等于功能验收，历史失败证据不得改写，未执行项不得用健康检查、fixture 或模拟事件代偿。

## 三、只读运维与受控执行

### 基础设施只读运维

资产公开投影与私有连接映射分开维护；导入复核管理员当前身份并保留不可变版本快照，未核验、禁用、跨项目或版本不符的目标零采集。模型进程与凭据执行层分离，固定工具、参数和已知主机密钥，模型不能获得自由Shell、SQL、Docker管理或账号配置入口。

日志在采集端按安全字段/已知事件先投影，再传输、存证或送模型；未知文本和用户内容过滤，保留时效、视角、过滤和截断说明，空摘要不代表完整日志或没有异常。外发范围和目的地仍须按实际阶段确认，不从旧问答授权推导。

测试使用独立专库、账号、认证Redis及回环端口，停止辅助进程核对本批次PID与启动时间；当前既有服务和历史证据保持。远端防重缓存仅属短期传输防重，任务/审计状态真相仍由ma_ops维护。具体契约、连接、工具和命令由建设专题及源码README维护。

### 受控执行

审批与执行必须区分模型提案、程序决定和真实动作；写能力默认关闭，临时演练说明明确对象、窗口和影响。阶段签收与执行窗口开放分开记录，不把文档同步视为生产执行授权。

新审批认证上下文与原规划上下文按实例归属清理；审批等待、规划和批准执行分别计时。审批消费后的不确定结果保留原失败，禁止自动补执行。写前审计不可保存则阻断；程序、模型、容器与页面证据分别登记，fixture不得代偿真实模型。

审批绑定程序保存的计划、目标身份、资产及策略版本；批准后不得由模型替换参数。一次消费与执行尝试同事务，受限broker发出动作前另持久防重；结果丢失也不得再写。本机演练只使用明确归属的隔离无状态对象和独立写签名，与服务器只读传输分开配置；验收外发工具范围按用户授权由程序限制，参数与命令归建设专题及源码README。

## 四、安全门禁与只读巡检

### 安全模型关联字段

服务协议的关联字段、身份、期限与签名由程序拥有；模型意见Schema与外部服务响应分开维护，未知模型字段拒绝，不对错误身份或关联标识自动修补。内部意见契约变动必须版本化策略/许可并独立回归，外部协议兼容单独判定。0731是所有者明确调整，原型号失败和旧候选保留；具体职责与Schema引用程序控制层。

### 安全运行门禁

运行许可与合成验收许可分离，版本显式匹配，不通过删除旧限制接入真实任务。审查记录/事件/门禁关联同事务存证；受审动作先保存计划，最后领取及一次消费再次核对。外发先程序最小投影再审查，实际发送前核对当前绑定；再次解释重新获许可，敏感报告不进入可重放模型历史。已执行事实独立于后审结论，恢复不授予续跑。第四阶段仍先本地集成后发布。

### 项目只读巡检

用户主动巡检以程序固定清单、登记范围/版本和当前身份为边界，task_kind独立标记且只读；逐工具缺能力与缺证据分开，资源观察不自行新增阈值。程序事实/确认发现与模型意见分别存证，报告意见不授权修复。新增许可与策略版本独立保留；模型、工具、程序、页面fixture及实际恢复分账，依赖恢复与专库回归串行，不拼接中断批次。完整敏感报告不进入可重放模型历史，再次解释重审最小摘要。具体契约与证据见[[01-项目调研规划与开发建设记录/第二版-智能体升级/多智能体协作建设/05-安全审查模型/05-功能开发与阶段交付/03-项目只读巡检/03-SEC-M3测试与交付]]及程序控制层，命令仅源码README维护。

## 五、发布与观察


交互问答采用按用户、全站及滚动时间窗的独立接纳额度，不与自动事件解读共享。最终上线观察必须校验固定镜像、重启基线和完成时长，不能仅记录字段而不判定；每轮只允许一个观察写者。证据账本以本轮文件摘要绑定，未完成、跳过或缺失证据不计为通过。

含中文路径的阶段脚本使用现有PowerShell7及显式UTF-8。停止命令成功后必须实测服务不可达，恢复后必须实测健康，不能把退出码单独当作故障注入证据。源码服务器没有Git时采用固定提交公开包和文件摘要；运行资产不变的测试/状态文档增量只核对摘要，运行代码、配置或知识变更则重跑受影响验收与最终观察。
