# 数据链路、现场记录与预测反馈

> 使用手册分卷：三个“只读看状态 / 追加上报事实”的功能。总入口是 [[03-平台使用运维与二次开发手册/平台使用手册|平台使用手册]]，开关与生产状态见 [[00-当前系统状态]]。

## 一、数据链路状态

**在哪里**：场站总览页标题下方的「数据链路状态」卡片；设备详情页的同一张卡片（设备口径）。卡片每分钟自动刷新，右上角「刷新」可立即取一次。

**谁能用**：登录即可，只读。没有写操作。

**四个数字分别在说什么**

| 字段 | 含义 | 不能证明 |
| --- | --- | --- |
| 最近接收 | 平台收到的最后一条原始上报时间（设备口径按该设备，总览按全平台最新） | 平台已经算完并入库 |
| 最近确认入库 | 该设备最近一条**已确认**样本的接收时间 | 历史派生、电量rollup 已完成 |
| 处理延迟 | 最新接收与最近确认样本接收时间之差；总览显示活跃设备的最大值 | 某台具体设备的延迟 |
| 7 天内待处理 / 7 天外滞留 | 后台探测快照：仍在正常队列内的条数 / 已超出窗口、不会再按正常路径处理的条数 | 实时精确计数；超过 3 个探测周期显示“未知” |

**阅读顺序**

1. 先看「当前状态」。五种取值：链路正常、平台处理延迟、设备离线、设备无新上报、未知。
2. 再看「最近接收」与「最近确认入库」的时间差，判断是**没有数据**还是**数据没走完**。
3. 设备详情页展开「近 7 个完整自然日的覆盖与缺口」：覆盖百分比来自已验证且未待重算的电量日数据；缺口条数与最长缺口秒数用于判断是否断过流。
4. 总览的两个队列数字用于判断“有没有积压”：7 天外滞留表示这些异常样本已离开正常队列，**不能当作成功入库**。

> **实时恢复不等于历史补齐。** 平台恢复收数后，最新数据会正常显示，但断流期间的历史日聚合与缺口需要单独回补；看到“链路正常”就认为历史已经补齐是错的。

**限制**

- 总览的队列数字来自后台探测快照，不是查询时实时统计；显示“未知”表示快照过期，不代表队列为空。
- 设备口径的覆盖只统计 `source_quality='verified'` 且未打待重算标记的日期，缺行即显示“未知”。
- 时间统一按北京时间与 UTC 记录，页面时间**固定按北京时间（Asia/Shanghai）显示**，不随浏览器所在时区变化；对时间有疑问时以设备详情的采样/接收两个时间为准。
- 开关 `POWERSYSTEM_LINK_STATUS=false` 会暂停这两个接口；专题见 [[01-数据链路状态]]。

## 二、现场记录

**在哪里**：设备详情页与告警详情面板下方的「现场记录」卡片。

**谁能用**：管理员与常规运维人员都可读；写入还受开关控制（`POWERSYSTEM_FIELD_RECORD_WRITES`，未配置时可用，显式设为 false 时返回“该功能暂时停用”）。

**怎么做**

1. 点「添加记录」展开表单，填三项：异常现象、处理措施、处理结果，每项 1–2000 字。
2. 点「保存记录」。保存成功后表单清空、卡片刷新，新记录出现在最上方。
3. 记录按 50 条一页，底部「更多记录」继续往前翻。

**预期结果**

- 记录显示操作人、提交时间；从告警详情提交的记录额外显示告警编号。
- 告警来源的记录同时出现在该告警与原设备详情下；从设备详情提交的记录只属于该设备，不带告警。
- 同一次提交的重试不会产生重复记录：页面为每次提交生成提交编号，保存失败后**原样重试**（不改内容）会返回同一条。保存成功后再提交相同内容、或改动后改回原样，都会生成新的提交编号，因此会新增一条记录；去重依据是提交编号，不是文字内容。

**写入暂停与异常状态**

| 状态 | 页面表现 | 原因 |
| --- | --- | --- |
| 写入暂停 | 「添加记录」按钮**仍然存在**、表单可填；提交时被拒绝并提示“该功能暂时停用”，已填内容保留 | 写入开关 `POWERSYSTEM_FIELD_RECORD_WRITES=false`；按钮不随开关隐藏 |
| 读取失败 | “现场记录暂不可读”并给「重试」 | 后端或数据库暂不可用 |
| 保存失败 | 表单下方红框报错，内容保留 | 校验不通过或服务暂不可用，改完可重试 |

**限制**

- 记录是**追加**的，不能编辑或删除；写错了再写一条更正，原记录保留。
- 现场记录**不改变告警状态**。确认与恢复仍走告警详情原有入口，两者互不替代。
- 每项上限 2000 字，超长会被拒绝；不要粘贴整段日志，必要时截取关键行。
- 专题见 [[01-现场记录输入]]。

## 三、预测反馈

**在哪里**：故障预测页打开一条预测的依据抽屉 → 「预测结果反馈」卡片；模型质量页的「人工复核」卡片汇总展示。

**谁能用**：登录用户本人；写入受 `POWERSYSTEM_PREDICTION_FEEDBACK_WRITES` 控制（未配置时可用）。

**三种反馈**

| 选项 | 何时可选 | 要填什么 |
| --- | --- | --- |
| 确认故障 | 故障已实际发生 | 实际发生时间（北京时间）与说明 |
| 未发生 | **该条预测的一小时观察窗口结束后** | 说明 |
| 待观察 | 任何时候 | 说明 |

**怎么做**

1. 在预测抽屉点「提交反馈」，选择结果、填写说明；选「确认故障」时补实际发生时间。
2. 保存后列表刷新，按时间倒序显示所有历史反馈。
3. 同一条预测可多次提交（例如先「待观察」、窗口结束后再改「未发生」）；每次都是新记录，旧的保留。

**预期结果**

- 反馈绑定**具体那一条预测**（不可变 `prediction_id`）与提交人，不绑定设备或时间段。
- 模型质量页「人工复核」显示按**每条预测的最新反馈**统计的三个计数，以及近期记录（含设备、预测时间、提交人）。
- 两人同时提交时，后到的一方会收到“提交编号已用于另一条”或版本冲突提示，页面自动刷新供其重新核对。

**限制**

- 反馈**不会**让模型自动学习、不会改变当前阈值或已生成的预测，也不立即改变线上精度指标；它是一份人工核对记录，与自动真值分表存放。
- 观察窗口未结束时不能选「未发生」；「确认故障」的时间不能晚于当前时间。
- 关闭写入开关后历史仍可查，新提交被拒。
- 专题见 [[01-预测结果反馈]]。
