# 04 · 非功能需求清单（NFR）

> 回到 [[00-索引·需求分析]]

本章定义系统要**做到什么程度**。对应手册任务 6（非功能需求部分）。

> 学生项目最容易完全忽略这一类，而企业评审恰恰最看重。**铁律：每条非功能需求必须有具体数字**——不写「系统要快」，写「列表页打开不超过 2 秒」。

## 一、清单总览

> 以下数字是验收目标。当前 M1/M2 只在三台合成设备上取得链路证据，200 台容量、页面响应、跨浏览器和完整安全基线尚未按本清单验收；不得把目标数字写成已达成结果。逐项状态见 [[项目验收与收尾清单]]。

| 类别 | 编号 | 需求 | 量化指标 |
| --- | --- | --- | --- |
| 性能 | NFR-01 | 设备接入容量 | 单服务器支持 **200 台设备每 5 秒上报一次** |
| 性能 | NFR-02 | 页面响应 | 列表页打开 **≤ 2 秒** |
| 实时性 | NFR-03 | 告警延迟 | 告警端到端延迟 **≤ 10 秒** |
| 可用性 | NFR-04 | 数据完整性 | 断网缓存，数据完整率 **≥ 99.9%** |
| 可用性 | NFR-05 | 断点续传 | 网关断网恢复后 **30 秒内**完成补传 |
| 安全 | NFR-06 | 接口鉴权 | 所有业务接口需登录鉴权（JWT） |
| 安全 | NFR-07 | 密码存储 | 密码加密存储，不落明文 |
| 安全 | NFR-08 | 合规对齐 | 对齐电力监控系统网络安全防护、等保 2.0 三级要求 |
| 可维护 | NFR-09 | 日志规范 | 结构化日志，分级、按天切割 |
| 可维护 | NFR-10 | 配置分离 | 配置与代码分离，密钥不入仓库 |
| 可维护 | NFR-11 | 架构分层 | 分层架构（handler/service/model），数据访问隔离 |
| 兼容性 | NFR-12 | 浏览器范围 | 支持 Chrome / Edge 最新两个大版本 |
| 可用性 | NFR-13 | 飞书业务通知可靠性 | 业务事件同事务入库；正常情况下每 2 秒检查待发送项，失败后按 2～128 秒退避重试；按事件键去重，允许网络不确定时少量重复送达 |

## 二、逐条说明

### 1. 性能（NFR-01、NFR-02）

- **NFR-01 设备接入容量**：单服务器（2 核 4G）支持 200 台设备、每 5 秒上报一次，即约 40 条/秒的遥测写入，不丢数据、不积压。这是本项目「低成本」定位的硬件边界承诺。
- **NFR-02 页面响应**：列表页打开 ≤ 2 秒，历史曲线查询 ≤ 2 秒（分页 + 时序库索引支撑）。

### 2. 实时性（NFR-03）

- **NFR-03 告警延迟**：从遥测越限到前端收到告警 ≤ 10 秒。这呼应 [[02-用户故事]] S-01 的「10 秒内弹告警」，是对 [[第一版-平台主体/行业调研与产品分析/01-行业背景与市场分析]] 痛点 3「故障发现滞后」的直接反击。

### 3. 可用性（NFR-04、NFR-05）

- **NFR-04 数据完整性**：边缘网关断网时本地缓存（SQLite/文件队列），恢复后补传，弱网环境数据完整率 ≥ 99.9%。这是 [[第一版-平台主体/行业调研与产品分析/05-产品定位与差异化]] 中「云边协同」定位的量化落地。
- **NFR-05 断点续传**：Broker 宕机或断网恢复后，网关 30 秒内完成缓存数据补传。

### 4. 安全（NFR-06 ~ NFR-08）

- **NFR-06**：所有业务接口需 JWT 鉴权，未登录不可访问。
- **NFR-07**：用户密码加密存储（bcrypt 等），接口响应不泄露密码哈希、内部路径。
- **NFR-08**：对齐 [[第一版-平台主体/行业调研与产品分析/02-政策环境与驱动力]] 中提到的电力监控系统网络安全防护、等保 2.0 三级要求（作为设计导向，学生项目做到「可说明对齐」即可）。

### 5. 可维护（NFR-09 ~ NFR-11）

- **NFR-09**：Go 后端用结构化日志（zap/logrus），统一格式、分级、按天切割。
- **NFR-10**：配置与代码分离（viper 管理），密钥/密码不进 Git 仓库。
- **NFR-11**：分层架构，数据访问隔离在 model 层，换数据库只需改一层。

> 阶段五飞书机器人地址、签名密钥和业务接口令牌依 NFR-10 保存在服务器 600 权限私有文件，并通过 Compose 私有挂载供相应服务读取；不写入公开仓库。此实现证据不替代 NFR-08 的合规认证。NFR-13 的轮询与退避时间是系统内部处理口径，不等同于外部飞书送达 SLA，见 [[第一版-平台主体/开发阶段5-飞书告警通知/01-链路与实现]]。

### 6. 兼容性（NFR-12）

- **NFR-12**：前端支持 Chrome / Edge 最新两个大版本，无需兼容老 IE。

## 三、量化承诺汇总（答辩速记）

> 一句话向评委报出全部数字：**「单机 200 台设备 5 秒上报、告警 10 秒内到、断网数据 99.9% 不丢、接口全鉴权密码加密、分层可维护。」**

| 指标 | 数字 |
| --- | --- |
| 设备接入 | 200 台 / 5 秒 |
| 告警延迟 | ≤ 10 秒 |
| 页面响应 | ≤ 2 秒 |
| 数据完整率 | ≥ 99.9% |
| 补传时效 | 30 秒 |
