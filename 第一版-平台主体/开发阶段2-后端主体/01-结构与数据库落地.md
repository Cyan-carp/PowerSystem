# 01 · 结构与数据库落地

> 回到 [[第一版-平台主体/开发阶段2-后端主体/00-索引·开发阶段2-后端主体]]；对应路线图第 5 周，落实 Gin 骨架和数据库设计。

## 一、阶段目录与职责

| 位置 | 职责 |
| --- | --- |
| `stages/02-backend/cmd/api` | Gin HTTP 与实时业务服务入口 |
| `stages/02-backend/cmd/gateway` | 阶段二 MQTT→TDengine 持久网关入口 |
| `internal/api` | handler、JWT 中间件、告警工作者及 WebSocket |
| `internal/ingest` | SQLite 待写队列、动态子表、批量入库 |
| `internal/model`、`internal/store` | 关系模型、迁移、PostgreSQL 与 Redis 访问 |
| `internal/service` | 告警收敛与恢复状态转换、收件事务处理 |
| `internal/telemetry`、`internal/tdengine` | 统一报文校验、受限时序查询与入库 |
| `deploy/`、`scripts/`、`test/` | SQL、Compose 与运行脚本、测试页 |

阶段二的网关单独实现，阶段一 M1 源码不改。两条路径都订阅 `device/telemetry`，各有固定 MQTT 客户端 ID 和持久会话。

## 二、数据库与配置

| 存储 | 内容 | 初始化 |
| --- | --- | --- |
| PostgreSQL `powersystem` | 用户、设备、规则、记录、遥测去重收件表 | `deploy/postgres/001_init.sql`，API 启动时幂等执行 |
| TDengine `powersystem_stage2` | 长期遥测超级表、按设备 ID 建子表 | `deploy/tdengine/init.sql`；新设备建档或首次入库时创建子表 |
| Redis | `device:<id>:latest` 和一次性 WebSocket 票据 | 服务运行时写入 |
| 本地 SQLite | 阶段二网关待写消息 | `artifacts/stage2-后端主体/runtime/gateway.sqlite` |

关键约定：

- PostgreSQL `devices.station_code` 与 MQTT 的 `station_id` 标签使用相同编号（例如 `ST-01`）。
- TDengine 子表名仅由数据库数字 ID 生成；设备编号 / 场站编号先通过字符白名单，再写入标签。
- `.env` 保存本机密码与 JWT 密钥；`.env.example` 只存占位值。
- 沿用阶段一 Compose 项目及原有卷，避免覆盖历史验收库。

## 三、基础验收

预检脚本须完成编译、迁移和三台演示设备登记。

- `GET /api/v1/ping` 返回 `code=0`
- 更改 `HTTP_ADDR` 环境变量可改变端口
- 日志由 Zap 输出 JSON

详细命令见 [[stages/02-backend/README.md]]。
