# 开发阶段6 · 公网安全与恢复能力索引

> 阶段六是第一版收官阶段新增的主要亮点：让公网演示入口具备可信加密和最小暴露，并让服务器数据在异地密文、隔离恢复和口令交接三个层面形成可核对的恢复链。它作为横跨部署、运维和发布的正式阶段纳入 M4，不另设 M6。

## 一、阶段目标与状态

| 目标 | 当前状态 | 验收边界 |
| --- | --- | --- |
| 公网加密 | 受信任 IP HTTPS/WSS 已上线，证书自动续期已演练 | 域名不属于第一版要求 |
| 攻击面收敛 | 旧 HTTP/FRP 外部直连已阻断，SSH 改为公钥，内部服务不直接映射公网 | 共享云主机的其他业务监听不属于本项目 |
| 仓库安全 | 当前候选、远端可达历史和服务器现用秘密完成模式/值比对，未发现已知真实凭据 | 静态扫描不能替代 GitHub 权限、Webhook 和 Deploy Key 管理端检查 |
| 异地备份 | 更新前后两份加密包已上传，云端与本机 SHA256 一致；每日定时器启用 | 密文保留策略和新增持久数据需持续复核 |
| 隔离恢复 | PostgreSQL、TDengine、两个 SQLite 队列、模型、`.env`、通知私有文件和业务投递表已核对 | 只证明本次版本与本次数据样本可恢复 |
| 整机灾难恢复 | 项目所有者已反馈 R730xd 之外的口令副本及 `MATCH` 核对完成 | 隔离恢复已通过；真实整机丢失后的生产切换未演练 |

## 二、为什么是项目亮点

- 公网链路从“能访问”提升为可信证书、最小端口和可续期的正式入口。
- 备份从服务器本地文件提升为异地密文、哈希对账和独立环境恢复，验证对象覆盖业务数据与恢复所需配置。
- 仓库公开、服务器访问和部署执行权被放在同一发布门禁中检查，降低“公开源码等同于暴露服务器控制权”的误判和实际风险。
- 失败证据被保留：旧 HTTP、旧备份脚本默认目标、首次错误容量包和口令交接前的缺口均有明确边界；交接后的状态另见正式测试记录。
