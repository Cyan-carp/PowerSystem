# 02 · 认证设备与数据查询

> 回到 [[开发阶段2-后端主体/00-索引·开发阶段2-后端主体]]；对应路线图第 6 周，落实 FR-05、FR-06、FR-08。

## 一、认证与接口边界

- 注册账号默认角色为 `operator`；密码经 bcrypt 后存入 PostgreSQL。
- 登录签发有效期 8 小时的 JWT；设备、规则、告警、总览、遥测与票据接口均要求 Bearer token。
- 当前单场站演示中，已登录用户都可维护设备与规则；更细的角色权限留到后续安全迭代。

## 二、设备与遥测

| 行为 | 约定 |
| --- | --- |
| 新建设备 | 编号、名称、类型、场站编号必填；编号与场站编号使用字母、数字、下划线或连字符 |
| 更新设备 | 可更新名称、类型、厂商和分组；编号与场站编号建档后不变 |
| 删除设备 | 软删除并禁用规则；遥测和历史告警继续保留 |
| MQTT 接入 | 阶段二网关按登记的编号和场站匹配，首次写入时动态建 TDengine 子表 |
| 历史查询 | 设备＋指标＋RFC3339 起止时间；单次跨度不超过 24 小时、最多 5000 点 |
| 最新值 | 后端确认 TDengine 入库后更新 Redis；没有遥测时返回资源不存在 |

## 三、可测试性

- 无 token 访问业务接口应为 401
- 错误密码不得登录
- 列表分页和分组筛选生效
- 新建设备可马上发送合法 MQTT 报文并查询其历史值
