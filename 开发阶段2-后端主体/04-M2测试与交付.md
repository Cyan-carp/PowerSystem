# 04 · M2 测试与交付

> 回到 [[开发阶段2-后端主体/00-索引·开发阶段2-后端主体]]；对应路线图第 8 周。记录可重复的功能自测、两小时联调与故障恢复证据。

## 一、功能与链路用例

`smoke-stage2.py` 自动登记独立测试设备，检查注册/登录、无效 token、设备 CRUD、分页、规则校验、Redis 最新值、TDengine 历史曲线、WebSocket 票据和告警闭环。实际执行情况写入运行目录的 `cases.csv`；未执行不得勾选通过。

## 二、M2 两小时运行

默认三台模拟器每 5 秒各发一条、每台 1440 条，约两小时。自动测试在第 20 分钟暂停并恢复 Broker、第 40 分钟重启阶段二网关、第 60 分钟重启 API；记录事件及服务状态。结束后比较模拟器 SQLite 账本、TDengine 序号、网关待写队列与 PostgreSQL 收件待处理数。短测只验证脚本路径，不代替完整 M2。

| 指标 | 通过条件 |
| --- | --- |
| 数据连续性 | 三台各 1440 条、无序号缺失/重复，模拟器与网关队列归零 |
| 告警 | 新设备越限 ≤10 秒推送；确认后持续越限不重报，恢复再越限重报 |
| API | 阶段二 Must 接口和至少 20 条自动用例通过 |
| 恢复 | Broker、网关、API 重启过程有时间记录，恢复后收件待处理归零 |
| 安全 | 审查包不包含 `.env`、密码或 JWT |

## 三、证据与状态

运行与停止命令见 [[stages/02-backend/README.md]]。每次运行输出 `run.json`、`events.jsonl`、`metrics.csv`、`cases.csv`、`reconciliation.json`、`summary.md` 和 `review-bundle.zip`，目录为 `artifacts/stage2/<运行编号>/`，不纳入 Git。**M2 是否通过只依据完整两小时运行后的实际对账与用例记录填写**；测试未完成时保持“待验收”。阶段一回归另运行其短测并记录结果。
