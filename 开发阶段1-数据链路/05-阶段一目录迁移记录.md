## 二、未随 Git 迁移的状态

公开仓库只保存源码、脚本、配置模板和笔记，不包含私有 `.env`、本机虚拟环境、`artifacts/`、Docker 卷或审查包。若要保留旧测试状态，应分别处理：

- **运行证据：** 备份所需的整个 `artifacts/stage1/<运行编号>/`，包括 `review-bundle.zip`；它不包含私有配置和完整 TDengine 数据库。
- **SQLite 队列：** 模拟器与网关账本可能带 `-wal`、`-shm` 配套文件。运行中应使用在线快照，不能只复制主文件；具体文件作用见 [[运行产物说明]]。
- **Docker 数据：** 当时的 `powersystem_emqx-data`、`powersystem_emqx-log`、`powersystem_tdengine-data`、`powersystem_tdengine-log` 卷需按保留目标单独备份。重新克隆 Git 不会恢复这些卷；不要为整理目录执行 `docker compose down -v`。
- **私有配置：** 旧卷恢复需要与其匹配的数据库口令；`.env` 应通过安全渠道备份和恢复，不能放进 Git 或审查包。`.venv/`、Go 编译缓存和 Windows 可执行文件通常重建即可。

以上卷名和路径属于阶段一当时的本机 Compose 项目。当前跨阶段部署和备份流程以 [[平台运维与二次开发手册]] 与 [阶段四部署说明](../stages/04-frontend/deploy/README.md) 为准。

## 四、今天如何使用这份记录

追溯阶段一整理结果时，用本页的运行编号和相对路径查本机证据；迁移到新电脑时，先确定 Git 提交与所需私有数据的备份范围，再按 [[平台运维与二次开发手册]] 和阶段一 README 恢复、预检并复核。确认备份可读后才考虑清理旧目录或卷。新增项目文件无需写入本页逐项登记，应按 [[项目工程规范]] 更新阶段索引、运行说明和 [[运行产物说明]]。
