# 04 · 阶段一测试与交付

> 回到 [[开发阶段1-数据链路/00-索引·开发阶段1-数据链路]]；对应路线图第 4 周。具体命令以 `stages/01-data-chain/README.md` 为准。

本页说明：**一小时测试怎么跑、验收标准是什么、结果怎么交付。**

## 一、测试如何运行

用户在项目根目录执行预检后，再执行：

```
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\stages\01-data-chain\scripts\run-stage1-test.ps1
```

| 脚本行为 | 说明 |
| --- | --- |
| 生成唯一运行编号 | 每次运行独立数据库 |
| 启动 3 台设备和网关 | 组成完整链路 |
| 注入故障 | 按时停止 EMQX 30 秒、重启网关 |
| 记录指标 | 约每 10 秒记录生成量、队列积压、入库量、进程状态 |
| 日志目录 | `artifacts/stage1/<运行编号>/` |
| 自动打包 | 退出时打包 `review-bundle.zip` |

## 二、验收目标（里程碑 M1）

| 指标 | 目标 |
| --- | --- |
| 数据量 | 每设备 720 条，总计 **2160 条** |
| 序号覆盖 | `seq` 均覆盖 0–719 |
| 一致性 | 时间戳与模拟器账本一致，无多余或重复序号 |
| 队列状态 | 两个待处理队列归零 |
| 事件可核 | 故障注入和恢复事件在 `events.jsonl` 中可核 |

> 恢复耗时由 `metrics.csv`、事件时间与入库日志判断。

## 三、交付与中断处理

| 情况 | 做法 |
| --- | --- |
| 正常完成 | 记录并提供审查包绝对路径 |
| 脚本失败 / 主动中断 | 保留终端最后错误和原因 |
| 断电 / 强制结束 | 恢复后用 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\stages\01-data-chain\scripts\collect-stage1-test.ps1 -RunId <运行编号>` 重新打包，说明大约中断时间，必要时附 Docker Desktop 错误截图 |

## 四、验收纪律

- **短测只能证明脚本和故障路径可执行，不能替代完整一小时 M1。**
- 审查发现问题后，在功能分支修复、短测并合入 `dev`。
- 首次完整 M1 已通过，`main` 已合并 `dev` 并创建 `stage1-m1-passed` 标签；本次目录迁移以短测验证路径，不改写原始验收记录。

## 一小时 M1 验收记录（2026-09-27）

运行编号：`stage1_20260927_161047_b8b6`。审查依据为该运行目录的 `run.json`、`events.jsonl`、`metrics.csv`、`reconciliation.json`、`telemetry.csv`、模拟器/网关/容器日志及 `review-bundle.zip`。压缩包完整性检查通过，所需日志齐全，未发现本地 TDengine 密码写入包内。

| 项目 | 实测结果 |
| --- | --- |
| 运行 | 约 3602 秒，状态 `completed` |
| 每设备入库 | `INV-1001`、`INV-1002`、`INV-1003` 各 720 条 |
| 总量 | 模拟器生成 2160 条，TDengine 入库 2160 条 |
| 完整性 | 每设备 `seq=0–719`，无缺口、额外序号、重复序号或时间戳错配 |
| 待处理队列 | 模拟器待发 0，网关待写 0；故障期间最大待发 39 |
| Broker 故障 | 08:30:59–08:31:30 UTC，记录的停机时长约 31.3 秒 |
| Broker 补传 | 网关 MQTT 重连于 08:31:57 UTC；首次指标确认全量追平于 08:32:11 UTC，约 13.6 秒（10 秒采样精度） |
| 网关重启 | 08:50:56 UTC；首次指标确认追平于 08:51:03 UTC，约 6.2 秒 |

Broker 的 `docker compose start` 命令在 08:31:30 UTC 返回，而 MQTT 客户端在约 27 秒后才实际重连。因此若从容器启动命令返回计时，指标首次显示追平是约 40.9 秒；NFR-05“恢复后 30 秒内补传”按**实际 MQTT 连接恢复**计时为约 13.6 秒。此口径在后续阶段应继续保持一致，并将 Broker 就绪时间单独写入自动日志，便于更精确核验。

网关日志中共收到 2163 次有效投递，较最终 2160 条多 3 次重投；数据库无重复，说明 `(device_id, seq)` 去重和重启续接生效。EMQX 在计划停机时输出了关闭过程错误日志；TDengine 启动时有缺少旧 vnode 文件的诊断日志。本次没有网关写库失败记录，最终对账仍为 100%。**结论：阶段一 M1 数据链路验收通过。**
