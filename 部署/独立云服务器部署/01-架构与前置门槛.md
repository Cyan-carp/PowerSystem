# 01 · 架构与前置门槛

> 本页给出双入口架构、备案限制和接入前的主机、DNS、空间及端口门槛。

```text
浏览器 ── HTTPS/WSS ── 新云 Nginx:443 ── 127.0.0.1:3667 ── 新云 frps:7000
                                                   │ 专用 TLS + token
                                                   └── R730xd 新 frpc ── 127.0.0.1:18080 (业务 Nginx)
管理 SSH ── 新云:7070 ── 同一新 frpc ── R730xd:22
浏览器 ── HTTPS/WSS ── 旧云:443 ── 旧共享 FRP ── 同一 R730xd 业务
R730xd backup.sh ── 同一 GPG 密文 ── 旧云 SFTP + 新云 SFTP
```

## 实施前必须记录的事实

1. 从**可信网络**查询 `www.cyancarp.cn` 的公开 A 与 AAAA、TTL，记录权威 DNS 与两个公共递归解析器的结果；A 应为 `8.138.42.212`，不应有误指向的 AAAA。当前开发沙箱曾返回测试地址，不能引用为证据。解析生效本身不等于备案允许开站。
2. 从阿里云控制台确认新云实例地域、系统、实例 ID、公网 IP、磁盘大小与安全组。若为中国内地实例，备案通过且接入信息覆盖该域名和接入商前，域名站点必须禁用；保留域名 Host 拦截。参考[阿里云备案说明](https://help.aliyun.com/zh/dns/pubz-filing-domain-name-related-faq)。
3. 首次连接前，在云控制台终端执行 `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`，将 SHA256 指纹和本地首次握手指纹逐字核对。指纹不一致立即停止，不输入密码。确认 root 密钥、另一应急会话和云控制台终端可用后再关闭密码登录；聊天中曾暴露的初始密码需要轮换。
4. 记录 R730xd 当前 `systemctl status frpc`、`docker compose ps`、旧 IP 登录/API/WSS、备份 timer、旧备份目标与最近有效密文大小；对现网先做一次成功备份。若旧链路已有故障，先明确基线再实施。
5. 新云可用空间必须满足 `max(10 GiB, 30 × 最近有效 .tar.gz.gpg 大小)`，否则**暂停新备份接入**。检查接收目录所在文件系统，而非只看根分区。30 倍是本轮约定的空间余量；每次增大备份格式/数据量后重算。
6. 查看新云 `ss -lntup`、`df -B1`、`free -h`、`nginx -V`、`sshd -T` 和安全组。端口目标：22 管理 SSH（限制运维来源），80 HTTP-01，443 HTTPS，7000 FRP 控制（仅 R730xd 出口 IP），7070 R730xd SSH 代理（限制运维来源）；3667 仅本机 Nginx 可访问，公网 IPv4/IPv6 均阻断。数据库、MQTT、Prometheus、Grafana 不映射公网。

## 变更闸口

- 新云入站安全组及主机防火墙都应核对；不能把 `Test-NetConnection` 的沙箱假成功当证据。部署前先保留云控制台远程登录能力，防火墙规则逐条添加并从独立网络复测 22 后再收紧。
- 首次备份接入前完成磁盘门槛、受限账号、SSH 主机密钥核验、公钥免密及传输路径测试。
- 备案前只允许独立 IP HTTPS 入口；80 仅供 IP 证书 HTTP-01。`www.cyancarp.cn` 的 80/443 Host 请求应返回拒绝且不得到达 R730xd。
- 部署记录中的每一项要保存 UTC 时间、操作人、实例 ID、配置版本、原始命令的**脱敏**输出和结论；机密数据不进 Git。失败与回退同样记录。
