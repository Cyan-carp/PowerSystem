# 04 · 备份、恢复、双入口切换与回退

> 本页说明同一密文的双目标上传、隔离恢复、入口切换和故障回退顺序。

## 双目标密文备份

R730xd 的 `backup.sh` 先导出 PostgreSQL、TDengine、SQLite 在线快照、模型、私有配置、Agent 审计/知识等现有范围并生成 SHA256 清单，再 tar+GPG AES256 加密；同一个 `.tar.gz.gpg` 和 `.sha256` 文件分别上传到旧云主目标与新云副目标。配置文件：`/etc/powersystem/backup-target` 是原目标；`/etc/powersystem/backup-secondary-target` 是新增目标，未配置时保留单目标行为。两者不得相同。传输均使用 R730xd 的 `/etc/powersystem/backup-ed25519` 与严格主机密钥核验。

上传会独立尝试两台云机。任何一个失败，脚本返回失败并保留本地密文及校验文件，**不进行七天本地清理**；修复后可重传同份密文，不必立即再导出一次在线数据库。每天检查 `systemctl status powersystem-backup.timer`、最近一次 `powersystem-backup.service` 结果及两云最新文件。对偶发失败设人工告警；长期只上传到一台不算双云备份验收。

首次接入把最近已验证备份复制到新云：在 R730xd 的备份目录对本地 `.sha256` 做 `sha256sum -c`，用备份私钥 `scp` 到新云 `/incoming/`；新云 root 先 `cd /srv/powersystem-backups/incoming`，再运行 `sha256sum -c <密文>.sha256`，旧云也核对同一个文件名/摘要。文件权限和空间重新检查。旧备份接收端及自动清理策略保持原样。

在 R730xd 对该密文运行 `bash stages/04-frontend/deploy/restore-verify.sh /var/backups/powersystem/<密文>.tar.gz.gpg`。隔离项目必须与生产 Compose 不同；核对两库、队列、模型、`.env`、飞书与 Agent 私有文件、知识索引和业务表，并保存退出码/行数。完整灾难恢复还依赖服务器外离线解密口令副本；新云不存该口令。恢复演练结束确认隔离项目和卷名后再清理，绝不对生产执行 `down -v`。

## 入口切换

| 情况 | 用户操作 | 运维检查 |
| --- | --- | --- |
| 新云或域名入口故障 | 改用 `https://8.138.10.222/` 并重新登录 | 旧入口/API/WSS 和 R730xd 容器；新云 frps/Nginx/证书/安全组 |
| 旧云故障 | 用 `https://8.138.42.212/` 并重新登录；备案后可用域名 | 新云入口和同一 R730xd 业务 |
| R730xd 故障 | 两入口均无法恢复业务 | 按业务服务器恢复流程处理，不宣称双云业务容灾 |

## 故障演练与回退顺序

1. 变更前保存原目标配置、原 `backup.sh` 版本、新云配置及关键服务状态。确认旧入口仍可用。
2. 受控停止新云 `powersystem-edge-frps` 或新机 Nginx 短时间，验证旧入口和 R730xd 业务继续运行；随后立即恢复新入口，观察至少 30 分钟，无服务重启/错误增加，记录时间和样本。
3. 若新入口不能修复：在 R730xd `systemctl disable --now powersystem-edge-frpc`；新云 `systemctl disable --now powersystem-edge-frps`，停用项目 Nginx 站点（不影响系统其他站点），`nginx -t && systemctl reload nginx`。删除或移走 `/etc/powersystem/backup-secondary-target`，保留 `/etc/powersystem/backup-target` 原值；确认下一次旧云单目标备份成功。不要关旧云共享 FRP、不要停生产 Compose。
4. 若仅新云备份失败而入口健康，先修复 SFTP/磁盘；应急可暂时移走副目标配置，记录双目标失效期间与补传计划。待空间和权限恢复，重传未送达的密文并恢复双目标。

回退与故障演练应记录新旧 HTTPS/WSS、登录、敏感路径拒绝（`/internal/` 与注册接口）、SSH 代理、外部 3667 阻断、证书状态和备份摘要；每项标注实际结果，不用“配置已写”代替现场验收。

## 常态巡检与维护

| 频率 | 检查 | 失败时动作 |
| --- | --- | --- |
| 每日 | 两个入口的 HTTPS/API/WSS；新云 `frps`、Nginx、R730xd 新旧 `frpc`；备份 timer 最近一次退出码、双云最新文件名及 SHA256；接收目录空间 | 标记故障起点；先确认旧入口和本地业务，再修复新入口/补传密文 |
| 每日 | IP 证书剩余有效期、自动续期 timer（六天短证书） | 立即测试 80 challenge、Certbot 日志和手动续期；不要等证书过期 |
| 每周 | SSH/FRP/Nginx 拒绝日志、暴露端口、安全组与主机防火墙、账号/密钥权限 | 排查未知来源连接，轮换受影响 token/密钥并记录 |
| 每月及格式变更后 | 选取新云一份密文在 R730xd 做隔离恢复；核对模型、数据库、队列、私有文件 | 修正备份范围/权限，保留失败密文与日志供复盘 |
| 每次系统升级后 | 重启验证自动启动、Nginx/FRP/SSH 版本、证书续期与 3667 阻断 | 回退变更或修复 unit/防火墙，重新跑验收矩阵 |

新云备份密文的清理期限先按现网保留策略核对；实施前不要擅自批量删除。设置保留任务时必须先确认至少一份近期可恢复备份、两云摘要与离线口令仍可用，再记录删除范围和容量变化。监控和日志不得输出 token、私钥或解密口令。
